# 功能规格：Windows 内置 Tesseract OCR

**功能分支**：`015-bundle-windows-tesseract`

**创建日期**：2026-06-25

**状态**：Draft

**输入**：用户描述："在windows上，将tesseract-ocr依赖项内置"

## 用户场景与测试 *(必填)*

### 用户故事 1 - Windows 安装后可识别扫描件 PDF (Priority: P1)

Windows 用户安装 pinvou 后，无需手动安装 OCR 组件或配置语言包，即可上传无文字层的扫描件 PDF，并获得由 OCR 提取的文本内容。

**为什么是此优先级**：扫描件 PDF 是当前文件上传解析链路中唯一依赖 OCR 的关键场景。若 Windows 安装包缺少 OCR 组件，用户会遇到解析失败或只能看到依赖缺失提示。

**独立测试**：在一台未安装 Tesseract OCR 的 Windows 机器上安装 pinvou，上传包含中文和英文内容的扫描件 PDF，验证应用能返回可读文本，并标注 OCR 识别可能存在误差。

**验收场景**：
1. **Given** Windows 系统未预装 Tesseract OCR，**When** 用户安装 pinvou 并上传扫描件 PDF，**Then** 系统能够提取 PDF 中的文字内容。
2. **Given** 扫描件 PDF 包含简体中文和英文，**When** 用户上传该文件，**Then** OCR 结果应同时覆盖中文和英文文本。
3. **Given** OCR 识别完成，**When** 结果展示给用户，**Then** 系统应提示内容由 OCR 提取且可能存在识别误差。

---

### 用户故事 2 - 依赖体检不再要求 Windows 用户手动补装 OCR (Priority: P2)

Windows 用户进入依赖体检页面时，不应再看到需要自行安装 Tesseract OCR 的阻断项；如内置 OCR 组件损坏或缺失，应看到指向修复或重新安装 pinvou 的提示。

**为什么是此优先级**：依赖体检是用户理解安装状态的入口。内置依赖后仍提示手动安装会造成误导。

**独立测试**：在干净 Windows 环境安装 pinvou 后打开依赖体检页面，验证 OCR 能力显示为可用；删除或破坏 OCR 组件后重新体检，验证提示指向修复安装而不是第三方手动安装。

**验收场景**：
1. **Given** pinvou 已正常安装，**When** 用户打开依赖体检页面，**Then** OCR 项应显示可用或不再要求手动安装 Tesseract OCR。
2. **Given** 内置 OCR 组件缺失，**When** 用户上传扫描件 PDF 或运行依赖体检，**Then** 系统应给出清晰的修复建议。

---

### 用户故事 3 - 维护者可复现 Windows OCR 安装验收 (Priority: P3)

维护者需要能确认 Windows 安装包包含 OCR 必需内容，并能在安装后通过扫描件 PDF 样本完成验收。

**为什么是此优先级**：OCR 组件包含可执行程序、语言数据和许可信息，若缺少可复现验收步骤，后续打包容易出现回归。

**独立测试**：维护者按发布验收说明检查安装目录中的 OCR 组件、许可文件和语言数据，并使用样本扫描件 PDF 完成端到端解析。

**验收场景**：
1. **Given** 维护者拿到 Windows 安装包，**When** 完成安装并检查安装目录，**Then** 可确认 OCR 运行所需文件和许可说明存在。
2. **Given** 发布验收样本包含扫描件 PDF，**When** 维护者执行上传测试，**Then** 可记录 OCR 识别成功、失败或质量不足的明确结果。

### 边界情况

- Windows 机器已安装系统级 Tesseract OCR 时，应用仍应优先保持自身安装后的可用性，不依赖用户的全局环境配置。
- OCR 组件或语言数据缺失、损坏、不可执行时，系统应返回可理解的修复提示，不应静默失败。
- 扫描件 PDF 页数较多时，仍沿用既有页数限制和截断提示，避免长文档导致处理时间过长。
- 非扫描件 PDF 仍优先使用文字层解析，不应因为内置 OCR 而降低已有解析质量。
- 普通图片上传的当前处理策略不在本 feature 范围内，不恢复为 Tesseract OCR 预解析主路径。
- Linux 依赖安装和体检行为保持现状，不因 Windows 内置 OCR 而改变。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 在 Windows 安装后提供扫描件 PDF OCR 所需的离线组件，使用户无需手动安装第三方 OCR 软件即可完成扫描件 PDF 文本提取。
- **FR-002**: 系统 MUST 支持简体中文和英文 OCR 识别能力；若中文识别能力不可用，必须向用户或维护者暴露明确的不可用原因。
- **FR-003**: 系统 MUST 在 Windows 运行时优先使用随应用安装的 OCR 能力，避免依赖用户系统 PATH 中是否存在 OCR 程序。
- **FR-004**: 系统 MUST 在依赖体检中正确反映 Windows OCR 能力状态；正常安装时不得提示用户手动安装 Tesseract OCR。
- **FR-005**: 系统 MUST 在内置 OCR 组件缺失、损坏或无法运行时给出可执行的修复建议，例如修复安装或重新安装 pinvou。
- **FR-006**: 系统 MUST 保留现有 PDF 解析顺序：有文字层的 PDF 使用文字层结果，无文字层或空结果时才进入 OCR 兜底。
- **FR-007**: 系统 MUST 在 Windows 安装包或随附材料中包含 OCR 组件的许可说明和来源说明，便于发布合规审查。
- **FR-008**: 系统 MUST 提供可复现的 Windows 验收方式，覆盖安装后 OCR 组件存在性检查和扫描件 PDF 上传解析。

### 关键实体

- **OCR 运行时组件**：Windows 安装后随 pinvou 可用的 OCR 执行能力，包含运行所需程序、配置和辅助文件。
- **OCR 语言数据**：用于识别简体中文和英文文本的语言资源，是扫描件 PDF 识别质量的关键前提。
- **扫描件 PDF**：无可提取文字层、需要先转为页面图像再识别文字的 PDF 文件。
- **依赖体检项**：用户在设置页面看到的解析能力状态，用于判断 OCR 能力是否可用以及如何修复。
- **许可说明**：随内置组件分发所需的版权、许可证和来源信息。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 在未预装 Tesseract OCR 的 Windows 测试机上，安装 pinvou 后上传标准扫描件 PDF，OCR 文本提取成功率达到 100%。
- **SC-002**: 对包含简体中文和英文的 3 页以内扫描件 PDF，用户从上传到看到 OCR 文本结果的时间不超过 30 秒。
- **SC-003**: Windows 依赖体检在正常安装后不再把 OCR 标记为需用户手动补装，测试覆盖率达到 100% 的目标安装场景。
- **SC-004**: 当 OCR 组件被人为移除或破坏时，用户看到的错误信息能够在一次阅读内定位到修复安装或重新安装 pinvou，且不会出现空白失败。
- **SC-005**: 发布验收记录能够确认 OCR 组件、中文和英文语言数据、许可说明均随 Windows 安装包交付。

## 假设

- Windows OCR 内置范围仅覆盖当前项目实际使用的扫描件 PDF 兜底链路。
- Windows 安装包体积增加是可接受的，但后续计划阶段需要评估最小可用组件集和压缩策略。
- Poppler 已在 Windows 安装包内置，扫描件 PDF 转图能力可复用现有交付能力。
- OCR 识别质量受扫描件清晰度、排版、语言混杂和图像质量影响，本 feature 目标是保证依赖可用和流程可完成，不承诺人工级识别准确率。
- Linux 仍通过系统包管理器安装 OCR 依赖，不纳入本 feature 改造范围。
