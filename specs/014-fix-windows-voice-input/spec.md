# 功能规格：修复 Windows 语音输入

**功能分支**：`014-fix-windows-voice-input`

**创建日期**：2026-06-24

**状态**：Draft

**输入**：用户描述：“windows下，语音输入功能不可用，请查明原因，并修复此问题”

## 用户场景与测试 *(必填)*

### 用户故事 1 - Windows 用户可以完成语音输入 (Priority: P1)

Windows 用户在聊天输入区点击语音输入入口后，可以授权麦克风、开始说话、停止录音，并将识别出的文本填入或发送到当前输入框。

**为什么是此优先级**：语音输入是直接影响对话入口的核心交互；在 Windows 版本不可用会让用户误以为功能损坏或应用权限异常。

**独立测试**：在 Windows 安装版或开发版中打开应用，使用可用麦克风完成一次语音输入，验证识别文本进入当前会话的输入区，且没有控制台弹窗、页面卡死或静默失败。

**验收场景**：

1. **Given** Windows 设备存在可用麦克风，**When** 用户点击语音输入并完成一次短句录入，**Then** 应用将识别出的文本呈现在当前输入框中，用户可以继续编辑或发送。
2. **Given** 用户首次使用语音输入，**When** 系统要求麦克风权限，**Then** 应用能够引导用户授权并在授权后继续完成录入。
3. **Given** 用户正在当前会话输入内容，**When** 用户使用语音输入追加文本，**Then** 识别文本不会写入其他会话或丢失当前输入内容。

---

### 用户故事 2 - 失败原因对用户可见 (Priority: P2)

当语音输入因为麦克风不可用、权限被拒绝、识别服务不可用或其他运行环境问题而无法完成时，用户可以看到明确、可操作的失败提示。

**为什么是此优先级**：语音输入涉及硬件、系统权限和识别能力，多种失败原因需要被区分；清晰提示可以显著降低排查成本。

**独立测试**：在 Windows 中分别禁用麦克风、拒绝权限、断开识别能力所需环境，触发语音输入并验证提示包含下一步处理建议。

**验收场景**：

1. **Given** 麦克风权限被拒绝，**When** 用户启动语音输入，**Then** 应用提示需要开启麦克风权限，而不是静默无响应。
2. **Given** 当前设备没有可用输入设备，**When** 用户启动语音输入，**Then** 应用提示未检测到可用麦克风。
3. **Given** 语音识别过程失败，**When** 用户停止录音或等待结果，**Then** 应用展示失败原因并允许用户重新尝试。

---

### 用户故事 3 - 现有非语音输入不受影响 (Priority: P3)

修复 Windows 语音输入后，文本输入、附件上传、会话切换和普通发送流程保持现有行为。

**为什么是此优先级**：语音输入是输入区增强能力，修复不能破坏用户最常用的文本对话流程。

**独立测试**：在修复后的 Windows 版本中执行普通文本发送、附件上传、会话切换，再执行语音输入，验证各流程互不干扰。

**验收场景**：

1. **Given** 用户已经输入一段文本，**When** 用户取消语音输入，**Then** 原有文本仍保留且可继续发送。
2. **Given** 用户在语音输入期间切换会话，**When** 识别结果返回，**Then** 应用不会把结果写入错误会话。

### 边界情况

- 用户拒绝或撤销麦克风权限。
- Windows 系统没有默认录音设备，或录音设备被其他应用独占。
- 语音输入启动后用户立即取消、停止或切换会话。
- 语音识别返回空文本、超时或异常中断。
- 应用处于安装版、开发版或权限状态不一致的环境中。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 在 Windows 环境中提供可用的语音输入入口，并允许用户从当前聊天输入区启动语音输入。
- **FR-002**: 系统 MUST 在语音输入前或输入过程中处理麦克风权限状态，并在权限不足时给出明确提示。
- **FR-003**: 系统 MUST 在录音、识别、完成、取消和失败状态之间提供可感知的状态反馈。
- **FR-004**: 系统 MUST 将成功识别的语音文本写入用户启动语音输入时所在的当前输入上下文，且不得写入错误会话。
- **FR-005**: 系统 MUST 在语音输入失败时展示可操作的错误信息，覆盖权限拒绝、设备不可用、识别失败和超时等常见场景。
- **FR-006**: 系统 MUST 保持现有文本输入、附件上传和会话切换行为不受语音输入修复影响。
- **FR-007**: 系统 MUST 为 Windows 语音输入修复提供可重复验证的诊断信息，使后续问题能够定位到权限、设备、录音或识别阶段。

### 关键实体 *(涉及数据或文档结构时填写)*

- **语音输入会话**：一次用户从启动录音到取消、失败或文本落入输入框的交互过程；包含所属会话、状态、错误类别和识别文本。
- **麦克风权限状态**：系统对当前应用访问录音设备的授权结果，包括未知、允许、拒绝或不可用。
- **语音识别结果**：由用户语音转换得到的文本内容，可能为空、成功或失败，并与启动语音输入的上下文绑定。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 在具备可用麦克风和必要权限的 Windows 设备上，用户 3 次语音输入中至少 3 次可以完成从启动到文本进入输入框的闭环。
- **SC-002**: 语音输入失败时，用户在 2 秒内看到明确提示，且提示能区分权限、设备或识别失败中的至少一种主要原因。
- **SC-003**: 语音输入修复后，普通文本发送、附件上传和会话切换的核心 smoke 流程通过率为 100%。
- **SC-004**: 在语音输入期间切换会话或取消输入时，识别结果误写入其他会话的次数为 0。

## 假设

- 目标平台为 Windows 桌面版 pinvou，Linux 或其他平台现有行为不在本 feature 范围内。
- 用户设备具备正常工作的麦克风时，应用应能使用系统允许的录音能力完成语音输入。
- 本 feature 的目标是恢复语音输入可用性和可诊断性，不新增长音频文件转写、说话人分离或音频附件解析能力。
- 如果语音识别依赖已有底座能力，本 feature 复用现有能力并修复 Windows 集成问题，不重新设计完整语音识别产品形态。
