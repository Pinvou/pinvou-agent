# 功能规格：Windows 系统监控改为 CPU 卡片

**功能分支**：`023-windows-cpu-monitor`

**创建日期**：2026-07-08

**状态**：Draft

**输入**：用户描述："在 Windows 上，系统监控页，将图形处理器（GPU）一栏的数据监控改为针对 CPU 的监控，需先确定监控数据的项"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 查看 CPU 负载状态 (Priority: P1)

Windows 用户打开系统监控页时，需要在原本图形处理器（GPU）卡片的位置看到 CPU 监控卡片，从而判断当前设备处理器负载是否过高，以及应用自身是否正在占用较多 CPU。

**为什么是此优先级**：Windows 用户不一定有 NVIDIA GPU 或可用的 GPU 监控工具，而 CPU 是所有 Windows 设备都具备且更稳定可观测的资源。

**独立测试**：在 Windows 设备上打开系统监控页，确认原 GPU 卡片不再出现，替换为 CPU 卡片，并展示 CPU 名称、总体 CPU 使用率、应用进程 CPU 使用率、逻辑处理器数和采样时间。

**验收场景**：

1. **Given** 用户在 Windows 上打开系统监控页，**When** 监控数据刷新成功，**Then** 页面显示 CPU 卡片而不是 GPU 卡片。
2. **Given** CPU 采样数据可用，**When** 用户查看 CPU 卡片，**Then** 用户能看到 CPU 名称、总体 CPU 使用率、应用进程 CPU 使用率和逻辑处理器数。

---

### 用户故事 2 - 识别 CPU 数据不可用状态 (Priority: P2)

Windows 用户在系统权限、设备信息或采样失败导致 CPU 数据不可用时，需要看到明确的不可用提示，而不是继续显示 GPU 相关文案或误导性的空值。

**为什么是此优先级**：监控数据失败时的可解释性直接影响用户对系统状态的判断，尤其是在排查卡顿或性能问题时。

**独立测试**：模拟 CPU 采样失败，打开系统监控页，确认 CPU 卡片显示不可用状态，并且页面其它监控区域仍正常显示。

**验收场景**：

1. **Given** CPU 采样失败，**When** 用户打开系统监控页，**Then** CPU 卡片显示 CPU 信息不可用的状态和占位值。
2. **Given** CPU 采样失败，**When** 系统监控页刷新，**Then** RAM、模型服务和应用指标不受 CPU 卡片失败影响。

---

### 用户故事 3 - 保持非 Windows 平台行为不变 (Priority: P3)

维护者需要确认本次需求只改变 Windows 上系统监控页的 GPU 卡片展示，不改变 Linux 等其它平台已有的 GPU 监控体验。

**为什么是此优先级**：Linux 侧已有面向 GPU/vLLM 的监控路径，本次需求只针对 Windows 页面体验，跨平台误改会扩大回归风险。

**独立测试**：在非 Windows 平台打开系统监控页，确认原有 GPU 卡片行为和显示项保持不变。

**验收场景**：

1. **Given** 用户在非 Windows 平台打开系统监控页，**When** 监控数据刷新，**Then** 原 GPU 卡片仍按现有逻辑展示。

### 边界情况

- CPU 名称无法获取时，卡片应保留 CPU 监控位置并显示明确的不可用名称。
- CPU 使用率暂时无法计算时，对应百分比应显示占位值，进度条不应误显示为高负载。
- 应用进程 CPU 使用率不可用时，不应影响总体 CPU 使用率展示。
- 逻辑处理器数无法获取时，应显示占位值，而不是隐藏整个 CPU 卡片。
- 系统监控页每次刷新应使用同一批采样数据，避免同一卡片内不同指标时间点明显不一致。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 在 Windows 上将系统监控页原图形处理器（GPU）卡片替换为处理器（CPU）卡片。
- **FR-002**: Windows CPU 卡片 MUST 展示 CPU 名称或明确的不可用名称。
- **FR-003**: Windows CPU 卡片 MUST 展示总体 CPU 使用率，使用百分比和进度条表达。
- **FR-004**: Windows CPU 卡片 MUST 展示 pinvou3 应用进程 CPU 使用率，使用百分比表达。
- **FR-005**: Windows CPU 卡片 MUST 展示逻辑处理器数量。
- **FR-006**: Windows CPU 卡片 MUST 展示或继承系统监控页当前采样时间，便于用户判断数据新鲜度。
- **FR-007**: Windows CPU 卡片 MUST 移除或替换 GPU 专属文案，包括 GPU、显存、nvidia-smi、核心利用率、温度和功耗等不再适用于 CPU 卡片的展示项。
- **FR-008**: 当任一 CPU 监控项不可用时，系统 MUST 对该项显示占位值或不可用提示，并保持系统监控页其它卡片继续工作。
- **FR-009**: 非 Windows 平台 MUST 保持现有 GPU 卡片和 GPU 监控行为不变。
- **FR-010**: 系统 SHOULD 避免展示 Windows 上不稳定或不可普遍获取的 CPU 温度、CPU 功耗等指标，除非后续明确补充可靠数据来源。

### 监控数据项

- **CPU 名称**：用户可识别的处理器型号或不可用提示。
- **总体 CPU 使用率**：当前设备所有处理器的整体占用百分比。
- **应用进程 CPU 使用率**：pinvou3 当前进程的 CPU 占用百分比。
- **逻辑处理器数量**：当前 Windows 设备可用的逻辑处理器个数。
- **采样时间**：本次监控快照生成或刷新时间。

### 关键实体 *(涉及数据或文档结构时填写)*

- **CPU 监控快照**：一次系统监控刷新中的 CPU 数据集合，包含 CPU 名称、总体使用率、应用进程使用率、逻辑处理器数量和采样时间。
- **系统监控卡片**：系统监控页中的资源展示区域；Windows 下该区域从 GPU 资源改为 CPU 资源，非 Windows 平台保持 GPU 资源。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 在 Windows 测试环境中，100% 的系统监控页加载结果都不再显示 GPU 卡片标题或 nvidia-smi 缺失提示。
- **SC-002**: 在 CPU 数据可用的 Windows 设备上，CPU 名称、总体 CPU 使用率、应用进程 CPU 使用率和逻辑处理器数均能在 2 秒内显示。
- **SC-003**: 在 CPU 部分数据不可用的场景中，系统监控页其它卡片仍能正常刷新，且 CPU 卡片没有误导性的 GPU 文案。
- **SC-004**: 在非 Windows 平台回归测试中，原 GPU 监控卡片展示行为保持不变。

## 假设

- 本 feature 仅要求 Windows 系统监控页替换 GPU 卡片；RAM、模型服务、应用自测指标等其它卡片不在本次范围内。
- CPU 监控项先限定为稳定且普遍可获取的指标：CPU 名称、总体 CPU 使用率、应用进程 CPU 使用率、逻辑处理器数和采样时间。
- CPU 温度、CPU 功耗、单核心明细、CPU 频率等指标暂不纳入本次范围，避免引入不稳定或设备差异较大的展示。
- 非 Windows 平台继续沿用当前 GPU 监控体验。
