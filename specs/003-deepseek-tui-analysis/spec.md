# 功能规格：DeepSeek-TUI 源码职责分析

**功能分支**：`003-deepseek-tui-analysis`

**创建日期**：2026-06-15

**状态**：Draft

**输入**：用户描述：“从源码层面，梳理分析以下，DeepSeek-TUI都做了些什么工作”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 建立底座职责全景 (Priority: P1)

作为刚接手 pinvou3 的 Windows 应用开发工程师，我需要从源码层面理解 DeepSeek-TUI 在项目中承担的底座职责，以便判断哪些能力应复用、哪些能力应在 pinvou3-app 中适配。

**为什么是此优先级**：这是后续维护、迁移和问题定位的基础；如果职责边界不清，容易在 pinvou3 中重复实现底座已有能力。

**独立测试**：阅读产出文档后，维护者可以说清 DeepSeek-TUI 的主要模块、运行时职责、对 pinvou3-app 暴露的能力边界，以及 pinvou3 不应重复实现的能力。

**验收场景**：
1. **Given** 维护者不了解 DeepSeek-TUI，**When** 阅读分析文档，**Then** 能在 10 分钟内获得模块全景和职责分层。
2. **Given** 维护者准备修改聊天、工具、会话或技能能力，**When** 查阅分析文档，**Then** 能判断应优先查看 DeepSeek-TUI 还是 pinvou3-app。

---

### 用户故事 2 - 追踪关键调用链 (Priority: P2)

作为维护者，我需要看到 pinvou3-app 如何调用 DeepSeek-TUI 的关键链路，包括启动、配置构造、会话、消息发送、事件回传、工具执行、技能发现和工作流相关能力。

**为什么是此优先级**：调用链是排查白屏、闪退、会话错乱、工具不可用和工作流异常的关键证据。

**独立测试**：依据文档中的调用链，维护者能从一个前端操作追踪到 Tauri 命令、pinvou3 bridge、DeepSeek-TUI engine、事件回传和会话落盘。

**验收场景**：
1. **Given** 用户点击发送消息，**When** 维护者按文档追踪调用链，**Then** 能定位消息从 UI 到 Engine 再到事件回传的主要节点。
2. **Given** 技能或工具不可用，**When** 维护者按文档查看依赖边界，**Then** 能区分是底座注册/发现问题还是 pinvou3 适配问题。

---

### 用户故事 3 - 沉淀维护注意事项 (Priority: P3)

作为后续迭代负责人，我需要文档明确 DeepSeek-TUI 相关的依赖约束、子模块版本风险、Windows 适配注意事项、测试建议和不应触碰的底座边界。

**为什么是此优先级**：这些信息能降低后续合并主分支、升级底座、打包 Windows 安装包时的回归风险。

**独立测试**：维护者可以根据文档完成一次变更风险检查，确认是否涉及底座 API、子模块指针、会话目录、工具安全策略或运行时配置。

**验收场景**：
1. **Given** 合入上游或主分支代码后，**When** 维护者执行文档中的检查项，**Then** 能发现子模块版本不匹配、锁文件变化或 API 字段不兼容等风险。
2. **Given** 需要新增能力，**When** 维护者查看边界说明，**Then** 能优先选择 SKILL、命令、MCP server 或 pinvou3-app 适配层，而不是重复实现底座能力。

### 边界情况

- DeepSeek-TUI 子模块检出的提交与 pinvou3-app 依赖的 API 版本不一致时，文档必须说明识别方式和影响。
- 源码存在上游通用能力与 pinvou3 fork 专用改动混杂时，文档必须区分二者。
- Windows 环境路径、进程锁、打包产物与运行目录可能影响调用链判断，文档必须单列注意事项。
- 如果某些能力仅在文档或测试中出现，未被 pinvou3-app 当前路径调用，文档必须标明“当前未直接接入”。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 文档 MUST 用中文说明 DeepSeek-TUI 在当前项目中的总体定位、职责边界和与 pinvou3-app 的关系。
- **FR-002**: 文档 MUST 按源码模块梳理 DeepSeek-TUI 的主要能力，包括运行时引擎、配置、协议、工具、会话、技能、MCP、Hooks、命令、工作流、TUI/CLI、发布与扩展集成。
- **FR-003**: 文档 MUST 描述 pinvou3-app 调用 DeepSeek-TUI 的关键链路，至少覆盖启动初始化、配置构造、会话创建/切换、用户消息发送、事件转译、工具/技能发现、工作流子任务。
- **FR-004**: 文档 MUST 标注 pinvou3-app 复用底座能力的边界，并列出不应在 pinvou3-app 重复实现的底座功能。
- **FR-005**: 文档 MUST 总结维护注意事项，包括子模块版本、锁文件、Windows 路径、release exe 进程占用、Rust 工具链、测试入口和升级风险。
- **FR-006**: 文档 MUST 对关键结论附带源码证据，证据可以是文件路径、模块名、关键类型或调用点。
- **FR-007**: 文档 MUST 给出面向后续维护的排查路径，让维护者能按问题类型找到应查看的代码区域。
- **FR-008**: 文档 MUST 明确分析范围，不把 DeepSeek-TUI 全部上游历史、未接入实验能力或外部部署细节扩展成主线内容。

### 关键实体 *(涉及数据或文档结构时填写)*

- **源码模块**：DeepSeek-TUI 工作区中的 crate、目录或重要文件，是分析文档的基础证据单元。
- **调用链**：从 pinvou3-app 的用户操作或启动流程进入 DeepSeek-TUI 底座能力的路径。
- **底座能力**：DeepSeek-TUI 已提供并应被 pinvou3 复用的引擎、工具、会话、技能、MCP、Hooks、Compaction、Cycle、命令路由等能力。
- **维护风险**：升级、合并、打包、运行时路径、进程占用、API 字段变化等会影响 Windows 维护工作的事项。
- **分析文档**：最终面向维护者的中文文档，应能独立阅读并支撑后续计划、任务和实现。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 新维护者阅读文档 10 分钟内，能够准确列出 DeepSeek-TUI 至少 8 类核心能力及其在 pinvou3 中的复用方式。
- **SC-002**: 文档覆盖至少 12 个源码证据点，并且每个关键结论都能追溯到文件、模块或类型。
- **SC-003**: 文档覆盖至少 6 条 pinvou3-app 到 DeepSeek-TUI 的关键调用链，且每条调用链包含入口、底座能力和结果输出。
- **SC-004**: 文档列出至少 8 条维护注意事项或风险检查项，覆盖 Windows、子模块、依赖版本、会话、工具安全和打包运行。
- **SC-005**: 维护者能依据文档完成一次合并后冒烟检查，识别子模块版本不匹配或构建产物被占用等问题。

## 假设

- 本 feature 的目标产物是中文源码分析文档，而不是修改 DeepSeek-TUI 或 pinvou3-app 的业务代码。
- 分析以当前仓库检出的 DeepSeek-TUI 子模块和 pinvou3-app 调用方式为准。
- 文档允许引用必要的英文技术名词、crate 名、类型名、命令名和路径。
- 不在本 feature 范围内：重构 DeepSeek-TUI、升级底座、修复运行时 bug、编写完整开发教程或替代上游官方文档。
