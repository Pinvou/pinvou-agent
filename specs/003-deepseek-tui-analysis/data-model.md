# 数据模型：DeepSeek-TUI 源码职责分析

## 实体：源码模块

**说明**：DeepSeek-TUI 或 pinvou3-app 中可被引用的源码单元。

**字段**：
- `名称`：crate、目录、文件或模块名。
- `路径`：仓库相对路径。
- `职责摘要`：该模块在系统中的主要工作。
- `接入状态`：当前直接接入 / 间接依赖 / 当前未直接接入。
- `证据类型`：文件路径、关键类型、调用点、测试或文档。

**校验规则**：
- 每个被列为关键证据的模块必须有路径。
- 接入状态必须明确，不允许含糊写成“可能使用”。

## 实体：底座能力

**说明**：DeepSeek-TUI 已提供、pinvou3 应优先复用的能力类别。

**字段**：
- `能力名称`：例如 Engine、ToolRegistry、Session、SkillRegistry、MCP、Hooks、Compaction。
- `能力边界`：它负责什么，不负责什么。
- `pinvou3 复用方式`：直接调用、配置注入、事件转译、包装适配或仅遵守边界。
- `不应重复实现事项`：pinvou3-app 中应避免重新造轮子的部分。

**校验规则**：
- 至少覆盖 8 类底座能力。
- 每类能力必须说明 pinvou3 的复用或边界关系。

## 实体：调用链

**说明**：从 pinvou3-app 用户操作或启动流程进入 DeepSeek-TUI 底座能力的路径。

**字段**：
- `场景`：启动、发送消息、切换 session、技能发现、工作流子任务等。
- `入口`：前端动作、Tauri command 或 Rust 初始化点。
- `pinvou3 适配层`：bridge、engine、engine_pool、commands、sessions 等。
- `DeepSeek-TUI 能力`：被调用的类型、Op、registry、manager 或配置。
- `输出/副作用`：事件回传、会话落盘、状态变更、工具执行、子任务启动等。

**校验规则**：
- 至少覆盖 6 条关键调用链。
- 每条调用链必须包含入口、底座能力和结果输出。

## 实体：维护风险

**说明**：接手、合并、升级、打包或运行时可能踩到的问题。

**字段**：
- `风险名称`：例如子模块版本不匹配、release exe 被占用。
- `触发条件`：什么时候容易发生。
- `识别方式`：命令、现象或日志。
- `影响`：编译失败、运行异常、白屏、闪退、会话错误等。
- `建议处理`：检查或规避方式。

**校验规则**：
- 至少列出 8 条维护风险。
- 每条风险必须包含识别方式和建议处理。

## 实体：分析文档

**说明**：最终交付给维护者的中文文档。

**字段**：
- `标题`：DeepSeek-TUI 源码职责分析。
- `目标读者`：pinvou3 Windows 应用开发与维护工程师。
- `范围`：当前仓库源码和 pinvou3 接入方式。
- `章节`：总览、模块职责、调用链、边界、风险、排查路径、后续建议。
- `验收清单`：证据点数量、调用链数量、风险数量、中文可读性。

**校验规则**：
- 必须独立可读，不依赖读者先阅读 Spec Kit 工件。
- 必须明确“不修改业务代码”的交付边界。

## 状态流转

```text
源码扫描 -> 证据归类 -> 调用链整理 -> 风险归纳 -> 文档成稿 -> 契约验收
```
