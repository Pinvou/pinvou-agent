## 用户场景与测试 *(必填)*

### 用户故事 1 - 查询并发现可用更新 (Priority: P1)

作为 Windows 上使用 pinvou3 的用户，我希望应用能够查询当前版本是否存在可用更新，并在存在更新时获得明确的更新信息，以便我可以安全地进入下载和安装流程。

**为什么是此优先级**：更新查询是整个软件更新流程的入口。没有可靠的查询结果，后续下载、安装和反馈都无法被正确触发。

**独立测试**：准备一个返回“有可用更新”的更新信息来源和一个返回“无更新”的来源，分别启动更新检查，验证应用能正确区分两种结果并展示或记录可理解的状态。

**验收场景**：

1. **Given** 当前 Windows 应用版本低于可用更新版本，**When** 用户或系统触发更新检查，**Then** 系统返回可安装更新的信息，包括版本、包地址、包类型和必要校验信息。
2. **Given** 当前 Windows 应用已经是最新版本，**When** 用户或系统触发更新检查，**Then** 系统明确返回无可用更新，不进入下载或安装流程。

---

### 用户故事 2 - 下载并解析更新包 (Priority: P2)

作为 Windows 上使用 pinvou3 的用户，我希望应用能够下载更新包，并从更新包清单中定位实际安装文件，以便安装流程使用正确的安装器而不是依赖人工查找。

**为什么是此优先级**：更新包下载和解析决定安装阶段是否能获得正确文件。若包损坏、清单缺失或安装文件定位错误，更新会失败并影响用户信任。

**独立测试**：提供一个符合约定结构的 zip 更新包，验证系统能完成下载、解压、读取 `FullPack/OtaInfo.json`，并定位和解压出其中声明的 `MSI` 安装文件。

**验收场景**：

1. **Given** 更新查询返回有效下载地址，**When** 用户确认或系统开始下载更新，**Then** 更新包被完整下载到受控位置，并记录下载成功状态。
2. **Given** 已下载的更新包包含 `FullPack/OtaInfo.json`，**When** 系统解析更新包，**Then** 系统根据清单找到正确的 `MSI` 安装文件并准备安装。
3. **Given** 更新包下载失败、包损坏、清单缺失或清单指向的安装文件不存在，**When** 系统处理更新包，**Then** 系统停止安装并记录可反馈的失败原因。

---

### 用户故事 3 - 启动安装并反馈结果 (Priority: P3)

作为 Windows 上使用 pinvou3 的用户和维护人员，我希望应用能够启动更新安装器，在安装器成功启动后退出当前 pinvou 进程，并在升级完成后反馈升级结果，以便更新服务能获知真实升级闭环。

**为什么是此优先级**：安装和反馈是更新闭环的最后阶段。只有安装器成功接管后退出当前进程，才能避免运行中文件占用；只有反馈结果，运维和发布系统才能判断更新质量。

**独立测试**：使用一个有效 `MSI` 安装文件触发安装，验证安装器启动后当前 pinvou 进程退出；在升级完成并再次运行后，验证系统向更新结果接收方提交成功、失败或取消结果。

**验收场景**：

1. **Given** 系统已准备好有效的 `MSI` 安装文件，**When** 用户或系统启动安装，**Then** Windows 安装器被启动，且在确认安装器已启动后当前 pinvou 进程退出。
2. **Given** 升级安装完成并再次启动 pinvou3，**When** 系统检测到存在待反馈的升级结果，**Then** 系统提交升级结果反馈并清理已反馈状态。
3. **Given** 安装器启动失败或升级结果无法确认，**When** 系统处理反馈，**Then** 系统记录失败或未知状态，并在可重试时保留反馈机会。

### 边界情况

- 当前运行环境不是 Windows 时，软件更新流程不得影响非 Windows 平台既有行为。
- 更新查询不可达、超时、返回格式不兼容或返回当前版本不适用时，系统应停止后续步骤并给出可诊断状态。
- 下载过程中网络中断、目标磁盘空间不足或用户取消时，系统应停止安装并保留失败原因。
- 更新包不是 zip、zip 无法解压、`FullPack/OtaInfo.json` 缺失或内容不完整时，系统不得尝试安装未知文件。
- `OtaInfo.json` 指向多个候选文件、相对路径越界或安装文件类型不是 Windows 安装包时，系统应拒绝继续并记录原因。
- 安装器已经启动但当前进程未能正常退出时，系统应避免重复启动多个安装器。
- 升级完成后的首次反馈失败时，系统应允许后续重试，避免永久丢失升级结果。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 在 Windows 环境下提供软件更新流程，覆盖更新信息查询、更新包下载、安装更新文件和反馈更新结果四个阶段。
- **FR-002**: 系统 MUST 在开始下载前判断是否存在适用于当前应用和当前版本的更新。
- **FR-003**: 系统 MUST 在无可用更新、查询失败或更新信息不适用时停止后续更新步骤，并保留可理解的状态。
- **FR-004**: 系统 MUST 使用更新信息中提供的下载位置获取更新包，并能区分下载成功、下载失败、取消和包校验失败。
- **FR-005**: 系统 MUST 仅接受符合约定的 zip 更新包，并将解压内容限制在受控目录内。
- **FR-006**: 系统 MUST 读取更新包中的 `FullPack/OtaInfo.json`，并根据其中声明的信息定位实际的 Windows 安装文件。
- **FR-007**: 系统 MUST 在安装文件缺失、类型不正确、路径不安全或与清单不一致时拒绝启动安装。
- **FR-008**: 用户 MUST 能触发或获得软件更新流程的关键状态，包括检查中、无更新、可更新、下载中、准备安装、安装启动失败和等待反馈。
- **FR-009**: 系统 MUST 在确认 Windows 安装器成功启动后退出当前 pinvou 进程。
- **FR-010**: 系统 MUST 在升级完成后提交升级结果反馈，反馈内容至少能区分成功、失败、取消和未知结果。
- **FR-011**: 系统 MUST 在反馈失败时保留必要状态，以便后续再次运行时重试反馈。
- **FR-012**: 系统 MUST 尽量将本功能范围限制在 Windows 更新相关路径，不改变非 Windows 平台更新行为或 DeepSeek-TUI 底座能力。

### 关键实体 *(涉及数据或文档结构时填写)*

- **更新信息**：描述当前应用是否存在可用更新的结果，包含目标版本、适用范围、下载位置、包类型、大小或校验信息、发布说明和反馈所需标识。
- **更新包**：从更新信息指向位置下载的压缩包，包含更新清单和一个或多个安装资源。
- **更新清单**：更新包内的 `FullPack/OtaInfo.json`，用于声明实际安装文件的位置、类型和版本等信息。
- **安装文件**：更新清单指向的 Windows 安装文件，本 feature 预期为 `MSI` 文件。
- **更新状态**：软件更新流程在四个阶段中的当前状态、进度、错误原因和可重试信息。
- **反馈记录**：升级完成后用于提交结果的记录，包含更新标识、目标版本、结果状态、错误原因和重试状态。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 在 Windows 环境中，使用有效更新信息和有效更新包时，更新流程能从查询进入安装器启动，人工验收 5 次成功率为 100%。
- **SC-002**: 当更新信息返回无可用更新时，系统在 5 秒内给出无更新状态，并且 0 次触发下载或安装。
- **SC-003**: 对符合约定结构的 zip 包，系统能在 10 秒内完成解压、清单读取和 `MSI` 文件定位，前提是包大小和磁盘性能处于常规桌面软件更新范围。
- **SC-004**: 对损坏包、缺失清单、清单路径越界和安装文件缺失 4 类异常包，系统拒绝安装率为 100%，并保留可诊断失败原因。
- **SC-005**: 安装器成功启动后，当前 pinvou 进程在 10 秒内退出，且不会重复启动第二个安装器。
- **SC-006**: 升级完成后的首次运行中，系统能在 30 秒内提交升级结果反馈；若网络不可用，后续恢复网络后可重试反馈。
- **SC-007**: 非 Windows 平台既有行为不因本 feature 改动而发生可观察变化。

## 假设

- 本 feature 面向 Windows 桌面应用更新；非 Windows 更新能力不在本次范围内。
- 更新信息查询和升级结果反馈应与既有 H3C 更新器行为保持兼容；参考项目和样例包用于确认字段语义、状态码和包结构。
- 更新包下载使用普通 HTTP/HTTPS 下载能力；若当前项目已有可复用下载能力，应保持一致的用户体验和错误语义。
- 下载的更新包结构以样例包为基准：zip 内包含 `FullPack/OtaInfo.json`，清单能指向实际 `MSI` 安装文件。
- 本 feature 负责启动安装器并退出当前 pinvou 进程，不负责实现安装器内部安装逻辑。
- 升级结果反馈发生在升级完成后的后续运行或可确认升级结果的时机。
- 本 feature 不修改 DeepSeek-TUI 的 Engine、Session、Commands、MCP、Hooks、Cycle 或 Compaction 等底座能力。
