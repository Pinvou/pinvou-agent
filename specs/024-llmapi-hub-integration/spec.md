# 功能规格：Pinvou 接入 LLM API Hub 中转站

**功能分支**：`024-llmapi-hub-integration`

**创建日期**：2026-07-08

**状态**：Draft

**输入**：用户希望“品悟通过中转站和大模型进行交互”，并提供了 LLM API Hub 文档、Pinvou 用户与 New API 用户/token 的后台绑定方案和额度展示方案；本规格明确采用“首次使用查询既有后台账户并绑定 token”作为落地方式，不由 Pinvou 客户端自动创建 New API 后台账户。

## Clarifications

### Session 2026-07-08

- Q: Pinvou 用户身份如何确定？ -> A: Windows 下直接使用由当前设备 BIOS SN 派生的 `device_binding_id` 作为 `pinvou_user_id`。
- Q: LLM API Hub 中转站接入功能需要覆盖哪些操作系统？ -> A: 仅在 Windows 系统上实现。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 首次使用时查询并绑定中转站资源 (Priority: P1)

在 Windows 系统上，用户第一次使用 AI 助手时，系统基于当前设备 BIOS SN 派生 `device_binding_id`，并以该值作为 `pinvou_user_id`，只查询中转站后台是否已存在对应 New API 用户；若存在，则继续准备 token 绑定并保存加密绑定，若不存在，则返回服务未开通提示，不自动创建 New API 后台账户；用户无需了解 New API 账号或 token。

**为什么是此优先级**：这是本功能的入口能力，决定普通 Pinvou 用户能否无感使用中转站模型服务。

**独立测试**：对一个没有任何本地中转站绑定、但后台已存在 New API 用户的设备发送首条 AI 助手消息，确认系统查询到后台用户后完成 token 绑定并继续完成模型调用；后台不存在时不得创建用户。

**验收场景**：

1. **Given** 当前 Windows 设备可读取有效 BIOS SN、本地没有中转站绑定且后台已存在对应 New API 用户，**When** 用户首次发送 AI 助手消息，**Then** 系统查询到 New API 用户、生成或取得 token、保存加密绑定，并继续通过中转站调用模型。
2. **Given** 后台不存在对应 New API 用户，**When** 用户首次发送 AI 助手消息，**Then** 系统不得创建 New API 用户或 token，并提示 AI 服务尚未开通或联系管理员。
3. **Given** 查询后台用户成功但创建 token 失败，**When** 用户再次触发 AI 助手调用，**Then** 系统应复用已查询到的后台用户并继续补偿创建 token，而不是尝试创建 New API 用户。

---

### 用户故事 2 - 使用 Pinvou 账号调用云端大模型 (Priority: P1)

在 Windows 系统上，已登录 Pinvou 的用户无需输入或查看 New API token，即可在 AI 助手中发起对话；Pinvou 后端根据当前 Pinvou 用户找到对应中转站绑定，使用加密保存的 token 调用 LLM API Hub，并返回与现有助手一致的流式或非流式结果。

**为什么是此优先级**：这是功能的核心价值，验证 Pinvou 能否通过中转站完成真实大模型交互，同时避免用户直接持有模型网关 token。

**独立测试**：为一个已完成中转站绑定的 Pinvou 用户发送一次普通对话，确认用户无需输入 New API token 即可获得模型回复。

**验收场景**：

1. **Given** 已登录 Pinvou 且存在有效中转站绑定，**When** 用户发送一条 AI 助手消息，**Then** 系统通过中转站完成模型调用并在 Pinvou 中展示回复。
2. **Given** 中转站返回鉴权失败，**When** 用户发起 AI 助手调用，**Then** 系统不暴露 token 内容，并提示账号 AI 服务暂不可用。
3. **Given** 管理员禁用了该用户的 AI 服务，**When** 用户发送 AI 助手消息，**Then** 系统阻止调用中转站并展示用户友好的不可用提示。

---

### 用户故事 3 - 用户查看 AI 额度和用量 (Priority: P2)

用户在 Pinvou 中查看自己的本月额度、已用量和剩余额度；Pinvou 展示的是额度快照，中转站负责真实限额、限流和超额拒绝。

**为什么是此优先级**：额度透明度能减少用户困惑，但不阻塞“完成绑定并可调用”的核心目标。

**独立测试**：用户完成一次模型调用后，Pinvou 中的已用量增加、剩余额度减少；若中转站拒绝超额调用，Pinvou 显示明确原因。

**验收场景**：

1. **Given** 用户有 1,000,000 tokens 月额度且已用 120,000 tokens，**When** 用户打开额度信息，**Then** 系统显示本月额度、已使用和剩余额度。
2. **Given** 模型响应包含 usage 信息，**When** 调用成功结束，**Then** Pinvou 更新用户额度快照。
3. **Given** Pinvou 额度快照与中转站真实额度短暂不一致，**When** 中转站拒绝调用，**Then** 以中转站拒绝结果为准并提示用户额度不足或服务受限。

---

### 用户故事 4 - 管理员管理中转站绑定策略和用户状态 (Priority: P2)

管理员可以查看 Pinvou 用户的查询绑定状态、New API 用户/token 标识、额度快照、启用状态和最近调用状态；管理员可以禁用/启用用户 AI 服务、重试失败的查询绑定任务，并调整默认额度、模型权限和限流策略。

**为什么是此优先级**：查询绑定降低了用户侧配置成本，但仍需要后台可观测和可恢复能力，避免个别用户绑定失败后无法定位。

**独立测试**：管理员查看一个查询绑定失败的用户，触发重试后用户恢复可用；禁用某用户后该用户无法继续通过中转站调用模型。

**验收场景**：

1. **Given** 某 Pinvou 用户查询绑定失败，**When** 管理员查看用户 AI 状态，**Then** 能看到失败阶段、最近错误分类和可重试入口。
2. **Given** 一个 Pinvou 用户已完成查询绑定，**When** 管理员禁用该用户 AI 服务，**Then** 该用户的 AI 助手调用被阻止。
3. **Given** 管理员已在后台准备用户并调整默认额度策略，**When** 新设备首次使用 AI 助手，**Then** 系统只查询既有后台用户，并按策略准备 token 绑定。

### 边界情况

- New API 管理接口不可用、鉴权失败、超时或返回 5xx 时，Pinvou 应阻止继续模型调用并记录查询绑定失败原因。
- 查询和 token 绑定过程中发生部分成功时，系统应具备幂等和补偿能力，避免为同一个设备派生身份创建多个有效 token。
- New API token 被撤销、过期或禁用时，Pinvou 应阻止调用并提示 AI 服务暂不可用，不展示敏感凭证。
- 用户额度已耗尽或达到限流时，Pinvou 应展示可理解的额度/限流提示，不显示上游原始敏感错误。
- 模型调用成功但响应缺少 usage 时，Pinvou 应保留调用结果，并标记该次用量待同步或不可计量。
- 中转站模型调用入口不可达、超时或返回 5xx 时，Pinvou 应按模型服务暂不可用处理，并允许用户稍后重试。
- 管理员禁用某 Pinvou 用户 AI 服务时，该用户无法继续通过旧绑定调用中转站。
- 绑定记录被误删或重复创建时，系统应避免多个 Pinvou 用户共享同一个 token，除非管理员明确设置为共享测试资源。
- BIOS SN 读取失败、BIOS SN 与可选绑定校验不一致、后台不存在对应 New API 用户或用户更换设备时，系统不得自动创建后台用户或继续调用中转站，并应提示用户联系管理员处理。
- 在非 Windows 系统上，本功能不得查询绑定、调用中转站或展示可用入口；如后端命令被调用，应返回非 Windows 平台暂不支持的非敏感错误。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 允许 Windows 系统上的用户在不输入 New API 账号或 token 的情况下使用 AI 助手。
- **FR-002**: 系统 MUST 由当前设备 BIOS SN 派生 `device_binding_id`，并直接使用该值作为 `pinvou_user_id`；BIOS SN 不得以明文形式出现在前端、普通日志或用户可导出数据中。
- **FR-003**: 系统 MUST 在 Windows 系统上的用户首次使用 AI 助手且没有有效绑定时，只调用 New API 管理能力查询既有后台用户；后台用户不存在时不得自动创建后台用户或 token。
- **FR-004**: 系统 MUST 为 Pinvou 用户维护唯一的中转站绑定关系，包含 Pinvou 用户身份、设备绑定标识、New API 用户标识、New API token 标识、加密后的 token、额度快照、绑定状态、失败原因和启用状态。
- **FR-005**: 系统 MUST 确保 New API token 不以明文形式出现在 Pinvou 前端、本地缓存、普通日志、错误提示或用户可导出的数据中。
- **FR-006**: 系统 MUST 在模型调用时基于当前 Pinvou 用户和当前设备绑定标识找到对应中转站 token，并通过中转站入口完成模型请求。
- **FR-007**: 系统 MUST 保证查询和 token 绑定流程具备幂等性；同一设备派生身份重复触发首次使用时，不得重复创建多个有效 token，也不得自动创建 New API 用户。
- **FR-008**: 系统 MUST 支持绑定启用/禁用状态；禁用后对应 Pinvou 用户不能继续使用 AI 助手中转调用。
- **FR-009**: 系统 MUST 在模型调用成功后根据响应 usage 更新 Pinvou 侧额度快照，至少包含本月额度、已使用量、剩余量和最近更新时间。
- **FR-010**: 系统 MUST 在中转站拒绝超额或限流请求时，以中转站结果为最终保护，并向用户展示清晰、非敏感的错误提示。
- **FR-011**: 系统 MUST 支持管理员查看用户查询绑定状态、设备绑定状态、绑定状态、额度快照、启用状态、最近调用更新时间和最近失败原因。
- **FR-012**: 系统 MUST 支持管理员对查询绑定失败的用户执行重试或禁用处理。
- **FR-013**: 系统 MUST 兼容中转站当前入口 `https://www.ma-xiao.com/llmapi/v1`，并允许后续迁移到独立子域入口时不影响 Pinvou 前端用户体验。
- **FR-014**: 系统 SHOULD 默认展示 Pinvou 侧额度快照；若快照与 New API 真实额度不一致，应以 New API 拒绝结果为准。
- **FR-015**: 系统 SHOULD 将模型调用错误归类为设备绑定失败、查询绑定失败、鉴权失败、额度不足、限流、服务不可达、上游错误和未知错误，方便前端展示和管理员排查。
- **FR-016**: 系统 MUST 不把 DeepSeek API Key 写入 Pinvou 客户端、Pinvou 代码仓库或普通配置导出中；DeepSeek API Key 仅由中转站后台渠道持有。
- **FR-017**: 系统 MUST 仅在 Windows 系统上实现本功能；非 Windows 系统不得实现 BIOS SN 绑定、查询绑定或中转站模型调用。

### 关键实体 *(涉及数据或文档结构时填写)*

- **Pinvou 用户**：本 feature 中不再依赖独立登录账号，`pinvou_user_id` 直接等于由当前设备 BIOS SN 派生的 `device_binding_id`。
- **设备绑定标识**：由当前设备 BIOS SN 规范化后派生的稳定标识，用作本 feature 的本地用户身份；不得在前端、普通日志或导出数据中暴露 BIOS SN 明文。
- **中转站绑定**：Pinvou 用户、设备绑定标识与 New API 用户/token 的映射，记录绑定状态、启用状态、加密 token、额度快照、失败原因和更新时间。
- **New API 用户**：中转站后台用户，用于隔离额度、限流、日志和模型权限；用户不直接感知。
- **New API Token**：模型网关访问凭证，由 Pinvou 后端使用并加密保存，不下发给前端。
- **查询绑定任务**：首次使用时查询既有 New API 用户、准备 token、设置额度/权限/限流并保存绑定的后台流程，需要支持幂等、失败记录和重试；不得自动创建 New API 用户。
- **额度快照**：Pinvou 展示用的额度视图，包含额度上限、已使用、剩余和最近同步时间；真实拒绝以中转站为准。
- **模型调用记录**：一次 AI 助手请求的用户、模型、状态、消耗和错误分类记录；默认不保存完整 prompt/response。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: Windows 系统上，可读取有效 BIOS SN 且后台已存在对应 New API 用户的新设备首次使用 AI 助手时，95% 的正常中转站管理接口场景可在一次用户请求内完成查询、token 绑定并继续完成模型调用。
- **SC-002**: Windows 系统上，已完成查询绑定的用户可在 95% 的正常网络场景下直接通过 Pinvou 完成 AI 对话，无需输入或查看 New API token。
- **SC-003**: 100% 的前端界面、用户可见错误、本地缓存和普通日志中不出现 New API token 明文。
- **SC-004**: 查询或 token 绑定部分失败时，同一设备派生身份重复触发 3 次不会产生 New API 用户，也不会产生多个有效 token。
- **SC-005**: 模型调用成功后，95% 的调用在 5 秒内更新 Pinvou 侧额度快照；缺少 usage 的调用被明确标记。
- **SC-006**: 当 token 无效、额度不足、限流、查询绑定失败或中转站不可达时，用户看到的错误提示能说明可采取的下一步，且不包含敏感凭证。
- **SC-007**: 管理员可在 2 分钟内定位指定用户是否已完成查询绑定、是否启用、额度是否耗尽、最近一次调用状态以及最近一次绑定失败原因。
- **SC-008**: 在非 Windows 系统上，100% 的本功能入口不可用或返回 `unsupported_platform`，且不会查询或创建 New API 用户、token 或本地中转站绑定。

## 假设

- 中转站已经部署并可通过 `https://www.ma-xiao.com/llmapi/v1` 由 Pinvou 后端访问；独立子域 `llmapi.ma-xiao.com` 不是当前必需项。
- New API 提供可由 Pinvou 后端调用的管理能力，用于查询既有用户、创建或取得 token、设置额度、设置模型权限和限流策略；若查询不到既有用户，用户首次使用将进入未开通/失败状态。
- New API 负责真实额度、限流、日志和超额拒绝；Pinvou 负责用户体验、查询绑定流程、绑定关系和额度快照展示。
- Pinvou 用户体系是主账号体系，用户不需要也不应登录 New API 前端。
- 当前设备必须能读取有效 BIOS SN 才能触发中转站查询和绑定；BIOS SN 仅用于派生设备绑定标识，不作为普通可见信息展示。
- 本 feature 的实现范围仅包含 Windows 桌面端；Linux 和其他非 Windows 平台不在本次交付范围内。
- 默认不保存完整 prompt 和 response，除非后续有明确审计需求并完成隐私与合规评估。
- 本 feature 不包含中转站服务器部署、DeepSeek 渠道配置、Nginx/证书运维和 New API 后台本身的二次开发。
