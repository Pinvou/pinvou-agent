# 快速开始：Windows 全功能测试参考

## 目标

帮助测试人员快速完成一次 Windows 冒烟和主路径回归，确认应用主要功能可用，并定位需要展开专项测试的模块。

## 前置条件

- Windows 测试机已安装当前版本 pinvou3。
- 至少准备一种模型服务场景：可连接或不可连接。
- 准备测试文件：普通文本、图片、PDF 或 Office 文档、压缩包、中文路径文件。
- 若测试更新，准备可用升级包或测试更新服务。
- 若测试工作流和市场，准备可访问网络或对应本地测试源。

## 冒烟流程

1. 启动应用，确认主窗口 10 秒内可交互。
2. 逐一进入聊天、监控、设置、工作流、专家卡、产物和工具市场页面，确认无空白页和崩溃。
3. 在设置页查看模型配置、语言、主题、后端状态、依赖检查和版本信息。
4. 若模型可用，创建新会话并发送一条消息，观察流式回复和取消生成。
5. 新建第二个会话，切换回第一个会话，确认历史内容和忙碌状态不丢失。
6. 添加一个普通文件和一张粘贴图片作为附件，确认附件状态可见。
7. 触发或查看一个产物，执行预览、系统打开和定位文件夹。
8. 进入 Plan 模式，发送一个需要计划的任务，验证计划卡片的接受或丢弃入口。
9. 打开专家卡池，筛选、装备并卸下一张专家卡。
10. 打开工作流页面，查看模板列表；如环境允许，启动一个简单工作流并查看角色状态。
11. 打开工具市场，验证列表加载、已安装状态和安装/卸载入口。
12. 在设置页执行检查更新；如存在测试升级包，继续验证下载、取消或安装路径。

## Windows 专项检查

- 使用包含中文、空格和括号的路径作为工作区、附件和产物路径。
- 在模型服务关闭时启动应用，确认主界面和设置页仍可用。
- 在无 GPU 或监控数据缺失环境打开监控页，确认页面降级展示。
- 对文件、目录和外部 URL 执行系统打开，确认 Windows 正确响应。
- 验证 UAC 场景：更新安装器需要管理员权限时应有授权提示。
- 验证用户拒绝 UAC 或 MSI 启动失败时，应用能展示明确错误且不误报成功。

## 更新专项简表

1. 在旧版本中打开设置页，点击检查更新。
2. 验证无更新、有更新和检查失败三类结果。
3. 有更新时点击下载并安装，观察进度和取消按钮。
4. 下载完成后确认 MSI 以管理员权限启动。
5. MSI 启动成功后确认当前应用退出。
6. 安装完成后确认新版本应用自动启动。
7. 查看设置页版本号是否为目标版本。
8. 断网启动一次，确认升级结果反馈失败不会阻塞主界面。

## 输出建议

测试完成后建议记录：

- Windows 版本、安装包版本、升级前后版本。
- 模型服务类型和可用性。
- 外部依赖安装状态。
- 失败模块、可复现步骤、截图或日志位置。
- 是否涉及中文路径、权限、UAC 或网络环境。
