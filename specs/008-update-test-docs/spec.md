# 功能规格：Windows 全功能测试参考清单

**功能分支**：`010-update-test-docs`

**创建日期**：2026-06-17

**状态**：Draft

**输入**：测试人员需要一份基于当前代码和 UI 交互的 Windows 全功能列表，用于制定测试范围、回归清单和验收口径。

## 用户场景与测试

### 用户故事 1 - 启动应用并完成基础导航 (Priority: P1)

测试人员需要确认 Windows 版本安装后可以正常启动、进入主界面，并能在聊天、监控、设置、工作流、专家卡、产物和工具市场等主要区域之间切换。

**为什么是此优先级**：这是所有功能测试的入口。若启动、主导航或页面切换不稳定，后续聊天、设置、文件、工作流和更新均无法可靠验证。

**独立测试**：在 Windows 测试机上安装应用，启动后逐一进入各主要页面，确认页面可渲染、无空白、无阻塞弹窗、导航状态正确。

**验收场景**：

1. **Given** 应用已安装，**When** 用户从开始菜单、桌面快捷方式或安装目录启动，**Then** 主窗口正常打开并显示默认工作区。
2. **Given** 用户位于任一主页面，**When** 点击侧边栏或顶部入口切换页面，**Then** 对应页面内容显示且当前导航状态更新。
3. **Given** 后端模型服务暂不可用，**When** 用户启动应用，**Then** 应用仍可进入主界面，并在相关状态区域展示不可用信息。
4. **Given** 当前系统为中文 Windows 且路径包含中文用户名或空格，**When** 应用启动并加载用户数据，**Then** 不应出现路径解析失败或界面空白。

---

### 用户故事 2 - 管理聊天会话并完成对话 (Priority: P1)

测试人员需要验证用户可以创建、切换、重命名、删除和恢复会话，可以发送消息、查看流式回复、取消生成、编辑上一轮、保存会话内容，并在多个会话之间保持正确状态。

**为什么是此优先级**：聊天与会话是应用核心体验，也是 DeepSeek-TUI 底座能力在 Windows UI 中的主要承载。

**独立测试**：准备可用模型服务，创建多个会话并执行发送、取消、切换、重命名、删除和重启恢复等操作。

**验收场景**：

1. **Given** 用户点击新建会话，**When** 输入第一条消息并发送，**Then** 会话被创建并进入生成状态。
2. **Given** 模型正在回复，**When** 用户点击停止或取消生成，**Then** 当前回复停止追加，会话状态恢复可输入。
3. **Given** 已存在多个会话，**When** 用户在生成过程中切换到其他会话，**Then** 原会话的忙碌状态、流式内容和未读提示保持正确。
4. **Given** 用户重命名或删除一个会话，**When** 操作完成，**Then** 会话列表立即反映变化，当前会话指向合理。
5. **Given** 用户关闭并重新打开应用，**When** 查看最近会话，**Then** 历史消息、会话标题、产物引用和相关事件保持一致。

---

### 用户故事 3 - 配置模型、语言、主题与系统能力 (Priority: P1)

测试人员需要验证设置页可以展示和保存模型供应商、服务地址、模型名、API Key、搜索配置、语言、主题、系统权限、依赖检查、版本与更新等配置。

**为什么是此优先级**：设置项决定应用是否能连接本地模型、是否能处理文件、是否能完成 Windows 权限与更新流程。

**独立测试**：分别在默认配置、错误配置和有效配置下保存设置，并验证应用重启后配置生效。

**验收场景**：

1. **Given** 用户进入设置页，**When** 修改模型地址、模型名或 API Key，**Then** 保存后配置被持久化，必要时提示重启或自动重启服务。
2. **Given** 模型服务不可达，**When** 用户查看后端状态，**Then** 页面显示明确的不可用状态而不是无限加载。
3. **Given** 用户切换语言或主题，**When** 设置保存并刷新界面，**Then** 主要 UI 文案和视觉主题符合选择。
4. **Given** 用户点击本地 vLLM 探测，**When** 系统存在或不存在本地服务，**Then** 页面分别展示发现结果或未发现提示。
5. **Given** 用户查看系统权限、依赖检查和版本更新区域，**When** 相关能力可用、缺失或失败，**Then** 每个区域都有清晰状态和可执行入口。

---

### 用户故事 4 - 添加附件并查看产物 (Priority: P1)

测试人员需要验证用户可以通过选择、拖拽或粘贴方式添加文件和图片，系统可以识别依赖状态，聊天过程中生成的文本、图片或其他产物可在产物面板中预览、打开和定位。

**为什么是此优先级**：文件输入和产物输出是应用从普通聊天变成工作台的关键能力，Windows 路径、外部工具和文件打开方式都需要重点覆盖。

**独立测试**：使用常见文档、图片、压缩包和包含中文路径的文件执行附件上传和产物查看流程。

**验收场景**：

1. **Given** 用户选择或拖拽文件到输入区，**When** 文件被接收，**Then** 附件列表显示文件名、类型和处理状态。
2. **Given** 用户从剪贴板粘贴图片，**When** 图片保存成功，**Then** 输入区出现图片附件并可随消息发送。
3. **Given** 文件处理依赖缺失，**When** 用户添加需要该依赖的文件，**Then** 页面显示依赖缺失或处理失败信息，并引导检查依赖。
4. **Given** 会话中产生了产物，**When** 用户打开产物面板，**Then** 可看到产物列表、元信息、预览入口、系统打开和定位文件夹入口。
5. **Given** 产物路径包含中文、空格或长路径，**When** 用户点击打开或定位，**Then** Windows 能正确打开目标文件或所在目录。

---

### 用户故事 5 - 使用 Plan 模式、工具调用和用户输入卡片 (Priority: P2)

测试人员需要验证用户可以在计划模式和执行模式之间切换，查看计划卡片、接受或丢弃计划，处理工具调用、工具阻塞、用户输入请求和上下文压缩提示。

**为什么是此优先级**：这些交互决定复杂任务是否可控，也容易出现状态错乱、按钮残留或跨会话串扰。

**独立测试**：构造需要计划、工具调用、用户确认和上下文压缩的对话，逐项验证卡片状态与按钮行为。

**验收场景**：

1. **Given** 用户进入 Plan 模式，**When** 发送需要计划的任务，**Then** 页面展示计划或等待确认的卡片，而不是直接执行不可逆操作。
2. **Given** 页面展示计划卡片，**When** 用户选择接受、丢弃或切换执行模式，**Then** 会话状态与输入区可用性同步变化。
3. **Given** 工具调用正在执行或失败，**When** 用户查看消息流，**Then** 工具卡片能展示执行中、完成、失败或阻塞状态。
4. **Given** 工具请求用户输入，**When** 用户提交或取消输入，**Then** 对话继续或恢复可输入状态，且卡片结果与用户操作一致。
5. **Given** 上下文接近上限，**When** 系统提示或用户手动压缩，**Then** 压缩状态、错误和完成提示可见。

---

### 用户故事 6 - 管理专家卡、技能和会话绑定 (Priority: P2)

测试人员需要验证专家卡池可以浏览、搜索、筛选、装备、卸下、创建、编辑和删除用户自定义卡片；技能列表可以查看详情、示例，并与会话建立或解除绑定。

**为什么是此优先级**：专家卡和技能是应用差异化能力，涉及会话上下文、个人配置和 UI 状态持久化。

**独立测试**：使用内置卡片和自定义卡片分别执行浏览、绑定、卸下和重启恢复操作。

**验收场景**：

1. **Given** 用户打开专家卡池，**When** 按分类、部门或关键词筛选，**Then** 列表展示匹配卡片并保留选中状态。
2. **Given** 用户装备某张专家卡到当前会话，**When** 返回聊天页，**Then** 会话显示当前专家卡，并在后续对话中保持绑定。
3. **Given** 用户创建或编辑自定义专家卡，**When** 保存完成，**Then** 卡片出现在卡池中并可被装备。
4. **Given** 用户删除自定义专家卡，**When** 卡片已被某会话使用，**Then** UI 给出合理结果，不应造成会话无法打开。
5. **Given** 用户查看技能详情或示例，**When** 启动技能会话或解除技能绑定，**Then** 当前会话绑定关系正确更新。

---

### 用户故事 7 - 执行工作流任务 (Priority: P2)

测试人员需要验证工作流页面可以列出模板、创建任务、添加材料、启动或继续执行、查看各角色状态、处理门禁审批、重试或取消角色，并查看角色输出、日志和提示词。

**为什么是此优先级**：工作流是多角色协作入口，涉及状态机、附件、审批、日志和长任务恢复。

**独立测试**：选择一个可执行工作流模板，创建任务并覆盖成功、失败、门禁审批和取消路径。

**验收场景**：

1. **Given** 用户进入工作流页面，**When** 查看模板列表，**Then** 模板名称、说明和可启动入口显示完整。
2. **Given** 用户创建新工作流任务，**When** 输入目标并添加材料，**Then** 任务卡片出现在运行列表中。
3. **Given** 工作流正在运行，**When** 某个角色生成输出、日志或等待审批，**Then** 页面展示对应状态并允许查看详情。
4. **Given** 工作流到达门禁节点，**When** 用户批准或拒绝，**Then** 后续状态按选择推进或终止。
5. **Given** 某角色失败或用户取消角色，**When** 执行重试或取消，**Then** 状态变化清晰且不会影响其他无关运行。

---

### 用户故事 8 - 查看监控、工具市场和系统集成状态 (Priority: P2)

测试人员需要验证监控页能展示后端、模型、GPU、内存或运行状态；工具市场可以列出工具、安装和卸载；系统打开文件、打开目录和外部链接等 Windows 集成行为正常。

**为什么是此优先级**：这些能力用于诊断环境和扩展应用，Windows 外部进程调用、权限和路径处理容易产生平台问题。

**独立测试**：在有无模型服务、有无 GPU、有无网络的环境下分别查看状态，并对市场工具执行安装和卸载。

**验收场景**：

1. **Given** 用户打开监控页，**When** 后端或模型可用，**Then** 页面显示当前连接和资源状态。
2. **Given** 本机无 GPU 或监控数据不可用，**When** 用户查看监控页，**Then** 页面显示不可用或空状态，不应报错崩溃。
3. **Given** 用户进入工具市场，**When** 工具列表加载成功，**Then** 可看到已安装、未安装和操作按钮状态。
4. **Given** 用户安装或卸载工具，**When** 操作完成或失败，**Then** 市场列表状态、错误提示和重试入口正确。
5. **Given** 用户点击打开外部 URL、文件或目录，**When** Windows 执行系统打开，**Then** 目标被正确打开，失败时展示明确错误。

---

### 用户故事 9 - 完成 Windows 更新、安装包和依赖验证 (Priority: P1)

测试人员需要验证设置页中的版本更新能力，包括检查更新、下载更新包、取消下载、启动 MSI 安装、管理员权限、安装后启动应用和升级结果反馈；同时验证依赖检查与安装入口的 Windows 表现。

**为什么是此优先级**：Windows 交付质量直接依赖 MSI 安装和升级路径，更新失败会导致用户停留在旧版本或进入卸载模式。

**独立测试**：使用 0.4.4 到 0.4.5 的升级包或等价测试包，在真实 Windows 环境执行完整升级和失败场景。

**验收场景**：

1. **Given** 用户打开设置页，**When** 点击检查更新，**Then** 页面显示检查中、已是最新、发现新版本或检查失败之一。
2. **Given** 发现新版本，**When** 用户点击下载并安装，**Then** 页面显示下载进度、取消入口和错误反馈。
3. **Given** 下载完成且更新包有效，**When** 系统启动 MSI，**Then** Windows 弹出管理员授权或以管理员权限启动安装器。
4. **Given** MSI 已启动，**When** 应用完成安装器交接，**Then** 当前 pinvou3 进程退出，安装器执行升级安装而不是只显示卸载模式。
5. **Given** MSI 安装完成，**When** 新版本应用启动，**Then** 设置页版本号变为目标版本，并静默反馈升级结果。
6. **Given** 依赖检查发现缺失项，**When** 用户查看或触发安装入口，**Then** 页面显示 Windows 下明确的可用、缺失、安装中、失败或不支持状态。

## 边界情况

- Windows 用户名、工作区路径、附件路径、产物路径包含中文、空格、括号和长路径。
- 模型服务不可达、返回错误、响应超时或流式响应中途断开。
- 用户在生成中切换会话、删除会话、关闭窗口或重启应用。
- 附件体积过大、格式不支持、文件被占用、权限不足或外部解析依赖缺失。
- 产物文件被移动、删除、锁定或由其他程序占用。
- 工作流运行中断、角色失败、门禁长时间未处理、材料追加失败。
- 工具市场网络不可用、安装失败、卸载失败或工具状态与本地文件不一致。
- 更新服务不可用、无更新、有更新但缺少下载地址、下载中断、校验失败、更新包结构异常、MSI 启动失败或用户拒绝 UAC。
- 静默启动任务失败时，不应阻塞主界面或基础聊天能力。
- 中文、英文、日文界面下主要按钮和状态文案不应为空、截断或混用。

## 需求

### 功能需求

- **FR-001**: 应用 MUST 在 Windows 上正常启动主窗口，并允许用户进入聊天、监控、设置、工作流、专家卡、产物和工具市场等主要区域。
- **FR-002**: 应用 MUST 在后端模型不可用时仍保持主界面可用，并在状态区域展示可诊断的信息。
- **FR-003**: 用户 MUST 能创建、加载、切换、重命名和删除聊天会话。
- **FR-004**: 用户 MUST 能发送消息、查看流式回复、取消生成、编辑上一轮并保存会话消息。
- **FR-005**: 系统 MUST 在多个会话同时存在或后台生成时保持每个会话的忙碌、未读、流式内容和输入状态独立。
- **FR-006**: 设置页 MUST 支持查看和保存模型供应商、服务地址、模型名、API Key、搜索配置、语言和主题。
- **FR-007**: 设置页 MUST 提供后端状态、本地服务探测、系统权限、依赖检查、版本与更新等状态入口。
- **FR-008**: 用户 MUST 能通过选择、拖拽或粘贴方式添加文件和图片附件。
- **FR-009**: 系统 MUST 对附件处理成功、处理中、失败或依赖缺失给出可见反馈。
- **FR-010**: 用户 MUST 能查看会话产物列表，并对产物执行预览、系统打开、定位文件夹和独立窗口打开。
- **FR-011**: 用户 MUST 能进入 Plan 模式，查看计划卡片，并接受、丢弃或切换到执行模式。
- **FR-012**: 系统 MUST 展示工具调用、工具失败、工具阻塞和用户输入请求的明确卡片状态。
- **FR-013**: 用户 MUST 能浏览、搜索、筛选、装备和卸下专家卡。
- **FR-014**: 用户 MUST 能创建、编辑和删除自定义专家卡，并在会话中保留专家卡绑定状态。
- **FR-015**: 用户 MUST 能查看技能详情、示例，并启动或解除会话技能绑定。
- **FR-016**: 用户 MUST 能查看工作流模板、创建工作流任务、添加材料并启动或继续运行。
- **FR-017**: 工作流页面 MUST 展示角色状态、输出、日志、提示词、门禁审批、重试和取消入口。
- **FR-018**: 监控页 MUST 展示后端、模型、资源或不可用状态，且在数据缺失时不崩溃。
- **FR-019**: 工具市场 MUST 展示工具列表和安装状态，并支持安装、卸载、失败提示和状态刷新。
- **FR-020**: 应用 MUST 能通过 Windows 系统方式打开文件、目录和外部 URL，并在失败时展示错误。
- **FR-021**: 设置页 MUST 提供版本查看、手动检查更新、发现新版本、下载、取消下载、安装和错误反馈。
- **FR-022**: Windows 更新流程 MUST 使用下载到的 MSI 安装包执行升级安装，并以管理员权限启动安装器。
- **FR-023**: Windows MSI 启动成功后，应用 MUST 退出当前进程，并在安装完成后由安装流程启动新版本应用。
- **FR-024**: 升级完成后的首次启动 MUST 静默反馈升级结果；反馈失败不得阻塞用户进入主界面。
- **FR-025**: 依赖检查入口 MUST 展示 Windows 下依赖可用、缺失、安装中、失败或不支持的明确状态。
- **FR-026**: 应用 MUST 在中文、英文、日文界面下保持主要按钮、状态、错误和空状态文案完整可读。

### 关键实体

- **会话**：聊天上下文，包含标题、消息、生成状态、附件、产物、专家卡绑定、技能绑定和持久化信息。
- **消息/聊天项**：用户输入、助手回复、工具调用、计划卡、用户输入卡、错误和上下文压缩提示。
- **设置**：模型、服务地址、语言、主题、搜索、权限、依赖和更新相关配置。
- **附件**：用户添加到会话的文件或图片，包含来源、类型、处理状态和错误信息。
- **产物**：模型或工具生成的文件、图片或文本结果，包含路径、类型、预览状态和系统打开能力。
- **专家卡/技能绑定**：会话使用的角色能力或技能能力，包含内置项、自定义项和绑定关系。
- **工作流运行**：由模板启动的多角色任务，包含材料、角色状态、输出、日志、门禁和恢复信息。
- **工具市场项**：可安装或卸载的扩展工具，包含来源、安装状态和错误状态。
- **监控快照**：后端、模型、资源和运行状态的只读展示数据。
- **更新任务**：检查、下载、安装和反馈升级结果的状态集合。
- **依赖状态**：外部工具、解析器或系统能力的可用性和安装状态。

## 成功标准

### 可度量结果

- **SC-001**: Windows 安装后，主窗口在 10 秒内进入可交互状态，核心导航页面均可打开。
- **SC-002**: 在模型服务可用环境下，聊天发送、流式回复、取消生成、会话切换和重启恢复通过率达到 95% 以上。
- **SC-003**: 设置保存后重启应用，模型、语言、主题和关键状态入口的显示与保存值一致。
- **SC-004**: 常见附件和粘贴图片流程在正常依赖环境下均能进入可发送或可诊断状态，不出现无反馈失败。
- **SC-005**: 产物预览、打开文件和定位目录在包含中文路径的样本中通过率达到 95% 以上。
- **SC-006**: Plan、工具调用、用户输入、专家卡和工作流关键卡片在成功、失败、取消路径下均无按钮残留或状态串扰。
- **SC-007**: 工具市场、监控、依赖检查和更新服务不可用时，100% 不阻塞主界面和基础聊天入口。
- **SC-008**: Windows 0.4.4 升级到 0.4.5 或等价测试包后，新版本能启动，设置页版本号正确，并完成或保留可重试的升级结果反馈。
- **SC-009**: 中文、英文、日文界面下，主要功能入口、按钮、状态和错误文案无空白、明显截断或乱码。

## 假设

- 本文档是给测试人员使用的 Windows 功能测试参考，不要求测试人员理解内部代码实现。
- 测试环境至少包含一台 Windows 机器，并可分别准备模型可用、模型不可用、网络可用和网络不可用场景。
- Windows 更新测试以当前 MSI 打包和升级路径为准，版本号样例可使用 0.4.4 到 0.4.5 或等价测试包。
- DeepSeek-TUI 的底座能力不在本文档中重新定义；本文档只描述 pinvou3 Windows UI 和桌面集成层可观察行为。
- 本文档不覆盖服务端更新后台、模型训练、远程市场源管理和非 Windows 平台完整回归。
