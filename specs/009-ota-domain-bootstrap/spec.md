**功能分支**：`011-ota-domain-bootstrap`

**创建日期**：2026-06-17

**状态**：Draft

**输入**：用户描述：“Windows 系统下，需要做一个域名引导功能，OTA 升级后台地址通过域名引导获取。参考 H3C.DomainRedirect C# 项目；域名引导后台默认使用 https://bootstrap.magic.h3c.com，并提供配置文件允许用户修改；请求 SN 使用设备 BIOS SN，如果设备 SN 不是以 2198 或 2199 开头，则使用固定 SN 219904A17T4257W00018；域名请求结果中 OTA 地址 key 为 smarthubOta。”

### Session 2026-06-17

## 用户场景与测试 *(必填)*

### 用户故事 1 - OTA 检查使用域名引导地址 (Priority: P1)

作为 Windows 用户，我希望应用检查更新时先通过域名引导获取 OTA 后台地址，再访问对应 OTA 服务，以便更新服务地址可以由后台按设备和环境统一调度。

**为什么是此优先级**：这是该功能的核心价值；没有它，OTA 仍依赖固定后台地址，无法实现后台引导和按设备分流。

**独立测试**：在 Windows 环境中配置一个可控的域名引导服务，使其返回 `smarthubOta` 地址；触发手动检查更新后，验证后续 OTA 查询使用该地址，并且用户能看到“已是最新”或“发现新版本”等正常结果。

**验收场景**：
1. **Given** Windows 应用可访问域名引导服务且服务返回 `smarthubOta`，**When** 用户点击“检查更新”，**Then** 应用使用返回的 OTA 后台地址完成更新信息查询。
2. **Given** 域名引导服务返回的 `smarthubOta` 指向一个有新版本的 OTA 后台，**When** 用户点击“检查更新”，**Then** 应用展示新版本信息，并保持后续下载、安装、反馈流程使用同一 OTA 来源。

---

### 用户故事 2 - 用户可配置域名引导后台地址 (Priority: P2)

作为部署或测试人员，我希望通过配置文件修改域名引导后台地址，以便在测试、预发布或专网环境中无需重新打包应用即可切换引导服务。

**为什么是此优先级**：该能力直接影响交付、测试和现场运维；默认地址满足生产使用，但配置能力是可测试和可维护的前提。

**独立测试**：删除或清空配置后触发更新检查，验证使用默认引导地址；写入自定义引导地址后再次触发检查，验证使用自定义地址。

**验收场景**：
1. **Given** 配置文件不存在，**When** 用户触发检查更新，**Then** 应用使用默认域名引导地址 `https://bootstrap.magic.h3c.com`。
2. **Given** 配置文件包含合法自定义引导地址，**When** 用户触发检查更新，**Then** 应用使用配置文件中的地址，而不是默认地址。
3. **Given** 配置文件包含无效地址，**When** 用户触发检查更新，**Then** 应用忽略该无效配置并使用默认域名引导地址 `https://bootstrap.magic.h3c.com`。

---

### 用户故事 3 - 根据 BIOS SN 确定域名引导请求身份 (Priority: P3)

作为更新后台维护者，我希望域名引导请求使用可信的设备 SN，并在非目标设备上使用固定测试 SN，以便后台能稳定识别目标设备类型并返回正确服务地址。

**为什么是此优先级**：SN 选择会影响后台路由结果；错误 SN 可能导致获取不到正确 OTA 地址或命中错误环境。

**独立测试**：分别模拟 BIOS SN 以 `2198` 开头、以 `2199` 开头、其他前缀、为空或不可读取，验证域名引导请求使用的有效 SN 符合规则。

**验收场景**：
1. **Given** 设备 BIOS SN 为 `2198` 或 `2199` 开头，**When** 应用请求域名引导服务，**Then** 请求使用该 BIOS SN。
2. **Given** 设备 BIOS SN 不是 `2198` 或 `2199` 开头，或无法读取，**When** 应用请求域名引导服务，**Then** 请求使用固定 SN `219904A17T4257W00018`。

### 边界情况

- 配置文件不存在、为空、缺少引导地址或引导地址格式无效时，应使用默认引导地址。
- 实际使用的域名引导地址不可访问时，应给出友好的检查失败提示，不应崩溃或卡死。
- BIOS SN 包含前后空白时，应先规整再判断前缀。
- BIOS SN 为空、不可读取或不符合目标前缀时，域名引导请求应使用固定 SN；后续 OTA 更新接口不得使用固定 SN。
- 域名引导服务返回失败、返回体为空、缺少服务地址数据或缺少 `smarthubOta` 时，应停止本次 OTA 检查并提示更新服务暂不可用。
- 域名引导返回多个服务地址时，本功能只使用 `smarthubOta` 对应的 OTA 地址。
- Linux 和其他非 Windows 系统的现有 OTA 行为不应因本功能改变。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 仅在 Windows OTA 流程中启用域名引导；非 Windows 平台现有更新流程保持不变。
- **FR-002**: 系统 MUST 提供用户可修改的配置文件，用于指定域名引导后台地址。
- **FR-003**: 当配置文件不存在、为空、未配置引导地址或配置的引导地址格式无效时，系统 MUST 使用默认引导地址 `https://bootstrap.magic.h3c.com`。
- **FR-004**: 当配置文件中存在合法引导地址时，系统 MUST 优先使用该地址执行域名引导。
- **FR-005**: 系统 MUST 在每次 Windows OTA 更新信息查询前，先通过域名引导获取 OTA 后台地址。
- **FR-006**: 系统 MUST 获取设备 BIOS SN，并在规整空白后判断是否以 `2198` 或 `2199` 开头。
- **FR-007**: 如果 BIOS SN 以 `2198` 或 `2199` 开头，系统 MUST 使用该 BIOS SN 作为域名引导请求 SN。
- **FR-008**: 如果 BIOS SN 不以 `2198` 或 `2199` 开头，或 BIOS SN 无法获取，系统 MUST 使用固定 SN `219904A17T4257W00018` 作为域名引导请求 SN。
- **FR-008a**: 系统 MUST 在 OTA 更新查询、下载信息查询和升级结果反馈请求中使用设备 BIOS SN；固定 SN `219904A17T4257W00018` 仅允许用于域名引导请求。
- **FR-009**: 系统 MUST 从域名引导结果中读取 key 为 `smarthubOta` 的 OTA 后台地址；key 匹配应兼容大小写差异，以保持与参考组件行为一致。
- **FR-010**: 当 `smarthubOta` 存在且地址有效时，系统 MUST 将其作为本次 OTA 更新信息查询、更新包下载和升级结果反馈的后台来源。
- **FR-011**: 当域名引导失败、结果缺少 `smarthubOta` 或 `smarthubOta` 地址无效时，系统 MUST 不继续访问 OTA 后台，并向用户展示友好的检查失败提示。
- **FR-012**: 系统 MUST 保留现有 OTA 用户体验，包括静默检查不打扰用户、手动检查展示明确结果、下载与安装流程不改变。
- **FR-013**: 系统 MUST 在日志或错误提示中避免不必要地暴露完整设备 SN；需要定位问题时，应优先使用脱敏信息。
- **FR-014**: 应用升级或重装不应主动覆盖用户已经修改过的域名引导配置。

### 关键实体

- **域名引导配置**：表示用户可修改的引导后台地址配置；关键属性包括引导地址、配置来源和有效性状态。
- **设备身份**：表示用于域名引导请求的设备标识；关键属性包括原始 BIOS SN、有效请求 SN、SN 来源和前缀判定结果。
- **域名引导结果**：表示引导后台返回的服务地址集合；关键属性包括服务 key、服务地址和结果有效性。
- **OTA 后台地址**：表示本次 Windows OTA 流程实际使用的后台地址；关键属性包括地址值、来源和是否可用于后续 OTA 步骤。
- **更新检查尝试**：表示一次用户触发或静默触发的检查更新过程；关键属性包括触发方式、引导结果、OTA 查询结果和用户可见状态。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 在域名引导服务可用且返回有效 `smarthubOta` 的测试环境中，100% 的 Windows 手动检查更新使用引导返回的 OTA 地址。
- **SC-002**: 在配置文件缺失、为空或引导地址格式无效场景中，100% 的 Windows 检查更新尝试使用默认引导地址。
- **SC-003**: 在配置文件指定合法自定义引导地址的场景中，100% 的 Windows 检查更新尝试使用自定义引导地址。
- **SC-004**: 在 BIOS SN 分别为 `2198`、`2199`、其他前缀、空值和不可读取的测试场景中，有效请求 SN 的选择结果 100% 符合规则。
- **SC-005**: 域名引导失败或缺少 `smarthubOta` 时，100% 的手动检查更新在 15 秒内返回友好失败提示，且应用保持可继续使用。
- **SC-006**: 本功能上线后，非 Windows 平台现有 OTA 更新测试用例通过率保持 100%。

## 假设

- 本 feature 只覆盖 Windows 下 OTA 后台地址的域名引导，不改变 Linux 或其他平台 OTA 行为。
- 域名引导参考组件的业务契约被视为有效来源；实现阶段可参考其请求身份、返回数据和 key 匹配行为。
- 默认引导后台地址由产品方指定为 `https://bootstrap.magic.h3c.com`。
- 固定 SN `219904A17T4257W00018` 由产品方指定，用于非目标设备或无法获取 BIOS SN 的场景。
- MVP 不包含离线缓存或使用旧 OTA 地址兜底；域名引导不可用时，本次更新检查失败但不影响应用其他功能。
- 配置文件的编辑入口可以是外部文件编辑方式；是否提供 UI 编辑入口不在本 feature 的必需范围内。
