# 功能规格：Windows 内置 7z

**功能分支**：`017-bundle-windows-7z`

**创建日期**：2026-06-25

**状态**：Draft

**输入**：用户描述：“Windows下内置7z，源文件使用 C:\Program Files\7-Zip”

## 用户场景与测试 *(必填)*

### 用户故事 1 - Windows 用户直接导入压缩包 (Priority: P1)

Windows 用户在新安装或升级后的 Pinvou3 中上传 zip、rar 或 7z 附件时，无需预先安装 7z/p7zip，也能完成压缩包内容解析，并看到压缩包内可识别文件的汇总内容。

**为什么是此优先级**：压缩包上传是现有文件导入能力的一部分；Windows 用户如果缺少外部 7z，会遇到上传失败或依赖缺失提示，破坏开箱即用体验。

**独立测试**：在没有系统级 7z 命令的 Windows 环境中安装应用，上传包含文本、PDF 或 Office 文件的 zip/rar/7z 压缩包，确认应用能解析内部文件并展示结果。

**验收场景**：

1. **Given** Windows 设备没有预装 7z，**When** 用户上传 zip 压缩包，**Then** 应用成功列出并解析压缩包内支持的文件。
2. **Given** Windows 设备没有预装 7z，**When** 用户上传 rar 或 7z 压缩包，**Then** 应用不提示用户安装 p7zip，并按现有压缩包规则处理内容。

---

### 用户故事 2 - 依赖体检不再误导 Windows 用户 (Priority: P2)

Windows 用户打开依赖体检页面时，不应再看到压缩包能力缺少 p7zip/7z 的修复项；应用应表达压缩包解析能力已随 Windows 安装包提供。

**为什么是此优先级**：依赖体检是用户判断安装是否完整的入口；如果 Windows 已内置能力但体检仍提示缺失，会造成错误操作和支持成本。

**独立测试**：在没有系统级 7z 的 Windows 环境中打开依赖体检，确认压缩包项不再要求用户自行安装外部 p7zip。

**验收场景**：

1. **Given** Windows 设备没有系统级 7z，**When** 用户运行依赖体检，**Then** 压缩包能力不显示为缺失外部依赖。

---

### 用户故事 3 - 非 Windows 平台行为保持稳定 (Priority: P3)

Linux 等非 Windows 用户继续按当前方式使用系统提供的 7z/p7zip 解析压缩包，现有依赖体检和安装提示不发生非预期变化。

**为什么是此优先级**：该需求的目标是补齐 Windows 分发能力，不应影响 Linux 上已验证的一键安装和系统依赖策略。

**独立测试**：在 Linux 环境中检查依赖体检和压缩包上传逻辑，确认仍按现有系统依赖方式工作。

**验收场景**：

1. **Given** Linux 设备缺少 7z，**When** 用户运行依赖体检，**Then** 应用仍提示安装当前支持的压缩包依赖。

### 边界情况

- Windows 安装包中压缩包解析资源缺失或损坏时，应用应给出明确错误，而不是静默失败。
- 压缩包为空、格式损坏、密码保护或超出安全限制时，应用应沿用现有的友好失败行为。
- 嵌套压缩包仍按当前规则处理，避免递归解压带来的安全和性能风险。
- 非 Windows 平台不得因为 Windows 内置资源而跳过已有系统依赖检查。

## 需求 *(必填)*

### 功能需求

- **FR-001**: Windows 安装后的应用 MUST 在无系统级 7z/p7zip 的情况下支持 zip、rar、7z 压缩包上传解析。
- **FR-002**: Windows 安装包 MUST 随附压缩包解析所需资源，用户不需要手动下载或安装额外压缩包工具。
- **FR-003**: Windows 依赖体检 MUST 不再把压缩包解析能力报告为缺少 p7zip 或系统级 7z。
- **FR-004**: 压缩包解析 MUST 保持现有安全限制，包括解压前预检、条目数量限制、解压后总大小限制和嵌套压缩包处理规则。
- **FR-005**: 当 Windows 随附资源不可用时，系统 MUST 返回可理解的错误信息，说明压缩包解析资源不可用。
- **FR-006**: 非 Windows 平台 MUST 保持现有压缩包依赖检查、提示和安装行为。
- **FR-007**: Windows 上 zip、rar、7z 三类格式的解析结果 MUST 与当前系统级 7z 可用时的用户可见结果保持一致。
- **FR-008**: Windows 安装包 MUST 仅随附压缩包解析必需的 7-Zip 运行文件和许可证/说明文件，不打包 GUI、帮助文档、SFX、卸载器或语言包等非运行必需内容。

### 关键实体 *(涉及数据或文档结构时填写)*

- **压缩包解析能力**：表示应用对 zip、rar、7z 附件的导入和内容汇总能力，包含可用状态、错误提示和安全限制。
- **Windows 随附资源**：表示随 Windows 应用安装一并提供的压缩包解析资源，供应用在没有系统级依赖时使用。
- **依赖体检项**：表示设置页中展示的可选能力状态，需区分 Windows 内置能力和非 Windows 系统依赖。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 在未安装系统级 7z 的 Windows 测试环境中，zip、rar、7z 三类样本压缩包均可完成上传解析。
- **SC-002**: Windows 依赖体检中，压缩包能力不再出现需要用户安装 p7zip/7z 的缺失提示。
- **SC-003**: 对同一组压缩包样本，Windows 内置能力解析出的文件数量和可见内容与系统级 7z 解析结果一致。
- **SC-004**: 损坏、空包、密码保护和超限压缩包均在 5 秒内返回可理解的失败信息或安全拦截信息。

## 假设

- 该功能仅改变 Windows 分发和运行体验；Linux 继续使用当前系统依赖策略。
- 用户已提供可作为 Windows 随附资源来源的 7-Zip 安装目录：`C:\Program Files\7-Zip`。
- 已验证最小运行文件集 `7z.exe` + `7z.dll` 可执行 `7z.exe i` 并保留 zip、7z、RAR/RAR5 支持；许可证和说明文件仍需随附用于合规说明。
- 当前支持的压缩包格式范围保持为 zip、rar、7z，不新增 tar、gz 或其他格式。
- 压缩包内部文件的递归解析能力沿用现有文件导入规则，本 feature 不扩大文件类型覆盖范围。
