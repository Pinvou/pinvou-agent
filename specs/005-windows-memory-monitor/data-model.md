# 数据模型：Windows 系统内存监控

## 系统内存快照

**用途**：表示一次系统内存采样结果，供“系统监控”页展示。

**字段**：

- `total_kib`：系统物理内存总量，单位 KiB，必须大于 0。
- `used_kib`：系统物理内存已用量，单位 KiB，必须小于或等于 `total_kib`。
- `swap_total_kib`：交换空间或页面文件总量，单位 KiB；不可获取时允许为 0。
- `swap_used_kib`：交换空间或页面文件已用量，单位 KiB；不可获取时允许为 0，必须小于或等于 `swap_total_kib`。

**验证规则**：

- 当平台采样成功时，`total_kib > 0`。
- 当平台采样成功时，`used_kib <= total_kib`。
- 当无法获取交换空间信息时，交换空间字段使用 0 降级，不影响物理内存展示。
- 当平台采样失败时，不返回系统内存快照，由监控快照中的 `ram` 为空表示。

## 平台内存采样能力

**用途**：隔离不同操作系统的内存数据来源。

**字段/行为**：

- 当前平台：由编译目标决定。
- 采样结果：返回系统内存快照或空。
- 失败策略：任何读取失败、解析失败或系统能力不可用，都返回空，不向上抛出导致完整监控失败的错误。

**关系**：

- Linux 平台实现负责读取 Linux 内存状态。
- Windows 平台实现负责读取 Windows 内存状态。
- 不支持的平台实现返回空。

## 监控快照

**用途**：系统监控页消费的聚合状态。

**相关字段**：

- `ram`：系统内存快照，可为空。
- `gpu`：GPU 快照，本功能不改变。
- `vllm`：vLLM 快照，本功能不改变。
- `app`：应用信息，本功能不改变。

**状态流转**：

- 打开监控页：前端启动轮询。
- 后端采样成功：`ram` 包含有效系统内存快照。
- 后端采样失败：`ram` 为空，其他字段照常返回。
- 离开监控页：前端停止轮询。
