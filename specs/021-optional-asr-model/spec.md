# 功能规格：ASR 模型可选下载

**功能分支**：`021-optional-asr-model`

**创建日期**：2026-07-06

**状态**：Draft

**输入**：用户描述："把 ASR 模型改成可选下载"

## Clarifications

### Session 2026-07-06

- Q: 是否需要优先复用当前 Linux 的 ASR 按需下载实现并尽量小改动？ -> A: 是，优先沿用 Linux 已有状态检测、按需下载、进度反馈和用户目录模型落点，Windows 改造以对齐该既有模式为主。
- Q: ASR 模型下载应使用哪个可信数据源？ -> A: Windows 默认使用 FunAudioLLM 官方 `SenseVoiceSmall-GGUF` / `fsmn-vad-GGUF` 的 ModelScope 下载源，Hugging Face 作为可配置镜像；下载前后必须按固定文件名、大小和 sha256 校验。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 精简安装并保留语音入口 (Priority: P1)

新用户安装 pinvou3 时，不需要随安装包获取大体积 ASR 模型；安装完成后仍能看到语音相关入口，并在需要使用语音能力时获得清晰的模型获取引导。

**为什么是此优先级**：这是安装包瘦身的核心价值，直接影响下载、分发、升级和首次安装体验。

**独立测试**：使用全新安装环境验证安装包不包含大体积 ASR 模型，安装后打开应用并进入语音相关入口，确认用户能看到模型缺失状态和下一步操作。

**验收场景**：
1. **Given** 用户首次安装 pinvou3 且本机没有 ASR 模型，**When** 用户打开应用，**Then** 应用正常启动，且不会因为模型缺失阻断非语音功能。
2. **Given** 用户进入语音输入或转写入口且本机没有 ASR 模型，**When** 系统检测到模型缺失，**Then** 用户看到模型大小、用途说明、下载操作和取消操作。

---

### 用户故事 2 - 按需获取模型后使用语音能力 (Priority: P2)

需要语音输入或转写的用户，可以在明确知情的情况下下载 ASR 模型；下载完成并通过校验后，语音能力自动变为可用。

**为什么是此优先级**：瘦身不能牺牲核心语音能力，用户需要从缺失状态平滑进入可用状态。

**独立测试**：在无模型环境中触发下载，观察下载进度、取消/重试能力、完成后的可用状态，以及重新启动后的状态保持。

**验收场景**：
1. **Given** 用户确认下载 ASR 模型，**When** 下载进行中，**Then** 用户可以看到明确进度、剩余状态和取消入口。
2. **Given** 模型下载完成，**When** 系统完成可用性校验，**Then** 语音输入或转写入口不再提示模型缺失，并可开始处理用户本地音频。
3. **Given** 用户下载完成后重启应用，**When** 用户再次进入语音入口，**Then** 应用识别已可用模型且不重复要求下载。

---

### 用户故事 3 - 处理下载失败和离线环境 (Priority: P3)

用户处于网络不稳定、下载被取消、模型损坏或离线环境时，系统应保持可恢复状态，并说明语音能力暂不可用而非让用户误以为应用故障。

**为什么是此优先级**：模型变成按需资源后，失败恢复和可解释性决定用户信任。

**独立测试**：模拟网络中断、用户取消、校验失败、磁盘空间不足和离线启动，验证提示、状态和重试路径。

**验收场景**：
1. **Given** 模型下载中断或失败，**When** 用户回到语音入口，**Then** 系统显示失败原因、可重试操作，并保持非语音功能可用。
2. **Given** 本地模型文件不可用或校验失败，**When** 用户尝试使用语音能力，**Then** 系统拒绝使用该模型，提示重新获取模型。

### 边界情况

- 用户拒绝下载模型后，语音能力保持不可用，但其它功能不受影响。
- 下载过程中应用关闭或系统重启后，系统能识别未完成状态，并允许用户继续、重试或清理后重新下载。
- 磁盘空间不足时，系统在开始或继续下载前给出明确提示，避免留下不可解释的损坏状态。
- 模型包损坏、版本不匹配或来源不可验证时，系统不得启用该模型。
- 用户已拥有旧版本内置模型或历史下载模型时，系统能识别是否可继续使用，必要时提示更新。
- 下载源不可用时，系统提供可理解的失败说明和后续重试路径。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 允许主安装包在不包含大体积 ASR 模型的情况下完成安装和启动。
- **FR-002**: 系统 MUST 在语音能力首次需要 ASR 模型时检测模型是否可用，并向用户展示缺失状态。
- **FR-003**: 系统 MUST 在用户下载前展示模型用途、预计大小、下载影响和取消选择。
- **FR-004**: 用户 MUST 能够主动确认、取消、重试 ASR 模型下载。
- **FR-005**: 系统 MUST 在下载期间展示可理解的进度状态，并在中断、取消或失败后保持可恢复状态。
- **FR-006**: 系统 MUST 在启用下载模型前验证模型完整性、来源可信度和版本适配性。
- **FR-007**: 系统 MUST 在模型可用后自动解除语音能力的模型缺失提示，并在后续启动中保持该状态。
- **FR-008**: 系统 MUST 在模型不可用时禁用或降级依赖 ASR 的具体操作，同时保持其它应用功能可用。
- **FR-009**: 系统 MUST 为用户提供查看当前 ASR 模型状态的能力，包括未安装、下载中、可用、失败、需要更新等状态。
- **FR-010**: 系统 MUST 避免在下载、错误提示、日志或诊断信息中暴露用户音频内容或其它隐私数据。
- **FR-011**: 系统 SHOULD 支持清理已下载 ASR 模型，以便用户回收本地磁盘空间。
- **FR-012**: 系统 SHOULD 在存在历史内置模型或历史下载模型时复用可验证且兼容的模型，避免不必要的重复下载。
- **FR-013**: 系统 MUST 优先复用当前 Linux 已有的 ASR 状态检测、按需下载、进度反馈和用户目录模型落点体验；其它平台改造应与该既有模式保持一致，避免重写语音链路或引入独立的并行机制。
- **FR-014**: Windows ASR 模型下载 MUST 默认使用 FunAudioLLM 官方 ModelScope 源 `https://www.modelscope.cn/models/FunAudioLLM/SenseVoiceSmall-GGUF/resolve/master/sensevoice-small-q8.gguf`，并允许通过配置或环境变量切换到 Hugging Face 镜像 `https://huggingface.co/FunAudioLLM/SenseVoiceSmall-GGUF/resolve/main/sensevoice-small-q8.gguf` 或内网镜像。

### 关键实体 *(涉及数据或文档结构时填写)*

- **ASR 模型包**：代表语音识别能力所需的大体积模型资源；关键属性包括名称、用途说明、预计大小、版本、下载来源、镜像来源、完整性状态、可用状态。Windows 默认模型为 `sensevoice-small-q8.gguf`，期望大小 `254208320` 字节，sha256 为 `4ae45c94422de949b387e2e0fb10d7e14e4c42c69db30c3444ecc7d4b844b7c5`。
- **ASR VAD 模型包**：代表 Windows ASR runtime 可选使用的语音活动检测资源；默认来源为 FunAudioLLM 官方 `fsmn-vad-GGUF`，文件名 `fsmn-vad.gguf`，期望大小 `1720512` 字节，sha256 为 `1270f2559c495f4e7b6e739541151027d360761a3fda43fc147034f5719f5479`。该文件体积较小，可继续随 runtime 打包；若后续也改为下载，必须沿用同一来源和校验策略。
- **模型获取任务**：代表一次用户确认后的模型下载过程；关键属性包括开始时间、进度、结果、失败原因、是否可继续或重试。
- **模型状态**：代表当前设备上 ASR 模型的可用性；关键状态包括未安装、获取中、可用、失败、需要更新、已清理。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: Windows 主安装包体积相比包含 ASR 模型的基线减少至少 150 MB。
- **SC-002**: 在无 ASR 模型的全新环境中，95% 的用户可以完成安装并打开非语音功能，不遇到模型缺失导致的阻断。
- **SC-003**: 在网络正常环境中，用户确认下载后，90% 的模型获取流程可以在无需重启应用的情况下进入语音可用状态。
- **SC-004**: 下载失败、取消、离线、模型损坏四类异常场景均能给出明确提示，并提供可执行的下一步操作。
- **SC-005**: 已下载模型的用户在后续启动应用时，语音入口不重复提示下载，除非模型缺失、损坏或需要更新。
- **SC-006**: 用户测试中，80% 以上参与者能够理解为什么语音能力需要额外获取模型，以及取消后哪些能力会暂不可用。

## 假设

- 本 feature 的目标是降低默认安装包体积，同时保留本地 ASR 能力作为可选能力。
- ASR 模型仍用于本地语音处理；本 feature 不改变语音识别能力的隐私边界和本地处理原则。
- 用户在首次需要语音能力时可以接受一次明确的模型获取决策。
- 模型获取来源、版本发布和完整性声明以 FunAudioLLM 官方 ModelScope 仓库为默认可信源；Hugging Face 或内网镜像只能作为相同文件名、大小和 sha256 的镜像来源。
- 本 feature 不负责重新设计语音识别算法，也不负责引入远程语音识别服务。
- 本 feature 不要求把 pandoc、OCR、poppler 等其它大体积资源一并改为可选组件。
- 实施策略默认采取小步改造：复用现有本地 ASR 入口、状态查询、安装触发和进度反馈能力；只有当前机制无法满足 Windows 模型可选下载时，才补充最小必要能力。
