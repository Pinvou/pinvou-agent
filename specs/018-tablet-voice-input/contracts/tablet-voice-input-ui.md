# UI 契约：平板语音输入强化

## 适用范围

本契约约束主聊天界面底部输入区在桌面、触屏平板、横屏、竖屏和输入内容变化时的用户可见行为。它不定义语音识别引擎、后端命令或模型能力。

## 入口可见性

### 桌面体验

- 保留现有输入框、附件按钮、小型语音按钮、模型选择、工具菜单和发送按钮的基本布局。
- 新增主语音入口不得遮挡输入框、消息内容、产物入口或发送操作。
- 若桌面环境不显示主语音入口，原有语音入口必须保持可用。

### 平板触屏体验

- 必须显示一个醒目的主语音入口。
- 主语音入口必须靠近底部输入区，用户能理解它会把识别结果写入当前输入框。
- 主语音入口触控目标不得小于常见手指点击目标，且与相邻操作保持足够间距。
- 主语音入口必须随底部输入区一起参与遮挡保护，最后一条消息不得被按钮覆盖。

## 语音状态

| 状态 | 主语音入口表现 | 用户可用动作 | 输入框要求 |
|---|---|---|---|
| `idle` | 可点击的麦克风入口 | 开始录音 | 保持可编辑 |
| `requesting_permission` | 忙碌或等待权限 | 可取消或等待 | 保持草稿 |
| `recording` | 明显录音中状态 | 结束录音、取消 | 保持草稿 |
| `transcribing` | 处理中状态 | 等待或取消提示 | 保持草稿，不发送 |
| `completed` | 短暂完成反馈 | 编辑、发送、清除 | 识别文本已写入 |
| `failed` | 错误状态 | 重试、关闭提示、文本输入 | 保持可编辑 |
| `cancelled` | 已取消反馈后回到空闲 | 重新录音或文本输入 | 不写入新文本 |

## 输入内容与操作按钮

| 输入状态 | 发送按钮 | 清除按钮 | 语音入口 |
|---|---|---|---|
| 输入框为空且无可发送附件 | 不作为主要操作展示，或展示为禁用态 | 不展示或弱化隐藏 | 可用 |
| 输入框仅包含空白字符 | 不可发送 | 不展示或可清空空白但不占主要区域 | 可用 |
| 输入框存在文本 | 显示且可点击 | 显示且可点击 | 可用，除非正在处理中 |
| 输入框存在语音识别文本 | 显示且可点击 | 显示且可点击 | 可继续补充语音 |
| 存在已解析附件但无文本 | 显示且可点击 | 不清除附件，除非使用附件自己的移除操作 | 可用 |
| 正在录音 | 不得误触发送半成品语音结果 | 不得导致录音状态混乱 | 显示结束录音含义 |
| 正在识别 | 避免重复触发录音 | 可保持不可用或延后清除 | 显示处理中 |

## 清除行为

- 清除按钮只清空输入框文本。
- 清除按钮不得移除附件；附件仍使用自身的移除控件。
- 清除按钮不得取消当前会话、删除历史消息或清除语音状态历史。
- 清除后，发送按钮应回到空内容状态，主语音入口保持可用。

## 发送行为

- 发送按钮必须复用现有发送流程。
- 发送成功后输入框应清空。
- 若当前会话正在生成，发送行为应沿用现有排队策略，不新增额外步骤。
- 发送按钮的可访问名称必须清晰表达“发送”。

## 可访问性

- 主语音入口、发送按钮和清除按钮必须有可理解的可访问名称。
- 录音中、处理中、失败、完成等状态必须能通过文本或语义状态被辅助技术理解。
- 键盘用户应能聚焦并操作新增按钮。
- 颜色变化不得是唯一状态表达方式。

## 布局验收

- 平板竖屏：主语音入口、输入框、发送和清除按钮不得重叠。
- 平板横屏：主语音入口不得遮挡消息列表底部内容。
- 桌面窗口：现有输入区视觉密度和主要操作顺序不得出现明显退化。
- 输入框自动增高时，底部遮挡保护必须随输入区高度同步更新。
