# 功能规格：Windows 兼容性问题扫描与修复

**功能分支**：`004-windows-compat-fixes`

**创建日期**：2026-06-16

**状态**：Draft

**输入**：用户描述：“当前项目原本基于linux开发，项目中存在很多属于linux系统的硬编码的问题，现在我想适配windows系统，请你帮我找出项目中存在的系统兼容性问题，并尝试修复它”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 识别 Windows 兼容性风险 (Priority: P1)

作为刚接手项目的 Windows 应用开发工程师，我需要知道项目中哪些行为、路径、脚本、命令或运行假设仍偏向 Linux，以便判断迁移到 Windows 后哪些问题会影响启动、构建、打包、运行和维护。

**为什么是此优先级**：如果不能先识别风险，就无法判断哪些问题需要修复、哪些只是历史遗留、哪些属于 DeepSeek-TUI 底座边界。

**独立测试**：在完成扫描后，维护者能够获得一份按影响程度分类的兼容性问题清单，每个问题包含现象、影响范围、验证方式和处理建议。

**验收场景**：

1. **Given** 维护者需要在 Windows 上构建和运行项目，**When** 查看兼容性扫描结果，**Then** 能看到与路径分隔符、shell 命令、环境变量、外部工具、权限、进程占用和用户目录相关的问题分类。
2. **Given** 扫描结果包含多个风险，**When** 维护者按优先级阅读，**Then** 能区分必须修复、建议修复、仅记录观察的项目。

---

### 用户故事 2 - 修复高价值低风险问题 (Priority: P2)

作为 Windows 应用开发工程师，我希望优先修复不会大范围改变项目行为的兼容性问题，让项目在 Windows 上更稳定地启动、构建、运行和打包。

**为什么是此优先级**：用户明确希望“尝试修复”，但项目存在 DeepSeek-TUI 底座边界，应优先处理 pinvou3-app 内部的低风险兼容性问题，避免为了迁移而引入新的回归。

**独立测试**：完成修复后，维护者可以在 Windows 上执行关键构建或冒烟步骤，确认修复没有破坏现有主流程。

**验收场景**：

1. **Given** 发现某个兼容性问题可以用跨平台方式表达，**When** 修复完成，**Then** 该行为在 Windows 上不再依赖 Linux-only 假设，并保持原有非 Windows 行为可用。
2. **Given** 某个问题涉及高风险底座逻辑或需要产品决策，**When** 实施阶段评估，**Then** 不应贸然修改，而应记录原因、影响和后续建议。

---

### 用户故事 3 - 建立后续维护验证路径 (Priority: P3)

作为后续维护者，我需要一套可重复的 Windows 兼容性检查和回归验证路径，以便合并主分支或更新 DeepSeek-TUI 子模块后快速发现系统兼容性回退。

**为什么是此优先级**：Windows 适配不是一次性动作；后续合并、打包和底座升级都可能重新引入 Linux 假设。

**独立测试**：维护者可以按文档或任务清单执行最小验证步骤，确认 Windows 兼容性没有明显退化。

**验收场景**：

1. **Given** 项目合并了新的上游或主分支变更，**When** 维护者执行兼容性验证，**Then** 能覆盖启动、构建、运行、路径、外部命令和打包产物等关键点。
2. **Given** 验证发现新问题，**When** 维护者查阅记录，**Then** 能定位问题所属类别和优先级。

### 边界情况

- Linux-only shell 命令被写在文档、测试、脚本或运行时代码中时，需要区分“仅文档示例”“开发脚本依赖”“真实运行路径”。
- 某些底座能力属于 DeepSeek-TUI fork，修复时必须遵守“底座优先”原则，不在 pinvou3-app 重写已有底座能力。
- 某些外部工具本身没有 Windows 原生命令时，应提供清晰检查和降级，而不是假设用户已经安装 Linux 环境。
- 路径包含中文用户名、空格、盘符、UNC 路径、反斜杠或正斜杠混用时，系统应保持可预测行为。
- Windows 上 release exe 被运行中进程占用时，构建或打包流程应能被维护者快速识别原因。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 产出一份 Windows 兼容性问题清单，覆盖路径、shell、外部工具、环境变量、权限、用户目录、进程占用、构建打包和运行时行为。
- **FR-002**: 每个已识别问题 MUST 标注影响范围、风险等级、是否已修复、验证方式和后续处理建议。
- **FR-003**: 系统 MUST 优先修复高价值、低风险、范围清晰的兼容性问题，并保持现有 Linux 行为不被破坏。pinvou3-app 本轮暂不新增 macOS 专属实现，DeepSeek-TUI 底座已有 macOS 代码保持不动。
- **FR-004**: 对于需要产品决策、底座重构或风险较高的问题，系统 MUST 保留记录并说明暂不修复原因。
- **FR-005**: 修复后的项目 MUST 提供可重复的 Windows 验证步骤，至少覆盖构建、启动、基础交互和打包相关路径。
- **FR-006**: 所有新增说明和交付文档 MUST 使用中文表达，英文仅保留技术名词、命令、路径和错误原文。
- **FR-007**: 修复过程中 MUST 避免大范围格式化和无关重构，业务代码变更应聚焦在兼容性问题本身。
- **FR-008**: 若改动涉及 DeepSeek-TUI fork，MUST 判断该改动是通用问题还是 pinvou3 专用问题，并按项目规则记录处理方式。

### 关键实体 *(涉及数据或文档结构时填写)*

- **兼容性问题**：一个会影响 Windows 构建、运行、打包、路径处理或维护体验的风险项；包含类别、现象、影响范围、优先级、修复状态和验证方式。
- **修复记录**：针对某个兼容性问题采取的变更说明；包含修改范围、行为预期、验证结果和剩余风险。
- **验证步骤**：维护者可重复执行的检查流程；包含命令、预期结果和失败时的排查入口。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 扫描结果至少覆盖 8 类 Windows 兼容性问题，并能区分已修复与待观察项。
- **SC-002**: 至少修复 1 个确认存在且低风险的 Windows 兼容性问题；若没有低风险可修复项，必须给出明确证据和原因。
- **SC-003**: 修复后关键验证步骤可在 Windows 环境执行，且不引入新的业务代码编译错误。
- **SC-004**: 文档或记录能让后续维护者在 10 分钟内判断一个新发现问题属于路径、shell、外部工具、构建、打包、运行时或底座边界中的哪一类。
- **SC-005**: 实施完成后，`git status` 中的业务代码改动仅限于 Windows 兼容性修复相关文件。

## 假设

- 当前目标平台以 Windows 桌面维护和打包为主，同时尽量保持非 Windows 平台不退化。
- 本 feature 优先处理当前仓库源码中可验证的问题，不追溯所有历史 commit。
- DeepSeek-TUI 是 agent 底座，pinvou3 不重复实现其已有 Engine、ToolRegistry、Session、SkillRegistry、MCP、Hooks、Cycle、Compaction 等能力。
- 如果问题只出现在文档示例中，默认先记录或修正文档，不把它等同于运行时缺陷。
- 如果问题需要安装额外外部工具，默认先提供检测、提示或降级，不假设用户拥有 Linux shell 环境。
