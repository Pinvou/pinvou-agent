# 数据模型：OS 调度抽象层与 Windows 兼容性修复

## 实体：OS 调度接口

**说明**：业务层调用的统一平台能力入口。

**字段**：

- `接口名称`：例如 `open_target`、`command_exists`、`nvidia_smi_candidates`、`user_home_dir`、`platform_compat_path`、`enable_super_permission`。
- `业务语义`：调用方真正想完成的动作。
- `Windows 行为`：Windows 平台实现或降级。
- `Linux 行为`：现有实现的包装或迁移。
- `其他平台行为`：暂不新增专属实现，统一明确不支持或 fallback。
- `错误语义`：用户可见错误或内部 warning。

**校验规则**：

- 调用方不得直接依赖 `xdg-open`、`pkexec`、`apt-get`、`which` 等平台命令，也不得直接维护平台路径分支。
- 不支持的平台必须返回明确错误。

## 实体：平台路径策略

**说明**：OS 调度层对家目录、临时目录兼容和用户配置路径的统一处理规则。

**字段**：

- `平台`：Windows / Linux / fallback。
- `家目录来源`：例如 `USERPROFILE`、`HOMEDRIVE` + `HOMEPATH`、`HOME`。
- `兼容输入`：例如测试或配置中出现的 `/tmp/...`。
- `归一化结果`：实际返回的 `PathBuf`。
- `业务目录组合方`：例如 `bridge/paths.rs` 继续组合 `~/.pinvou3`、sessions、workflows、bundle 等目录。

**校验规则**：

- `bridge/paths.rs` 不直接出现平台路径调度用的 `cfg` 分支。
- Windows `/tmp/...` 兼容映射集中在 OS 调度层。
- 路径策略不得改变 pinvou3 业务目录布局。

## 实体：平台实现

**说明**：某个 OS 下对调度接口的实际实现。

**字段**：

- `平台`：Windows / Linux / fallback。
- `实现文件`：例如 `os/windows/windows_path.rs`。
- `系统命令`：该平台会调用的命令。
- `安全边界`：allowlist、路径校验、包名白名单、权限限制。
- `保留行为`：与现有 Linux 实现保持一致的点。

**校验规则**：

- Linux 实现应优先复用当前行为。
- Windows 实现不得调用 Linux-only 命令。
- 安装或提权类能力必须有白名单或明确不支持。

## 实体：兼容性问题

**说明**：一个会影响 Windows 构建、启动、运行、打包、路径处理或维护体验的风险项。

**字段**：

- `编号`
- `类别`
- `位置`
- `问题描述`
- `影响范围`
- `优先级`
- `修复状态`
- `是否纳入 OS 抽象层`
- `验证方式`

**校验规则**：

- 已修复项必须说明是否已迁入 OS 抽象层。
- 暂不修复项必须说明原因。

## 实体：验证步骤

**说明**：维护者可重复执行的检查流程。

**字段**：

- `名称`
- `命令或动作`
- `预期结果`
- `失败排查入口`

**校验规则**：

- 至少包含编译检查和静态扫描。
- OS 抽象层新增后，应能扫描业务文件中是否仍直接调用平台命令。

## 状态流转

```text
发现 OS 差异 -> 归类到调度接口 -> Linux 实现包装现有逻辑 -> Windows 实现或降级 -> 调用点改为统一接口 -> 验证
```
