# 功能规格：加密存储大模型 API Key

**功能分支**：`019-encrypt-api-keys`

**创建日期**：2026-06-26

**状态**：Draft

**输入**：用户描述：“当前配置大模型API，key是用明文存储在配置文件里的，这样有风险，我希望能够通过加密存储”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 新配置的 API Key 不再明文落盘 (Priority: P1)

用户在应用设置中配置大模型服务 API Key 后，希望应用能继续正常调用模型，同时本地配置文件中不再出现可直接复制使用的明文 Key。

**为什么是此优先级**：这是该功能的核心安全价值，直接降低凭据泄露风险。

**独立测试**：在干净环境中配置一个测试 Key，保存并重启应用；确认模型配置仍可使用，同时检查用户可访问的配置文件中没有完整明文 Key。

**验收场景**：
1. **Given** 用户打开大模型配置页且尚未保存 Key，**When** 用户输入并保存 API Key，**Then** 应用保存成功并且配置文件中不包含完整明文 Key。
2. **Given** 用户已保存受保护的 API Key，**When** 用户重启应用并发起一次需要该 Key 的模型请求，**Then** 应用能继续使用该 Key 完成请求。

---

### 用户故事 2 - 已有明文 Key 可平滑迁移 (Priority: P1)

已安装用户可能已经在配置文件中保存过明文 API Key。升级后，用户希望不需要重新配置，也不希望明文 Key 长期保留。

**为什么是此优先级**：如果不能迁移旧配置，已安装用户会继续暴露风险或遭遇升级后不可用。

**独立测试**：准备一个包含明文 API Key 的旧配置环境，启动升级后的应用；确认配置仍可用，并且迁移完成后旧配置文件中不再保留完整明文 Key。

**验收场景**：
1. **Given** 本地存在旧版明文 API Key 配置，**When** 用户首次启动升级后的应用，**Then** 应用自动将 Key 转为受保护存储并保留模型调用能力。
2. **Given** 明文 Key 已完成迁移，**When** 用户再次重启应用，**Then** 应用不再重复迁移，也不会重新写入明文 Key。

---

### 用户故事 3 - 用户可安全查看、替换和删除 Key (Priority: P2)

用户在设置页管理大模型 Key 时，希望界面默认隐藏敏感内容，只在明确编辑时输入新 Key，并能清除不再使用的 Key。

**为什么是此优先级**：配置管理体验必须与加密存储配套，否则用户无法判断当前状态或安全地更新凭据。

**独立测试**：保存 Key 后重新进入设置页，确认界面不会展示完整 Key；替换 Key 后旧 Key 不再可用；删除 Key 后应用不再尝试使用该凭据。

**验收场景**：
1. **Given** 已保存 API Key，**When** 用户打开设置页，**Then** 界面只显示“已配置”或掩码状态，不展示完整 Key。
2. **Given** 用户输入新 Key 并保存，**When** 应用之后发起模型请求，**Then** 使用新 Key，并且旧 Key 不再保留为可用凭据。
3. **Given** 用户删除 Key，**When** 保存设置后发起需要该 Key 的模型请求，**Then** 应用提示用户需要重新配置 Key。

---

### 用户故事 4 - 异常情况下不泄露凭据 (Priority: P3)

当受保护凭据不可读取、损坏或当前用户无权访问时，用户希望应用给出清晰提示，而不是把 Key 写回明文或在日志、错误信息中泄露敏感内容。

**为什么是此优先级**：异常路径是凭据泄露的高风险场景，需要明确约束。

**独立测试**：模拟受保护凭据不可读取的状态，确认应用提示重新配置或修复环境，且配置文件、日志、错误提示中没有完整 Key。

**验收场景**：
1. **Given** 已保存的受保护 Key 无法读取，**When** 用户发起模型请求，**Then** 应用提示需要重新配置或恢复凭据访问，不展示或写出完整 Key。
2. **Given** 保存 Key 时发生失败，**When** 应用向用户提示错误，**Then** 错误信息不包含用户输入的完整 Key。

### 边界情况

- 用户从旧版本升级，配置文件中已有一个或多个明文大模型 API Key。
- 用户保存空 Key、删除 Key、替换 Key 或取消编辑。
- 同一台设备存在多个系统用户，某用户不应读取另一个用户保存的受保护 Key。
- 受保护凭据损坏、被系统清理、权限变化或配置文件被手工编辑。
- 日志、诊断包、错误提示、配置导出和调试信息不得包含完整明文 Key。
- 应用离线启动时仍应能读取已保存的本地受保护 Key。

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 在用户保存大模型 API Key 后，避免将完整明文 Key 持久化到普通配置文件中。
- **FR-002**: 系统 MUST 在需要调用大模型服务时，能够使用已保存的受保护 Key，而不要求用户每次重新输入。
- **FR-003**: 系统 MUST 自动识别旧配置中的明文大模型 API Key，并在不破坏用户配置的前提下迁移为受保护存储。
- **FR-004**: 系统 MUST 在迁移成功后移除普通配置文件中的完整明文 Key，或将其替换为不可直接用于认证的占位状态。
- **FR-005**: 系统 MUST 在设置界面默认隐藏完整 Key，仅展示未配置、已配置、需重新配置等安全状态。
- **FR-006**: 用户 MUST 能够替换已保存的大模型 API Key，保存后系统只使用新 Key。
- **FR-007**: 用户 MUST 能够删除已保存的大模型 API Key，删除后系统不得继续使用旧 Key。
- **FR-008**: 系统 MUST 避免在日志、错误提示、诊断数据、配置导出和界面状态中显示完整明文 Key。
- **FR-009**: 当受保护 Key 无法读取或已失效时，系统 MUST 给出可理解的恢复提示，并不得自动降级为明文持久化。
- **FR-010**: 系统 MUST 保持不使用 API Key 的本地模型或无需凭据的配置不受影响。

### 关键实体 *(涉及数据或文档结构时填写)*

- **模型服务配置**：用户为某个大模型服务保存的连接信息，包含服务名称、地址、模型标识、认证状态等非敏感配置。
- **受保护凭据**：与模型服务配置关联的敏感 API Key，仅以受保护形式保存和读取，不在普通配置中展示完整内容。
- **凭据状态**：设置页和调用流程使用的状态信息，例如未配置、已配置、迁移成功、读取失败、需重新配置。
- **迁移记录**：用于确认旧版明文 Key 是否已处理的状态，避免重复迁移或回写明文。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**: 在配置并保存大模型 API Key 后，100% 的普通用户配置文件检查中不得出现完整明文 Key。
- **SC-002**: 对包含旧版明文 Key 的升级环境，首次启动后的迁移成功率达到 95% 以上；失败时 100% 提供明确恢复提示。
- **SC-003**: 已保存 Key 的用户重启应用后，能够在 30 秒内完成一次需要该 Key 的模型连接验证或请求尝试。
- **SC-004**: 设置页中涉及 Key 的展示状态 100% 不显示完整明文 Key。
- **SC-005**: 日志、错误提示和诊断导出抽样检查中，完整 API Key 泄露次数为 0。

## 假设

- 本 feature 范围限定为大模型服务 API Key；搜索服务、反馈服务或其它第三方凭据不在本次范围内。
- 用户已经通过系统账号登录到本机；受保护 Key 默认只需要对当前系统用户可用。
- 本 feature 不改变大模型服务的新增、删除、切换和连接验证业务流程，只改变 Key 的保存、展示、迁移和异常处理方式。
- 对无法迁移或无法读取的 Key，应用以提示重新配置为默认恢复路径，而不是尝试显示或导出旧 Key。
