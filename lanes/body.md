## Summary

Aligns the native **work-mode (plain chat) lane** with the native code lane for shadow-git turn checkpoints and rewind. ACP sessions and scheduled sessions stay excluded; the native code lane keeps its orchestration and semantics, with these deliberate shared-surface changes, all test-covered and documented (§7 for the dialog notes; §12 and in-code comments for the ordinal/gate mechanics): the r4 preview-gating and disclosure notes, the frontendEcho exclusion, the reconciliation gate (with the busy+1 tolerance), and the r7 undo-chip placement parity; web remains desktop-only.

Design basis: the code lane's accepted shadow-git checkpoint model (design doc §12 budgets: 2GB workspace admission, 500MB shadow-repo pressure gate, 200k-entry walk cap, 20-checkpoint LRU). Per-turn cost is the code lane's accepted shape: measured ~0.3–0.6s warm per message on a 100k-file workspace, 5–6s after a large change, inline on the send path with a 120s kill-tree timeout per git call (no cancel/progress feedback; only pure-FS IO is unbounded) (recorded as a known limitation in §12, follow-up candidate).

### Backend (`pinvou3-app/src-tauri/src/app/commands/`)

- **`chat.rs`** — the per-turn snapshot gate switches from `is_code_session` (product-mode axis) to `!is_scheduled && !is_aux_session_id` (lane + aux axes; the aux axis was previously undocumented in this body — r22 minor 4). ACP is rejected at both chat entries (desktop `chat()` and the web seam); unbound sessions snapshot their session-private directory (self-excluded, small).
- **`interaction.rs`** — `accept_plan` gets the same lane gate (plus an explicit ACP rejection) and resolves session roots unconditionally, matching the chat() shape. `compact_now` also rejects ACP session ids with the shared literal (added in the r3 review round: the command is web-access-policy allowlisted and EnginePool is ACP-unaware; compaction never spawns an engine, so the gate is defense-in-depth).

- **`pinvou-cli/crates/cli/src/code.rs`** — `code checkpoints rewind` migrates onto the prepare/pending/apply protocol the GUI uses (r19 M10): a crash between apply and truncate now leaves the pending marker, so a guided retry reuses the FIRST PreRestore (the true pre-rewind state) instead of snapshotting the restored tree and orphaning the undo target. The unmigrated CLI would have bypassed the pending protocol the GUI relies on.
- **`memory.rs`** — `edit_last_turn` rejects ACP session ids with the shared literal (added in the r3 review round): the command is web-allowlisted and its reserve→truncate→resend path genuinely spawns a native engine via `get_or_spawn`, so an ACP session id could rewrite history through the native lane. `ACP_CHAT_LANE_REJECTED` is now shared by six call sites (chat (x2, incl. the chat_with_reservation in-seam check), accept_plan, compact_now, edit_last_turn, web seam).
- **`checkpoints.rs`** — the command family (`list_checkpoints` / `checkpoint_diff` / `rewind_to_turn` / `rewind_undo_state` / `undo_last_rewind`) is ungated by product mode: the new lane predicate is `SessionKind::Chat && !acp_pool.is_acp(id)` (the `is_acp` check injected as a predicate seam so it stays unit-testable). Rejection copy becomes lane-neutral (「仅原生会话支持检查点」); `rewind_undo_state` keeps the soft `Ok(None)` for non-native lanes. All five commands gain `State<AcpPool>`.
- **`remote_control.rs`** — `web_access_chat_for_session` rejects ACP session ids (both web chat entries), closing a lane-widening leak where the web seam could drive a native-engine turn (and snapshot) on an ACP session. The shared rejection literal is hoisted to `ACP_CHAT_LANE_REJECTED`.

### Frontend (`pinvou3-app/src/features/`)

- `checkpoints.js` and `RewindChip.jsx` move from `features/codex/` to `features/conversation/` (shared timeline layer; `components/ModalShell.jsx` after the upstream promotion); `CodexAcpView` re-imports from there.
