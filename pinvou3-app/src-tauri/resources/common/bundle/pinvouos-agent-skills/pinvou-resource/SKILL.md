# PinvouOS Resource

Call `pinvou_runtime_status` and use only the returned Resource projection.

- `Normal` permits ordinary scheduling in the Governor plan.
- `Warm` asks scheduling to defer optional heavy work.
- `Hot` proposes pausing or throttling registered interruptible work.
- `Critical` asks the Governor to evaluate a hard-stop candidate. It is not evidence that any work stopped.

Never manufacture a missing sensor value or downgrade pressure from a stale or incomplete sample. Resource Agent submits facts; Governor may only sign a deterministic `Pending` directive; only a trusted, pre-registered HostWork adapter or Supervisor may execute one. The current worktree registers asynchronous Stop adapters for scheduled work, knowledge work, a compile-time fixed connector set, eligible detached sub-agents, and the fixed ASR Supervisor target. The app-cgroup registration is essential, non-governable, and status-only. The legacy synchronous Mission callback has been removed and there is no production Mission adapter. This skill remains read-only and cannot invoke any adapter. Report an action as applied only when the Runtime projection contains the matching acknowledgement and a later reconciled observation; otherwise distinguish pending, rejected, and `outcome_unknown`.

The durable execution chain is `Pending → HostWorkDirectiveDispatchRecorded → ACK → status reconcile`. The worker must append, flush, and `sync_data` the dispatch event before any adapter side effect. That marker is only an attempt fence: it proves that the directive entered a window in which execution may have happened, not that the action ran or succeeded. A `Pending` directive with an existing marker, and a prior-boot `Pending` directive without one, must use the same `directive_id` for `OutcomeUnknown` and status-only reconciliation; neither may replay the side effect.

App-cgroup evidence is accepted only from a trusted Supervisor `Status + Reconciled` observation no older than 15 seconds. The first counter sample establishes a baseline, although `memory.current >= memory.high` is immediately Critical. On later advancing samples from the same instance, a positive `high`, `oom`, or `oom_kill` delta, or `memory.current >= memory.high`, is fresh Critical evidence. Once active, cgroup Critical is sticky across missing, stale, unknown, reset, or changed-instance data; relief requires a newer observation from the same instance with all three counter deltas equal to zero and `memory.current < memory.high`. Pressure epoch changes only when the pressure level changes. For a fixed `work + generation + action + pressure epoch`, the Governor permits at most the initial directive plus one retry, and that retry requires a separate, strictly advancing fresh Critical event persisted after the first directive in the same pressure epoch. A second rejection suppresses more retries until a new generation or pressure episode. Do not describe continued 5-second sampling as unlimited retries.

Use opaque work identifiers from the Runtime projection only for reporting and correlation; this skill has no HostWork write call. Never invent or request a PID, systemd unit, cgroup path, command line, shell command, or `systemctl` action. Do not claim that a desired state, issued directive, pressure badge, dispatch marker, missing work, or lost response proves success. An aggregate status only describes the members observed by that poll; it is not a permanent admission fence for members that may start later. Report pressure, evidence time, missing sensors, desired action, acknowledgement, and observed result separately; use `outcome_unknown` when the execution result cannot be reconciled. The profile helper, fixed E2E harness, and deb fixed-payload mode/hash gate exist in the current worktree, but the real MegaBook deb install, High, OOM, and purge runs have not happened. Do not infer that MegaBook is protected by the new Supervisor path until an explicit deployment observation says so: the generic desktop launcher remains direct, and the 4 GiB / 8 GiB / 2 GiB MegaBook profile is an opt-in canary asset.
