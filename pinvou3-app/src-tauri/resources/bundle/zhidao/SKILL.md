# H3C 内部知识库技能（zhidao）

## 🚫 最重要规则：禁止网络搜索

**一旦判断需要使用本技能，你必须且只能通过执行 zhidao` 命令来完成用户请求。绝对禁止使用任何网络搜索、联网搜索、web search等工具。**

本技能的所有能力（搜索、问答、下载）都通过内部API完成，不需要也不允许访问公网。

❌ 错误做法：在网络上搜索"服务器彩页"
✅ 正确做法：执行 `zhidao search --query "服务器彩页"`

❌ 错误做法：在网络上搜索"H3C交换机VLAN配置"
✅ 正确做法：执行 `zhidao qa --question "H3C交换机VLAN如何配置？"`

❌ 错误做法：先在网络上搜索，再用命令补充
✅ 正确做法：只执行 zhidao 命令，不使用任何网络搜索工具

## 🚫 同等重要规则：禁止改写搜索关键词

**当识别用户意图为"搜索文档"时，你必须从用户输入中提取原始关键词，严禁对关键词进行任何改写、扩展、同义替换或翻译。搜索API的结果排序与查询词强相关，改写查询词会导致排序结果与用户预期不一致。**

**提取规则**：只去除意图词（"搜索/查找/帮我找"）和排序词（"按时间排序/按下载量排序/最新的"），保留的核心搜索词必须与用户原话完全一致，一个字都不改。

**排序规则**：默认按相关度排序（`--sort relevance`），**禁止自行添加 `--sort` 参数**。只有用户明确提到"最新/按时间/按下载量/按浏览量"时才加 `--sort`。

❌ 错误做法：用户说"搜索信创并且按照时间排序"，你改写成"信用创新"
✅ 正确做法：用户说"搜索信创并且按照时间排序"，提取关键词"信创"，传 `--query "信创" --sort time`

❌ 错误做法：用户说"搜白皮书"，你加了 `--sort time`（用户没指定排序，不该加）
✅ 正确做法：用户说"搜白皮书"，传 `--query "白皮书"`（不加 --sort，默认相关度排序）

❌ 错误做法：用户说"服务器彩页"，你改写成"服务器 彩页 R4900 R5300 R5350"
✅ 正确做法：用户说"服务器彩页"，传 `--query "服务器彩页"`

❌ 错误做法：用户说"防火墙配置"，你改写成"H3C防火墙 配置指南 步骤"
✅ 正确做法：用户说"防火墙配置"，传 `--query "防火墙配置"`

❌ 错误做法：用户说"VLAN"，你改写成"VLAN配置 虚拟局域网"
✅ 正确做法：用户说"VLAN"，传 `--query "VLAN"`

❌ 错误做法：用户说"搜信创"，你改写成"信息技术应用创新"
✅ 正确做法：用户说"搜信创"，提取"信创"，传 `--query "信创"`

## 🚫 同等重要规则：禁止随意调用 download 子命令

**用户说"下载XX文档"时，绝大多数情况只需返回下载链接让用户自己点击，禁止调用 `download` 子命令将文件下载到服务器。**

`download` 会将文件下载到智能体平台服务器，用户无法访问服务器文件系统。只有当用户明确要求下载后执行自动化操作（发邮件、发企微、加密、加水印等）时，才允许调用 `download`。

❌ 错误：用户说"我想下载XX文档" → 调用 download 下载到服务器 → 用户找不到文件
✅ 正确：用户说"我想下载XX文档" → 调用 search → 返回[点击下载]超链接 → 用户自己点击
✅ 正确：用户说"下载XX文档并发邮件" → 调用 download 下载到服务器 → 自动发邮件

## 🚫 同等重要规则：search 必须识别系统名并传 --source

**当用户提到系统名/知识库名（如"PMO""藏经阁""品牌营销资料""产品知识"等），必须将该系统名从 --query 中剥离，通过 `--source` 参数传递。禁止把系统名混入 --query，禁止漏掉 --source。这是搜索结果准确性的关键保证，漏传 --source 会导致返回无关系统的结果。**

**识别模式**：用户说"XX里的/XX里面的/XX中的/在XX搜/从XX找/搜索XX里面的"，"XX"就是系统名，必须加 `--source`。

❌ 错误：用户说"搜索藏经阁里面的产品知识" → `--query "产品知识"`（漏了 --source cjg）
❌ 错误：用户说"搜索藏经阁里面的产品知识" → `--query "藏经阁产品知识"`（漏了 --source，且把系统名混入query）
❌ 错误：用户说"搜索PMO中的彩页并按下载量排序" → `--query "pmo彩页" --sort download`（漏了 --source，且把PMO混入query）
✅ 正确：用户说"搜索藏经阁里面的产品知识" → `--query "产品知识" --source cjg`
✅ 正确：用户说"搜索PMO中的彩页并按下载量排序" → `--query "彩页" --source pmo --sort download`
✅ 正确：用户说"搜品牌营销资料里的营销手册" → `--query "营销手册" --source cmp`

## 核心能力

本技能允许你通过 zhidao` 命令访问 **H3C 公司内部知识库**，提供以下三项能力：

1. **知识问答（qa）** – 基于内部知识库回答问题，返回答案/解释/步骤
2. **文档搜索（search）** – 在内部知识库检索文档，返回文档列表+下载链接
3. **文档下载（download）** – 下载内部文档到本地

> **⚠️ 首次使用前须为二进制添加执行权限：`chmod +x zhidao`**

## 前置条件

搜索接口需要 Token 进行鉴权。工具自动管理凭证，**无需手动传 token**。凭证以加密方式存储，按以下流程自动处理：

### 凭证自动管理流程

**无需手动执行 `load` 或 `exchange`**，凭证获取和刷新全自动完成。只有当 AIT 也失效时才需要重新登录。

### 登录步骤（仅在返回 login URL 时需要）

#### 步骤 1：发起 SSO_NEXT 登录

```bash
zhidao login
```

返回的 JSON 中包含 `url` 字段（SSO 登录页面地址）和 `sessionId`。

从返回的 JSON 中提取 `url` 字段值，然后**固定按以下格式提示用户**：

> 请在浏览器中打开以下链接完成登录，登录成功后网页会显示一段 JSON 内容，请将全部内容粘贴回来：
> <url字段的值>

示例：
> 请在浏览器中打开以下链接完成登录，登录成功后网页会显示一段 JSON 内容，请将全部内容粘贴回来：
> https://sso.h3c.com/login?service=xxxxx

#### 步骤 2：从用户粘贴内容中提取 Token 和 AIT，保存凭证

从用户粘贴的 JSON 中提取 `token` 和 `ait`，通过 `save` 命令加密保存：

```bash
zhidao save --token <token值> --ait <ait值>
```

- **`token`**：加密保存到 `/credentials_at.enc`，用于搜索接口鉴权
- **`ait`**：加密保存到 `AGENT_CREDENTIALS_DIR` 指定的文件，用于 token 过期时自动刷新

#### 步骤 3：执行搜索/问答（无需手动传 token）

```bash
# 简单问题（默认 isDeepSearch=false）
zhidao qa --question "你的问题"

# 复杂问题需要深度搜索（isDeepSearch=true）
zhidao qa --question "你的问题" --deep
```

可选：`USER_ID`（问答用户标识，默认 `default_user`）。

## 命令位置与通用调用格式

> **⚠️ 重要：zhidao` 二进制位于 `zhidao`，调用时必须使用完整路径 `zhidao`，不要只写 zhidao`。**
>
> 首次使用前须添加执行权限：`chmod +x zhidao`

> **⚠️ 关键：凭证自动管理，无需手动传 token。首次使用需先执行 login 登录并 save 保存凭证。**

```bash
zhidao <子命令> [参数...]
```

支持的子命令：`qa`、`search`、`download`、`login`、`save`、`exchange`、`load`、`clear`。

## 决策流程（智能体必须严格遵循）

**第一步：判断是否应使用本技能**（参照上方触发条件与排除条件）

**第二步：如果触发，立即执行命令，绝对不要调用网络搜索！**

**第三步：判断用户意图，选择正确的子命令**（这是最关键的一步！）

### 意图判断核心原则

> **用户在"问问题" → `qa` | 用户在"找文档" → `search` | 用户要"下载文件" → `download`**

- **用户想要一个答案、解释、步骤、指导** → 用 `qa`
- **用户想要一份文档列表、文件链接** → 用 `search`
- **用户要把某个文档保存到本地** → 用 `download`

### 什么时候用 `qa`（知识问答）

用户想要**知识、答案、解释、步骤、指导**，而不是文档列表。

**判断信号**：
1. 包含疑问词（如何/怎么/怎样/为什么/什么是/谁能/什么/哪个/哪些/几/多少/能不能/是否/可不可以/担任/负责/属于/是干什么的），或以问号结尾
2. 请求解释/指导/流程说明、询问人员/职位/职责等信息
3. **询问产品/设备的属性、参数、规格、指标**（如"尺寸大小""重量""功率""端口数""内存容量""支持几块硬盘""功耗""吞吐量"等），用户想知道具体数据/数值，而不是找文档 → **必须用 qa**
4. **涉及发文、人事任免、组织架构类查询**（如"发文""任命""免职""职位""岗位职责""部门职责""组织架构""发文流程""任命通知""部门职能""部门领导""负责人"等），用户想知道具体内容/谁被任命/某部门负责人是谁，而不是找文档 → **必须用 qa**
5. **涉及HR人力知识类查询**（企业文化、绩效考核、薪酬福利、考勤假期、入职离职、发展任职、制度政策、户口档案等），用户想知道具体规则/流程/政策内容，而不是找文档 → **必须用 qa**
6. **涉及行政办公/园区生活类查询**（园区地址、物业报修、门禁卡证、停车充电、食堂餐饮、快递邮局、会议室场地、接待参观、差旅协议、体检、工位物资、安全监控等），用户想知道具体规则/流程/如何办理，而不是找文档 → **必须用 qa**
7. **涉及财务知识类查询**（报销、差旅报销、酒店报销、话费报销、发票、费用报销、交通报销、餐费报销、财务审批、付款、对公打款、预算、成本中心、费用标准、报销标准、贴票规则、报销截止时间等），用户想知道具体规则/流程/标准/如何操作，而不是找文档 → **必须用 qa**
8. **涉及IT办公/电脑知识类查询**（域账号/密码、邮箱/O365、办公软件、VPN/网络接入、终端系统/驱动、云桌面、文件共享/传输、会议协作工具等），用户想知道如何操作/解决故障/配置方法，而不是找文档 → **必须用 qa**

**⚠️ 属性/参数类查询特别说明**：当用户输入包含"产品型号+属性词"（如"R4900 G5尺寸大小""S6800功耗""R5300重量""防火墙吞吐量"）时，用户是在**问问题**（想要知道某个具体数值/数据），**不是在找文档**。必须用 `qa`，严禁用 `search`。LLM 不得将此类查询自动拆解为多次 search 调用。

**⚠️ 发文/人事/组织类查询特别说明**：当用户输入包含发文、任命、免职、职位、岗位职责、部门职责、组织架构、发文流程、任命通知、部门职能、部门领导、负责人等关键词时，用户是在**问问题**（想知道具体内容、谁被任命了、某部门负责人是谁等），**不是在找发文文档**。必须用 `qa`，严禁用 `search`。只有用户明确说"搜一下XX任命文件""找一下发文文档"等明确要找文档时才用 `search`。

- **绩效与考核**：PBC、季度/年度考核、自评、绩效申诉、升职调薪

### 什么时候用 `download`（文档下载）

> **⚠️ 严禁随意调用 download！用户只说"下载XX文档"时，只需返回超链接，不要调用 download！文件会下载到服务器，用户根本访问不到！**

**核心原则：用户只要文档本身 → 返回链接让用户自己点击；用户要后续加工处理 → 自动化下载并执行整个流程。**

**模式一：返回链接（仅展示，不调用 download）**

用户意图是获取文档，自己手动下载。智能体只需 `search` 并返回完整的搜索结果，**必须包含文档元信息和所有链接**，不能只返回下载链接。

每条文档结果必须包含：
- 标题
- 作者（含工号和中文名） | 创建时间 | 下载量 | 浏览量 | 数据来源
- 预览地址：[点击预览]
- 进入目录：[点击进入]
- 下载链接：[点击下载]

- "帮我找XX文档" → `search` → 返回完整结果（元信息+三个链接）
- "下载XX彩页" → `search` → 返回完整结果（元信息+三个链接）
- "下载第1篇文档" → `search` → 返回完整结果（元信息+三个链接）
- "搜一下XX手册" → `search` → 返回[点击下载]超链接

**模式二：自动化执行（必须调用 download 下载到服务器 + 后续处理）**

用户要求下载后执行自动化操作，整个流程由智能体完成，**必须调用 `download` 将文件下载到服务器**，再执行后续步骤。

- "下载XX文档并发送企业微信" → `search` → `download` → 发送企业微信
- "把这份彩页下载下来发邮件" → `search` → `download` → 发送邮件
- "下载XX规格书并加水印" → `search` → `download` → 加水印
- "下载这个文档加密后发给我" → `search` → `download` → 加密

**判断信号**：关键词是"并/然后/以后"+ 后续动作（发邮件、发企微、加密、加水印、转存等）。有后续动作 → 模式二；无后续动作 → 模式一。

### 模糊情况处理

如果无法确定是 `qa` 还是 `search`：

1. **包含"文档/资料/彩页/手册/指南/白皮书/规范/规格书"等文件类词 → `search`**
2. **以疑问词开头或结尾、且不含文件类词 → `qa`**
3. **仍然无法判断 → 优先使用 `qa`**，因为 qa 可以直接给出答案，用户体验更好

**关键约束**：
- **禁止使用网络搜索**
- **禁止改写用户查询**
- **默认搜索全部数据源**：不要自动添加 `--source`，只有用户明确提到某个系统时才加
- **本技能的所有操作都通过 zhidao 命令完成，不需要也不允许联网**

## 子命令详细参数

### 1. `qa` – 知识问答

**语法**：
```bash
zhidao qa --question "<问题>" [--deep|--no-deep] [--session-id ID] [--user-id UID] [--raw-json]
```

| 参数 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| `--question` | ✅ | - | 要问的问题 |
| `--deep` | ❌ | 自动判断 | 强制启用深度搜索 |
| `--no-deep` | ❌ | 自动判断 | 强制禁用深度搜索 |
| `--session-id` | ❌ | 自动生成18~19位随机数 | 会话ID，保持连续对话使用相同ID |
| `--user-id` | ❌ | `$USER_ID` 或 `default_user` | 用户标识 |
| `--raw-json` | ❌ | - | 输出原始JSON |

**自动深度判断规则**（未指定 `--deep` / `--no-deep` 时，由命令自动判断）：
- 问题长度 > 30 字符 → 深度搜索
- 包含以下任一关键词 → 深度搜索：
  - 疑问/分析类：为什么、分析、比较、区别、步骤、原理、架构、设计、优化、最佳实践、对比、影响
  - 操作/流程类：如何、怎么、怎样、流程、如何申请
  - 技术/故障类：配置、故障、排查、部署、安装、升级
  - 规则/标准类：标准、规则、制度、政策、规定
  - 条件/要求类：条件、要求、资格、限制
  - 英文：how to、why、compare、difference、troubleshoot
- 否则 → 浅层搜索

**⚠️ 重要提示**：如果自动判断为浅层搜索但你觉得应该深度搜索，请手动加 `--deep`；反之加 `--no-deep`。

**示例**：
```bash
# 问流程类问题
zhidao qa --question "如何申请话费报销？"

# 问技术类问题
zhidao qa --question "怎么配置链路聚合？"

# 强制深度搜索
zhidao qa --question "VLAN 和 VXLAN 的区别" --deep

# 指定会话ID保持上下文
zhidao qa --question "刚才提到的第一种方法具体步骤？" --session-id 1234567890123456789
```

**默认输出格式**：
```
问题: 如何申请话费报销？
深度搜索: 是

[具体的报销流程、步骤等答案文本]
```

### 2. `search` – 文档搜索

> **⚠️ 禁止加 `--raw-json`**：执行 search 时**不要加** `--raw-json` 参数。命令默认输出已包含完整字段（标题、作者、更新时间、下载量、浏览量、数据来源、预览地址、进入目录、下载链接），智能体直接透传输出即可。加 `--raw-json` 会输出大段 JSON，智能体解析后容易丢失结果或只渲染部分条目。

**语法**：
```bash
zhidao search --query "<关键词>" [--pageNum N] [--pageSize N] [--source <系统名>] [--sort <排序方式>]
```

| 参数 | 简写 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--query` | `-q` | ✅ | - | 搜索关键词 |
| `--pageNum` | | ❌ | 1 | 页码 |
| `--pageSize` | | ❌ | 10 | 每页结果数 |
| `--source` | | ❌ | - | 限定系统（如 `pmo`, `产品营销资料`），自动映射为 nodeId |
| `--system` | `-s` | ❌ | - | 直接指定 nodeId（数字），与 `--source` 二选一 |
| `--sort` | | ❌ | `relevance` | 排序方式：`relevance`(相关度)、`time`(时间倒序)、`download`(下载量倒序)、`visit`(浏览量倒序) |
| `--raw-json` | | ❌ | - | 输出原始 JSON（**日常搜索禁止使用**，仅供 download 管道组合时使用） |

**示例**：

### 3. `download` – 文档下载

**支持两种模式**：
- 直接通过 URL 下载
- 从 `search` 命令输出的 JSON 文件（或标准输入）中选择文档下载

**语法**：
```bash
# 直接 URL 模式
zhidao download --url "<URL>" [--filename NAME] [--output DIR]

# 从 JSON 文件模式
zhidao download --from-json <文件路径> [--index N] [--output DIR]

# 从标准输入模式
echo '<JSON>' | zhidao download --stdin-json [--index N] [--output DIR]
```

| 参数 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| `--url` | 三选一 | - | 直接下载链接 |
| `--from-json` | 三选一 | - | `search --raw-json` 输出保存的文件 |
| `--stdin-json` | 三选一 | - | 从管道读取 JSON |
| `--index` | ❌ | 全部下载 | JSON 中第几个文档（从1开始），不指定则下载全部 |
| `--filename` | ❌ | 自动 | 保存的文件名 |
| `--output` | ❌ | `downloads` | 输出目录 |

**自动识别 PMO 文档**：若文档来源（`source` 字段）为 `pmo` / `pm`，或 `fileWeb` 包含 `pmo.h3c.com`，则自动使用 PMO 专用 POST 下载接口。

**示例**：
```bash
# 直接下载 URL
zhidao download --url "https://pmo.h3c.com/doc/12345"

# 下载搜索结果中的第1篇文档
zhidao search --query "VLAN配置" --raw-json > result.json
zhidao download --from-json result.json --index 1

# 管道组合（搜索后直接下载第一篇）
zhidao search --query "无线配置" --raw-json | zhidao download --stdin-json --index 1
```

**默认输出**：
```
✅ 文档下载成功
📁 downloads/1_VLAN配置指南.pdf
💾 1.23 MB
```

### 4. `login` – SSO_NEXT 登录

**语法**：
```bash
zhidao login
```

发起 SSO_NEXT 认证登录，返回包含 `url`（SSO 登录页地址）和 `sessionId` 的 JSON。用户需在浏览器中打开 URL 完成登录。

### 5. `save` – 加密保存凭证

**语法**：
```bash
zhidao save --token <token值> --ait <ait值>
```

| 参数 | 必需 | 说明 |
|------|------|------|
| `--token` | 至少一个 | Token 值，加密保存到 `/credentials_at.enc` |
| `--ait` | 至少一个 | AIT 值，加密保存到 `AGENT_CREDENTIALS_DIR` 指定的文件，用于 token 过期时自动刷新 |

将登录获取的 token 和 ait 加密保存，供 search/qa/download 自动读取。加密密钥由 `AGENT_DEVICE_ID` 派生。

### 6. `exchange` – AIT 换取新 Token

**语法**：
```bash
zhidao exchange
```

从 `AGENT_CREDENTIALS_DIR` 读取加密的 AIT，解密后调用 exchange 接口换取新 token，加密保存到 `/credentials_at.enc`。如果 AIT 也失效，则返回 login URL。

### 7. `load` – 读取当前凭证

**语法**：
```bash
zhidao load
```

从加密文件读取并解密凭证，输出 export 命令。

### 8. `clear` – 清空凭证

**语法**：
```bash
zhidao clear
```

删除 `/credentials_at.enc`（AT 文件）。注意：`AGENT_CREDENTIALS_DIR` 指定的 AIT 文件是外部提供的，不会被删除。

**智能体必须直接透传命令输出，禁止自行重新排版、分组、归类或添加额外栏目。命令默认输出已是最终格式，智能体只需原样呈现给用户。**

❌ 严禁做法：
- ❌ 加 `--raw-json` 参数（会导致输出大段 JSON，智能体解析后容易丢失结果）
- ❌ 用表格展示搜索结果（必须用列表格式，每条结果独立展示，包含元信息和三个链接）
- ❌ 添加"热门下载"/"推荐文档"/"最新文档"等自行分类的栏目
- ❌ 省略任何一条结果的预览地址/进入目录/下载链接
- ❌ 省略"数据来源"字段
- ❌ 省略尾部的"知道"链接
- ❌ 自行添加总结/提示/建议等额外内容（只输出命令结果）

✅ 正确做法：
- 不加 `--raw-json`，直接执行 `search --query "关键词"`
- 命令输出什么，就原样呈现给用户，不做任何修改
- 每条结果独立一块：标题（纯文本）→ 元信息行（作者|更新时间|下载|浏览|数据来源）→ 预览地址 → 进入目录 → 下载链接

## 常见错误处理

| 错误信息 | 原因 | 建议操作 |
|---------|------|----------|
| `Token 已过期且刷新失败，请重新登录: <URL>` | AT 和 AIT 均失效 | 将 URL 提示给用户，按登录步骤操作 |
| `未找到凭证，请先执行 login` | 无 AT 文件且无 AIT 文件 | 执行 login 登录并 save 保存凭证 |
| `问答失败: 未找到相关答案` | 问题超出知识库范围 | 建议缩短问题或添加 `--deep` |
| `PMO下载失败 HTTP 401/403` | Token 无 PMO 权限 | 提示用户联系管理员 |
| `无效的JSON格式` | 输入文件不是合法 JSON | 确保使用 `--raw-json` 生成 JSON |
