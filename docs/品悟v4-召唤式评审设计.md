# 品悟 v4 · 召唤式评审 — 交互与收敛机制

> 状态:设计定稿 · 2026-06-11(Boss 拍板)
> 基础:v4 召唤式 MVP 已落地(`summon_pinvou` command + `pinvou_review.rs::summon` + `PinvouSummonCard` + sidecar 持久化)。本稿在其上补全召唤入口、卡片裁决、收敛规则三件事。
> 取代:v3 三人协同的嘴替/自动 loop 方向(已推翻)。

---

## 1. 召唤时机:就近图标,常驻入口删除

两个锚点,品悟图标出现在对象附近,点击才召唤:

| 锚点 | 图标位置 | 品悟做什么 |
|---|---|---|
| 产出物落盘 | 产出物卡旁 | 审**这个产出物**:完整性 / 可信度 / 内容 |
| `request_user_input` 弹出 | 模态框旁 | 对**这个问题**给决策推荐 `{topic, pick, why}`,Boss 拍板 |

- **召唤自带作用域**:prompt 只喂锚定对象 + 相关上下文,不泛审全会话。
- 决策推荐是**辅助决策**(给 Boss 推荐),不是嘴替(替 Boss 回答)——决策权始终在 Boss。
- 普通对话回复不提供审阅入口。常驻召唤按钮删除。
- 已知依赖:主 AI 文本列选项时常不弹 `request_user_input`(C 诊断:`instructions §2.4` 触发词窄,未修)。场景 A 的曝光率受此牵制,扩宽触发词可顺手做。

## 2. 评审卡:逐条裁决

- 每张卡 **3–5 条**完整建议(强制重要性排序),每条带:severity + 依据(为什么)+ 建议动作。
- 涉及外部事实(班次/价格/政策)只能标 **「需核实」**,不得标「硬伤」——评审无外部知识,确信断言是已实证的事故源。
- 每条 Boss 二选一:
  - ✅ **「让 AI 按此修改」**——可附补充信息;**high 默认勾**,其余默认不勾。
  - **「接受现状,不予处理」**——明确判决,入账后核账轮不得再提。
- **「按勾选修订」**按钮:组装定向修订指令经 B1 通道发主 AI——只处理勾选条目、逐条闭合、**定向编辑涉及段落,禁全文重写**(防修订 churn 引入新错误)。
- 落盘:`pinvou_reviews.json` 每条 issue/rec 加 `resolution` 字段(`modify`+note / `accept`);卡片与勾选状态随 rerender 还原(切会话不丢)。

## 3. 收敛规则:立账核账

- **首轮立账 = 全部账目**。对同一产出物的后续召唤进入核账模式,**禁新增条例**。
- 唯一例外:本次修订**在被修订段落内**新引入的错误可入账,须指明由哪次修订引入(范围锁死在 diff 内)。
- 翻案须给新证据;「接受现状」条目视为已结。
- **终态**:勾选条目全闭合 → 品悟必须输出「通过,可交付」并停。轮数硬上限 2–3。
- 工程落点:核账 = `summon` 读 sidecar 历史账目喂回(即现有未做项「连续召唤接续」)。

## 4. 实证依据

- 2026-06-04 loop 实验:自由批评 3 轮震荡不收敛;首轮立账 + 后续核账 2 轮干净收敛。
- 2026-06-10 session `tejz7cxrd5jd0` 反例(无账本时):6 轮评审 4 个版本不收敛——幻觉权威打掉正确方案(「巴黎—阿姆无直达高铁」实为有)、无新证据翻案(回程方案三轮三立场)、用户输入型 issue 连提 4 轮(孩子年龄)、无重要性阈值(7.5 万取整 vs 70,900 被判「严重错误」)、评审从不输出「通过」。
- 已知代价:首轮立账质量 = loop 上限(首轮盲区被锁死)。v0 接受,靠 3–5 条上限 + Boss 勾选过滤兜底,不做多视角立账。
