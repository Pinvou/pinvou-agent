# 品悟 v4 · 召唤式评审 — 交互与收敛机制

> 状态:已落地 · 2026-06-12
> 注:`v4` 为内部迭代称谓,v1–v3 无公开文档。正文文件路径已更新为现行 `features/` 与 `platform/` 布局。
> 基础:`summon_pinvou` command(`app/commands/interaction.rs`)+ `features/review/mod.rs`(品/悟双镜头三 prompt + 品审增量)+ 前端弹窗 + `pinvou_reviews.json` sidecar 持久化。
> 说明:早期常驻(自动触发)方案已被召唤式取代。
> 相对最初设计意图,落地演化出四项差异:**双镜头 / 弹窗交互 / kind 分流裁决 / 品审增量**。

## 1. 召唤入口:最新成品卡上的「品」「悟」

- 只有**最新一张成品卡**带两个按钮,历史卡无入口(对旧产物召唤会产生收敛歧义):
  - **📋 品**(`summonPinvou(path)`)— 查错:揪风险 / 遗漏 / 与需求的偏差。
  - **✨ 悟**(`inspectPinvou(path)` → coverage)— 发散:补维度、给新思路。
- 召唤自带作用域:只喂锚定产物 + 相关上下文,不泛审全会话。
- `request_user_input`(场景 A 决策推荐)的品悟介入**已删除**——实测无用、且会丢选项卡。普通对话回复也无入口。

## 2. 两个镜头:品(查错·收敛) / 悟(发散·覆盖)

| 镜头 | prompt | 干什么 | 产出 |
|---|---|---|---|
| **品** | `PROMPT`(首轮立账)/ `RECONCILE_PROMPT`(核账) | 挑产物的错:缺陷、遗漏、与 Boss 需求冲突 | issues + recommendations |
| **悟** | `COVERAGE_PROMPT` | 不挑对错,只看「全不全」:自判领域专家 → 列完整性维度框架 → 标缺/薄弱维度 | framework + coverage(gaps) |

品的发现**各进各篮、不重叠**(prompt 铁律,防自相矛盾的两份处置):
- **issues** = AI 自己改得动的缺陷。
- **recommendations** = 需 Boss 拍板的决策点(无客观答案的待定项:预算 / 日期 / 同行人……),给推荐 + 理由,拍板权归 Boss。
- 外部事实(班次 / 票价 / 政策)只能标 `kind="needs_verify"`、severity≤medium,**绝不标 high 硬伤、绝不断言"不存在"**——确信的外部断言是已实证的事故源(把本有直达的"巴黎→阿姆"误断"无直达"会打掉对的方案)。

- **四类对象各自分流**:

  | 对象 | 裁决动作 | 转交主 AI 时怎么说 |
  |---|---|---|
  | issue(缺陷) | `fix` / `accept` | fix:只定向改对应段落、不全文重写;accept:接受现状、不处理(入账闭合) |
  | needs_verify(外部事实) | `verify` / `confirmed` | verify:**先查证再改、标依据,别凭记忆直接改** |
  | recommendation(决策点) | `adopt` / `ask` | adopt:我已拍板按此更新;ask:用 `request_user_input` 正式问我 |
  | coverage(缺维度) | `fill` / `skip` | fill:补进去(保留其余、只增不改);skip:跳过 |

  只有需转交的(fix / verify / adopt / ask / fill)组装消息发主 AI;不转交的(accept / confirmed / skip)只写 resolution。
- **整卡跳过**(`dismissPinvouReview`):看了不处理,关窗即可(sidecar entry 留着、无 resolution,无害)。
- 切 session 自动关窗;resolution 落 sidecar,rerender 还原。

## 4. 转交:Boss 驾驶,一条消息发主 AI

裁决后按动作分组,组装**一条 Boss 消息**发给主 AI(非自动回传——Boss 始终在驾驶位):
- 转交气泡特殊样式:顶部「📋 Pinvou · 品 · 转交修订」/「✨ … 悟 …」标签 + 圆角气泡,仅展示层(`meta.pinvouTransfer`),**不进 messages / LLM**;rerender 从转交固定措辞还原品/悟样式。
- **核实强化**:主 AI 默认凭记忆直接改(某次实测 session 中 3 次转交「先核实」全被 read+edit、0 web_search)→ `verify` 单独成组硬指令「先查证再改」,不指定具体工具(让 AI 自选 web_search / fetch_url / 已有依据)。

## 5. 收敛:立账核账 + 品审增量(current_pos 守门)

品的多轮收敛(核心机制,经三轮迭代定稿):
1. **首轮品 → 立账**(全部账目)。
2. AI 按转交改 → **再点品 → 核账**(`RECONCILE_PROMPT`):逐条对账、**禁新增**、pass 时 trace 逐条点名各账目结论(让 Boss 看到逐条对过、非空泛放行)。
3. `accept` / `confirmed` 的账目 = 已结,核账跳过(`is_ledger_closed`)。
4. **品审增量**:最近一轮品 pass + 产物又被改过(`current_pos > 那轮 pos`,说明悟补的 / AI 又动过)→ **重新立账**审这次增量(新补内容可能有新错);**连点品**(产物没变)→ 核最近立账、稳定 pass 不震荡。守门键 = `current_pos`。
5. 找最近【品】entry 时**跳过【悟】的 coverage entry**(issues 空 + 无 verdict),否则悟 record 让 current_pos 守门失效。

> 演进留痕(没它会重蹈覆辙):读「最近一轮」→ pass 轮空账目退化成自由批评、pass↔continue 震荡(实测连点品三态循环);改读「首轮」→ 稳定但不反映悟的增量;终态 **current_pos 守门** → 产物真改才重审、连点稳定,两者兼得。

## 6. 上下文策略(实测背书)

- **能全喂就全喂**(产物 + 会话 ≤ `FULL_FEED_CHAR_LIMIT` = 24000 字),超过才确定性投影降级——实测 1.2 万 token、94% tool 噪音下不崩还能事实核查。
- 产物**整篇读 workspace 文件**(≤ `ARTIFACT_CHAR_LIMIT` = 30000 字),本地 256k 扛得住。

## 7. 实证

- **品审增量收敛**:实证脚本 `pinvou_relist_sim.py`(内部历史脚本,不随开源仓库分发)真模型连点品 6 轮、产物不变 → 稳定 pass 不震荡(current_pos 守门)。
- **某次实测 session**:跑通 品立账→核账 pass→悟→品审增量→核账 pass→悟→品审增量…的多轮闭环;品挑的是真错误(25% 儿童票实为婴儿标准、A'DAM 观景塔、Thalys 更名 Eurostar)。
- 模型能力(独立性抗诱导 / 无产物场景能审 / 少说 / 跨领域塌缩)经内部实测验证,11 场景全过。
