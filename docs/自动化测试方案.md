session replay auditor 单测、MCP 协议/产物契约、桌面/Web Vite 构建、通用 Mock GUI、工具商店
装卸/授权、知识库 Mock GUI、WebUI Relay v2 协议与完整 WebUI 浏览器旅程；还可附加真实 session replay audit 与 L1 真模型 harness。完整覆盖矩阵见

## 验证分层

```
L2 Backend 确定性测试 (cargo test --lib)           ← PR gate
Mock GUI smoke (Chromium + mock Tauri)             ← 本机 / 可进 CI
MCP contract (真实 stdio + 临时目录产物)            ← 本机 / PR gate
完整 WebUI smoke (真实 relay + 共享 UI + WS 桌面模拟)  ← 本机 / CI
Session replay audit (真实 session JSON)           ← 本机 / 可进 CI
L1 真 vLLM dialog harness (cargo test --ignored)   ← 本地手跑 + 落 transcript
Judge 跨模型离线评 Qwen 答案质量                   ← 读 transcript 写报告
```

**L1 跟 cargo test PASS/FAIL 解耦**:L1 只断 judge 看不见的硬指标 (`files_exist` 文件落盘 / `max_duration_s` 耗时上限);行为质量评判全部委托 Judge。

### Windows 本机 L2 风险记录（已定位，CI 已缓解）

2026-07-21 在 Windows 本机验证时，`cargo test --manifest-path pinvou3-app/src-tauri/Cargo.toml --lib -- --test-threads=1`
能完成编译，但测试可执行文件启动前退出，错误为 `STATUS_ENTRYPOINT_NOT_FOUND`。该失败发生在
Rust test harness 进入用例前，不是具体单测断言失败。

根因已定位（不再是未决问题）：`muda` 静态导入 `TaskDialogIndirect`，该符号仅存在于
Common-Controls v6 side-by-side assembly，而 `link.exe` 嵌入默认 manifest 后 Windows 会忽略
旁置 `<exe>.manifest` → 测试 exe 缺 v6 依赖即报 `STATUS_ENTRYPOINT_NOT_FOUND`。
缓解 = 给测试 exe 重嵌 comctl32 v6 manifest；CI 的 `windows-rust-test` job 已把
「manifest 嵌入 + 导入表诊断 + 直接运行补丁后二进制回归」固化为每条 Windows Rust 流水线的
标准步骤，根因与步骤详见 `docs/windows-rust-ci.md`（§What the job runs 第 6-9 步）。排除过程中的旁证（`fastembed`/`ort`
默认特性只影响依赖图，与本失败无关）留作记录。

### 设置页全局自动化测试

本轮设置页重构把通用、模型、搜索、记忆等场景重新分组，模型与搜索源统一为列表式交互。高风险点单独用
`pinvou3-app/tests/settings_ui_smoke.js` 锁定：

- 模型：本地模型显示“本地模型”标签且不可删除；默认模型用左侧圆圈选择；删除模型必须先出现 270px 级 iOS 确认框；新增云模型不显示无效 API 地址，API Key 为空时保存置灰。
- 编辑模型：云模型编辑时保留并展示用户已保存的 API Key 状态；默认直接显示掩码点位，不显示“已配置”这类技术状态文案。点“显示”后仅对后端已保存的密钥做明文回显；环境变量覆盖的 Key 不回显明文，只保持掩码状态。模型 ID、API Key、API 地址等输入框必须连续输入不丢焦点。编辑已有云模型时，“更换”只允许切换同一厂商下的其他模型，因为同厂商 Key 通常通用；`OpenAI Compatible` 这类自定义兼容端点不跨端点复用 Key，不同 base URL 走新增模型。
- 搜索：不再出现“保存搜索配置”按钮；新增搜索源先进入编辑弹窗，未点击弹窗“保存”不得写入；已有搜索源未输入新 Key 时“保存”置灰，只有新增 Bing 或输入新 Key 后才能保存；点击保存后只显示重启确认，点“现在重启”才调用 `save_search_settings_and_restart`。
- 权限：高级执行权限打开失败时回滚开关，并用 toast 显示错误，不进入设置页错误边界。
- 帮助反馈：反馈弹窗按模型/搜索弹窗统一规格实现，宽度 430px 级、最大宽度不超过 viewport、22px 圆角、紧凑 header、单层列表式表单组和底部操作区；不得使用 520px 级大弹窗、过大标题、卡片套卡片或系统原生 `alert` 成功提示。
- 任务收纳联动：收纳成功 toast 的“前往查看”必须直达对话管理页并展开“已收纳”面板，收纳记录在已收纳列表中可见；toast 按钮文本不得折行。
- 响应式布局：设置弹窗必须随 PINVOU 主窗口宽高动态收缩，侧栏和内容区不得撑出 viewport；通用页的“界面语言”等短标签不能被压成逐字竖排。聊天首页欢迎语在小窗口下必须换行或降到小号断点，不得产生横向溢出。

本地最小回归命令：

```bash
cd pinvou3-app
npm run build:ui
npm run test:settings-ui
```

更完整的设置页风险回归走统一入口：

```bash
bash scripts/run-user-journey-tests.sh
```

该入口必须实际运行 `settings_ui_smoke.js`；若旧 GUI smoke 因本机缺浏览器被 skip，需要在结果中明确记录 skip 原因，不能等同于完整通过。

### 模型目录刷新方案

2026-07-21 已按厂商官方文档核对并刷新前端 `MODEL_CATALOG`，当前发版候选以内置列表和自定义入口共同覆盖可接入模型。更新原则：

- 内置列表只放各厂商当前主推、仍可新接入、适合文本/Agent/代码对话的模型；旧模型不从已有用户配置里删除，但不再出现在“添加/更换”推荐列表。
- 每个厂商仍保留“自定义模型 ID”，避免官方灰度、地域差异、企业专属模型无法接入。
- 编辑已有云模型时只展示同一厂商的可选模型；跨厂商或 OpenAI-compatible 不同 base URL 走新增模型。
- `OpenAI Compatible` 不是 OpenAI 官方模型目录，内置项仅作为兼容端点示例；无法确认真实可用时优先使用“自定义兼容模型”。
- 官方文档无法给出稳定公开模型 ID 的厂商，不臆造完整列表，只放官方明确的通用/Agent 模型，并保留自定义入口。

当前内置列表不在此复制第二份（避免与真源漂移）：唯一事实源是
`pinvou3-app/src/features/settings/model-catalog.js`，各厂商均保留"自定义模型 ID"入口；
`OpenAI Compatible` 类别不预填示例模型，全部由用户手填。

自动化覆盖：

- `settings_ui_smoke.js` 断言新增/编辑模型的推荐列表不出现官方已下线或标注弃用的模型名，并验证多个厂商代表模型存在——内置列表的"新鲜度"由该断言与 `tests/model_catalog_grouping.test.js` 守门，不靠本文档。
- 保存链路当前覆盖 DeepSeek 内置模型和 DeepSeek 自定义模型 ID 连续输入；自定义模型入口仍可手填任意模型 ID。
- 逐厂商保存链路尚未展开成矩阵测试，若后续每个厂商出现不同字段或校验规则，需要把每个厂商至少一个内置项纳入保存回归。
- 不把模型目录写成"永久正确"；每次发版前需要按官方文档重新核对。

## 完整 WebUI 覆盖边界

自动化覆盖三层：Relay v2 协议与安全、真实共享 React WebUI 的浏览器边界、桌面 Rust
WebAccessManager 的确定性边界。浏览器旅程先执行 `build:web`，再由真实 Relay 提供静态资源；
同一份页面分别以 1440×900 电脑 viewport 和 390×844 手机 viewport 加载。测试用
WebSocket 模拟持久 desktop endpoint，给页面启动阶段的 allowlisted RPC 返回最小有效值，
并验证 fragment 中的 endpoint/token 不进入 HTTP URL、唯一 Web lease 接管、至少一次带
`client_request_id` 的 RPC 往返，以及事件 `stream_epoch + seq` 写入游标后在重连时通过
`after_seq` 续传。浏览器运行时错误和手机横向溢出也会直接使测试失败。

Rust 确定性测试负责 RPC 去重缓存、事件 epoch/单调序号/有界 journal、重放与 reset、
endpoint 凭据持久化和撤销、host file picker 范围及 Session 产物下载路径边界。Relay 测试
负责 token/secret hash、鉴权时限、消息类型白名单、旧 lease 隔离、桌面离线恢复、容量/限流、
healthz 脱敏和 SPA 缓存头。未自动化的是 Firefox/iOS Safari/Android Chrome 的浏览器差异、
真机触屏键盘与安全区、弱网切换、公网 TLS/反向代理及真 Tauri 桌面事件桥；这些保留为
发版前人工或线上 smoke。

`build:web` 产生 `remote-control-relay/web/dist/`。生产发布走内部流程，不在本仓库。

## Judge — Claude 跨模型评 Qwen

详 `docs/L1-judge-rubric.md` (当前 rubric **r2**,加 subagent 评估 2 维)。

**核心机制**:
- Qwen 跑 → harness 落 transcript md → Claude 读 → 写 judge report → ≤3 离群点追加进离群点跟进记录
- 6 维 × 1-5 分: 准确性 / 完整性 / 简洁性 / 工具使用合理性 / **任务拆分合理性 (r2 新)** / **结果综合能力 (r2 新)** (N/A 跳过)
- 后 2 维只对 subagent scenario 评 (非 subagent 永远 N/A)
- **跟 L1 cargo test 解耦** — judge 漂移不阻塞 PR

**Baseline 多维命名** (`v<app_ver>[-<vllm_tag>]-r<rubric_ver>[-<suffix>]/`):
- `<app_ver>` 代码版本 + INSTRUCTIONS_MD
- `<vllm_tag>` 可选,标 vLLM 配置变更 (例 `vllm2`)
- `<rubric_ver>` 评分尺子版本
- `<suffix>` scenario 集合大小 (例 `13scn` / `17scn`)
- 跨 rubric diff 拒绝;跨 vllm 配置可 diff 但需意识底座变了
- 历史基线分数（内部时期产物，未随开源发布）: `v0.8.37-r1` (5 scn,4.75) / `v0.8.37-r1-13scn` (13 scn,4.67) / `v0.8.37-vllm2-r2-17scn` (17 scn,4.46;含 4 subagent + vLLM 优化)

**离群点闭环**:
- 任一维度 ≤3 → judge report 列出 + 追加到「L1 judge 离群点跟进」记录
- 重复出现 grep 同 scenario+维度,改状态行为 🔁
- 状态: 🆕 / 🔁 / ✅ / 🧪 / ❌

**Sanity 协议**:
- 同 session retake 是"演习"不是考试
- 真 sanity 要"开新 session 让 Claude 不带记忆评同一批 transcript"
- 重大里程碑前可考虑跨模型 (GPT/Gemini) 评同 rubric

## 关键设计决策 (已拍板)

| 决策 | 选择 | 理由 |
|---|---|---|
| L1 真 vLLM | 是 | 质量回归只能真 LLM 抓 |
| L2 走纯函数路径 | 是 | 避免改 spawn_engine 接口,LLM-dependent 留 L1 |
| **L1 砍机器断言** | 只留 files_exist + max_duration_s | judge 在语义层评得更准,机器断言对 LLM 创新方式过于刚性 |
| **Judge = Claude** | 跨模型 | 比 Qwen 自评有独立性 (本地零成本,不需 API key) |
| **Judge 跟 cargo test 解耦** | 是 | judge 漂移/换 rubric 不能阻塞 PR |
| CI 决策 | L2 进 CI / L1 本地手跑 + pre-release | vLLM 部署在内网环境,GitHub Actions 进不来 |
| 健康探针 exit 0 | 是 | nightly 不告警 |

## Lesson learned (踩过的坑)

### reminder 改造单样本不可信
2026-05-18 尝试给 Plan/Planning system-reminder 加"禁过渡语 + text summary" 条款 (commit `7b983b6`),单 scenario 验证后 revert (commit `ec2f788`):
- 副作用确定: text 23→556 字暴增 (+24×) + system prompt 占位
- 改进不可信: 完整性 3→5 是单样本可能 LLM 抽奖
- 核心问题没解: LLM 仍写 5 次 "让我..." (mode-independent 行为)

**规则**: 改 reminder/INSTRUCTIONS_MD 前要 (a) 积累 3+ 次离群点证据 (b) 改后 2+ scenario A/B 验证（该规则沉淀自内部时期的离群点跟进记录，记录本身未随开源发布）。

### vLLM 配置变更可能"免费修"离群点
2026-05-18 本地 vLLM 参数优化 (max-model-len 262144 / kv-cache fp8 / prefix-caching / chunked-prefill / max-num-seqs 8),baseline `v0.8.37-r1-13scn → vllm2-r2-17scn` 13 老 scenarios 子集:
- 总均分 4.67 → 4.77 (**+0.10**)
