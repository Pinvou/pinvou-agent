# pinvou3 自动化测试方案

> 更新 2026-05-18 · 已落地 · 文档为现状描述

## 三层架构

```
L2  Backend 纯函数 (cargo test --lib)             ← PR-gate
L1  真 vLLM dialog harness (cargo test --ignored) ← 本地手跑 + 落 transcript
Judge  Claude 离线评 Qwen 答案质量                ← 读 transcript 写报告
```

**L1 跟 cargo test PASS/FAIL 解耦**:L1 只断 judge 看不见的硬指标 (`files_exist` 文件落盘 / `max_duration_s` 耗时上限);行为质量评判全部委托 Judge。

## L2 — 49 backend tests

- 位置: `pinvou3-app/src-tauri/src/{commands,bridge/mod,file_ingest,lib}.rs::tests`
- 覆盖: `validate_user_path` 边界 / `pinvou3_blocklist` 契约 / bridge mode 字段 / `{{PINVOU3_WORKSPACE}}` 占位符 / file_ingest dispatch
- 跑: `cargo test --lib` 每 PR 自动跑,<1s

## L1 — 13 scenario harness

- 位置: `pinvou3-app/src-tauri/tests/l1_dialog_harness.rs`
- 跑: `cargo test --test l1_dialog_harness -- --ignored --test-threads=1` (~6-10 分钟)
- 健康探针: vLLM `/v1/models` 3s 探活,不在线 `exit 0` 不告警
- Auto-approve / auto-cancel-user-input: harness 内置,模拟生产 event_forwarder

## Judge — Claude 跨模型评 Qwen

详 `docs/L1-judge-rubric.md` (当前 rubric **r1**)。

**核心机制**:
- Qwen 跑 → harness 落 transcript md → Claude 读 → 写 judge report → ≤3 离群点 auto-append `process.md`
- 4 维 × 1-5 分: 准确性 / 完整性 / 简洁性 / 工具使用合理性 (N/A 跳过)
- **跟 L1 cargo test 解耦** — judge 漂移不阻塞 PR

**Baseline 双版本号** (`docs/l1-baselines/v<app_ver>-r<rubric_ver>[-<suffix>]/`):
- 跨 rubric 版本 diff 拒绝 (4 分@r1 ≠ 4 分@r2)
- 历史 baseline 文件夹永不动,新 rubric 起新文件夹
- 已有: `v0.8.37-r1` (5 scn) / `v0.8.37-r1-13scn` (13 scn,均分 4.67)

**离群点闭环**:
- 任一维度 ≤3 → judge report 列出 + auto-append `process.md` `## L1 judge 离群点跟进`
- 重复出现 grep 同 scenario+维度,改状态行为 🔁
- 状态: 🆕 / 🔁 / ✅ / 🧪 / ❌

**Sanity 协议**:
- 同 session retake 是"演习"不是考试
- 真 sanity 要"开新 session 让 Claude 不带记忆评同一批 transcript"
- 重大里程碑前可考虑跨模型 (GPT/Gemini) 评同 rubric

## 关键设计决策 (已拍板)

| 决策 | 选择 | 理由 |
|---|---|---|
| L1 真 vLLM | 是 | 质量回归只能真 LLM 抓 |
| L2 走纯函数路径 | 是 | 避免改 spawn_engine 接口,LLM-dependent 留 L1 |
| **L1 砍机器断言** | 只留 files_exist + max_duration_s | judge 在语义层评得更准,机器断言对 LLM 创新方式过于刚性 |
| **Judge = Claude** | 跨模型 | 比 Qwen 自评有独立性 (本地零成本,不需 API key) |
| **Judge 跟 cargo test 解耦** | 是 | judge 漂移/换 rubric 不能阻塞 PR |
| CI 决策 | L2 进 CI / L1 本地手跑 + pre-release | vLLM 在 10.214.74.113 内网,GitHub Actions 进不来 |
| 健康探针 exit 0 | 是 | nightly 不告警 |

## Lesson learned (踩过的坑)

### reminder 改造单样本不可信
2026-05-18 尝试给 Plan/Planning system-reminder 加"禁过渡语 + text summary" 条款 (commit `7b983b6`),单 scenario 验证后 revert (commit `ec2f788`):
- 副作用确定: text 23→556 字暴增 (+24×) + system prompt 占位
- 改进不可信: 完整性 3→5 是单样本可能 LLM 抽奖
- 核心问题没解: LLM 仍写 5 次 "让我..." (mode-independent 行为)

**规则**: 改 reminder/INSTRUCTIONS_MD 前要 (a) 积累 3+ 次离群点证据 (b) 改后 2+ scenario A/B 验证。详 `process.md` `## L1 judge 离群点跟进` 下方 lesson learned。
