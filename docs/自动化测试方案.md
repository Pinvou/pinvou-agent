# pinvou3 自动化测试方案

> 创建：2026-05-18
> 状态：方案设计完成，待落地（建议 L1 MVP 优先）
> 范围：pinvou3 端到端测试 / backend 业务测试 / GUI 测试的分层架构

---

## 1. 现状与问题

| 层级 | 现有 | 暴露的盲区 |
|---|---|---|
| 单元测试 | 底座 ~3000 个，pinvou3 几乎 0 | bridge 路径无覆盖 |
| 集成测试 | 上游 mock LLM 5 个用例（`tests/integration_mock_llm.rs`） | OpenAI streaming batch tool_calls bug 没测出，本轮靠手测 7 个 write_file 发现 |
| 端到端 | 手测 + 验证报告（5 个任务 ×3 模式，见 `docs/验证报告-qwen3.6-deepseek-tui.md`） | 慢、人工、回归靠用户体验 |
| GUI | 0 | 产物面板 / Plan mode / mode 切换 都靠肉眼 |

**本轮 session 暴露的真实回归点**——下次随便改一行 INSTRUCTIONS_MD 或 bridge 都可能全部 regression 没人知道：

- L1.5 工具表精简 → AI 是否真没调被屏蔽工具
- OpenAI streaming batch tool_calls → 多 write_file 是否产物全记录
- Plan trust_mode → list_dir 跨 workspace 是否不报错
- validate_user_path → /tmp 路径是否能 open
- INSTRUCTIONS_MD workspace 引导 → AI 是否不再 list_dir 上层探

## 3. L1 — AI dialog harness（真 vLLM 端到端）

### 3.1 入口

不走 Tauri IPC（重 + 需 display），不走 deepseek-tui binary CLI（one-shot 限制）。
直接用底座 `EngineHandle` API + pinvou3 真实 bridge。

但 **当前 bridge / AppEngine API 不支持测试构造**，需要先做 2 处 plumbing 改造（见 §3.7）。改造完后入口长这样：

```rust
// pinvou3-bench/src/runner.rs（新 workspace member）
use pinvou3_tauri::bridge::Pinvou3Bridge;
use pinvou3_tauri::engine::AppEngine;
use deepseek_tui::core::engine::Op;

async fn run_scenario(scenario: &Scenario) -> ScenarioResult {
    // plumbing fix 1: bridge 加 boot_with_workspace 让 scenario 用 tempdir
    let bridge = Pinvou3Bridge::boot_with_workspace(scenario.tempdir.clone())?;
    // plumbing fix 2: AppEngine 加 spawn_headless 不要 AppHandle / 不启 forwarder
    let engine = AppEngine::spawn_headless(bridge).await?;

    for turn in &scenario.turns {
        let op = engine.bridge.build_send_message_op(
            turn.user.clone(),
            scenario.mode,
            turn.plan_phase,
        );
        engine.handle.send(op).await?;

        // 直接消费 engine.handle.rx_event 拿到所有 Event::ToolCallStarted /
        // ToolCallComplete / TurnComplete 等
        let events = collect_events_until_turn_complete(&engine.handle).await?;
        verify_expectations(&events, &turn.expect)?;
    }
}
```

### 3.2 Scenario 结构

```rust
struct Scenario {
    name: &'static str,
    mode: AppMode,                          // Plan / Yolo
    setup: Setup,                           // tempdir / fixture files
    turns: Vec<Turn>,
}

struct Turn {
    user: String,
    plan_phase: PlanPhase,                  // Planning / Executing / None
    expect: Expect,
}

struct Expect {
    tool_use_events_count: HashMap<&'static str, RangeInclusive<usize>>,
    tools_never_called: Vec<&'static str>,
    files_exist: Vec<PathBuf>,
    output_contains_any: Vec<&'static str>,
    output_NOT_contains: Vec<&'static str>,  // 用户自定义补充
    max_duration_s: f64,
}

// 每个 Expect 自动合并这组拒绝词，防关键词断言伪绿
const DEFAULT_OUTPUT_NEVER: &[&str] = &[
    "我无法", "抱歉", "I cannot", "I'm sorry", "我不会",
    "无法获取", "无法访问", "Sorry, I",
];
```

### 3.3 5 类断言

| 类型 | 例 | 检查方式 |
|---|---|---|
| 工具调用计数 | write_file 必须 7 次 | 收集 `Event::ToolCallComplete` |
| 工具非调用 | agent_open 永不出现 | 同上反向 |
| 文件落地 | path 存在 + 内容含关键词 | `fs::read` 检查 |
| 输出关键词 | "本地" 或 "性能" | regex / 子串 |
| 拒绝词兜底 | 不含 "我无法" / "抱歉" 等 | DEFAULT_OUTPUT_NEVER 自动套 |
| 耗时上限 | turn < 15s | 起止 Instant |

**可选 AI-as-judge**：把"输出质量"主观维度交另一个 LLM 打分。慢 + 不确定，**留 M3 阶段**。

### 3.4 场景库（基于真实回归点）

| Scenario | 覆盖 | 防的回归 |
|---|---|---|
| `translate_no_tool` | 简单 QA 不调工具 | INSTRUCTIONS_MD 引导别过激 |
| `data_analysis_csv` | read_file + code_execution 链式 | tool 链路 |
| `plan_travel_web` | web_search + 长文档 | 联网 + 多步 |
| `write_okr_md` | write_file 单次 | 简单产物 |
| **`batch_create_7_files`** | write_file × 7 | **streaming batch bug** |
| **`plan_mode_list_dir`** | Plan 模式调 list_dir ../.. | **trust_mode 配置** |
| **`save_to_tmp_no_validate_fail`** | 写 /tmp 后产物面板可 open | **validate_user_path 放宽** |
| **`no_blocklist_tools`** | 跨所有 scenarios 不调 agent_*/rlm_*/task_* | **L1.5 回归** |
| `no_overprobe_workspace` | 新对话不调 list_dir ../.. | INSTRUCTIONS_MD workspace 引导 |
| `multi_turn_context` | 第 2/3 turn 引用第 1 turn 内容 | 上下文连续性 |
| `reasoning_off_speed` | 单 turn < 15s | thinking 关、prefill 缩短 |

**MVP 5 个**：粗体 4 + `reasoning_off_speed`，防本轮新引入的回归点。

### 3.5 健康探针（pre-flight check）

runner main 进入 scenario loop 前先 ping vLLM 端点：

```rust
async fn vllm_alive() -> bool {
    let url = std::env::var("DEEPSEEK_BASE_URL")
        .unwrap_or_else(|_| "http://10.214.74.113:8000/v1".into());
    let r = tokio::time::timeout(
        Duration::from_secs(3),
        reqwest::get(format!("{}/models", url)),
    ).await;
    matches!(r, Ok(Ok(resp)) if resp.status().is_success())
}

async fn main() {
    if !vllm_alive().await {
        eprintln!("SKIP: vLLM endpoint unreachable (set DEEPSEEK_BASE_URL or check 10.214.74.113:8000)");
        std::process::exit(0);   // 注意 exit 0，否则 nightly 告警噪声
    }
    run_scenarios().await;
}
```

### 3.7 必需的 plumbing 改造（共 2 处 fork patch）

| 改造 | 文件 | 行数 |
|---|---|---|
| `Pinvou3Bridge::boot_with_workspace(ws: PathBuf) -> Result<Self>` | `pinvou3-app/src-tauri/src/bridge/mod.rs` | ~10 |
| `AppEngine::spawn_headless(bridge: Pinvou3Bridge) -> Result<Self>` 不要 AppHandle / 不启 event forwarder | `pinvou3-app/src-tauri/src/engine.rs` | ~20 |

不动 deepseek-tui fork——`spawn_engine(config, &dt_config)` 接口保留不变，测试直接用现成接口。

### 3.9 CI 集成（写死决策 D：本地 + pre-release）

- 标 `#[ignore]`（默认 `cargo test` 不跑，不阻塞 PR）
- 跑法：`cargo test --package pinvou3-bench -- --ignored --test-threads=1`
- 时机：
  - **本地手动**：开发到关键节点或改 INSTRUCTIONS_MD / bridge / blocklist 后跑一遍
  - **release 前强制跑**：标 release tag 前必须 11/11 PASS
- 不接入 GitHub 公网 runner——vLLM 在 10.214.74.113 内网，GitHub Actions runner 进不来
- **GB10 self-hosted runner**：列为待办，等后续基建（见 §8）

## 4. L2 — Backend 纯函数测试

### 4.1 范围（决策 Y）

只测**不依赖 LLM 调用的 pure functions**，避免 mock LLM 改造 spawn_engine 的复杂度。LLM-dependent 路径（tool dispatch / streaming）留给 L1 真 vLLM 测。

可测目标：

| 测试 | 文件位置 | 覆盖什么 |
|---|---|---|
| `validate_user_path_allows_tmp` | `commands.rs::tests` | path 校验放宽到 /tmp |
| `validate_user_path_blocks_ssh` | `commands.rs::tests` | 凭据目录拦截 |
| `validate_user_path_blocks_etc_shadow` | `commands.rs::tests` | 系统敏感前缀拦截 |
| `pinvou3_blocklist_hides_state_tools` | `tools/pinvou3_blocklist.rs::tests`（已有 3 个，可扩） | L1.5 工具隐藏清单 |
| `bridge_yolo_mode_trust_mode_true` | `bridge/mod.rs::tests` | mode 字段计算 |
| `bridge_plan_mode_trust_mode_true_after_p1` | `bridge/mod.rs::tests` | P1 修复回归 |
| `bridge_plan_mode_allow_shell_true` | `bridge/mod.rs::tests` | Plan tool_setup 路由依赖 |
| `instructions_md_session_workspace_subst` | `bridge/mod.rs::tests` | `{{PINVOU3_WORKSPACE}}` 占位符替换 |
| `file_ingest_pandoc_detects_docx` | `file_ingest.rs::tests` | 附件 mime 类型识别（为 §6.1 附件 pipeline 准备） |

### 4.2 入口

`#[cfg(test)] mod tests` 直接放各自源文件末尾——**无需任何 plumbing 改造**，不需要构造 `AppEngine` 或 spawn engine。

```rust
// pinvou3-app/src-tauri/src/commands.rs 末尾
#[cfg(test)]
mod tests {
    use super::*;
    use std::path::PathBuf;

    #[test]
    fn validate_user_path_allows_tmp() {
        let tmp = std::env::temp_dir().join("pinvou3-validate-test");
        std::fs::create_dir_all(&tmp).unwrap();
        let p = tmp.join("foo.txt");
        std::fs::write(&p, "").unwrap();
        assert!(validate_user_path(p.to_str().unwrap()).is_ok());
        std::fs::remove_dir_all(&tmp).ok();
    }

    #[test]
    fn validate_user_path_blocks_ssh_components() {
        let p = format!("{}/.ssh/id_rsa", std::env::var("HOME").unwrap());
        assert!(validate_user_path(&p).is_err());
    }

    // ... 其余测试同样模式，纯函数 in-out 断言
}
```

### 4.3 工程量

| 任务 | 工期 |
|---|---|
| 9 个 backend pure-function 测试 | 1 天 |
| **合计** | **1 天** |

### 4.4 CI 集成

- 不标 `#[ignore]`，每个 PR `cargo test` 自动跑
- 全部 < 1s 每个，9 个 < 10s 总
- 失败 → block PR
- **跟 vLLM 无关，公网 GitHub Actions runner 能跑**

## 7. 关键设计决策（已拍板）

| 决策 | 选择 | 理由 |
|---|---|---|
| **L1 真 vLLM** | 是 | 质量回归只能真 LLM 抓 |
| **L2 走纯函数路径**（决策 Y） | 是 | 避免改 spawn_engine 接口的复杂度；LLM-dependent 留 L1 |
| **CI 决策 D**（L2 进 CI / L1 本地 + pre-release） | 是 | vLLM 内网，公网 runner 进不来，GB10 self-hosted 排进 §8 待办 |
| **健康探针** | runner pre-flight exit 0 | nightly 告警免噪声 |
| **DEFAULT_OUTPUT_NEVER 自动套** | 是 | 防关键词断言伪绿 |
| **AI-as-judge** | 排 M3 | 慢 + 不确定，关键词正反向先用 |
| **L3 暂缓** | 是 | UI 改动少时 ROI 低 |

## 8. 待办：GB10 self-hosted GitHub Actions runner

L1 真 vLLM 测试当前**仅本地手跑**。要进 CI nightly 必须在能访问 10.214.74.113 的机器（GB10 自己 / 团队内网 jumphost）起一个 self-hosted runner。

涉及：
- GB10 装 actions-runner（systemd unit）
- 配 webhook + token
- runner label e.g. `self-hosted, vllm-internal`
- workflow yaml 加 `runs-on: [self-hosted, vllm-internal]`
- 监控 runner 在线状态

**优先级**：低（L1 本地手跑能 cover 短期需求），等 pinvou3 团队扩到 ≥2 人或发版频率上升再做。
