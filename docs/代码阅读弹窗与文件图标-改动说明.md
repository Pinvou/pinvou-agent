## 1. 本次改动了什么

### 1.1 代码阅读弹窗（提交一）

**用户可见行为**：在 Codex 会话右侧"工作区"面板点击任意文件，不再挤占面板内嵌区域，而是弹出居中的代码阅读弹窗：

- 代码按文件类型语法高亮（highlight.js，复用应用现有 markdown 代码块配色，明暗主题自动跟随）。
- 弹窗右侧、下侧、右下角均可拖拽调整大小（右下角双向），尺寸记忆在本地（localStorage），下次打开保持；双击右下角恢复默认尺寸。
- 头部 A−/A+ 按钮调整代码字号（10–24px，默认 12px，行高按 1.6 倍联动），同样经 localStorage（`pinvou_code_viewer_font_size`）记忆，重开保持。
- 文件树行悬浮按钮（左起）：新窗口打开（`AppWindow`，文件，一步并入阅读器窗口）→ 复制相对路径（`Link`，**文件与目录都有**，点击后短暂变绿勾反馈）→ 添加到对话（`+`，文件）→ 外部应用打开（`ExternalLink`，文件）。与行点击的内嵌代码弹窗分工：行点击=内嵌看代码，行尾按钮=拆到独立阅读器或调系统应用。
- 选定项目工作区后（发送首条消息前）即可浏览工作区：`list/search/preview/open/reveal_codex_workspace*` 五个命令的 `session_id` 改为可选并新增可选 `workspace_path` 参数，无会话时经 `validate_codex_project_workspace` 校验后直接按路径浏览；选定项目即默认展开面板，draft 输入区提供工作区开关按钮。"变更"tab 依赖会话基线，无会话时显示专属空态文案（"创建会话后，这里会列出本会话对项目的更改"），不发起 changes 请求。
- 弹窗头部新增「在新窗口打开」：拆出独立原生阅读器窗口（`code-reader` 单例），可跨屏拖拽；后续文件再点「在新窗口打开」不再新建窗口，而是在阅读器内以顶部标签页累积/切换（Win11 记事本模式），同一文件去重激活。打开采用推拉双保险：`code-reader:open` 事件广播 + pending 队列（先 emit 后入队，emit 失败原样报错不入队），ReaderApp 启动时拉取 pending，窗口获得焦点时再次拉取（DOM focus 原生事件兜底，事件投递失败也不丢文件）。`open_code_reader` 命令在入队前校验工作区可读且目标文件存在，失败前置、弹窗不关闭。
- 头部提供：语言徽标、复制内容、复制路径、在文件管理器显示、用系统应用打开、关闭。
- 图片文件直接看图；超过 512KB 的文本显示"仅显示前一部分"提示条；不支持的二进制给出引导文案；读取失败显示错误态。
- Esc、点击遮罩、关闭按钮均可关闭；打开期间锁定背景滚动。

## 2. 关于"是否需要移植 VSCode 核心"

**不需要，也不应该。** 结论与依据：

1. VSCode 的文件图标是**文件图标主题（File Icon Theme）**机制：一套 SVG/字体图标 + 一份「文件名/扩展名 → 图标」映射表，与编辑器内核（monaco）、workbench、主题服务完全解耦。VSCode 自带的 Seti 图标和市场上的 Material Icon Theme 都是独立扩展包。
2. 本次用约 1 天工作量、43 个 MIT 许可 SVG + 一个 100 余行的映射模块即达到 VSCode 同风格观感；移植 VSCode 核心则是月级工程，还会引入长期同步维护负担，对本需求没有收益。
3. 后续若要扩充图标覆盖面，只需从上游主题包追加 SVG 并在 `file-icon-theme.js` 补映射项即可，边际成本极低。

## 5. 已知边界与后续项

- 弹窗为只读查看，不支持编辑（设计内）。
- 阅读器窗口为首期实现：标签页列表不持久化（关窗即清空，Win11 记事本式恢复留作后续）；主题在窗口加载时应用一次，主应用切主题不联动；窗口标题为建窗时的静态中文（ReaderApp 挂载后按语言更新 document.title，原生标题栏同步情况同 pet 窗口现状）；阅读器内「外部打开/定位」失败仅 console.error，无界面错误条；`?window=reader` 入口仅注册在桌面构建（web 构建不含 reader.html）。
- 预览的文本识别对白名单外文件做内容嗅探（头部 8KB，无 NUL + 合法 UTF-8，容忍截断点不完整序列）；UTF-16 等含 NUL 的编码仍判为 binary（低频，按需再扩）。`.env` 等特殊文件名按文本明文预览，与编辑器查看本地文件的常规行为一致，属有意为之。
- 文本高亮超过 128KB 自动回落纯文本（沿用 `syntax-highlighter.js` 既有保护），文件内容本身上限 512KB。
- 原面板内嵌预览底部的"添加到对话"未迁入弹窗；文件树每行悬浮 `+` 按钮仍可添加引用。
- 图标映射未覆盖的扩展名回落默认文件图标，可按需增量扩充。
- 冒烟测试覆盖文本场景；image/unsupported/error 分支走同一代码路径，未逐一做浏览器断言。

## 7. 后续修复记录

### 2026-08 深色模式下弹窗文字颜色修复

- **问题**：代码阅读弹窗（文件/差异两种模式）在深色模式下，非高亮 token 的文本——普通代码行、diff 上下文行与「# 已暂存 / # 未暂存」分段标题——颜色为浏览器默认纯黑，与深色背景 `#1E1E20` 对比度几乎为零，文本不可见。
- **根因**：`CodeViewerModal` 的 dialog 只切换了背景（`dark:bg-[#1E1E20]`）未设置文字色；弹窗经 `createPortal` 挂载到 `document.body`，绕过主应用 `#root` 的文字色上下文；`pre.pinvou-code-block` 与 `code.hljs` 未定义默认 `color`，裸文本继承浏览器默认黑色。高亮 token 颜色由 `--pinvou-hl-*` 变量驱动不受影响——因此浅色模式与 token 行均正常，仅裸文本在深色下出错（headless 实测：深色下 pre/code 计算色 `rgb(0,0,0)`，`+` 行 token 色正常）。
- **修复**：dialog 补充 `text-gray-900 dark:text-gray-100`（与阅读器窗口容器一致），头部文件名与内容区裸文本随主题切换。
- **波及范围排查**：阅读器窗口容器已有明暗文字色（正常）；产出物面板 diff 视图（`tool-common.jsx`）全部行显式 `isDark` 分支配色（正常）；仅弹窗受影响。`code_viewer_modal_smoke` 与 `code_viewer_diff_smoke` 各补一段深色模式文字色断言。

### 2026-08 diff 文件头行着色（修改块误染 → 红绿文字提示加减侧）

- **问题**：diff 弹窗中 `--- a/xxx` 与 `+++ b/xxx` 文件头行最初被轻量高亮器按 `-`/`+` 前缀误归为 `hljs-deletion`/`hljs-addition`，染成红/绿背景修改块，观感像整段大修改。
- **修复（两步）**：`highlightDiffCode` 逐行规则改为——`@@` → `hljs-meta`；`diff --git` / `index ` / `\ No newline` → `hljs-comment`；`---` / `+++` 文件头 → 新增 `hljs-diff-file-header old/new` 类（base.css 配 `--pinvou-hl-deletion/addition` 文字色）：**红/绿文字提示加减侧、无背景块**，与 GitHub/VS Code 的 diff 文件头惯例一致；`+` → `hljs-addition`；`-` → `hljs-deletion`。
- **测试**：`code_viewer_diff_smoke` fixture 补 `--- a/`、`+++ b/` 头行，断言：头行渲染为 `hljs-diff-file-header old/new`、文字色与修改行一致（`---` 红 / `+++` 绿）、无背景块。
