# 卡牌池设计

> 留档 2026-06-03 · worktree `card-pool-agency`(Side B)。

## 是什么

卡牌池是一个「专家能力库」:每张卡是一份**专家能力档案**(完整人设正文——职责/工作流/规则/交付物/沟通风格)。用户挑一张「加持」给 AI,AI 之后就按这位专家的方法论和视角干活。卡片可浏览、搜索、按部门筛,也可以由用户自己创建。

> 注意:这跟底座的 skill 加载系统是**两套独立机制**——卡牌走 persona 注入(文本 prepend),不进 SkillRegistry、不扫 skill 目录。详见 `skills-loading-status.md`。

## 数据源(三源合并)

卡片来自三个地方,`personas::all_summaries()/get()` 合并后给前端:

| 源 | source | 位置 | 可变 |
|---|---|---|---|
| agency-agents-zh(201 张) | `builtin` | 编译期内嵌 `resources/bundle/personas/agency-agents.json` | 否 |
| pinvou3 内置(目前只有「卡牌制造专家」) | `builtin` | `personas.rs::builtin_extra()` | 否 |
| 用户自创 | `user` | `~/.pinvou3/user/personas/<id>.json` | 增删改,**永不被覆写** |

内嵌源走 `OnceLock` 缓存(只读、零成本);用户卡走 `RwLock`,每次 CRUD 后 `reload_user()` 重新扫盘刷新。`bundle/` 升级会覆写,`user/` 永远不动——这是 pinvou3 一贯的 bundle/user 分离铁律,保证用户的卡不会因版本升级丢失。

## 数据模型 `PersonaCard`

字段:`id · dept · name · description · emoji · color · body · source`

- **dept**:17 个业务部门(engineering/design/marketing/…)+ 一个 `tool`(内置工具卡专用)。前端 `DEPT_LABELS/COLOR/ORDER` 做中文标签+配色。
- **body**:完整人设 markdown,是加持时真正注入给 AI 的东西。它太大(~6K 字/张),所以列表接口不下发——用去掉 body 的 `PersonaSummary`,详情/加持时才按需取。
- **用户卡 id**:前缀 `user-`,只允许 `[a-z0-9-]`,防路径穿越。中文名 slug 兜底成 `card`,靠纳秒后缀保证唯一。

## 加持机制(为什么这么设计)

per-session 存一个 `active_persona`(只存 id)。难点是 body 太长——每轮都灌会撑爆上下文,所以拆成两段:

- **一次性**:加持后**首条** chat 把完整 body 一次性 prepend 进去(`equip_body_injection` → 挂 `pending_persona_body`,消费一次即清,机制仿底座 skill 的 pending_instruction)。
- **每 turn**:之后每轮只注入一句 ~70 字的轻锚点(`equip_anchor`)进 `<system-reminder>`。原因是本地 Qwen3.6 在长对话里容易"忘了自己是谁",每轮顶端重申一下身份命中率高,又不重复灌 body。

换卡时新 body 覆盖 pending;但旧专家的 body 仍留在对话历史里(切几次会累积 token),这是 Side B 全正文路线的固有代价。

## 用户自创(三条路)

1. **手动建**:卡牌池「＋ 新建卡牌」→ 表单(`PersonaEditorModal`)→ `create_persona` 落盘。适合想直接填/快速改的用户。
2. **编辑 / 删除**:自制卡有「✎ 编辑」入口;编辑器内可删(两步确认)。内置卡只读,改不动。
3. **卡牌制造专家**(主打体验):一张内置专家卡,加持它 → 对话里它访谈你、设计一张新卡 → 最终把成品以 ` ```persona-card ` JSON 代码块输出 → 前端 `extractPersonaDraft` 从消息里抠出来 → 渲染「🃏 卡牌草稿 · 存入卡牌池」按钮 → 点开编辑器**预审/微调** → 保存。
   > 选「结构化输出 + 编辑器预审」而不是让 AI 直接调工具存卡:一是避开 Qwen3.6 带大 body 的工具调用可靠性问题,二是保留用户的审阅步骤(AI 生成的卡先过目再入库)。

## 前端

- **卡牌池视图**(`CardPoolView`):部门 facet + 「🃏 我的卡牌」facet + 关键词搜索 + tilt/FLIP 动效;自制卡带 `🃏 自制` 角标区分内置卡。
- **挂件**(`Lanyard`,聊天室左上角):常驻,一眼看出当前对话有没有加持、加持了谁。未加持时是「＋ 加持卡牌」入口;已加持显示专家卡,可点开换人、点 ✕ 摘下。
- **加持目标**:卡牌池顶部横幅常显"会注入到哪个对话"+ 加持后 toast;侧栏对应的 session 也会高亮——解决"从导航进卡牌池不知道注入到哪"的问题。
