# 知识集批量导入续作

知识集批量导入任务持久化在 `~/.pinvou3/knowledge/index.db`，与知识集文档、分块共用同一 SQLite 事务边界。应用异常退出后，启动时会把遗留的运行中文件恢复为待处理状态；用户可在知识库页选择继续或取消。

## 状态与幂等边界

- `knowledge_import_jobs` 保存任务、知识集、原始选择路径和任务状态。
- `knowledge_import_items` 保存每个文件的状态、尝试次数、错误及分块进度。
- `knowledge_import_staged_chunks` 只保存当前未完成文件的分块检查点，不参与检索。
- 文件全部分块完成后，正式 `chunks`、`documents` 状态和任务文件状态在同一事务内提交。
- 续作只领取 `pending` 文件，已完成或已跳过的文件不会重复处理；内容哈希不变时，已暂存分块不会重复计算。
- 单文件重试只把所选失败文件重新排队，不改变同任务内其他文件的终态。

用户主动取消会清理未完成分块检查点，已经完整提交的文档仍保留在知识集中。删除知识集时，其导入任务和检查点会一并删除，但不会删除磁盘上的源文件。

## 命令

- `kb_collection_add_sources`：创建并启动持久化导入任务。
- `kb_index_status`：读取最近任务及文件/分块进度。
- `kb_index_resume`：继续中断任务。
- `kb_index_retry_file`：重试指定失败文件。
- `kb_index_cancel`：取消当前或待续作任务。
