# 工作目录重绑定的恢复边界

移动工作目录后，重绑定流程会处理项目根、代码会话和普通聊天绑定，并在提交项目根前再次扫描两条会话链路，
将运行期间新增但尚未迁移的会话加入失败清单，供后续重试。纯会话项目归属调整不修改目录，允许在重绑定期间执行。

代码会话的重试覆盖已经移到目标目录的候选；只有缺失、损坏或目录已变化的基线才重新捕获。
当前目录的有效基线会保留“从会话开始以来的变化”语义，路径别名先规范化后比较。
重绑定重写 sidecar 时保留首次绑定时间，时间未知时不伪造。路径后缀转换拒绝空基准及包含 `..` 的路径。

重叠、嵌套或重复项目根使用冲突提示；其余验证失败保留原诊断，持久化失败保持独立分类。
Web 界面在没有项目桥接能力时不呈现不可用的项目改名和删除操作。

现有边界：尾部扫描后新增的绑定可能到下一次重绑定才被发现；基线按目录和会话起点判断，
返回先前目录时会保留该目录对应的既有基线。扫描失败与已删除会话遵循现有降级和重试规则。
