# Eval Markdown 分析报告设计

## 1. 背景

当前 Product eval 会把逐用例状态、Token usage、milestone 和错误写入 JSONL，并在终端打印简短 Markdown 表格。JSONL 适合机器消费，但不足以帮助开发者快速回答以下问题：

- 本轮整体表现是否健康；
- 哪些用例暴露了正确性、工具使用或性能问题；
- 问题的证据是什么；
- 下一步应优先改什么；
- 哪些结论是确定性事实，哪些只是模型评审的推断。

本功能为每次 eval 自动生成一份可直接阅读的 Markdown 分析报告，同时保留 JSONL 作为机器可读事实源。

## 2. 目标

1. 每次 Product eval 同时生成同 basename 的 `.jsonl` 和 `.md`。
2. 使用确定性规则提取可复现的问题事实。
3. 使用与被测模型不同的独立 Judge 模型补充回答质量诊断。
4. 输出带证据、影响和动作建议的优先级列表。
5. Judge 不可用时仍生成完整规则报告，且不改变 eval 用例本身的退出语义。
6. 原始提示、完整回答和完整工具轨迹只在内存中供分析使用，不写入报告。

## 3. 非目标

- 不把 Product mode 结果包装成 BFCL 或其他公开榜单成绩。
- 不保存完整对话以支持事后重新运行 Judge。
- 不在本阶段建立跨运行趋势数据库或可视化仪表盘。
- 不让 Judge 的主观结论覆盖确定性规则事实。
- 不把 5 条 smoke case 的单次结果解释为统计显著的长期趋势。

## 4. 方案选择

采用在现有 eval runner 内增加分析阶段的方案：逐 case JSONL 增量写入保持不变；整批结束后，在内存中运行规则分析与独立 Judge，合并结构化诊断并原子写入 Markdown。

未采用事后读取 JSONL 的分析命令，因为当前隐私约束禁止把 Judge 所需的完整回答写入 JSONL。未采用独立报告服务，因为当前 smoke 规模不值得引入新的部署和接口边界。

## 5. 用户接口

Product eval 增加独立 Judge 参数：

```powershell
cargo run --bin eval_smoke --features dev-tools -- \
  --mode product \
  --judge-model-id <saved-model-id>
```

语义如下：

- `--judge-model-id` 指向 Pinvou 已保存的模型配置 ID；
- Judge 的解析后 provider/model 身份必须与本轮被测模型不同；相同时跳过 AI 分析并在报告中写明原因；
- 未提供 Judge、配置不可用、调用超时或返回非法结构时，自动降级为纯规则报告；
- Judge 失败不使已成功的 eval 变为失败，进程退出码仍只由 eval case 的运行结果决定；
- 终端打印 Markdown 摘要、JSONL 路径和 Markdown 报告路径。

## 6. 数据流

```text
Eval case 执行
  ├─ 逐 case 写入 JSONL（现有事实记录）
  └─ 保留批次级内存分析材料
       ├─ 规则分析器
       └─ 独立 Judge
            ↓
       诊断合并与排序
            ↓
       Markdown renderer
            ↓
       .md.tmp → 原子改名为 .md
```

内存分析材料可以包含 case 提示、最终回答、usage、milestones 和精简工具事件，但生命周期不得超过本轮报告生成过程。报告层持久化结构只包含评分、置信度、简短证据摘要、问题分类和建议动作。Product runtime 为执行真实链路而创建的临时 Session 沿用现有存储语义，但必须在本轮结束后删除；本功能不得新增原文持久化副本。

## 7. 模块边界

### 7.1 规则分析器

规则分析器是无网络、可复现的纯分析模块。输入为整批结构化结果，输出为带来源和证据的 findings。

首批规则覆盖：

- case 失败、超时和工具错误；
- 首 Token 延迟或总耗时异常；
- Token 消耗过高；
- 缓存命中异常偏低；
- 工具重复调用、调用失败或明显无效；
- 简单任务使用不必要工具；
- 单 case 相对批次基线出现明显异常值。

阈值同时使用明确绝对门槛和批次中位数偏差。只有一个条件成立时通常不升级为高优先级，以减少将天气检索等天然复杂任务误判为性能回归。样本不足时，报告明确提示限制，不输出趋势性结论。

### 7.2 独立 Judge

Judge adapter 负责：

- 从已保存模型 ID 解析独立模型配置；
- 校验 Judge 与被测模型隔离；
- 构造最小化评审输入；
- 请求严格结构化 JSON；
- 校验 schema、分数范围、置信度和证据字段；
- 将超时、配置错误和解析错误转换为可降级状态。

Judge 对每个 case 评估以下维度：

- 任务完成度；
- 正确性；
- 工具选择；
- 效率；
- 安全与边界；
- 总体质量。

每个维度必须包含分数、置信度和简短证据摘要。Judge 只能基于本次运行材料得出结论，不得声称结果可与公开榜单直接比较。

### 7.3 诊断合并器

合并器负责：

- 为 finding 标记 `rule` 或 `judge` 来源；
- 合并语义高度相近但证据一致的问题；
- 规则与 Judge 冲突时并列保留，不自动覆盖；
- 按影响和证据强度生成 `P0`、`P1`、`P2` 优先级；
- 确保每条建议包含证据、影响和建议动作。

没有具体证据的泛化建议不进入最终报告。

### 7.4 Markdown renderer

Renderer 只消费结构化运行摘要和诊断，不直接访问模型或执行分析。报告固定包含：

1. 运行结论；
2. 关键指标；
3. 逐用例诊断；
4. 工具与性能观察；
5. 确定性规则发现；
6. 独立 Judge 评分；
7. P0/P1/P2 改进建议；
8. 评测限制与可比性说明。

规则事实和 AI 推断必须使用清晰标签区分。Markdown 先写入 `.md.tmp`，flush 成功后再原子改名，避免中断时留下看似完整的报告。

## 8. 报告文件与兼容性

若 JSONL 路径为：

```text
~/.pinvou3/eval/<run-name>.jsonl
```

Markdown 路径为：

```text
~/.pinvou3/eval/<run-name>.md
```

JSONL 继续作为运行事实的向后兼容格式。允许在 complete 记录中增加可选分析状态和 Markdown 路径，但现有字段及其语义不得改变。旧消费者忽略新增字段后仍能正常工作。

## 9. 失败处理

- eval case 失败：记录 case 错误，继续其余 case，并在规则报告中提升优先级；退出码按现有 all-succeeded 语义决定。
- Judge 未配置：生成规则报告，AI 分析章节标记“未配置”。
- Judge 与被测模型相同：不执行 Judge，章节标记“模型隔离校验失败”。
- Judge 超时、调用失败或响应非法：生成规则报告，记录不含敏感信息的降级原因。
- Markdown 写入失败：JSONL 保持可用；命令明确报告生成错误并返回非零退出码，不把残留 `.md.tmp` 作为正式产物。此退出码表示报告交付失败，与 Judge 降级不同。
- 进程中断：JSONL 和 Markdown 临时文件保留现有可恢复/可识别语义，不伪装成完整报告。

## 10. 隐私与安全

- `.jsonl` 和 `.md` 均不得写入原始提示、完整回答、完整工具输入输出、API key、Token、Cookie 或 Authorization header。运行期间的现有临时 Session 不属于报告产物，但必须按既有清理契约删除。
- Judge 请求只发送完成质量评估所需的最小材料，并使用用户明确配置的 Judge provider。
- Judge 的证据摘要必须受长度限制并经过敏感字段过滤。
- 报告中的模型身份只使用既有非敏感 provider/model 标识和保存模型 ID。

## 11. 测试与验收

### 11.1 单元测试

- 全成功、部分失败和全失败的规则报告；
- 高延迟、高 Token、低缓存、重复工具和工具失败规则；
- 优先级排序、相似 finding 合并及冲突保留；
- Markdown escaping、固定章节和原子文件命名；
- Judge 正常结构、超时、非法 JSON、越界分数和模型相同；
- 隐私过滤不允许原始回答、密钥和认证字段进入持久化产物。

### 11.2 集成验收

一次真实 Product smoke 应满足：

- JSONL 与 Markdown 使用同一 run ID 和 basename；
- CLI 打印两个绝对路径；
- Judge 可用时报告包含六维评分和带证据建议；
- Judge 不可用时报告完整生成并明确标记降级；
- eval 退出码不受 Judge 降级影响；
- 完成后没有对应临时 session、`.jsonl.tmp` 或 `.md.tmp` 残留；
- 报告敏感信息扫描无真实凭据或原始内容命中。

## 12. 完成标准

功能完成必须同时满足：

1. CLI 可以为一次 Product smoke 自动生成 JSONL 和 Markdown；
2. Markdown 对当前问题给出可追溯的规则事实和优先级建议；
3. 独立 Judge 能输出结构化评分，且失败时安全降级；
4. 原始评测内容不落盘；
5. 自动化测试覆盖规则、Judge、renderer、降级和隐私边界；
6. 文档说明运行命令、Judge 配置、报告结构和可比性限制。
