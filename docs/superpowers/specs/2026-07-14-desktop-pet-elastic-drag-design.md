# 桌宠弹性拖拽修复设计

## 背景

`feat/desktop-pet` 分支已经实现独立透明桌宠窗口、对话气泡、动画、缩放、右键菜单、位置持久化，以及带惯性和边缘反弹的弹性拖拽。当前桌宠能显示和响应会话事件，但按住后无法移动。

现有拖动链路在动画帧中使用 `window.__TAURI__.window.PhysicalPosition` 构造窗口坐标。Tauri 2 的全局 API 将 DPI 类型放在 `window.__TAURI__.dpi` 下，因此该构造调用会在首个物理动画帧同步抛错。异常发生在 Promise 创建之前，后续 `.catch()` 无法捕获，动画循环也不会继续调度，表现为桌宠完全拖不动。

## 目标

- 恢复桌宠拖动功能。
- 保留现有弹簧跟随、松手惯性、显示器边缘反弹和水平倾斜效果。
- 保留点击摸宠、滚轮缩放、右键菜单和位置持久化行为。
- 拖动失败时安全终止本轮动画，避免未捕获异常和失控的动画循环。
- 用自动化测试覆盖物理逻辑，防止 Tauri API 路径和拖动行为再次回归。

## 非目标

- 不改为操作系统原生的一比一窗口拖动。
- 不把每帧物理计算迁移到 Rust。
- 不调整桌宠素材、动画帧、对话状态聚合或主窗口聊天协议。
- 不扩展新的桌宠功能或重构无关模块。

## 方案选择

采用“前端纯物理逻辑 + Tauri 窗口适配层”的方案。

相较于 Rust 驱动物理，该方案不需要每帧 IPC，延迟和复杂度更低；相较于原生窗口拖动，它能保留已批准的弹性手感。修复将在现有实现基础上拆出小型纯函数，使坐标推进和碰撞行为可在 Node 测试中稳定验证。

## 组件与职责

### 物理逻辑模块

新增桌宠拖动纯逻辑模块，负责：

- 根据目标点、当前位置、速度、按住状态计算下一帧。
- 在松手阶段施加摩擦衰减。
- 将窗口限制在当前显示器边界内，并按既定系数反弹。
- 判断松手后的运动是否已经低于停止阈值。
- 计算精灵随水平速度产生的倾斜角。

该模块不访问 DOM、React 或 Tauri，因此可直接用 Node 测试。

### React 交互层

`PetWindow` 继续负责：

- 捕获 pointer down/move/up。
- 区分短点击和实际拖动。
- 读取窗口初始位置、窗口尺寸和当前显示器边界。
- 用 `requestAnimationFrame` 驱动物理模块。
- 将物理坐标交给窗口适配层，并更新精灵倾斜。
- 在组件卸载或错误时取消动画并清理拖动状态。

### Tauri 窗口适配层

窗口位置更新统一使用 `window.__TAURI__.dpi.PhysicalPosition`。调用前验证 `window`、`dpi`、`getCurrentWindow` 和位置构造器均存在。

同步构造异常与异步 `setPosition` 拒绝都由同一失败路径处理：结束当前拖动、清除倾斜并取消后续动画。这样不会把 API 错误静默转换成“拖不动”。

## 数据流

1. 左键按下桌宠，保存屏幕坐标并捕获 pointer。
2. 异步读取窗口物理位置、尺寸和当前显示器。
3. 初始化物理状态并启动动画循环。
4. pointer move 更新目标物理坐标，不直接移动窗口。
5. 每帧由纯函数计算新位置和速度。
6. 通过 Tauri DPI 物理坐标更新窗口位置。
7. pointer up 切换到惯性阶段；速度衰减并在边界反弹。
8. 速度低于阈值后停止；现有 `onMoved` 防抖逻辑保存最终位置。

## 坐标与多显示器

- `outerPosition()`、`outerSize()` 和显示器信息均按物理像素处理。
- `PointerEvent.screenX/screenY` 按 WebView 的屏幕坐标输入；沿用现有 `devicePixelRatio` 换算，保证高 DPI 环境下目标位移与物理窗口位移一致。
- 边界使用按下时所在的当前显示器矩形，允许负坐标显示器。
- 窗口最大坐标减去窗口宽高，保证桌宠不会完全飞出屏幕。

## 错误处理

- 初始化窗口信息失败：放弃本次拖动并恢复静止姿态。
- Tauri API 或 DPI 构造器缺失：放弃本次拖动并恢复静止姿态。
- `setPosition` 同步或异步失败：只终止本轮拖动，不影响桌宠事件、气泡或菜单功能。
- 组件卸载：取消活动动画帧，避免后台循环。

## 测试设计

按测试驱动方式实施：

1. 先新增失败测试，证明现有代码没有可验证的拖动物理接口，并覆盖弹簧推进、惯性衰减、四边碰撞和停止条件。
2. 实现最小纯函数使测试通过。
3. 新增窗口适配测试，要求从 `dpi.PhysicalPosition` 构造坐标，而不是错误的 `window.PhysicalPosition`。
4. 运行桌宠逻辑测试和项目既有测试。
5. 在 Tauri 开发窗口中手动验证：拖动跟随、松手惯性、边缘反弹、点击摸宠、滚轮缩放、右键菜单、重启位置恢复。

## 验收标准

- 桌宠按住并移动鼠标时能够弹性跟随。
- 快速松手后桌宠继续惯性移动，并在当前显示器四边反弹。
- 慢速松手后桌宠及时停止，不持续抖动或占用动画循环。
- 拖动过程不会触发摸宠点击动画；短点击仍可触发。
- 多次连续抓取、松手后不会出现窗口失控或动画循环叠加。
- 位置稳定后保存，重新显示或重启应用能恢复位置。
- Git 工作区中只有本次修复、测试和规格/计划相关改动。
