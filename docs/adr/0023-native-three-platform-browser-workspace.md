# Native three-platform browser workspace

Domain terms and naming boundaries for the browser workspace are defined in [`docs/browser-workspace-context.md`](../browser-workspace-context.md); the acceptance contract lives in [`docs/browser-workspace-acceptance.md`](../browser-workspace-acceptance.md).

Pinvou's task browser uses WebView2 on Windows, WKWebView on macOS, and WebKitGTK on Linux to host real pages. A shared BrowserService owns task sessions, tabs, identity, control, security, and the core tool contract. Each platform declares core browser capabilities explicitly; the ability to display a page never implies that the Agent can automate it. We do not use an external Chrome screenshot stream as the display path or as a failure fallback, and we do not introduce CEF while its size and maintenance cost remain disproportionate. Users therefore do not need to install Chrome.

## Current implementation boundary

| Capability or build artifact | Windows | macOS | Linux |
|---|---|---|---|
| `browser_native_display` | Enabled (WebView2) | Disabled in normal releases; host layer is compiled | Enabled (WebKitGTK) |
| `browser_agent_automation` | Enabled | Disabled in normal releases | Enabled (BrowserCore + WebKitWebDriver) |
| `browser_cdp` | Enabled only for the application-owned WebView2 loopback endpoint | Disabled | Disabled |
| `chrome-devtools-mcp` adapter | Prepared at build time and bundled | Not prepared, bundled, or started | Not prepared, bundled, or started |
| External Chrome fallback | Forbidden | Forbidden | Forbidden |

Browser identity is application-scoped rather than task-scoped. In particular, the macOS preview uses the application's persistent `WKWebsiteDataStore`, so cookies and local storage are shared across task conversations even though pages, tabs, restore manifests, and control leases remain task-isolated. Plain scheduled-run sessions intentionally receive the same browser tools and shared identity as other work sessions; native code and external ACP sessions do not.

Linux uses the shared Pinvou BrowserCore. DOM and structural observation run inside the task-owned WebKitGTK page. Clicks, fills, text input, and key presses use open-source WebKitWebDriver element endpoints and produce page events with `isTrusted=true`. Browser dialogs are accepted, dismissed, or given prompt text through W3C alert endpoints inside the same operation gate. Task isolation, multi-tab behavior, hidden-page restrictions, and restart restoration reuse the shared host. The `.deb` package declares `webkit2gtk-driver` as a required dependency, and a development environment without the driver does not register the browser MCP server.

The current WebKitGTK W3C pointer actions are not reliable on the tested hardware, so Linux does not expose `hover` or `drag` to the Agent and never substitutes synthetic JavaScript events. Upstream `resize_page` changes the content viewport of a top-level window, while a Linux browser page is an embedded child WebView whose bounds belong to the right Dock. Linux therefore hides `resize_page` and rejects direct calls as unsupported instead of resizing the application window or temporarily overriding Dock bounds. Agent-facing screenshots are also hidden until the tool-result image pipeline can deliver real image input, and the current BrowserCore catalog has no standalone scroll tool. Linux verification is therefore limited to DOM structure and supported interactions; it cannot establish visual styling. The macOS implementation is available only through the explicit preview feature while the normal product capability remains disabled. Chrome DevTools-specific diagnostics remain available only on Windows when declared by capability.

After a Linux WebDriver session crashes, the host may briefly navigate a page to a one-time random internal marker while rebuilding the safe WebView-to-WebDriver-handle mapping, then reload the original URL. This recovery does not preserve form values, Canvas contents, or JavaScript memory. The marker exists only as a transient host-controlled URL; no stable identity or binding script is injected into the remote page's main world.

## Lifecycle and control boundary

- Restart restoration persists only URLs, tab order, and the active index through an atomic write with user-private permissions. The new process creates new WebViews, tab tokens, target IDs, and leases; runtime mappings from the old process are never reused. Restored control begins unclaimed, and the next real user action or Agent lease claims it atomically. A normal exit retains the restoration manifest, while an explicit stop or task deletion removes it. Task deletion also removes the session browser MCP configuration.
- Agent-created tabs use hidden staging: discover the application-owned WebView target, let the host commit the requested URL as the first navigation, then publish it through a final compare-and-swap using the complete lease captured before creation. A late cancellation may roll back only while the creation revision has not been superseded by user takeover or a later mutation.
- A tool that has begun dispatch is atomic. User takeover invalidates its lease and blocks the next tool but does not promise to interrupt a call already submitted to the platform backend. The `finally` path immediately revokes active-operation state. Only calls that actually dispatched native input retain a post-dispatch callback grace period of at most 100 ms. Explicit UI takeover clears that grace period immediately; 750 ms is only the fail-safe upper bound for an abnormal dispatch exit.
- When an already-started dispatch receives external cancellation or an internal timeout, the wrapper requests cooperative cancellation from the upstream backend. It must wait for the real terminal result, or terminate the child process and prove that it has stopped, before calling `end_agent_operation`. An upstream success remains authoritative. If a failure leaves commit state unknown, the wrapper returns a non-retryable commit-unknown result so the Agent cannot replay the action. Child-process crashes, stdin closure, watchdog shutdown, and process signals share one graceful-shutdown barrier.
- Native mutation and optional post-mutation observation are separate commit phases. A successful mutation remains successful even if the optional snapshot fails; the result includes `observationWarning` and the action must not be replayed. `fill_form` validates the complete batch before its first write. A mid-batch failure returns a non-retryable partial result with `completedCount` and `failedIndex` so fields already filled are not repeated.
- The durable Prepare journal is the commit/compensation witness across a host restart. A readable but unsettled record is reconciled before browser admission. For an unreadable record with a canonical lowercase session-token filename, recovery pins private directory handles and uses no-follow, same-filesystem atomic renames to isolate that token's process-local runtime mapping, restore manifest, and journal into a private generation slot, in that order; the journal moves last as the completion marker. An I/O failure before the marker remains globally fail-closed and retries the same incomplete slot. After all three active paths are empty, other tasks and a fresh generation for the same task may proceed; completed slots are removed through the same anchored handles by task cleanup or startup orphan reconciliation. A regular journal whose filename cannot be trusted is isolated alone in an unassigned slot and cannot authorize changes to any task state. If a newer host-authoritative runtime revision proves that a committed Prepare was superseded, recovery first atomically neutralizes the old compensation record, then removes process-local state and retires the WAL, so every crash point preserves the newer restore manifest and makes a late old cancellation a no-op.
- A popup never receives Agent mutation authority from a short-lived boolean. Only a popup captured during an already-started dispatch with a complete, still-valid lease can remain Agent-owned through hidden staging and final compare-and-swap. Other page-created popups become user-owned tabs in the same task. A user takeover committed before the final compare-and-swap rejects the late publication. Remote pages never receive global clipboard-read permission. Embedded downloads are denied by default and direct the user to the system browser.
- `pinvou-user-takeover://interaction/...` is an unauthenticated, reserved navigation signal used only to pause Agent control after a real page interaction. A remote page that deliberately navigates to this scheme can cause a low-privilege denial of Agent control until the normal idle hand-back or explicit user hand-back occurs, but the signal conveys no data and grants no browser, filesystem, clipboard, credential, or other capability.
