# 辅助对话获得恰好一个受限读取工具（父任务会话记录）

> 状态：已决策；决策记录先行登记，引擎侧实现随 `feat/aux-parent-context`（实现 PR）落地，
> 落地前主干保持零工具现状。

工作规划与验收矩阵见 `docs/aux-parent-context-design-and-acceptance.md`；本 ADR 记录决策本身。
修订对象：ADR-0006 的 2026-09-15 / 09-18 / 09-19 / 09-25（M8）各条辅助对话补充（文末勘误）。

## 背景与目标

辅助对话（PR #433）刻意"盲"：引擎整组隔离（空工具表、最小 `AUX_SESSION_INSTRUCTIONS`、
无 MCP/子代理/记忆/视觉），指令明确承诺"不访问主任务的执行与上下文"，用户只能手工粘贴
上下文。零工具是 #433 的设计残留而非疏漏。session-reader（PR #585，只读 L0）已在主线后，
本决策把辅助引擎的**零工具不变量**升级为**受限只读不变量**：恰好一个工具——spawn 时钉死在
父任务会话 id 上的 session-reader 实例——其余一切隔离属性逐字节保留。辅助对话由此可以回答
"这个任务进行到哪了 / 刚才的报错什么意思 / 总结一下结论"。

## 决策条款

1. **能力形状**：模型可见工具恰为 `mcp_session-reader_read_session`。`list_sessions` 保持
   服务端实现但不进辅助白名单（父 id 已随指令下发，列表不增加信息量，最小目录 = 最小
   工具游走面）。
2. **范围锚点**：spawn 时在按-aux 生成的 MCP 配置文件上以 `--only-session <parent_id>`
   参数钉死范围，服务端进程内强制。身份由 App 锚定（bridge 从 aux id 派生父 id），永不由
   模型声明——与 browser wrapper 的 per-session-config 先例（`write_work_mode_mcp_config`）
   及服务端既有 argparse 形态（`--sessions-dir`）一致。
3. **boot 门控**：辅助引擎**启用** `Feature::Mcp`，`mcp_config_path` 指向仅含该受限
   session-reader 条目的按-aux 文件。`Feature::Mcp` 门控 boot、`allowed_tools` 只过滤目录，
   因此单条目专属文件意味着 boot 恰好拉起一个本地 python 子进程——无用户 MCP 服务器、无网络。
   该文件写入失败时**失败关闭**：spawn 退回旧零工具分支（`Feature::Mcp` 关闭、空工具表、
   全局 mcp 路径），绝不回退到全局 mcp.json（那会让辅助引擎 boot 全部用户服务器——范围逃逸）。
4. **每回合强制**：`Op::SendMessage.allowed_tools` 的组装点改为三路：aux（按引擎自身 id
   判定）→ 受限单工具表；`restrict` → 空表；其余 → 全量白名单。aux 判定以引擎自身会话 id
   为键，保留 `TurnToolRestrict`"伪造令牌不能解除 aux 限制"的性质（现在同样不能把 aux
   抬到受限面之上）。`EditLastTurn` 重发无每回合表面，继承引擎配置的受限白名单。
5. **父 id 派生**：大小写不敏感地剥掉 `aux-` 前缀，父部分原样保留；隔离前缀父
   （`aux-sched-x` / `aux-aux-x` / `aux-eval_x`，含大小写变体）→ `ZeroTool` 兜底（旧分支
   逐字节等价）。构造上辅助父恒为普通会话（store 在创建处拒绝 sched/aux 父），但配置组装
   不信任构造。
6. **决策中心**：单一函数 `aux_tool_surface(session_id) -> AuxToolSurface { ZeroTool,
   ParentScopedRead { parent_id } }`，spawn 配置与每回合组装点都只消费这一个接缝；未来一切
   辅助能力变更（多会话范围、写族、指示器、定时投递）从新增变体/消费点开始，不散落
   `is_aux` 判断。
7. **指令与提醒**：`AUX_SESSION_INSTRUCTIONS` 保持中文，改写为点名唯一受限工具 + 父会话
   id 槽位 + 不可信立场（不再承诺"不访问主任务上下文"，改为"仅经该只读工具读取会话记录"）；
   `AUX_ZERO_TOOL_REMINDER` 更名 `AUX_SCOPED_TOOL_REMINDER` 并改写为"恰一工具 + 范围 +
   不得发出其他标记"。改写是未经测试覆盖的行为变更：沿用 #433 的披露立场（zh 保留、
   ADR 记录、A1 手工验收兜底）。
8. **特性开关（v1）**：不设独立开关。受限实例沿用 `read_session` 既有的
   `session-mention`+`long-memory` 并集门控（两者全关 → 结构化 `feature_disabled`）。
   并集语义在 manifest 层是实例全局的；独立 `aux-context` 开关需要实例级映射覆盖——
   预留（R3），本期不做。v1 关闭辅助上下文 = 同时关 `session-mention` 与 `long-memory`。
9. **受限 `list_sessions`**：若白名单将来放宽，服务端受限模式返回恰一条（受限会话自身的
   元数据；记录缺失则空表）——宽限设计 + 廉价的父存在性探针 + 零秘密面。
10. **服务端版本**：`manifest.json` 1.0.0 → 1.1.0（行为新增；内置包按字节比对重释放，
    `ensure_package_released` 自动升级存量安装）。市场实例的 `tools/list` 不变——目录过滤
    由引擎白名单完成；`aux-` 等隔离前缀在市场实例中照旧拒绝。

## 读面登记（read-surface register）

辅助会话隔离是"读面默认拒绝 + 显式例外"的契约（`docs/builtin-toolset-contract.md` §5）。
本 ADR 登记两个**既有**的任何 id 可读面（它们先于本决策存在，登记的是事实而非新授权）：

- `export_session`（app 命令）：任何已持久化会话 id 均可导出（含 `sched-`、`aux-`）——
  只读语义，与 `load_session` 同姿态；菜单入口仅出现在普通会话上，能力面本身不拒绝。
- `get_session_timeline`（app 命令）：任何合法字符集 id 均可读 timing——辅助 id 的读取
  确实发生（诊断入口按 id 直读，不经排除 aux 的侧栏列表），但并非渲染承载性：前端对
  该读取 try/catch 退空，且辅助面板不投影 timelineEvents。规范要点是"此读面不得长出
  id 类别拒绝"，而非"面板依赖它"。

写面的准确边界（较窄，勿扩大表述）：**模型可见的写族工具**（投递/消息类，尚未落地）
不接受 aux 作为请求者或目标——将来落地时按契约 §5 需显式所有权设计。远程控制对 aux
**不**拒绝请求者：`aux-` id 豁免多智能体 Web 执行黑名单是**设计行为**（`validate_multi_agent_session_web_scope` 对 aux 形状的会话参数提前放行，auxChat 中继是经认可的用户中介通道）；删除与 aux 的交互也走设计内的级联/重置（主删除级联派生 aux、按 aux id 删除即「重开话题」）。本 ADR 不改变任何写面。

## 预留接口（R1–R5）

- **R1 `AuxToolSurface` 决策中心**：见条款 6。
- **R2 `--only-session` 单 id 起步，按集合编写**：将来辅助侧 @-引用（`feat/session-mention`、
  PR #586 合并后）
  需要多 id 时扩为逗号分隔或重复旗标；服务端范围判定已按集合语义实现。
- **R3 `--gate-feature <id>` 槽位**：实例级特性映射覆盖（辅助实例单独挂 `aux-context`
  开关）——v2 独立开关的设计位，未实现。
- **R4 按-aux 配置写入器对条目表泛化**（map 而非硬编码单例）：未来的辅助域服务器以数据
  加入，不需要新写入器。
- **R5 递延决策登记**：写族辅助所有权（契约 §5 要求的 explicit ownership design）、
  S1 模型传播 + 面板指示器、定时投递进辅助。记录在案，不静默敞口。

## 代价与披露的限制

- **提示注入面扩大**：父任务转录内的指令现在可及辅助模型的回答。缓解 = 不可信契约
  （工具描述 + 指令措辞 + 每回合提醒，与 session-mention 同姿态）；E5 钉住信封。
- **每个活跃辅助引擎一个 python 子进程**（随引擎空闲回收）。有界；披露。
- **并集门控开关**：见条款 8。不独立——R3。
- **指令/提醒文本的 Rust 形状钉是 `contains()` 式**（#433 登记过的既有缺口）；接受并披露。
- **辅助转录首次出现 tool_use/tool_result 块**：辅助面板投影从未渲染过工具调用
  （零工具时代不存在）；A5 钉住通用工具卡的中性渲染，不接受一方破损。
- **v1 无 UI**：无面板改动、无 i18n 键；模型自行决定何时查询父任务，可见入口是后续工作。
- 零 CodeWhale 改动；无新 Tauri 命令；无新事件。
