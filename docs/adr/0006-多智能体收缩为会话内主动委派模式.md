# 多智能体收缩为会话内主动委派模式（取代 ADR-0005 的入口与协议设计）

真机使用与代码复盘暴露出方向性偏差：底座（CodeWhale）在本分支开发前就原生同时提供裸 `agent`
与 `workflow` 两条派生路径、`agents/list·message·followup·interrupt·wait` 一族协调工具，且普通
会话默认可用裸 agent。本分支却把多智能体做成了一套 Workflow 专用调度系统——宿主轮只许
`workflow`、封禁裸 agent、每张编排图强制确认、App 侧自建运行台账与生命周期状态机。复杂度
（App 侧 +9k 行、fork 侧 +4.5k 行）主要来自这层自加约束，而非产品价值；真机事故（联网任务
被派给被钳成四个本地文件工具的"只读"子任务、汇总者翻转录烧穿预算）也源于此。

因此按以下定义收缩：

> **多智能体模式 = 普通会话能力 + 主动委派 + 专家可视化 + 只读/执行权限。**

- **会话内开关，不是会话类型**：开关位于输入框模型选择器下方，会话级记忆。开启后本会话装配
  专家名册并每轮注入主动委派指令（工具面不变，与主线一致——`workflow` 立场见下条）；
  关闭停止注入，在跑的子智能体不打断。
  不再有专属的 `wf-` 会话形态。存量 `wf-` 会话降级为遗留数据：会话与执行记录仍可打开查看
  （transcripts 走原运行目录）、侧栏保留「多智能体」徽标、删除时级联清理 `agent-runs/` 目录；
  引擎侧沿用名册装配（等同开关常开，工具面与所有会话一致），但不再能新建。
  开关状态持久化在 `sessions/_multi_agent.json`（2026-08-01 复审补），重启后 Web 门禁与
  每轮注入不失效。
  开启同时把会话私有工作区（`~/.pinvou3/sessions/<id>/workspace/`）初始化为本地 git 仓库，
  并在每轮发送前快照（2026-08-03 复审补）：底座 worktree 隔离要求可检出的 HEAD，且并行派发
  的 git 根查找在非仓库工作区会向上逃逸到用户主目录、以"多仓库歧义"整批拒发（真机事故）；
  非 worktree 的裸派本不需要 git，提前建仓是为了模型随时可用 worktree。仅本地留痕：不设远端、
  不上传、不改用户全局 git identity；git 因此是多智能体模式的可选系统依赖（缺失时开关安全
  失败并指向「设置 → 依赖体检」一键安装，开关提示如实告知）。快照沿用 git 忽略语义：
  全局 gitignore 命中的文件不属输入范围（强制收录会把依赖目录类巨物拖进每个 worktree），
  需要传给子智能体的输入放非忽略路径即可。
- **主动委派，只走 agent 集群**：单个独立任务派一个裸 `agent`；多阶段任务派一群、由父模型亲自
  协调等待与汇总（结果天然回流父上下文）；简单任务不委派。承担者用底座正式契约字段
  `profile` 指定名册成员（`role` 会被当成内置类型别名截走，命中不了名册人设）。
  `workflow` 保持主线原状（2026-08-03 复审校正：全局禁用属能力回退，撤销）：底座
  subagents_enabled 连带注册的 WorkflowTool 对所有会话可用，但委派提醒**不教学、不推荐**
  该路径——底座把 read_only 子任务钳成四个本地文件工具、结构化阶段默认不传递上游结果
  （`depends_on_results` 留空）两处基线行为未修（真机"调研断网、汇总烧穿预算"事故根因），
  模型自行选用时由会话既有的 Plan/Yolo 与底座审批语义兜底。
- **只读/执行 = 既有 Plan/Yolo 两档**：不新增权限概念，不做专家级工具白名单。Plan 档委派限于
  调研/审查类子智能体（底座只读姿态原生保留联网）；Yolo 档继承会话完整工具与审批策略——
  编排图审批随之几乎不可达，确认卡、审批命令与审批落盘整链退役。
- **最小父子索引 = 底座 worker ledger**：子智能体的身份、任务摘要、状态、时间戳直接读底座落盘
  的 `subagents.v1.json` 与 transcripts，App 零新增持久化；专家头像由角色名在渲染时映射专家池，
  无匹配回退通用头像。Workflow 专属运行台账（`agent-runs/run.json` 状态机、attempt tracker、
  进程租约、轮末对账）退役。
- **子智能体面板是只读执行记录**：形似普通对话，但不是第二个聊天入口；追问、打断、取消一律
  经父对话表达。卡片无取消按钮；主对话既有「停止」按钮级联取消父任务与全部子智能体。
- **取消与善后（App 薄适配，不改底座）**：所有引擎回收路径在 `Op::Shutdown` 前先发
  `Op::CancelSubAgents`（同通道顺序保证）；删除会话不拦截、不等待确认。已知限制如实记录：
  取消是 abort 不 join，子智能体已启动的独立 shell 子进程可能残留——这是底座基线对所有会话
  的既有缺口，若实际使用中成为问题，再单独决策给底座补一个最小有序关闭接口。
- **`[BLOCKED]` 只是展示提示**：子任务受阻约定用于界面标注（不显示成绿色完成），不参与任何
  生命周期判断。

代价与取舍：Yolo 档下会写文件的编排图不再有"开工前看整图"的机会（Plan 档天然保留"先出方案
等接受"）；这是把确认从"协议仪式"降级为"执行安全机制"的有意选择，对标 Codex 的委派形态。
已建成果不粗暴回滚：Codex 式只读面板、transcript 适配层、受阻标注、专家头像映射全部沿用；
拆除按四批次进行（行为放开+取消级联 → 台账/审批退役+专家卡 → 开关上线 → 存量降级与收尾），
每批次独立成提交且全绿。ADR-0004（编排建在底座）仍然成立——变的是入口与协议层，不是底座
选型。ADR-0005 的入口形态与"宿主轮只允许 workflow"决策由本文取代。
