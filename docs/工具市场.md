# 工具市场

本文说明工具市场的当前实现。历史方案、旧接口和已废弃的内置共享 Key 设计请查 Git 历史，不再保留在现行文档中。

## 设计边界

- MCP 的连接、OAuth、工具发现和调用复用 CodeWhale，不在 pinvou3 重写。
- pinvou3 负责工具清单、安装状态、系统凭据、前端交互和 Tauri 命令编排。
- 一个工具可以包含 MCP server、配套 Skill 和动态路由说明。
- 工具源文件编译进应用，运行时释放到 `~/.pinvou3/bundle/`。

## 代码位置

| 职责 | 位置 |
|---|---|
| MCP 工具清单 | `pinvou3-app/resources/mcp-servers/*/manifest.json` |
| 工具市场核心 | `pinvou3-app/src-tauri/src/features/marketplace/mod.rs` |
| Skill 安装管理 | `pinvou3-app/src-tauri/src/features/marketplace/skill_marketplace.rs` |
| Tauri 命令与 OAuth 编排 | `pinvou3-app/src-tauri/src/app/commands/marketplace.rs` |
| 工具商店界面 | `pinvou3-app/src/features/tools/ToolStoreView.jsx` |
| 前端工具元数据 | `pinvou3-app/src/features/tools/tool-common.jsx` |

`manifest.json` 是 MCP 配置的单一真相源。前端元数据负责展示文案和配置入口，不应复制密钥或后端连接参数。

## 运行时数据

| 数据 | 位置 |
|---|---|
| 已安装工具 | `~/.pinvou3/marketplace/installed.json` |
| MCP 配置 | `~/.pinvou3/bundle/mcp.json` |
| 禁用连接器 | `~/.pinvou3/disabled_connectors.json` |
| 密钥 | 当前平台的系统凭据存储 |
| OAuth token | CodeWhale 的 MCP OAuth 凭据存储 |

安装时先写入有效的 MCP 配置，再记录 `installed.json`，避免出现“显示已安装但 MCP 未注册”的半安装状态。卸载时同步清理 MCP 配置、对应凭据和配套 Skill。

## 凭据规则

工具市场不内置、编译或发布高德、问财、企查查共享 Key。

- 高德天气：用户填写自己的高德 Web 服务 API Key。
- 同花顺问财：用户填写自己的问财 API Key。
- 企查查：使用 `qcc-company` 远程 MCP OAuth，不填写 API Key。
- 智慧芽：用户填写自己的 API Key。
- Canva、华宇元典等远程 MCP：使用各自 OAuth。

用户填写的密钥只保存到系统凭据存储。`mcp.json` 只保存环境变量名或受支持的凭据引用，运行时再把密钥注入 MCP 进程或请求头。

旧版本可能已把天气、问财或企查查凭据写入明文配置或系统凭据。启动和安装流程保留迁移逻辑，用于移除明文并避免误删用户自己的凭据；旧共享凭据是否失效由对应服务端吊销或轮换决定。

Windows WoSign 签名凭据不属于工具市场，由构建机上的 `scripts/.builtin-secrets.env` 和签名脚本单独管理，不会编译进应用。

## Manifest 关键字段

常用字段如下：

| 字段 | 说明 |
|---|---|
| `id`、`name`、`description`、`version` | 工具身份与展示信息 |
| `command`、`args` | 本地 stdio MCP 启动方式 |
| `servers` | 远程 MCP 的 URL、scope 和 OAuth resource |
| `mcp_tools` | 已知工具名；远程动态发现时可以为空 |
| `config_fields` | 前端向用户收集的配置 |
| `secret_env` | 写入 MCP 进程环境的敏感配置 |
| `secret_headers` | 通过受支持的环境变量引用写入远程请求头 |
| `routing_rules`、`tool_table_entries` | 安装后加入模型上下文的路由说明 |
| `companion_skills` | 随 MCP 一起安装或卸载的 Skill |
| `validate_on_install` | 安装后是否真实连接远程 MCP 并校验工具列表 |

敏感字段必须声明为 `secret: true`，不得在 manifest、前端源码、文档、测试样例或发布脚本中写真实凭据。

## 安装流程

### 用户 Key 工具

1. 前端根据 `config_fields` 显示配置弹窗并校验必填项。
2. Tauri 调用 `install_marketplace_tool`。
3. Rust 把密钥写入系统凭据存储，在 `mcp.json` 中写入引用。
4. MCP 配置成功后更新 `installed.json`。
5. 如声明了 `validate_on_install`，真实连接并发现工具；失败则回滚安装。

### OAuth 工具

1. 先安装远程 MCP 配置。
2. 前端调用 `start_marketplace_tool_oauth_login`，由 CodeWhale 打开浏览器并处理回调。
3. 只有 MCP 配置存在且 OAuth token 有效时，界面才显示已连接。
4. 用户取消、超时或服务方拒绝时保留“待授权”状态，可重新授权。
5. 卸载前先删除 OAuth token；删除失败时停止卸载，避免残留有效授权。

## 预置技能更新机制

预置技能（`government-writing` / `pptx` / `visualizer` / `ima-skills` / `package-author` / `skill-author`）安装后落在按包聚合的 `~/.pinvou3/bundles/<pkg>/skills/<name>/`，**不随 App 升级自动刷新**。更新采用"打开商店时检测 + 手动按钮"模式：

- **无版本号**：来源与内容指纹写入统一真相源 `bundles.json`（`BundleStore` 记录）；`.installed-from` 标记已退役，不再参与检测。
- **检测**：`list_marketplace_skills` 对已安装的预置技能做"记录指纹 vs 当前编译进应用的嵌入资源"的比对，不一致即 `update_available = true`，卡片出现"更新"按钮。App 升级带入的新版技能由此被检出；用户对技能目录的本地修改同样会被检出。
- **更新**：`update_marketplace_skill` 复用安装的原子覆盖管线（staged 解包 → 备份 → rename），前端先弹确认（覆盖会丢失本地修改）。与"新装"不同，更新**不重置**技能在各 scope 的启用/停用状态。
- **范围**：仅预置技能；用户上传的 zip 技能无嵌入对应物，不参与检测；MCP manifest / server 脚本由启动时的 `write_mcp_servers` 按已装记录补齐，不在此机制内。
- ima-skills 不单独成卡（归 ima 连接器卡认领），其"更新"入口挂在 ima 连接器卡上。

## 新增工具

1. 优先确认 CodeWhale 是否已经支持所需 transport、OAuth 和工具发现能力。
2. 在 `resources/mcp-servers/<id>/` 添加 manifest 和必要的本地 server 文件。
3. 在 `tool-common.jsx` 添加用户可见元数据；需要配置时提供获取凭据的官方入口。**详细编入规则见 `tsToolsData` 头部注释指南**（2026-08 能力包归一后）：一个产品 = 一张卡，组合包（MCP + 配套技能）不加第二张卡——商店卡由后端技能数据自动合成，连接器条目仅作元数据源，渲染层按 `bundleMcpIds` 自动过滤。
4. 如果有配套 Skill，通过 `companion_skills` 声明，不要在 Rust 中硬编码领域行为；配套技能落 `skill-marketplace/<name>/SKILL.md` 并注册 `preset_manifests()`；**使用知识（路由规则、流程约束）一律进 SKILL.md，不在 manifest 内嵌 `routing_rules`**（gongwen/pptx 已归一，其余 7 个 manifest 的内嵌字段属旧实现，新增勿模仿）。
5. 连接器认领的技能（如 ima-skills 归 ima）加入 `ToolStoreView` 的 `CONNECTOR_CLAIMED_SKILLS`，防止「一个产品两张卡」。
6. 补充契约、Rust 和浏览器 smoke 测试。
7. 检查安装失败、重复安装、取消 OAuth、卸载和旧配置迁移路径。

## 验证

常用检查：

```bash
cd pinvou3-app
npm run test:marketplace-oauth
npm run test:tool-store
npm run lint:ui
npm run build:ui

cd ..
python3 scripts/mcp-server-contract-smoke.py

cd pinvou3-app/src-tauri
cargo test marketplace -- --nocapture
```

涉及外部配置入口时，还需运行外链白名单测试；涉及 CodeWhale 或 submodule gitlink 时，按 `docs/fork-policy.md` 和 `docs/fork-modifications.md` 补齐 fork 验证。
