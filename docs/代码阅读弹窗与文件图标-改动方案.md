# 代码阅读弹窗与文件图标着色 — 改动方案

> 分支：`feat/code-viewer-popup`（基于 `feat/kimi-coding-optimization`）
> 状态：方案评审稿 → 实施完成后以《代码阅读弹窗与文件图标-改动说明.md》归档实际结果

## 1. 背景与目标

Codex ACP 会话视图右侧的工作区面板（`CodexWorkspacePanel`）目前点击文件后，是在面板内切换出一个内嵌预览页：空间受面板宽度限制（默认 380px），文本以无语法高亮的 `<pre>` 直接渲染，阅读长代码体验差。

本次改动两个目标：

1. **代码阅读弹窗**：在工作区点击文件后，以模态弹窗形式展示文件内容，代码带语法高亮，弹窗大小可由用户拖拽调整并记忆。交互参考 VSCode 智能体（Copilot Chat）窗口中"点击变更文件弹出只读代码视图"的逻辑。
2. **文件图标着色**：为工作区文件树引入 VSCode 风格的按类型彩色文件图标，并回答"是否需要移植 VSCode 核心"的可行性问题。

非目标：

- 不做代码编辑（弹窗只读）。
- 不改动"变更"tab 的 diff 面板内预览逻辑。
- 不引入 monaco-editor / VSCode 核心。

## 2. 现状调研结论

| 依赖 | 现状 | 结论 |
|---|---|---|
| 文件内容读取 | Tauri command `preview_codex_workspace_file`（`src-tauri/src/features/codex_acp/workspace.rs:177`），文本 ≤512KB 带 `truncated` 标记，图片返回 dataUrl | 直接复用，无需新增 Rust 命令 |
| 语法高亮 | `src/shared/syntax-highlighter.js` 导出 `highlightCode(code, hint)`，highlight.js 11，~75 语言，LRU 缓存 + 超限回落纯文本；hljs 主题变量已在 `src/styles/base.css` | 直接复用，输出放入 `.pinvou-code-block` 容器即获得配色 |
| 弹窗惯例 | 无通用 Modal；各页面手写 `fixed inset-0` 遮罩 + `createPortal` 挂 body（遮罩关闭、Esc 关闭） | 按现有惯例手写新组件 |
| 可调整大小 | `CodexWorkspacePanel.jsx:264-311` 已有 mousedown + document mousemove + rAF 节流 + localStorage 持久化的拖拽实现 | 复用同一模式 |
| 文件图标 | 工作区树目录一律 `FolderOpen`、文件一律 `FileText`（`src/components/icons.jsx`，单色 stroke）；仓库另有 `src/file-icons/*.svg` 12 个静态彩色图标和 `FileTypeIcon` | 工作区树需要一套新的彩色图标映射 |
| i18n | `src/shared/i18n.js` 字典，zh/en/ja 三语言必须齐全，有 `tests/ui_language_coverage.test.mjs` 强制 | 新增文案挂 `uiCodexWorkspace` section 三语言 |
| 测试 | 无 Vitest；`tests/` 下 node 脚本 + puppeteer 冒烟（参照 `tests/diff_viewer_ui_smoke.mjs` fixture 模式） | 新弹窗补 fixture + smoke 脚本 |

## 3. 弹窗设计

新组件 `pinvou3-app/src/features/codex/CodeViewerModal.jsx`：

- **结构**：`createPortal` 到 `document.body`；`fixed inset-0 z-[300]` 遮罩（点击关闭）；居中对话框，默认约 70vw×78vh，min 480×320，max 95vw/95vh。
- **头部**：彩色文件图标 + 文件名与相对路径、语言标签（来自 `highlightCode` 返回值）、操作按钮（复制路径 / 复制内容 / 在文件管理器显示 / 用系统应用打开，沿用现有 Tauri commands）+ 关闭按钮。
- **内容区**：
  - 文本：`highlightCode(text, ext)` → `<pre class="pinvou-code-block">` + `<code class="hljs">`，等宽字体、行列距与现有 markdown 代码块一致；`truncated` 时顶部显示截断提示条。
  - 图片：`<img>` dataUrl 自适应居中。
  - 其他二进制：友好提示（不支持预览）。
  - 加载中 / 读取失败两种状态。
- **调整大小**：右、下、右下三个拖拽 handle（`role="separator"`），复用面板同款 mousemove + rAF 节流实现；宽高持久化到 localStorage（`pinvou_code_viewer_size`），双击右下角 handle 恢复默认。
- **关闭**：Esc、遮罩点击、头部关闭按钮。

## 4. 接入点改动

- `CodexWorkspacePanel.jsx`：文件树 `onPreview` 改为打开 `CodeViewerModal`；原面板内 `PreviewPane` 相关代码随之下线（其头部按钮能力迁移进弹窗头部）；"变更"tab 的 diff 预览保留面板内现状。
- `i18n.js`：`uiCodexWorkspace` 三语言新增弹窗所需文案（复制内容、截断提示、不支持预览、加载失败、调整大小 aria 等）。

## 5. 文件图标着色方案（第二阶段）

**结论先行：不需要移植 VSCode 核心。** VSCode 的文件图标是"文件图标主题（File Icon Theme）"机制：一套 SVG/字体图标 + 一份「扩展名 / 完整文件名 / 语言 ID → 图标」映射表 + 主题配色，与其编辑器内核完全解耦。VSCode 自带默认主题（Seti 系）也是独立包。移植 VSCode 核心（monaco + 主题服务 + workbench）对本需求没有任何必要，工程量以"月"计且带来长期维护负担，不予考虑。

可行方案对比：

| 方案 | 说明 | 工作量 | 评价 |
|---|---|---|---|
| A. 自绘少量 SVG + 映射 | 按扩展名归类手写十几个彩色图标 | 小 | 风格难统一，观感一般 |
| B. 引入开源图标主题子集（推荐） | 选用 MIT 许可的成熟 VSCode 图标主题（Material Icon Theme / Seti UI），抽取常用 SVG + 其映射表思路，落为本地 sprite | 1–2 天 | 观感与 VSCode 一致，许可清晰 |
| C. 移植 VSCode 核心 | — | 月级 | 无必要，排除 |

实施要点（方案 B）：

1. 新增 `src/components/files/FileColoredIcon.jsx` + `src/components/files/file-icon-theme.js`（映射表：特殊文件名 > 扩展名 > 默认；目录 / 打开目录单独图标）。
2. 图标资产放 `src/file-icons/theme/`，仅引入映射覆盖到的图标，避免整包体积；在文件头注明来源与 MIT 许可。
3. `WorkspaceTree` 替换 `FolderOpen`/`FileText` 为 `FileColoredIcon`；弹窗头部复用同一组件。
4. 暗色模式下图标本身为彩色 SVG，无需额外适配。

## 7. 验收标准

- 工作区点击任意文本文件弹出代码弹窗，语法高亮生效（至少验证 js/ts/rs/py/md/json）。
- 弹窗可通过右侧、下侧、右下角拖拽调整大小，刷新后保持上次尺寸；双击右下角恢复默认。
- Esc、点击遮罩、关闭按钮均可关闭；再次打开其他文件正常。
- 图片文件显示图片；超过 512KB 文本显示截断提示；二进制显示不支持提示。
- 面板"变更"tab 行为不变；新增三语言文案齐全（`test:ui-language` 通过）。
- 文件树与弹窗头部显示与 VSCode 同风格的彩色文件图标，常见扩展名（js/ts/tsx/rs/py/json/md/yml/toml/html/css/png 等）与特殊文件名（package.json、Cargo.toml、Dockerfile 等）均有专属图标。
- `npm test`、相关冒烟测试与 `scripts/architecture-guard.py` 通过。

## 8. 风险与边界

- 图标主题包的许可需在引入时逐一核对（仅选 MIT/CC-BY 且保留署名）。
- 大文件高亮已由 `syntax-highlighter.js` 的 128KB 上限保护，超限回落纯文本，不阻塞 UI。
- 弹窗 z-index 取项目现有最高层（z-[300]），与工具市场等弹层同级；不与全局快捷键冲突（仅注册 Esc）。
