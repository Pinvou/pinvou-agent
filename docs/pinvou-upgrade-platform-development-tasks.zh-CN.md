### 1.2 什么是一个完整任务

一个任务对应一项可以独立评审、测试和交付的职责，明确输入、输出、状态归属和失败处理。有依赖并不影响职责独立；依赖通过冻结接口交付，不通过跨模块直接修改状态实现。

业务任务同时交付领域逻辑、持久化及恢复、必要 API、对应管理操作或客户端交互、权限与错误处理、测试和操作说明。不另拆“建表”“写接口”“补前端”“最后做国际化”“最后补安全”等无法单独形成完整能力的任务。服务端和客户端对同一协议的实现可以分别交付，但分别拥有远端资格和本地安全事实，不能互相替代。

T01—T03 交付可执行的协议/适配合约包，包括校验器、固定夹具、模型或参考测试；它们的完成只代表合约能力完成。业务模块完成还须通过本任务实现测试，整体上线还须通过 T43 的真实系统验收。夹具自身不能充当生产审批、真实本机能力或上线证据。T46 可在隔离环境用冻结的签名控制合约夹具替代远端响应，运行同一实际本地验证/执行路径和真实 helper/launcher/平台/数据，产出限定范围的本地模式前置认证；本地事实不得伪造。远端 CAS、资格竞争、恢复及完整控制面互通仍由相应真实业务任务和 T43 验证。

完成口径分为“模块实现验证”“真实本地前置认证”“真实控制面互通及上线认证”。客户端模块针对冻结控制端口独立交付；生产端口始终使用固定控制域名与当前信任链，不在用户配置中提供换根/换域名/跳过授权选项。隔离资格测试 harness 的响应注入只存在于测试装配，不进入生产可选路径。依赖表列必须实际实现的内部能力，远端契约接口不等于必须先启用生产投放。

### 1.3 每个任务共同适用的完成条件

1. 对应规范制品已落盘、完成兼容性评审、冻结版本并通过合约测试；不能仅依据 Markdown 实现隐含字段。
2. 正常、非法输入、权限不足、不支持、取消/到期及相关崩溃恢复均有唯一、可解释的结果。涉及最终提交的任务覆盖读取集变化、CAS 冲突、重试和响应丢失。
3. 状态只由其负责模块的命令修改。跨实体原子操作组合各负责模块的守卫和写集，使用同一个提交边界；不能异步拼出“最终大致一致”。
4. 用户文案、发布说明及稳定错误提示提供简中、英文、日文；应用文案复用现有 i18n。支持入口由固定 supportGuideCode 映射，不接受响应中的任意支持地址。
5. 秘密、原始 SN、完整下载 URL、备份内容和敏感路径不进入普通日志、事件、崩溃报告或导出；诊断按允许列表、最小权限和审计提供。
6. 保持现有配置、数据和公共接口兼容；有必要的破坏性变更先决策并提供迁移。社区客户端完整升级不依赖私有服务、内部地址或企业数据。
7. 按变更范围执行仓库要求的检查和真实验证。每个任务提交其验证记录；T43 验证组合场景，不能替代前面任务的测试。

### 1.4 一期必须保持的范围

- 四个目标：`windows-x86_64-nsis-perMachine`、`linux-x86_64-deb-perMachine`、`linux-arm64-deb-perMachine`、`macos-universal-dmg-perMachine`。Universal 在 Intel/Apple Silicon 分别验收；Windows/Linux 的已认证 OS 按 R §13 和实际批准列表执行。
- 每个正式目标均支持 directInstall 与 stagedRestart，并通过 normal、silent、forced 全流程。不可把 silent 降为下载后提示安装，不可缺少某平台的静默激活。
- 生产 `incrementalPackages=[]`，客户端增量能力为空；非空候选仅用于隔离合约测试，忽略后回退完整包。不实现补丁执行、基础制品缓存、重建或恢复包。
- 下载不设总时长或累计重试硬截止。单连接/无响应检测只触发重试、退避、换源或提示；有可信进度、可确认网络等待或暂停则持续记未完成，样本不足时维持灰度。只有按已审批失联间隔无法确认状态才记未知；不因超过 24 小时失败或自动冻结。
- 短期决定、URL、授权、会话及事件窗口继续有效。长下载使用当前资格下的新会话续接同一 workflow，保留原阶段/分组，只记录未来动作，不补签旧事件或增加样本。
- 不降级、不自动恢复旧版、不合并多跳安装。错误后的修复使用独立、更高版本的前向修复事务；本机解门与旧候选质量恢复分别判断。

## 2. 模块边界与状态归属

### 2.1 代码落点

- 前端业务沿用 `pinvou3-app/src/features/updater/`，按检查、下载、普通/静默/强制流程、渠道及修复等职责组织子模块；宿主调用放在 `src/platform/tauri/`，Web 明确返回能力不支持。
- Rust 业务沿用 `pinvou3-app/src-tauri/src/features/updater/`，按职责组织模块，升级专属 OS 适配放在其 `platform/`。helper/launcher 的可执行入口保持薄层，复用这些领域接口，安装后部署在应用目录之外的受保护位置。
- 只有跨 feature 复用的 OS 原语进入全局 `platform/`；全局平台层不拥有升级资格、事务、槽位、备份留存或保护门策略。React 通过语义能力和桥接接口工作，不检查 userAgent 或直接访问 Tauri 全局。
- 构建使用项目 npm 命令及现有版本同步流程，根 VERSION 仍是产品版本唯一来源；本清单 V1.0 不修改产品版本。
- 升级服务和管理后台使用下表的逻辑模块。仓库/目录、语言、存储和部署方式尚未由八份文档固定，须在实施决策中确定，不在本清单擅自创建服务端项目。
- CodeWhale 不承担升级业务。模型调用、Sessions、Skills、MCP 等基础能力不在这些任务中重写。

当前仓库 updater 的平台实现仍含 `unsupported` 占位，已有界面、桥接和测试可作为兼容性检查对象，不能视为新协议或真实安装能力已经实现。

远端 staged 与本地 staged 是不同事实：T44保存合法预安装完成/激活修订，T38保存真实槽内容及本地提示；必须精确对应才可激活。T19执行当前资格/用途策略，T44在T06同一提交内原子消费授权、创建事务并写outcome；T20验证事件后调用T44合法执行边。T44自身完成生命周期超时，不反向调用尚未交付的T17/T19/T20业务实现。渠道切换由T40在同一提交组合渠道修订与T44命令，不能逐条异步修改。

服务间通过只读事实投影和窄命令接口组合。例如选择器与投放审核使用T13的路径校验；T17读取T47的Rollout投影，不导入T15质量驱动实现。声明接口或只读投影不能消除真实写入依赖，T17创建会话、T19消费和T20执行迁移均必须使用已实现的T44。T14父状态命令调用已实现T47生成合法子写集，与父状态及T08发布同事务提交；T15后续调用同一内核推进灰度。T47不回调T14/T15/T21；完整最终读取集由调用方在同一T06提交中执行，不能用夹具提前通过真实父子写入。客户端控制端口、T46隔离签名响应和生产端口的区分必须可验证；不能把真实缺失的本地宿主/冻结/备份/门当作接口夹具通过。

## 5. 控制面、事件与质量任务

### T21 原阶段质量投影、保守评估与冻结锁存

- **依据**：R §8.2.1/§11.3；D §16.1；C §10；M §6；K §3.1。

### T22 消费未知的独立受限对账闭环

- **验收**：贡献合格后k19抑制无人数、k20可见；预养scope/单簇污染不能绕过贡献限制，不能借网络周报的聚合值计算合格人数；总21/可见20/隐藏1不能相减；首流程/换源归类唯一，导出不补隐藏值/合计/网络关联键；各查询面不能构造第二统计入口，越权拒绝并审计。
- **依据**：R §8.4；D §16.2；S §15.2；C §10。

### T25 网络来源去重、防滥用与隐私周报

- **交付与接口**：边缘即时派生ASN及IPv4 /24、IPv6 /48前缀，按用途/UTC周KMS-HMAC，提供stage-quality/release-quality各自受限贡献判定端口，绑定合法lineage、消费用途、对应窗口/分组、策略版本/证据水位，只返回合格/不合格及最小原因。网络隐私周报独立计算五维完整叶子、贡献上限与冻结，原IP边缘日志≤7d/摘要≤30d清理；给T40提供准确目的/数据形式/保留期三语说明契约。

- **依据**：R §16；D §16.3；S §15.1；C §10。

## 6. 客户端共同能力与平台任务

### T26 跨离线/关机可信期限、预算及故障处置

### 8.3 任务启动卡与提交要求

每个任务启动时先检索已有issue、PR、现有模块及基础能力，确认可复用实现；再填写负责人、对应任务编号、输入合约版本、依赖能力状态、唯一写入对象、导出接口、验收场景及验证环境、预计PR批次。若发现必须改变上游接口，先进行兼容性评审并修订合约，不能在双方实现里各加一个不同字段。

每次PR按仓库CONTRIBUTING执行同步、DCO、提交格式与适用检查；应用架构调整运行architecture guard及受影响测试。未经真实验证的平台行为明确列未验证，不能用“已有代码/单元测试通过”关闭认证任务。若修改涉及CodeWhale fork特有行为，先按fork边界判断必要性，履行登记/指纹/行为测试及fork guard要求；本计划本身不要求改fork。

## 11. 二期候选的独立边界

一期只交付兼容字段、空能力、空生产候选及完整包回退合约。以下不列入47个一期任务，不以“预留”名义提前实现：

| 候选任务 | 独立功能及边界 | 启动前置条件 |
|---|---|---|
| P2-01 增量算法及参考重建合约 | 冻结算法ID/版本、基础/目标身份、资源预算与参考重建；不直接启用生产候选 | 一期合约与完整包上线基线稳定，二期需求批准 |
| P2-02 精确基础制品缓存 | 缓存可信基础字节、引用和失效策略，独立于一期断点下载缓存 | P2-01冻结，隐私/磁盘预算与清理规则批准 |
| P2-03 受保护增量重建执行 | 在预算内重建并验证最终目标，错误完整包回退；不放宽平台真实性或在线授权 | P2-01/P2-02，真实算法与各平台测试通过 |
| P2-04 生产增量审批及受控启用 | 从真实重建证据到渠道审批、能力选择、灰度质量和生产开关闭环 | P2-03认证及兼容性验收；独立批准后才允许非空生产候选 |
| P2-05 新平台/格式接入 | 新targetKey及等价适配/真实性/两模式/人工路径，不改现有选择与状态语义 | 单独批准支持范围，完成平台合约与真实系统认证 |

更丰富的质量自动化、企业扩展和报表查询形状另行需求评审；当前固定周报的隐私约束不能因扩展而绕过。
