# 添加本地模型交互与测试方案

## 背景

当前「设置 -> 模型 -> 添加模型」已经支持新增模型配置，但本地模型路径偏向固定的本地 vLLM 默认值：

- 默认地址：`http://127.0.0.1:8000/v1`
- 默认模型：`qwen36_35b_256k`

这会导致两个问题：

1. 用户安装了 Ollama、LM Studio 或其他 OpenAI-compatible 本地服务时，不知道如何配置。
2. 用户使用 CodingPlan 等本地服务时，实际服务地址可能与默认地址不一致。

本方案先解决「添加模型弹窗里的本地模型配置体验」，保持现有云端模型路径不变。

## 目标

1. 「添加模型」弹窗增加 `云端模型 / 本地模型` tab，默认停留在 `云端模型`。
2. 本地模型 tab 提供极简路径：
   - 自动检测本地模型。
   - 检测到后可一键添加。
   - 检测不到时可手动添加。
3. UI 风格延续现有设置弹窗的 iOS 风格，不引入新的视觉体系。
4. 底层继续复用现有 `advanced.saved_models`，避免重做模型存储和会话切换逻辑。
5. 自动化测试覆盖探测、保存、UI 交互和回归风险。

## 非目标

1. 本次不重命名 `local_vllm` 存储枚举。
   - UI 展示为「本地模型」。
   - 内部暂时继续复用 `preset = "local_vllm"`。
2. 本次不做高级参数配置首屏化。
   - `context_window_tokens`、`max_output_tokens` 继续放在编辑模型表单或后端自动探测兜底。
3. 本次不主动扫描任意端口。
   - 只检测明确白名单地址，避免慢、吵和安全风险。
4. 本次不为 CodingPlan 单独写一套模型逻辑。
   - CodingPlan 视为 OpenAI-compatible 本地 endpoint，通过候选地址或手动添加接入。

## 交互设计

### 添加模型弹窗首层

弹窗顶部增加 segmented control：

```text
云端模型 | 本地模型
```

默认选中 `云端模型`，展示现有云端模型列表。

切换到 `本地模型` 后，展示两块内容：

```text
自动检测本地模型                         检测

手动添加本地模型                         >
```

检测完成后，如果发现模型：

```text
自动检测本地模型                         重新检测

qwen2.5-coder:32b
Ollama · http://127.0.0.1:11434/v1       添加

deepseek-r1:14b
Ollama · http://127.0.0.1:11434/v1       添加

qwen36_35b_256k
vLLM · http://127.0.0.1:8000/v1          添加

手动添加本地模型                         >
```

检测完成后，如果没有发现模型：

```text
自动检测本地模型                         重新检测

未检测到运行中的本地模型

手动添加本地模型                         >
```

### 一键添加

用户点击检测结果右侧 `添加`：

1. 直接创建一条 `SavedModel`。
2. 不进入二级确认页。
3. 保存成功后，结果行变为已添加状态，或展示轻提示。
4. 用户仍可在模型列表里设为默认。

保存字段：

```json
{
  "id": "m_<generated>",
  "name": "本地 qwen2.5-coder:32b",
  "preset": "local_vllm",
  "model": "qwen2.5-coder:32b",
  "base_url": "http://127.0.0.1:11434/v1",
  "api_key": "",
  "credential_action": "keep_existing",
  "context_window_tokens": null,
  "max_output_tokens": null
}
```

如果探测结果包含 `max_model_len`，可写入 `context_window_tokens`。没有则留空，由后端按现有预算兜底处理。

### 手动添加

点击 `手动添加本地模型` 后，在同一个弹窗内进入表单页，保持 iOS 设置项风格：

```text
API 地址          http://127.0.0.1:11434/v1
模型 ID           qwen2.5-coder:32b
显示名称          本地 qwen2.5-coder
需要 API Key      关闭
```

当 `需要 API Key` 开启时，展开：

```text
API Key           ********
```

底部操作：

```text
测试连接
保存
```

保存校验：

1. `API 地址` 必填。
2. `模型 ID` 必填。
3. loopback 地址默认不要求 API Key。
4. 非 loopback 地址如果未填 API Key，允许保存，但提示该服务可能要求鉴权。

## 本地检测设计

### 候选地址

首批检测地址：

```text
http://127.0.0.1:8000/v1   vLLM
http://127.0.0.1:8001/v1   vLLM
http://127.0.0.1:8002/v1   vLLM
http://127.0.0.1:11434/v1  Ollama
http://127.0.0.1:1234/v1   LM Studio
```

同时保留当前表单地址和已保存地址作为优先候选。

CodingPlan 地址如果是固定地址，加入白名单候选；如果不同环境会变化，则通过手动添加解决，不写死成默认。

### 探测协议

统一请求：

```text
GET {base_url}/models
```

期望兼容 OpenAI models 响应：

```json
{
  "data": [
    { "id": "qwen2.5-coder:32b" }
  ]
}
```

vLLM 如果能额外探测到 `max_model_len`，继续带回前端。

### 探测结果结构

后端返回给前端：

```json
{
  "candidates": [
    {
      "provider": "ollama",
      "label": "Ollama",
      "base_url": "http://127.0.0.1:11434/v1",
      "models": [
        {
          "id": "qwen2.5-coder:32b",
          "context_window_tokens": null
        }
      ]
    }
  ]
}
```

如果为了减少后端改动，也可以先复用现有 `LocalVllmCandidate` 并扩展字段：

```rust
pub struct LocalVllmCandidate {
    pub base_url: String,
    pub status: VllmStatus,
    pub model: Option<String>,
    pub models: Vec<String>,
    pub provider: Option<String>,
    pub max_model_len: Option<u32>,
}
```

## 开发方案

### 前端

主要文件：

- `pinvou3-app/src/features/settings/SettingsView.jsx`
- `pinvou3-app/src/platform/web/bridge.js`
- `pinvou3-app/src/hooks/useBridge.js`

开发步骤：

1. 在 `ModelFormModal` 的新增模型 picker 页增加 tab 状态：
   - `cloud`
   - `local`
2. `cloud` tab 复用现有 `MODEL_CATALOG.cloud`。
3. `local` tab 新增：
   - 自动检测 row。
   - 检测结果 rows。
   - 手动添加 row。
4. 新增本地手动添加表单视图：
   - 复用现有 `renderInlineField`。
   - 默认隐藏 API Key。
5. 新增一键添加处理：
   - 根据检测结果构造 `SavedModel`。
   - 调用现有保存模型逻辑。
6. 保持视觉一致：
   - 圆角分组 row。
   - `#007AFF` 蓝色操作。
   - 现有暗色/亮色变量。
   - 不新增卡片式营销说明。

### 后端

主要文件：

- `pinvou3-app/src-tauri/src/app/commands/monitor.rs`
- `pinvou3-app/src-tauri/src/app/commands/settings.rs`
- `pinvou3-app/src-tauri/src/features/monitor/*`
- `pinvou3-app/src-tauri/src/platform/prefs.rs`

开发步骤：

1. 扩展本地发现命令。
   - 当前 `discover_local_vllm` 只覆盖 `8000-8002`。
   - 增加 `11434`、`1234`。
   - 命令命名可以暂时保持，或新增 `discover_local_models`。
2. 对每个候选地址请求 `/models`。
3. 返回模型列表，而不是只返回单个模型。
4. 标记服务类型：
   - `8000-8002` 默认 `vllm`
   - `11434` 默认 `ollama`
   - `1234` 默认 `lm_studio`
   - 手动地址默认 `openai_compatible`
5. 保存时继续走 `save_model` / `update_settings` 现有链路，API Key 继续进系统凭据库。
6. loopback 地址继续允许无 Key。

### 数据兼容

不迁移旧数据。

旧的本地模型：

```json
{
  "preset": "local_vllm",
  "base_url": "http://127.0.0.1:8000/v1",
  "model": "qwen36_35b_256k"
}
```

继续可用。

新增 Ollama / LM Studio 也暂存为：

```json
{
  "preset": "local_vllm",
  "base_url": "http://127.0.0.1:11434/v1",
  "model": "qwen2.5-coder:32b"
}
```

后续如需语义更准确，再单独迁移到 `local_openai_compatible`。

## 自动化测试方案

### Rust 单元测试

覆盖文件：

- `pinvou3-app/src-tauri/src/app/commands/monitor.rs`
- `pinvou3-app/src-tauri/src/features/assistant/platform/bridge.rs`
- `pinvou3-app/src-tauri/src/platform/prefs.rs`

测试点：

1. `normalize_local_vllm_base_url` 支持：
   - `http://127.0.0.1:8000/v1`
   - `http://127.0.0.1:8001/v1`
   - `http://127.0.0.1:8002/v1`
   - `http://127.0.0.1:11434/v1`
   - `http://127.0.0.1:1234/v1`
2. 拒绝非白名单端口：
   - `http://127.0.0.1:9999/v1`
3. 拒绝非本机地址进入自动探测：
   - `http://192.168.1.2:8000/v1`
   - `https://example.com/v1`
4. loopback 本地模型不要求 API Key。
5. 新增本地模型后 `bridge.provider()` 仍能给底座可用 provider。

### JS 逻辑测试

覆盖文件：

- `pinvou3-app/tests/settings_ui_smoke.js`
- 可新增 `pinvou3-app/tests/local_model_add_logic.test.js`

测试点：

1. 添加模型弹窗默认展示 `云端模型` tab。
2. 切换到 `本地模型` tab 后展示：
   - 自动检测本地模型
   - 手动添加本地模型
3. 检测结果渲染正确：
   - 模型名展示为主标题。
   - 服务类型和地址展示为副标题。
   - 每条结果有 `添加` 按钮。
4. 点击检测结果 `添加` 后构造正确的模型 payload：
   - `preset = local_vllm`
   - `model = 检测结果模型 ID`
   - `base_url = 检测结果地址`
   - `api_key = ""`
5. 手动添加表单默认不展示 API Key。
6. 开启 `需要 API Key` 后展示 API Key 输入框。

### 端到端 Smoke 测试

覆盖场景：

1. Mock `discoverLocalVllm` 返回 Ollama 模型。
2. 打开设置 -> 模型 -> 添加模型。
3. 切换到本地模型 tab。
4. 点击检测。
5. 点击某个模型的添加。
6. 断言模型列表出现新增模型。

建议测试数据：

```json
{
  "candidates": [
    {
      "provider": "ollama",
      "label": "Ollama",
      "base_url": "http://127.0.0.1:11434/v1",
      "models": ["qwen2.5-coder:32b", "deepseek-r1:14b"]
    }
  ]
}
```

### 回归测试

必须确认：

1. 云端添加模型原流程不变。
2. 编辑已有模型不受影响。
3. 删除模型不受影响。
4. 设置默认模型不受影响。
5. 会话顶部模型 chip 切换不受影响。
6. 旧的 `qwen36_35b_256k + 127.0.0.1:8000/v1` 仍能正常显示和使用。

## 验收标准

1. 用户能通过 `添加模型 -> 本地模型 -> 自动检测 -> 添加` 完成本地模型接入。
2. 用户能通过 `添加模型 -> 本地模型 -> 手动添加` 接入非默认地址服务。
3. 本地 loopback 模型不强制 API Key。
4. UI 与现有设置弹窗风格一致。
5. 自动化测试覆盖新增本地模型主流程。
6. 现有云端模型添加流程无回归。

## 风险与处理

1. 部分本地服务不支持 `/v1/models`。
   - 先走手动添加兜底。
   - 后续按服务类型补专用探测。
2. Ollama 的 OpenAI-compatible 行为随版本变化。
   - 自动检测失败不阻塞手动配置。
3. `local_vllm` 内部命名不准确。
   - 本次先不迁移，降低风险。
   - 后续可设计 `local_openai_compatible` 数据迁移。
4. 自动探测端口范围扩大可能变慢。
   - 只探 5 个白名单地址，并设置短超时。
