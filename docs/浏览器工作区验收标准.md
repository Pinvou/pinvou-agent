# 浏览器工作区验收标准

## 产品边界

- 浏览器是当前任务对话的右侧工作表面，不是左侧全局功能页。
- 页面、标签和当前标签归任务对话；默认浏览身份与登录状态归应用。
- 用户与 Agent 操作同一个系统原生 WebView 页面，用户可直接接管。
- 连续截图、JPEG/base64 帧传输和外部 Chrome 不作为展示或故障回退。
- 一个任务可有多个标签；普通观察和交互只能作用于该任务当前可见标签。
- 后台任务可继续操作自己的当前标签，但不得改变用户正在查看的任务或 Dock。

## 工具对齐不变量

页面级工具执行前必须依次完成：

1. 验证 `pageId` 属于当前任务；
2. 激活其对应的原生标签；
3. 选择自动化后端中的同一页面；
4. 重新读取宿主工作区和页面列表，确认“可见标签 = 选中页面”；
5. 执行实际工具并验证结果。

任一步失败都不得执行实际工具。首次前台 `new_page` 在工作区只有一个、且该标签的宿主 token 等于任务 session token、页面仍为受控 `about:blank` 时，复用该初始化占位页并在正常可见页 lease 内导航，不额外留下空白标签；除此之外，`new_page` 必须先在隐藏 staging WebView 中发现新 target 并由宿主提交请求 URL 首航，最后携创建前的完整 lease 做一次 CAS 发布。绑定/首航/CAS 任一步失败只销毁该 request generation。`new_page(background: true)` 永不复用占位页，只允许预创建和预加载；后续观察或交互仍须先激活。

已经通过 `begin_agent_operation` 的单个工具按原子 dispatch 完成：用户接管立即使 lease 失效并阻止下一项工具，但不承诺中途中断已提交给平台后端的当前调用。`finally` 立即撤销 active operation；只有确实派发过原生输入的调用保留不超过 100ms 的 post-dispatch callback grace，用于吸收该输入稍晚到达的 WebView 回调。显式 UI 接管立即清除该窗口；750ms 仅是 dispatch 异常退出时的保险上限。

取消、超时与平台后端退出必须共用同一原子收口：已 `begin` 的调用收到取消后只向后端发送合作取消，直到真实响应到达；超时后仍不允许先 `end`，后端在宽限期内未响应时须先终止并确认子进程退出。只有在确认后端不能再派发输入后才执行 `end_agent_operation`。终态无法证明动作未发生时返回 `actionMayHaveCommitted=true`、`retryable=false` 的结构化结果，Agent 不得重放。验收须覆盖“取消后端忽略取消但稍后成功”与“执行中后端崩溃”两条 completion-before-end 时序。

原生 mutation 一旦成功返回即视为已经提交。其后的可选 `includeSnapshot` 只是观察步骤：观察失败必须仍返回成功，并在 `structuredContent.observationWarning` 中声明 `actionCommitted=true`、`retryable=false`，提示 Agent 另行调用 `take_snapshot`，不得重放 mutation。`fill_form` 必须在第一次写入前校验完整字段数组；中途失败以 `isError=true` 的结构化部分结果返回 `completedCount`、零基 `failedIndex`、`totalCount` 与 `retryable=false`，不得把整表作为宿主错误自动重试。

用户直接点击、输入或滚动时取得短时控制权；每次真实操作都前进 revision 并重新开始 3 秒空闲窗口。只有与最后一次用户操作 revision 一致的定时释放可以把 owner 恢复为 Agent，旧定时器不得覆盖后续用户操作或显式 hand-back。“交还 Agent”作为立即恢复快捷入口保留，不再是唯一恢复路径。

`window.open`/`target=_blank` 只有在上述已 begin dispatch 中捕获到完整、仍有效的宿主 lease 时，才作为 Agent 标签通过隐藏 staging、target 绑定、首航和最终 CAS 发布；没有有效 dispatch 授权时按 User 标签创建。不得用短期 bool 推断 Agent 身份，用户接管先提交时不得发布晚到 popup。

## 当前 PR 能力声明

| Capability / 运行时 | Windows | macOS | Linux |
|---|---|---|---|
| `browser_native_display` | `true`（WebView2） | `false`（承载层已编译，入口未开放） | `true`（WebKitGTK） |
| `browser_agent_automation` | `true` | `false` | `true`（BrowserCore + WebKitWebDriver） |
| `browser_cdp` | `true`（仅应用自有回环端点） | `false` | `false` |
| Agent 浏览器工具 | 核心工具 + Chrome 诊断扩展 | 必须明确返回 unsupported | 核心工具可用（含 W3C `handle_dialog`）；`hover`/`drag`/`resize_page` 暂不暴露 |
| `chrome-devtools-mcp` 构建/安装包 | Windows adapter | 无 | 无 |
| 外部 Chrome 或截图流回退 | 禁止 | 禁止 | 禁止 |

Linux 已形成可达的原生页面与 Agent 自动化闭环：使用系统 WebKitGTK 显示同一真实页面，以 WebKitWebDriver 元素端点产生可信点击和键盘输入，并在同一 operation gate 内通过 W3C alert 端点处理 `alert`、`confirm` 和 `prompt`，不打包或启动 Chrome MCP。`.deb` 必须依赖 `webkit2gtk-driver`；开发环境缺失驱动时不得注册一个调用后才失败的假工具目录。WebKitGTK pointer actions 在当前实机验证中会阻塞，因此 `hover`/`drag` 必须从 Linux 工具目录隐藏并快速拒绝直呼，直到可信实现通过验收。`resize_page` 不能调用 W3C Set Window Rect 改变 Tauri 顶层窗口，也不能绕过 Dock 布局临时设置子 WebView bounds；在形成独立且可恢复的 viewport 模拟前必须同样隐藏并快速拒绝直呼。macOS 仍保持 capability 关闭，不得以 display-only、外部 Chrome、截图流或 JavaScript 合成交互冒充完成。

Linux WebDriver session 崩溃后，安全重建 handle 映射允许宿主把该页短暂导航到随机内部 marker，再重新加载原 URL；验收时不得期待保留表单、Canvas 或 JavaScript 内存，但必须确认远程页面主世界从未获得稳定绑定身份，且恢复后页面仍归属原任务和原标签。

## 三端完整自动化目标

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| 原生页面 | WebView2 | WKWebView | WebKitGTK |
| 任务隔离与多标签 | 必须 | 必须 | 必须 |
| 导航、DOM/可访问结构、点击、输入、按键、滚动、等待、脚本、截图、弹窗 | 必须 | 必须 | 必须 |
| Agent 原生可信输入 | WebView2/CDP | 原生事件适配 | WebKitWebDriver（无需抢占全局鼠标键盘） |
| Chrome DevTools 高级诊断 | capability 开放 | 不承诺 | 不承诺 |
| 外部 Chrome 依赖 | 无 | 无 | 无 |

任一平台只实现 display-only，或只实现 `isTrusted=false` 的 JavaScript 合成交互时，不得宣称核心能力完成，也不得提前打开 `browser_agent_automation`。平台暂缺的工具必须从目录隐藏并对直呼快速失败，不能用超时伪装支持。

## 性能门禁

- 原生模式连续截图帧数：`0`。
- 页面展示链路 JPEG/base64 传输字节：`0`。
- 隐藏或空闲时连续 bounds IPC：`0`。
- bounds 更新：每个显示帧最多一次，相同 session、tab 和 bounds 不调用原生层。
- 热态 Dock 展开、恢复和标签切换的应用附加延迟：P95 `< 100 ms`。
- Agent 目标页对齐并开始派发的应用附加延迟：P95 `< 200 ms`。
- 用户原生输入可见反馈：不超过一个显示帧。
- 最小化、DPI 变化和缩小后恢复：边界误差不超过 `1` 个物理像素。
- 阻塞弹窗、全屏预览、非 Browser Dock 内容或主窗口不可见时，原生页面必须先隐藏；恢复后不得闪烁、黑屏或穿透覆盖层。
- 关闭任务后不得残留孤儿 WebView、CDP 端点、任务 MCP 配置或恢复清单；应用正常重启只保留当前用户私有权限的最小 URL/顺序/active-index 清单，旧 tab token、targetId、lease 和运行期映射必须删除。

### 性能采集与判定

- Windows 真实机验收至少采集每项 `30` 个热态样本；少于该数量只显示数据，不得标记通过。
- 前端 DevTools 执行 `window.__PINVOU_BROWSER_PERF__.snapshot()` 可读取 Dock 原生表面提交、恢复状态查询和标签切换的 count/P50/P95/max；执行 `reset()` 可开始一轮独立采样。
- 启动应用前设置 `PINVOU3_BROWSER_PERF_LOG=1`，wrapper 会把 Agent 目标页对齐样本以 `[browser-perf]` JSONL 写入 stderr。使用 `node pinvou3-app/scripts/browser-performance-report.mjs <日志文件> --min-samples=30` 聚合并按上述阈值返回退出码。
- Node/静态契约测试只验证采样、去重和阈值计算正确，不能代替 Windows 真实 WebView2 的 P95、输入帧延迟或 DPI 实测。

固定内存预算必须在三端真实机基线采集后制定；在此之前记录每增加一个任务和标签的增量工作集、空闲回收结果及异常峰值，不以猜测的 MB 数作为通过条件。

## 响应式与恢复

- 桌面宽度足够时，对话与唯一 Right Dock 按用户比例并排。
- 空间不足时切为“对话或 Dock”单栏模式，不把对话压成竖条，也不把临时宽度写回偏好。
- 放大恢复沿用缩小前比例；拖拽取消、窗口失焦、最小化和 DPI 切换都不得留下临时像素宽度。
- 应用重启后按任务恢复标签 URL、顺序和当前标签，并沿用默认浏览身份；控制权进入中立未认领态，下一次真实用户操作或 Agent lease 原子认领，不能把重启伪装成用户接管或静默授权。持久化失败必须按任务可见并持续退避重试；不承诺恢复网页进程内的表单、Canvas 或 JavaScript 内存状态。

## 安全门禁

- 页面导航、新窗口和重定向只允许 `http`、`https` 与受控的 `about:blank`；拒绝 `file`、`data`、`javascript`、`chrome` 等协议。
- CDP 仅绑定回环地址，协调文件使用当前用户私有权限；不得关闭 SmartScreen 等平台保护。
- 不为远程页面全局开放剪贴板读取。内嵌下载当前安全默认拒绝，按任务和标签提示用户可在系统浏览器打开后自行下载；不得写入或向事件暴露本地下载路径。本期侧栏没有文件选择审批 broker，因此 `mcp_browser_upload_file` 不暴露，直呼也必须在启动上游或接触文件前拒绝，不得以其他工具绕过。摄像头、麦克风、定位和通知在形成明确请求闭环前保持内核默认拒绝/提示，不得静默授权。
- 付款、删除和最终提交等语义风险由通用 Agent 审批框架处理，不以浏览器协议白名单代替。
