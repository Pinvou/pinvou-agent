PinvouOS · Memory Architecture

持续理解一个人，而不是保存一堆会话

这是 PinvouOS 的完整目标架构：统一事件账本负责保留事实，Memory Agent 将在后台整理事实、偏好、习惯、经历与教训。当前 Runtime 决策核心与热投影 已接通；异步消费、完整上下文编译和 Obsidian 工作台仍待接入。

不能跨越的系统边界

这些边界决定了 PinvouOS 能否在无 Session、长期运行和多任务并发下仍然保持可靠。

没有 Session 真相边界

记忆按身份空间、时间、环境和证据关系组织；Mission 与 Run 只保留因果出处。

任务进度不进入长期记忆

承诺、阻塞和下一步属于 Runtime Mission / Run Work Graph；经过验证的结果才能形成行动经历。

交互协议不是记忆分区

AG-UI threadId / runId 只负责交互路由与证据关联；Memory 仍按身份、时间、环境和证据组织，不按交互线程切割。

模型只能提出候选

高置信度不能提高来源权威；明确用户证据和模型推断始终分开。

Obsidian 不是数据库

接入后承担展示、纠错和归档；修改必须回到事件门禁，实时读取也不扫描 Vault。

缓存不是记忆

模型前缀缓存可以随时失效或清除；记忆仍由账本与可重建投影保证。
