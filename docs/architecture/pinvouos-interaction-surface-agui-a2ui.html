02 · 目标架构

一位 Front，双协议轨道

Front 是唯一交互权威，但不是事实数据库、策略裁判或 CSS 生成器。它把用户意图路由到系统，把系统事实翻译为可理解的交互与呈现。

这张图怎么读 1用户从系统入口提出需求 2Front 统一理解、回应和调度 3简单任务直做，复杂任务才编排 4AG-UI 报进度，A2UI 描述界面 5前端按设计系统画出最终画面
01Runtime 事实优先界面与事实冲突时，Runtime Ledger 的状态覆盖 Front 和客户端投影。
02Front 独占 Agent 画布写权只有 Front 可申请 front/* 内容画布；projection/* 与 system/* 由确定性宿主管理，其他 Agent 只返回结构化结果。
03Host 决定最终视觉目录组件、布局模板、token、动效、触控与降级由宿主代码控制。
04Policy 评估，Kernel 强制高风险动作先过硬门禁，再被渲染为确认或审批，不依赖 LLM 自觉。
03 · Protocol fit

协议各司其职，不互相冒充

两套协议的价值在于省掉“事件流”和“生成式 UI 表达”这两类轮子。它们不负责 PinvouOS 的 Agent 拓扑、Mission 持久化、安全策略或全局画布治理。

04 · Authority & state

隔离的关键不是“藏起来”，而是“无写权”

其他 Agent 可以很强，但它们没有用户关系，也没有主画布写权限。它们只把证据和结构化结果交给 Front。Front 负责解释，不负责篡改事实。

Front Interaction Authority

一位人格、一个交互入口、一个 Agent 内容呈现决策点。

✓
唯一 Agent 画布写者只有 Front 可通过受控 present_surface 申请 front/* 变更；Runtime Projector 与 Kernel 系统层不属于 Agent 写画布。
✓
唯一可做普通业务提问Mission Agent 把 missing fields 返回 Orchestrator / Front，Front 决定何时、怎样澄清；Kernel/Host 仍可显示不可绕过的系统确认。
✓
唯一可做用户态叙事把 tool、Run、artifact 和风险压缩成可理解的进度与结果。
✓
不能绕过 Runtime / Policy不能把失败写成成功，不能把 deny 写成可点击动作。

其他 Agent 的统一回传合同

这里的执行者专指按 Mission / Runtime Run 临时创建的 Dynamic Mission Agent，不包括 12 个常驻系统角色。它可以建议“语义重点”，不能创建、更新或删除 A2UI Surface，更不能直接触碰 Renderer。

07 · Decisions & provenance

明确决定，也明确没决定什么

本文是 Interaction / Presentation Plane 的真相源；Agent 拓扑和 Memory 仍由各自架构文档负责。已验证切片标记为 Implemented，尚未实现的目标继续标记为 Proposed。

D-01
不新建第二个用户人格“UI Agent”收敛为 Front 内部 Presentation Planner，不与 Front 抢用户关系。
D-02
交互标识与任务标识分离Mission 工作区通常映射为 threadId；AG-UI runId 使用独立 interactionRunId，Runtime Run 通过 correlation 关联。全局 Pinvou 画面使用稳定 interaction scope，不引入产品 Session。
D-03
Tauri 继续做 transport先做 AG-UI wire compatibility，不为协议形式重写桌面通信栈。
D-04
A2UI wire v0.9 做基线wire 使用规范声明的 v0.9；SDK / 仓库 revision 单独 pin。v1.0 经 adapter 试验，不直接绑定 main 分支变化。
D-05
自有 Catalog，不自创协议Pinvou Renderer 实现 A2UI Surface 和数据绑定；视觉原语由宿主定义。
D-06
Adaptive Cards 只借思想继承 host-owned visual、action whitelist、version fallback；不作为核心运行协议。
D-07
Policy 高于 PresentationPolicy Agent 评估，Kernel 强制；Host 生成不可隐藏的 system/* 确认层，Front 只负责用户态解释。
D-08
协议状态不是第二真相源AG-UI state 与 A2UI data model 都是投影；业务事实与需要精确恢复的 Front Presentation Intent 均写入同一 Runtime Ledger。
D-09
三个 Surface 写权分区projection/* 属于 Runtime Projector，front/* 属于 Front，system/* 属于 Kernel/Host；“Front 唯一写者”只指 Agent 内容画布。
D-10
原生 Catalog 与沙箱 App 分层A2UI 承担原生卡片、表单、Modal 与 system/*；复杂 HTML 只能通过 front/* 中的 opaque AppSurface 由 Host 沙箱化挂载，不能进入 system/* 或成为任意 HTML 对话框后门。
