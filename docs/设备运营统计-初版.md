# 设备运营统计初版

日期：2026-07-14

## 范围

初版只统计唯一设备、在线状态和匿名使用量，不建立用户、安装实例或进程管理模型。

- 不上传消息正文、session 标题、文件路径、工具参数或工具输出。
- `device_id` 是服务端签发的不透明 ID；硬件原始声明只用于服务端 HMAC 去重，不落盘。
- 每轮 `TurnComplete` 只记录 input/output token 和成功状态。
- 遥测服务故障不阻塞 Pinvou 启动、聊天或本地工具执行。

## 客户端

实现位于 `pinvou3-app/src-tauri/src/telemetry.rs`。

运行时目录：

```text
~/.pinvou3/telemetry/identity.json
~/.pinvou3/telemetry/outbox.sqlite3
```

设备身份按以下优先级选取：

1. `PINVOU_TELEMETRY_DEVICE_CLAIM`（受管环境覆盖）。
2. Linux DMI product UUID / product serial / board serial。
3. Linux `/etc/machine-id`。
4. Windows `Win32_ComputerSystemProduct.UUID`。
5. 本地持久随机 ID；此时 `identity_quality=installation_only`，卸载并删除用户数据后无法跨重装去重。

环境变量：

```text
PINVOU_TELEMETRY_BASE_URL=https://www.ma-xiao.com/pinvou3/telemetry
PINVOU_TELEMETRY_DISABLED=1
PINVOU_TELEMETRY_DEVICE_CLAIM=<企业资产编号或测试覆盖>
```

客户端每 2 分钟发送心跳。在线设备口径是服务端最近 5 分钟收到心跳。看板登录后每 30 秒刷新一次。

用量事件先写 SQLite outbox，服务端返回 accepted/duplicates 后才删除。本地网络重试不会重复计数。

## 服务端

实现位于：

```text
remote-control-relay/telemetry-service.js
remote-control-relay/web/stats.html
```

初版复用 47.120.8.237 上已经受公网代理保护的 8787 HTTP 服务入口，但代码、路由、数据和管理员鉴权相互独立。

服务器数据：

```text
/var/lib/pinvou-telemetry/devices.json
/var/lib/pinvou-telemetry/usage-events.jsonl
/var/lib/pinvou-telemetry/ip2region_v4.xdb
/var/lib/pinvou-telemetry/ip2region_v6.xdb
```

密钥配置：

```text
/etc/pinvou-telemetry.env                         # root:root 0600
/etc/systemd/system/pinvou-remote-relay.service.d/20-telemetry.conf
/root/pinvou-stats-credentials.txt                # 看板管理员密码
```

公开 `/pinvou3/telemetry/healthz` 只返回 `{"ok":true}`。设备明细和汇总 API 需要看板登录后签发的 HttpOnly、Secure、SameSite=Strict cookie。

### 统计口径

所有日期按北京时间自然日计算。

- 当前在线：最近 5 分钟收到设备心跳。
- 今日活跃：今日产生过至少一条有效对话的唯一设备数。
- 近 7 日活跃：包含今日在内，近 7 个自然日产生过对话的唯一设备数。
- 近 30 日使用趋势：每个自然日产生过对话的唯一设备数和对话总次数。
- 活跃版本覆盖率：按近 7 日活跃设备的当前版本汇总。
- 设备明细：展示匿名设备 ID、在线状态、版本、系统、所在区域、首次登记、最后活跃和近 7 日对话。

所在区域由服务端根据可信反向代理传入的真实公网 IP，通过本地离线 `ip2region` 数据库解析到国家/省/市。服务端只保存粗粒度区域，不保存原始 IP；同一设备最多每 24 小时刷新一次区域。离线库不可用、IP 为内网地址或无法命中时显示“未知”，已有设备会在下一次心跳时补全。

## 公网反向代理

公网 Nginx 需要把两个独立子目录转发到 47.120.8.237:8787，并保留客户端 IP：
仓库中的可部署配置为 `remote-control-relay/nginx-telemetry-stats.conf`。

```nginx
location = /pinvou3/stats {
    proxy_pass http://47.120.8.237:8787;
    proxy_set_header Host 47.120.8.237;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location ^~ /pinvou3/stats/ {
    proxy_pass http://47.120.8.237:8787;
    proxy_set_header Host 47.120.8.237;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location ^~ /pinvou3/telemetry/ {
    proxy_pass http://47.120.8.237:8787;
    proxy_set_header Host 47.120.8.237;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

代理机必须是 `PINVOU_REMOTE_ALLOWED_PROXY_IPS` / `PINVOU_REMOTE_TRUSTED_PROXY_IPS` 中的受信地址。

## 发布与验证

部署继续使用：

```bash
./scripts/deploy-remote-relay.sh
```

脚本会一起部署 relay、遥测模块和看板，并验证远控公开入口及服务器环回遥测健康检查。部署失败会恢复同一份备份目录中的旧文件。

服务器检查：

```bash
systemctl status pinvou-remote-relay.service
curl -fsS http://127.0.0.1:8787/pinvou3/telemetry/healthz
cat /root/pinvou-stats-credentials.txt
```

公网代理配置完成后检查：

```bash
curl -fsS https://www.ma-xiao.com/pinvou3/telemetry/healthz
curl -fsS https://www.ma-xiao.com/pinvou3/stats | grep 'PINVOU · 设备运营中心'
```

## 初版限制

- JSON/JSONL 存储适合当前小规模上线；设备或事件量明显增长后迁移 PostgreSQL。
- 没有可靠硬件身份的设备只能按持久随机 ID 去重，删除 `~/.pinvou3` 后会被视为新设备。
- 客户端注册门槛只能防一般污染，不能替代 TPM/企业设备证书。后续需要更强真实性时增加设备证明。
- 看板只做设备维度统计，不追踪用户身份。
