# 语音输入兼容边界

语音入口统一放在输入栏发送按钮旁。桌面支持听写和编辑预览；编辑只有确认后才替换草稿。
Alt 快捷键需用户开启，Windows 原生配置以 Rust 用户设置为权威，localStorage 仅作界面镜像。
按钮和快捷键先向 Rust 原子申请窗口与操作 token 绑定的录音所有权，成功后才开麦；
其他窗口或旧操作不能抢占、清除当前录音。已按住 Shift/Ctrl/Win 时 Alt 透传系统组合键。
语音整理可在设置中关闭；关闭后只使用本地识别和确定性文字纠正，不调用模型整理服务。
开启整理时，识别文本及编辑所需草稿会发送给当前选择的模型服务；它们不属于行为埋点。
Web 保留无会话首页录音，仅使用 ASR，不开放模型整理或自动任务入口。

## 操作及模型归属

- 每次录音有独立归属（实现为录音会话的 token 守卫，见 `bridge/voice.js` 的 `voiceShortcutRecordingToken`），在异步写回前交给输入栏，并保留到草稿真正发送或放弃。
- 隐藏完成提示、应用编辑预览不等于放弃草稿；清空输入或取消预览才结束未发送的操作。
- 发送受理期间的取消先等待受理结果；已提交操作不会再被记录为取消。
- 首轮明确拒绝保留可重试归属，结果未知则继续等待对账；已恢复草稿不代表任务已受理。
- 任务发送只消费仍与本次写回一致的草稿；拒绝或异常按原会话恢复一次，并保留等待期间的新输入。桥接层已恢复的草稿不重复恢复，普通手工发送的恢复语义不变。
- 能力准备及首次建会话期间切走会中止语音发送：已有新会话时恢复其后台草稿，创建失败时仅在内存保留原草稿 epoch 的恢复记录。同一 epoch 返回草稿才消费一次；进入新草稿后清理，不继承旧文本或语音统计归属。
- 多智能体开关保存失败导致的同草稿回滚会保留等待期间输入，并同步迁移语音关联以便手动重试；只有导航 token 与原创建会话仍匹配才视为回滚，用户真正切会话或新建草稿不会触发迁移。
- 桌面和 Web 聊天都在后端真实受理后关联实际 session/attempt；首次建会话不能沿用草稿标识。
- native 代码会话使用自身模型和 session；ACP 仅结束本地语音操作，不虚构聊天任务 attempt。
- 无会话模型整理通过 RuntimeModelProvider 准备凭据，不借用另一个聊天会话的绑定。
  内建模型仍由后台管理凭据，用户无需编辑 API Key。

## 协议和隐私

桌面录音 IPC 使用 base64 WAV（替代 JSON 数字数组）；Web 继续使用已有 audioBase64 协议。
桌面保留 60 秒录音上限和解码前大小检查；Web 保留 20 秒及 1 MiB 解码上限。
错误 code/category 跨远控协议透传，界面使用三语受控提示。
行为事件只收集受控结果、耗时和错误分类，不上传音频、识别文本、编辑草稿、文件路径、凭据或原始错误。

验证入口：`npm --prefix pinvou3-app run test:voice-input`
及 bridge 协议测试。Windows Alt/AltGr、UAC、真实麦克风和多窗口焦点仍需真机验证；
自动化覆盖原生键盘状态机、窗口路由、录音 token、异步写回及提交终态。
