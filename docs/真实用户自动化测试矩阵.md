# 真实用户自动化测试矩阵

> 目标：把 pinvou3 的自动化测试从“函数是否正确”推进到“真实用户旅程是否还能跑通”。本文件描述可执行入口、覆盖范围和分层边界。
>
> 注：本文回填自内部仓库 2026-07 快照并按 2026-09 现状修订；正文个别场景描述沿用历史工具/模式拼写（如 `web_search`、Plan/YOLO、`instructions.md`），现行工具面与模式命名以 `docs/tool-governance.md` 为准。

## 分层

| 层级 | 入口 | 是否进 CI | 覆盖什么 |
|---|---|---|---|
| L2 后端确定性 | `cargo test --manifest-path pinvou3-app/src-tauri/Cargo.toml --lib -- --test-threads=1` | 是 | bridge、session、路径安全、知识库、fork 回归；含 Web RPC 去重、事件 journal/游标恢复、endpoint 持久化与 Session 产物路径边界 |
| L3 Mock GUI smoke | `node pinvou3-app/tests/ui_smoke.js` + `node pinvou3-app/tests/settings_ui_smoke.js` + `node pinvou3-app/tests/kb_smoke.js` + `node pinvou3-app/tests/tool_store_smoke.js` | 前端改动按 paths 进入 `frontend-test`；本机必跑 | 加载 Vite `dist/`，mock TauriBridge，覆盖启动、设置页模型/搜索/权限、工具商店真实装卸/授权交互、产物卡、品悟卡、模式 chip、本地模型引导、本地文件与知识库 |
| MCP 协议与产物契约 | `python3 scripts/mcp-server-contract-smoke.py` | 是（fast-gate） | 启动 6 个本地 stdio MCP，验证 initialize/tools/list/tools/call；校验 11 个可安装清单，覆盖 Obsidian 读写、PPTX/公文产物和 QCC 远端清单 |
| WebUI Relay v2 协议 | `npm --prefix remote-control-relay test` | Relay 改动按 paths 触发独立 `relay-test` job；本机必跑 | 持久 endpoint 注册/鉴权、单 Web lease 接管、类型白名单盲转发、桌面离线/恢复、撤销、限流、healthz 脱敏与静态站点缓存策略 |
| 完整 WebUI 浏览器旅程 | `npm --prefix pinvou3-app run test:webui` | 前端/Relay 改动按 paths 进入 `frontend-test`；本机必跑 | 构建共享 React WebUI 并启动真实本地 Relay；模拟 desktop endpoint v2，验证电脑/手机 viewport、fragment 凭据隔离、接管、RPC 往返和事件游标重连 |
| Session replay audit | `python3 scripts/session-replay-audit.py --latest 5` | 审计器单测进 fast-gate；真实 session 本机跑 | 用真实 `~/.pinvou3/sessions/*.json` 做 transcript 结构审计，覆盖 `request_user_input`、tool_use/tool_result、artifact 引用；自动排除内部元数据和 pre-restore 备份 |
| L1 真模型 dialog harness | `PINVOU3_L1_REQUIRE_VLLM=1 cargo test --manifest-path pinvou3-app/src-tauri/Cargo.toml --test l1_dialog_harness -- --ignored --test-threads=1` | 不进 CI（scenario 全部 `#[ignore]`，仅随 `cargo check --all-targets` 做编译期把关）；真模型暂不进 CI | 真 Qwen/vLLM 跑端到端对话，覆盖工具链、多轮、Plan/YOLO、web_search、subagent、文件落盘；严格模式下 pre-flight 不可达或 turn 内 Engine Error 都直接失败，不能静默假绿 |
| Judge 语义评审 | `docs/L1-judge-rubric.md` 流程 | 不阻塞 PR | 读 L1 transcript，评回答质量、工具使用、任务拆分、结果综合 |

> 历史注记：2026-07-21 某台内部 Windows 本机的 `cargo test --lib` 测试 exe 曾在进入用例前以 `STATUS_ENTRYPOINT_NOT_FOUND` 退出，属该机环境故障快照，不代表公开平台的普遍行为。根因（`muda` 静态导入 `TaskDialogIndirect`，需 Common-Controls v6 manifest）与 CI 侧的系统性缓解见 `docs/windows-rust-ci.md`。

## 一键入口

快速跑不依赖真模型的用户旅程 smoke：

```bash
./scripts/run-user-journey-tests.sh
```

入口默认运行 Markdown smoke、审计器单测、MCP 协议/产物契约、桌面/Web Vite 构建、
WebUI Relay v2 协议测试、通用 GUI smoke、设置页 GUI smoke、工具商店装卸/授权 smoke、
知识库 GUI smoke 和完整 WebUI 浏览器旅程。首次运行若缺少 `node_modules`，
会按 `package-lock.json` 自动执行一次 `npm ci --prefer-offline --no-audit`；缺 Chromium /
puppeteer 时 GUI 项按 skip 处理。Windows 本机入口会自动探测 Chrome/Edge 常见安装路径；
发版前若关键 GUI smoke 仍是 skip，需要补齐 `CHROME` 环境变量后重跑。

附加审计最近 5 个真实 session：

```bash
PINVOU3_AUDIT_LATEST_SESSIONS=5 ./scripts/run-user-journey-tests.sh
```

附加跑真模型 L1：

```bash
PINVOU3_RUN_L1=1 ./scripts/run-user-journey-tests.sh
```

## 边界

- 能机器断言的：事件流是否完成、文件是否落盘、session JSON 是否可回放、UI 控件是否出现、工具调用是否配对。
- 不适合机器硬断言的：回答是否“聪明”、方案是否“好”、品悟建议是否主观上更优。这里继续走 L1 transcript + Judge。
- 真实 vLLM、网络、bge-m3、外部 connector 都不得放进默认 PR gate；需要 `#[ignore]`、环境变量或本机/nightly 入口。

## 维护规则

- 新增真实失败案例时，优先把 session JSON 路径或脱敏 fixture 放进 replay audit，而不是只写一条人工复现说明。
- 修改 `instructions.md`、工具策略、Plan/YOLO、subagent 或 `request_user_input` 前后，至少跑一次 L1 小集合或相关 replay。
- 修改内置模型目录或发版前，需要按厂商官方文档核对推荐模型；旧用户配置继续兼容，但已下线/弃用模型不得出现在添加/更换推荐列表。
- GUI 改动至少跑 `./scripts/run-user-journey-tests.sh`；如果缺 Chromium/puppeteer，runner 会以 exit 2 视为 skip。
- 设置页、工具商店、知识库这类主流程 GUI 改动不能只接受 skip 结果；本机需要确保至少对应专项 smoke 实际执行并通过。
- 修改 `remote_control/`、`remote-control-relay/` 或共享 WebUI bridge 时，除统一入口外还要跑一次 `cargo test --manifest-path pinvou3-app/src-tauri/Cargo.toml remote_control:: -- --test-threads=1`。
