# 真实用户自动化测试矩阵

> 目标：把 pinvou3 的自动化测试从“函数是否正确”推进到“真实用户旅程是否还能跑通”。本文件描述可执行入口、覆盖范围和分层边界。

## 分层

| 层级 | 入口 | 是否进 CI | 覆盖什么 |
|---|---|---|---|
| L2 后端确定性 | `cargo test --manifest-path pinvou3-app/src-tauri/Cargo.toml --lib -- --test-threads=1` | 是 | bridge、session、路径安全、知识库、fork 回归；含 Remote 消息去重、session snapshot、产物预览与跨会话路径逃逸 |
| L3 Mock GUI smoke | `node pinvou3-app/tests/ui_smoke.js` + `node pinvou3-app/tests/kb_smoke.js` + `node pinvou3-app/tests/tool_store_smoke.js` | workflow 已接线，`frontend-test` 当前暂停；本机必跑 | 加载 Vite `dist/`，mock TauriBridge，覆盖启动、工具商店真实装卸/授权交互、产物卡、品悟卡、模式 chip、本地模型引导、本地文件与知识库 |
| MCP 协议与产物契约 | `python3 scripts/mcp-server-contract-smoke.py` | 是（fast-gate） | 启动 5 个本地 stdio MCP，验证 initialize/tools/list/tools/call；覆盖 Obsidian 读写、PPTX/公文产物和 QCC 远端清单 |
| Remote relay 协议 | `npm --prefix remote-control-relay test` | workflow 已接线，`frontend-test` 当前暂停；本机必跑 | room 注册/鉴权、token、桌面与手机转发、断线宽限重连、限流、healthz 脱敏、部署回滚 |
| 手机 Remote 浏览器旅程 | `node remote-control-relay/test/mobile-ui.smoke.cjs` | workflow 已接线，`frontend-test` 当前暂停；本机必跑 | 启动真实本地 relay，用 Chromium 手机 viewport 打开真实 Remote Web，并用 WebSocket 模拟桌面端完成配对、会话恢复、消息/工具/Plan/提问/产物/断线重连/旧二维码失效 |
| Session replay audit | `python3 scripts/session-replay-audit.py --latest 5` | 审计器单测进 fast-gate；真实 session 本机跑 | 用真实 `~/.pinvou3/sessions/*.json` 做 transcript 结构审计，覆盖 `request_user_input`、tool_use/tool_result、artifact 引用；自动排除内部元数据和 pre-restore 备份 |
| L1 真模型 dialog harness | `PINVOU3_L1_REQUIRE_VLLM=1 cargo test --manifest-path pinvou3-app/src-tauri/Cargo.toml --test l1_dialog_harness -- --ignored --test-threads=1` | 纯函数错误回归进 Rust CI；真模型暂不进 CI | 真 Qwen/vLLM 跑端到端对话，覆盖工具链、多轮、Plan/YOLO、web_search、subagent、文件落盘；严格模式下 pre-flight 不可达或 turn 内 Engine Error 都直接失败，不能静默假绿 |
| Judge 语义评审 | `docs/L1-judge-rubric.md` 流程 | 不阻塞 PR | 读 L1 transcript，评回答质量、工具使用、任务拆分、结果综合 |

## 一键入口

快速跑不依赖真模型的用户旅程 smoke：

```bash
./scripts/run-user-journey-tests.sh
```

入口默认运行 Markdown smoke、审计器单测、MCP 协议/产物契约、Vite 构建、Remote relay
协议测试、通用 GUI smoke、工具商店装卸/授权 smoke、知识库 GUI smoke和手机 Remote
浏览器旅程。首次运行若缺少 `node_modules`，
会按 `package-lock.json` 自动执行一次 `npm ci --prefer-offline --no-audit`；缺 Chromium /
puppeteer 时 GUI 项按 skip 处理。

附加审计最近 5 个真实 session：

```bash
PINVOU3_AUDIT_LATEST_SESSIONS=5 ./scripts/run-user-journey-tests.sh
```

附加跑真模型 L1：

```bash
PINVOU3_RUN_L1=1 ./scripts/run-user-journey-tests.sh
```

## 边界

- 能机器断言的：事件流是否完成、文件是否落盘、session JSON 是否可回放、UI 控件是否出现、工具调用是否配对。
- 不适合机器硬断言的：回答是否“聪明”、方案是否“好”、品悟建议是否主观上更优。这里继续走 L1 transcript + Judge。
- 真实 vLLM、网络、bge-m3、外部 connector 都不得放进默认 PR gate；需要 `#[ignore]`、环境变量或本机/nightly 入口。

## 维护规则

- 新增真实失败案例时，优先把 session JSON 路径或脱敏 fixture 放进 replay audit，而不是只写一条人工复现说明。
- 修改 `instructions.md`、工具策略、Plan/YOLO、subagent 或 `request_user_input` 前后，至少跑一次 L1 小集合或相关 replay。
- GUI 改动至少跑 `./scripts/run-user-journey-tests.sh`；如果缺 Chromium/puppeteer，runner 会以 exit 2 视为 skip。
- 修改 `remote_control/`、`remote-control-relay/` 或 Remote Web 页面时，除统一入口外还要跑一次 `cargo test --manifest-path pinvou3-app/src-tauri/Cargo.toml remote_control:: -- --test-threads=1`。
