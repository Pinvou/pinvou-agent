# 应用内升级（deb）设计

> 2026-06-04 实装（commit f1ac20a），全链路 e2e 已验证。

## 一句话

App 启动静默检查阿里云上的 `latest.json`，有新版则设置图标亮红点，用户在设置页一键「下载并安装」（sha256 校验 + pkexec 提权 apt），重启生效。

```
启动/手动 → check_for_update (GET latest.json, 三段版本比较)
          → download_update (流式下载 ~/.pinvou3/updates/, 边下边算 sha256, update:progress 事件)
          → install_update  (pkexec apt-get install -y, Depends 自动拉齐)
          → restart_app     (app.restart(), exec 新 inode)
```

## 关键决策与 why

| 决策 | why |
|---|---|
| 自建轻量机制，不用 Tauri updater plugin | 官方 updater 不支持 deb |
| 静态 HTTP + latest.json，零服务端逻辑 | nginx 托管两个文件即可，无服务要维护 |
| 路径方式 `pinvou.com/pinvou3/`，不建二级域名 | 使用 Pinvou 独立品牌域名和 HTTPS 证书，复用现有源站及 `/pinvou3/` 发布目录 |
| 更新源 URL 硬编码常量，不进 settings.json | 是基础设施不是用户偏好，可改会成攻击面；`PINVOU3_UPDATE_URL` env 可覆盖（仅测试用） |
| 下载目录 `~/.pinvou3/updates/`，不用 /tmp | tmpfs 受内存限制 + 重启清空（下载完提示重启后文件就没了） |
| 安装走 pkexec 弹系统密码框 | 与 super_permission.rs 同套路；但用 `.output()` 捕 stderr 透传 apt 真实报错（lock 占用/磁盘不足） |
| 仅 `latest > current` 才提示 | 天然降级保护，服务器版本 ≤ 本地不打扰 |
| 装完不自动重启 | apt 替换 `/usr/bin/pinvou3` 后老进程持旧 inode 继续跑无害，用户点「立即重启」才 exec 新版 |
| 启动检查失败全静默 | 内网/断网环境不打扰用户；设置页手动检查才显示错误 |
| 发布脚本先传 deb 后传 latest.json | 避免清单已指向新版而 deb 还没传完，客户端 404 |

## 代码地图

| 文件 | 职责 |
|---|---|
| `pinvou3-app/src-tauri/src/updater.rs` | 4 个 command + 三段版本比较 + deb 路径白名单校验 + 单测 |

## latest.json 格式

```json
{
  "version": "0.3.0",
  "notes": "更新说明（纯文本）",
  "pub_date": "2026-06-10T08:00:00Z",
  "url": "https://pinvou.com/pinvou3/pinvou3_0.3.0_amd64.deb",
  "sha256": "<64位hex>",
  "size": 48291840
}
```

版本号必须纯三段数字（发布脚本保证）；sha256 下载后强校验，不匹配删文件拒装。

## 发版流程（两步）

1. bump 三处版本号：`tauri.conf.json` / `Cargo.toml` / `package.json`（脚本会校验一致）
2. `./scripts/release-deb.sh "本次更新说明"`

## 服务端现状（阿里云 8.218.49.20）

- 文件目录 `/var/www/pinvou3/`（admin 属主，rsync 直传免 sudo）
- nginx：正式域名使用 `/etc/nginx/sites-available/pinvou`，源文件是 `deploy/nginx-pinvou-domain.conf`；迁移期旧域名仍继续 include `/home/admin/pinvou3-deploy/nginx-pinvou3-updates.conf`
- HTTPS：Certbot 证书位于 `/etc/letsencrypt/live/pinvou.com/`，`certbot.timer` 自动续期，deploy hook 在续期成功后检查并 reload nginx
- 验证：`curl https://pinvou.com/pinvou3/latest.json`（latest.json 带 `Cache-Control: no-cache`，客户端每次拿最新）

## e2e 验证方法

```bash
# 1. 假更新源：latest.json(version=9.9.9) + 真 deb（sha256 重算填入）
cd /tmp/fake-updates && python3 -m http.server 8899
# 2. env 指向假源启动
PINVOU3_UPDATE_URL=http://127.0.0.1:8899/pinvou3/latest.json ./pinvou3-app/run-dev.sh
# 3. 红点 → 设置页发现 9.9.9 → 下载进度 → pkexec → 安装 → 重启
# 4. 降级保护：清单改 0.0.1 → 应显示「已是最新版本」
```

2026-06-04 实测通过：检查/下载/sha256/pkexec 安装/重启/降级保护全链路 ✅（`cargo test --lib` 105 过）。

## 边界情况

| 情况 | 处理 |
|---|---|
| apt lock 占用 / 磁盘不足 | stderr 末尾透传，设置页红字显示 |
| sha256 不匹配 | 删文件 + 报错，不进安装 |
| pkexec 取消（exit 126） | 报「用户取消授权」，状态回滚 |
| 重复下载 | 同版本文件已存在且 sha256 匹配则跳过 |
| 前端传任意路径给 install | canonicalize 后必须在 `~/.pinvou3/updates/` 内且 `.deb` 结尾，否则拒绝 |
