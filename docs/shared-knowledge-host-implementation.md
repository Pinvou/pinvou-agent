# PINVOU 托管共享知识库实施拆解

本文将 ADR-0022 拆成可验收的实现批次。任何批次都不能把尚未闭环的入口暴露为可用功能；草稿 PR 完成全部首版闭环后才进入合并评审。

## 产品结构

共享知识库页面只有一个知识工作区。用户选择的共享知识库决定其当前关系和能力：

- 尚未创建或加入时，只显示“创建共享知识库”和“加入共享知识库”。
- “此设备共享”由当前 Linux 主机持有，显示分享、成员和设置入口。
- 加入的共享知识库使用同一套知识集、文档、上传、回收站和检索组件，并按只读、内容管理或所有者设备关系显示操作。
- 分享、成员和设置使用抽屉或二级页面，不在主工作区堆叠端口、路径、进程和初始化状态。
- 页面不出现“远程知识库”“Web 后台”“初始化密钥”“检索就绪”等实现语言；失败时提供可执行的恢复动作和可展开诊断。

## 第一批：服务身份与授权协议

- 服务首次创建时生成稳定服务身份和本机 CA，叶子证书覆盖当前候选地址并可在地址变化后重新签发。
- 客户端连接保存服务身份、CA 公钥、多个候选地址和设备凭据，先验证身份再发送凭据。
- 服务端角色为只读、内容管理、所有者设备；所有者设备隐含完整内容管理能力。
- 新增加入申请、批准、拒绝、取消和轮询领取凭据的状态机。分享连接默认二十四小时有效、可多人申请、可提前停止，且不携带知识访问凭据。
- 自动批准只读只绑定某个仍有效的分享连接；附近发现提交的申请默认仍需批准。
- 只有本机控制面可以提升或取消所有者设备。远程所有者可以审批申请、管理普通成员和内容，但不能执行任何主机生命周期操作。
- 删除浏览器页面、密码登录、Cookie 会话、初始化密钥和旧快速加入产品入口；保留结构化且强制鉴权的管理 API。

## 第二批：Linux 本机托管

- Linux 安装包携带匹配版本的知识库服务组件，不在创建时从网络下载可执行文件。
- 主机功能通过平台能力声明，仅在受支持的 Linux 安装形态显示；Windows、macOS 和不受支持的便携形态只显示加入能力。
- Pinvou 使用原生系统管理员授权安装服务、创建受保护数据目录并启用开机启动，不读取或保存 sudo 密码。
- 本机控制通道与网络 API 分离，安装、显式升级、停服、移除、存储迁移、恢复和接管不能通过远程令牌调用。
- 服务升级由升级后的主机 Pinvou 明确提示并触发；升级前形成恢复点，健康检查失败自动恢复旧二进制和配置。
- 卸载 Pinvou 不自动停服或删数据；“移除共享知识库”分别提供保留数据和永久删除全部共享数据两种二次确认操作。

## 第三批：模型与内容

- Linux 本地知识库与共享服务使用统一的只读模型仓库，以模型名称、固定 revision 和文件摘要确定版本。
- 已存在且校验一致的 BGE-M3 直接复用；缺失时由后台服务继续下载，关闭 Pinvou 不中断任务。
- 创建共享知识库默认不导入任何本地内容。
- “发布到共享知识库”显式复制选中的本地知识集和源文档，发布后本地与共享副本独立，不建立文件监听或双向同步。
- 主机创建完成后自动连接“此设备共享”，但任何共享知识集都不会自动挂载到既有或新会话。

## 第四批：原生所有者控制台

- 复用 Pinvou 现有知识集、文档、上传、文件夹导入、回收站、进度、确认框和文件类型组件，不嵌入旧后台 HTML。
- 分享抽屉生成一个包含服务身份和多个私网候选地址的二十四小时连接，可复制、查看剩余时间、停止分享，并可显式开启同期限自动批准只读。
- 成员抽屉显示待处理申请和现有设备，支持批准为只读/内容管理、调整普通成员权限、撤销、恢复和删除；主机额外支持把现有成员提升或取消为所有者设备。
- 设置页显示名称、运行状态、版本、模型、存储占用、备份和升级。端口、地址、数据目录和诊断日志仅在高级信息中出现。
- 所有者在线时收到系统通知和页面标记；离线时申请保存在服务端，下次打开后加载。加入者可查看等待状态并取消申请。

## 第五批：发现与连接

- 共享服务仅在普通局域网发布最小候选信息：未经认证的显示名称、产品标记、端口和协议版本；不广播服务身份、CA、知识集、成员、文档、设备凭据或分享秘密。
- Pinvou 的“加入共享知识库”启动时显示检测状态并列出实际可达的附近服务；发现不扫描 Tailscale 节点，也不依赖 Tailscale CLI。
- 用户可以手动输入局域网 `IP:端口`、Tailnet `100.64.0.0/10` 地址或 `.ts.net` 名称。公网地址不属于支持范围，未填写端口时使用共享服务默认端口。
- 附近发现与手动地址只产生未受信候选。客户端先做不携带凭据的服务探测，用户在客户端与宿主界面核对稳定 CA 派生的身份码后才固定服务器身份并提交申请；这类申请必须由所有者审批，不能走分享链接的自动批准。
- 分享连接继续用于局域网、Tailnet、跨网段和群组分享，并可直接提供服务器身份、CA 与申请凭据。客户端在候选地址间验证并选择可达入口；地址切换不得改变服务引用或会话挂载身份。

## 第六批：备份、恢复与现有部署纳管

- Pinvou 请求服务创建一致性快照并输出有版本、清单和摘要的加密备份包；模型不进入备份。
- 正式产品通过 root helper 进入维护窗口：先停止服务，再生成数据库与源文档一致的快照，完成后恢复服务。即使绕过产品直接调用备份命令，源文档也会按数据库快照复制并复核大小与摘要，变化时明确失败而不产出混合时点备份。
- 本机恢复从系统安全存储读取备份密钥，只要求系统管理员确认；跨主机或本机密钥丢失时才要求恢复码。
- 恢复码与备份分开保存，只能解密备份，不能登录服务或取得所有权。
- 同机恢复保留当前服务身份和成员；换主机恢复只迁移知识内容，生成新身份且成员重新申请加入。
- 现有 Cube 数据在切换前自动备份，保留知识集、源文档、索引、模型、回收站和普通设备授权；一次性纳管创建本机所有者能力和加密服务身份，成功后永久关闭 Web 页面和旧明文入口。
- 团队成员可以先升级 PINVOU：旧连接配置会完整保留，并明确提示主机所有者升级服务；为避免向旧明文地址发送凭据，主机升级完成前暂停访问。主机完成升级后，客户端重新绑定服务证书并恢复连接；日常升级不再触发重新纳管。

## 首版非目标

- Windows 或 macOS 创建共享知识库。
- 无桌面 Linux、NAS 应用商店、Docker 或 SSH 远程部署的普通用户流程。
- Tailnet 节点扫描、Tailscale Services 自动注册或公网服务目录。
- 多主机高可用、横向扩容、一台主机多个共享服务。
- 用户账号、知识集级 ACL、部门权限或个人私有区。
- 自动同步本地知识、定时自动备份和网络存储上的实时数据库。

## 发布门禁

- 从全新 Linux 安装到团队成员读取的流程不需要终端、浏览器后台、IP 地址、端口或初始化密码。
- 关闭 Pinvou、注销桌面会话和重启主机后，共享服务按预期保持或恢复；主机休眠、关机和离线状态表达清楚。
- 任何网络令牌都不能执行主机生命周期操作，所有网络内容请求均验证稳定服务身份并加密传输。
- 分享连接泄露不会直接取得知识访问权；停止分享或到期只影响新申请，不影响已授权设备。
- 本地内容不会因创建服务而自动共享，发布、删除、恢复、移除和迁移均有准确作用域与二次确认。
- 服务升级、批量发布、备份和恢复展示真实进度；关闭进度面板只收起界面，不表示取消 root 操作。等待超时后会明确提示系统操作可能仍在收尾，并要求刷新状态后再决定是否重试。模型下载支持真实取消；所有路径均有失败恢复，不出现永久旋转或把结果未知误报为安全失败。
- Linux helper 以 polkit 管理员授权为信任边界，并强制绑定 `PKEXEC_UID`；请求中的宿主 UID、主组、模型目录链和既有数据目录必须属于同一发起用户。多管理员机器不会静默接管其他用户创建的共享知识库。
- 中、英、日文案、无障碍标签、键盘操作、窄屏布局及现有知识库视觉语言一致。
- 旧后台资源、密码/Cookie 认证和初始化密钥无产品可达路径，CI 覆盖服务端、Linux 托管、原生 UI、发现、加密、备份与迁移关键路径。
