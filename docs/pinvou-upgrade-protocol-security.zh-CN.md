# 品悟升级协议与安全要求

> 状态：V1.0
>
> 日期：2026-10-08
>
> 适用范围：品悟统一升级平台控制面、文件面、客户端升级助手和管理后台

## 1. 文档定位

本文定义升级平台必须满足的安全目标、信任边界和对外协议要求，不规定数据库表、锁、租约、CAS 或恢复 worker 的具体实现。

产品行为见 [品悟统一升级平台需求文档](pinvou-upgrade-platform-requirements.zh-CN.md)，实现方案见 [品悟统一升级平台技术设计草案](pinvou-upgrade-platform-technical-design.zh-CN.md)。

## 2. 为什么需要签名和密钥

升级文件最终会以高权限执行。攻击者一旦能够替换安装包、Manifest、升级助手或在线授权，就可能在所有客户端执行任意代码。

HTTPS 只能保护客户端与当前连接端点之间的传输，不能单独解决以下问题：

- 文件来自第三方 CDN 或对象存储时，如何证明它仍是品悟发布的文件。
- 文件服务、缓存、代理或存储配置错误时，如何发现内容被替换。
- 历史合法文件被拿来冒充当前允许发布时，如何区分“文件真实”和“现在允许安装”。
- 在线服务密钥泄露、轮换或吊销后，客户端如何拒绝新的伪造授权。
- Windows、Linux、macOS 如何验证安装器和升级助手的发布者身份。

因此必须同时使用：

1. **不可变内容身份**：以大小和 SHA-256 识别精确字节。
2. **发布方签名**：证明 Manifest 和制品身份由品悟认可。
3. **平台真实性校验**：证明安装器和可执行文件符合操作系统平台信任要求。
4. **短期在线授权**：证明某个已经验真的版本在当前时间仍允许由该安装事务执行。

这些能力用于建立升级安全边界，不用于用户身份、许可证或设备准入。

## 3. 威胁模型

平台至少防范：

- 控制响应、Manifest、安装包、补丁包或助手文件被替换。
- 第三方文件服务返回错误、陈旧或恶意内容。
- 合法响应被跨客户端、跨平台、跨渠道或跨事务重放。
- 已暂停/撤回的 Deployment、已吊销的 Release Target、已隔离的 Artifact，或未获当前在线桥接资格的历史发布被重放并取得新的安装权。
- 客户端 UI 或普通用户进程伪造当前版本、平台、助手状态或安装结果。
- 旧 helper 在接管后恢复运行并继续写事务。
- 无服务端凭据的虚假遥测污染发布质量判断。
- 日志、错误信息或下载 URL 泄露令牌、SN 或本地敏感路径。

首期不承诺抵抗已经取得本机系统管理员/root 权限并能完全控制运行环境的攻击者，但此类环境仍不能改变服务端发布状态或伪造品悟签名。

## 4. 信任边界

### 4.1 可信主体

- 客户端内置的品悟升级信任根。
- 经发布流程签名的 Target、Release 和 Package Manifest。
- Windows Authenticode、macOS 代码签名与公证、Linux 包及元数据签名。
- `update.pinvou.com` 按用途签发的决定、预安装/直接安装/激活授权、独立任务与事件凭据；仅在签名、时限、绑定及当前资格均有效时可信。
- 经可信链及平台身份验证、系统级受保护的 launcher/helper，以及准备、执行、槽位、对账和门的本地事实；普通进程自报不能替代这些事实。

### 4.2 不可信输入

- UI、普通应用进程和请求中自报的版本或能力。
- 原始硬件 SN、installId 和 installationScopeId；它们都是分组或关联标识，不是身份凭证。
- 第三方下载地址及其 HTTP Header。
- 客户端上报的安装结果和质量事件。
- 文件名、扩展名、Content-Type 和压缩包内部声明。

所有不可信输入必须与可信 Manifest、平台探测或受保护本地事实交叉验证。UI 只提交有限语义请求；helper 不接受任意命令、程序路径、删除集合或数据路径，服务端签名也不能覆盖本地 scope、当前事实、用途和安全边界的验证。

## 5. 控制面安全

- 控制接口固定使用 `https://update.pinvou.com`，最低 TLS 1.2，生产环境优先 TLS 1.3。
- 客户端不得通过不可信响应发现或替换控制面域名。
- 动态响应不得被共享缓存；敏感令牌不得写入 URL、普通日志或崩溃报告。控制请求不跟随跨域重定向，不将控制面认证信息转交第三方。
- 请求和响应必须有严格 Schema、长度限制、字段类型及未知关键字段处理规则。
- 同一有副作用请求重试必须得到同一业务结果，不能重复创建会话、授权、消费或取消。
- 三用途 consume 的长期对账统一使用 consume-status，覆盖 backupPolicy=required/notRequired；它只能返回最小 consumed/cancelled/expired 与 transactionId，不是执行、下载或事件授权。窗口关闭后的独立对账任务按 §9.6 隔离，不能恢复旧执行权。
- 具体幂等和并发实现属于技术设计，但不能降低本文的安全结果。

## 6. Manifest 与制品安全

### 6.1 分层职责

| 层级 | 负责内容 |
|---|---|
| Target Metadata | 产品、渠道、平台目标、宿主约束和支持下界 |
| Release Manifest | 目标版本、来源要求、策略、安装包候选和目标 launcher |
| Package Manifest | 上传内容中的完整包、增量候选、重建结果、helper、SBOM 和来源证明的精确字节身份；不绑定外层 ZIP |

客户端必须验证引用关系、产品/组件、平台目标、版本、packageId、大小和哈希一致，不能只验证最内层文件。签名必须来自当前可信 Root 授权的角色、作用域及算法，并满足该角色已配置阈值，不能接受文件内自带公钥作为新信任根、未知关键字段、算法降级或跨角色签名。封装 Schema、规范化/签名输入与域分离由版本化规范及固定向量冻结，覆盖角色、product/component、作用域、版本及精确内容；未冻结不能进入验收。候选 Release 必须另外验证其封装摘要对当前 Target `rolloutSetCommitment` 的开封关系；在线决定签名不能替代该父级授权关系。

这里的“复合包”表示 Package Manifest 对内部条目及其关系的声明，不表示 Manifest 绑定包含自身的外层上传 ZIP 哈希；外层 ZIP 的传输哈希由上传会话在 Manifest 外保存。

Package Manifest 内部不得包含要求等于自身签名封装哈希的字段。可选 manifestId 只是非安全逻辑标识；权威身份 `manifestEnvelopeSha256` 由上层 Release 对完整签名封装外部计算并引用。

新 SelectionScope 可预生成由正式角色签名的 staged Target/Snapshot，但它们必须绑定生成时的产品 RootPublishHead、product/component MetadataPublishHead 和完整安全读集，不被 current Timestamp 引用、不可通过公共端点解析，也不能签发任何决定。首次激活只有两级 head 比较/CAS 成功、同一原子提交发布新 Timestamp 指针并把 staged 集合提升为 current 后，才形成客户端可信元数据链；任一 head/Root/引用 revision 变化或超过 15 分钟的 staged 集合不得提升，必须基于最新完整集合重签。staged 完整内容使用独立访问控制，不进普通日志/导出，并在成功、替换或到期后 24 小时内删除，只留审计摘要。

### 6.2 Package Manifest 永不过期

Package Manifest 是某组制品的不可变身份声明，不设置 `expiresAt`，也不会因为时间推移自动失效。

以下状态仍可阻止安装：

- Deployment 已暂停或撤回。
- Release Target 被安全吊销。
- Artifact 被隔离。
- 在线安装授权到期或拒绝。
- 当前平台、来源版本或升级助手能力不满足要求。

“Manifest 不过期”不等于“该版本永远允许安装”。

`superseded` 本身不是安全吊销。一个历史 Deployment 只有仍在当前可信 Snapshot、Release=closed、Release Target=approved、全部 Artifact=valid、渠道 SupplyChainApproval 当前有效、同渠道 BridgeEligibility 明确启用且在线服务重新确认其位于当前前向路径时，才能取得桥接下载和安装授权；bridge 只替换 Deployment active 这一项正向条件。安全要求禁止的是绕过当前资格的旧版本重放，不禁止经过当前在线授权的历史桥接。

BridgeEligibility 的 ID/revision 必须绑定决定、下载资格和三用途授权；任何启用、禁用或重新启用都增加 selectionGeneration，并按 PublishSelectionChange 发布 current 元数据；紧急禁用可先 deny 并进入 metadata_sync_pending。download-info、validate 和 consume 在最终提交前重新读取当前 ID/revision 与状态，旧 revision 不因资格恢复为 enabled 而重新有效。

决定同时绑定 endpointKind=baseline|candidate 和 hopKind=ordinary|bridge，分别绑定两条完整正向实体链、ID/revision、时间窗、Package/Artifact 和激活模式。candidate 始终复核其 Rollout；bridge 复核独立 BridgeEligibility；ordinary 实际跳不是终点时，必须是本渠道有效基线或当前 Target/Snapshot 明确登记并独立批准的 active 前置路径跳，绑定审批修订。该跳自身 Rollout paused/aborted、未命中候选或仅制品批准均不得借另一有效终点绕过。资格及审批修订变化纳入 generation/current 元数据，四组合在所有动态端点及执行边界前同时复核双链。候选必须按需求 §6.2 严格高于当前基线，不能用签名合法历史对象降低基线。

### 6.3 文件校验

- 每个可下载文件必须绑定 packageId、精确大小和 SHA-256。
- 下载完成后先验证容器，再验证最终将执行的安装器或重建结果。
- 完整包与增量包必须得到同一个受信任最终安装器身份。
- 同一 packageId 的内容不得原地替换；需要修改时创建新的 packageId 和发布记录。
- 校验失败的内容必须删除或隔离，不能进入 staging 执行区。
- 复合 ZIP 和客户端下载单元限制解压总量、单项大小、数量及嵌套深度；规范化后拒绝路径逃逸、重复/冲突条目及平台危险路径。解压只写独占受保护 staging，不通过符号/硬链接、Windows reparse point 或目录替换触达任意路径、活动版本或其他 scope；包格式所需合法内部链接仅按已认证平台契约验证。
- 校验至执行之间保持精确字节身份、目录权限及所有权；启动 helper/安装器或切换槽前复核实际对象，不能先校验文件 A、再按可替换路径执行 B。权限不足或对象变化失败关闭，不把普通用户可写缓存直接交给高权限执行。

### 6.4 软件供应链证据

生产复合上传包必须包含与最终安装器哈希对应的 SBOM 和构建来源证明。它们由后台发布闸门验证，不要求客户端下载：

- SBOM 使用版本化的 CycloneDX JSON Schema；构建来源证明至少绑定源码修订、受控流水线身份和最终安装器 SHA-256。
- 漏洞数据源、评分版本和数据库更新时间必须记录；数据库超过 72 小时未更新时不能批准新的 Stable Release Target。
- 默认阻止存在任何已知 Critical 或 High 漏洞的制品进入 Stable 审批；只有下一条规定的双人限时安全例外可以放行。Internal/Beta 也必须展示并审计风险，不能静默忽略。
- 例外必须记录漏洞 ID、受影响范围、缓解措施、到期时间，并由安全负责人和发布负责人双人批准；例外到期后自动阻止新的 Deployment 和扩量。
- 渠道级 SupplyChainApproval 绑定漏洞快照及例外 ID/revision/expiresAt。Stable Deployment 进入 scheduled/active、从 paused 恢复、下载/授权以及 Rollout 启动、扩量、完成都在提交点复核该审批；draft/in_review 可先创建但不产生资格。Beta/Internal 的风险接受不能复用于 Stable。到期、吊销或当前链切换到新批准 revision 恢复/扩大资格都增加 selectionGeneration；恢复/扩大通过 PublishSelectionChange，失效先写即时 deny 和 metadata_sync_pending。
- SBOM/来源证明缺失、哈希不匹配、流水线身份不在允许列表或扫描结果被篡改时，Artifact 不能进入 valid。
- Stable 正式版显式同步到 Beta/Internal 只复用不可变制品及其供应链证据，不复用来源渠道审批、风险接受、例外批准或任何客户端凭据。每个目标渠道必须完成自己的 SupplyChainApproval，并在后续投放及动态端点提交点按本渠道验证；草稿创建不授予更新资格。共享 Release Target 吊销或 Artifact 隔离对全部引用渠道生效，单渠道 Deployment 暂停/撤回仅约束该投放。
- 具体扫描器属于实现选择，不能改变以上最低安全结果。

## 7. 第三方文件服务

文件信息接口可以返回第三方域名的短期 URL。客户端信任的是控制面签发的文件身份，不是 URL 所属域名。

- URL 不能修改 packageId、大小、哈希或平台身份。
- 重定向、Content-Disposition、文件名和 Content-Type 都不能覆盖 Manifest。
- URL过期后以当前合法决定重新请求文件信息；下载不设总时长/累计重试硬限。单次网络超时仅用于重试/退避/换源，不因长下载或短期凭据到期判执行失败；新check/会话按凭据规范续接同一workflow未来动作及下载缓存，原阶段/样本不变、旧事件不补签，当前资格失效不授越界权。
- 第三方服务被替换、返回旧内容或发生缓存污染时，客户端必须通过大小、哈希和平台签名发现。
- 下载 URL 不进入长期事件、普通日志或支持导出。
- 初始及重定向 URL 仅用经发布审批许可的 HTTPS 文件源，拒绝凭据注入、非网络协议和未获批准的本机/网络目的地；DNS/重定向变化不得绕过目的地策略。文件请求不携带控制面 Authorization、Cookie、SN、安装标识或环境隐式认证，不把下载地址拼入 shell 命令。

## 8. 平台真实性

### 8.1 Windows

- 安装器、launcher 和 helper 分别校验 Authenticode。
- 校验允许的发布者身份、证书链和时间戳策略。
- 文件哈希相同但签名身份不符仍必须拒绝。

### 8.2 macOS

- 校验代码签名、Team ID、designated requirement 和公证状态。
- helper 和主应用分别声明身份，不能用主应用签名代替 helper 校验。

### 8.3 Linux

- 校验签名元数据链、DEB 身份、ELF 类型和目标架构。
- 安装过程不得通过临时未知软件源下载并执行未在发布中声明的代码。

### 8.4 新平台

新平台接入必须定义等价的发布者身份、可执行文件真实性和撤销检查机制；不能仅依赖 SHA-256 而缺少发布方身份。

## 9. 在线决定与安装授权

### 9.1 决定凭据

每次成功检查，无论有无更新，都签发短期决定凭据，至少绑定：

- 本次请求随机数和决定 ID。
- product、component、平台目标、当前版本和渠道 revision。
- installId、installationScopeId。
- 当前 updater 事实摘要。
- 发布选择世代。
- 有更新时的 Release、Deployment、允许 packageId 和目标版本。
- 无更新时的稳定 reason。

`SCOPE_UNACTIVATED` 是检查前置条件不满足的 typed non-success，固定使用 HTTP 409、`retryable=true` 和普通检查间隔；它不属于“成功检查”，不签发决定凭据或遥测会话，也不要求不存在的 current Target/metadataSet。后台 staged Target/Snapshot 不改变该结果。其响应 Schema 不含 Release、下载或安装资格字段。

决定凭据不能跨设备标识、渠道、平台、来源事实或检查请求复用。

### 9.2 三用途授权与执行边界

预安装、直接安装与激活授权均为服务端短期一次性许可，不是管理员权限或用户确认；purpose/type/audience 和完整绑定必须显式区分，不能跨用途消费。共同前提是可信内容、实际来源/平台/scope/updater 事实、两条当前正向链、适用灰度/桥接/前置路径资格及模式认证均有效，目标严格高于当前版本。

本文在越界和安全停用证明中所称“受保护写入”，指本次对活动版本或受影响业务数据的执行写入；准备/审计记录、冻结元数据和隔离非活动槽不构成该执行边界。它们仍须受权限、唯一所有权和清理规则保护，不能因不越界而任意写入或省略安全核对。

| 用途 | 签发及消费前置条件 | 允许动作与边界 |
|---|---|---|
| 直接安装（normal/forced） | normal 用户明确确认本次实际 hop；forced 按门内流程推进；必要 OS 权限、预检、独占准备、全范围冻结及 required 备份已验证，位于安装区间 | 消费后调用平台安装器，调用瞬间跨 executionCommitBoundary |
| 非活动槽预安装（silent） | 已可见且未到期，包支持 stagedRestart，可信 helper 既有权限足够；不要求提前冻结/备份活动数据，可早于 installNotBefore | 消费后只写绑定非活动槽并隔离验证，不能迁移活动数据或切活动指针，不跨执行边界 |
| 重启激活（silent） | 用户发起应用重启或系统重启，仍精确选择 staged hop，旧渠道/槽/修订未失效；独占准备、全范围冻结及 required 备份已验证，位于安装区间 | 新授权/新事务消费及最后在线复核后，首次活动数据写入或指针切换中较早者跨边界 |

授权至少绑定 purpose/type/audience、product/component、installId/installationScopeId、decision/transaction ID、当前来源及目标版本、两链 ID/revision/时间窗、packageId/Manifest/最终制品身份、模式、当前事实、目标 helper、channelRevision、generation、授权 ID/有效期及本次准备/冻结/必要备份摘要。激活另绑定原预安装事务、staged revision/槽位身份/原期限；消费只比较 waiting 修订并取得唯一事务占用。notRequired 不创建备份或伪造成功摘要；irreversible 必须 required。

授权消费与取消/到期互斥，只有一个结果；消费前可以取得准备所有权并创建受保护记录、冻结与备份，但不能执行该用途的安装写入、helper 更新/执行接管或版本切换。消费后仍不是离线执行通行证：直接安装/激活跨边界的紧前一步在线复核两链、当前安全状态、时间窗与本次授权的合法消费状态；不得重复消费或用已消费授权发起第二事务。silent 使用既有可信 helper，不自动弹提权窗口；权限缺失安全保持旧版及已有门，只给用户主动修复组件入口。

### 9.3 资格收紧与分层时间规则

新决定、下载及三用途授权均按当前实体链和元数据验证。releaseVisibleAt 前不展示/下载；可见后 normal 点击才下载、forced 可预下载、silent 可预安装。installNotBefore 前拒绝直接安装/激活授权及活动版本切换，但不拒绝上述合法准备；到非空 installNotAfter 立即拒绝所有新资格，旧 URL 最多残留原十五分钟，不能据此越界。时间使用可信 UTC 与 [start,end)，end=null 无日历终点。

Deployment/Rollout paused、Deployment withdrawn/superseded、Rollout aborted、Target revoked、Artifact quarantined、BridgeEligibility disabled、SupplyChainApproval expired/revoked 及即时 deny，按需求 §6.2 用途/执行边界矩阵收敛：

- 未消费：拒绝签发/刷新/消费旧资格；已经下载或签名真实不构成执行许可。
- 直接安装/激活已消费未越界：确认安全停止、未发生受保护写入后取消；不把 ACK 丢失或超时当作取消。
- 进行中预安装：安全取消并隔离/清理未完成槽，不建立应用修复门。
- 已完成 staged：只有同对象临时 paused 隐藏提示并保留至原 stagedValidUntil；到期、永久撤销、改选或渠道改变失去资格并安全清理，不重写 staging_completed。
- 已越界：资格收紧不强杀安装器/迁移、不自动恢复旧版；保持唯一所有权及必要保护，核对至 succeeded 或 failed_manual_repair_required，不因原发布失效解除失败修复门。事件是否可上传仍独立遵守事件密钥 deny。

forced 按当前 hop 判定门，不把历史 hop 成功越界套到下一跳。终点失效且当前 hop 未越界、当前版本健康时安全取消并解本次强制门；仅路径失效保留受限门，独立失败门不随之解除。边界后失败只用同 scope/原失败关联、严格更高且数据/活动身份/健康通过的独立前向修复解除对应门。正常升级每 hop 重新确认，任何类型不合并多跳为一次安装。

channelRevision 改变只允许已经消费的直接安装或激活事务使用冻结 revision 继续既有收敛/events；其他旧资格失效，进行中预安装取消，尚未消费激活的 staged 清理，新渠道同 packageId 不复用。已消费例外不授予任何新下载/授权/执行能力。

### 9.4 不可放宽的时间上限

以下是 V1 安全上限，具体实现只能缩短，不能延长：

| 对象 | 最大有效或发生窗口 | 最大补报/恢复窗口 |
|---|---:|---:|
| 检查决定凭据 | 签发后 15 分钟 | 不补报；过期后重新检查或按受控刷新规则取得新决定 |
| 文件下载 URL | 签发后 15 分钟 | 过期后按同一 packageId 重新请求，不延长制品身份 |
| 一次性预安装/直接安装/激活授权 | 签发后 5 分钟 | 已提交幂等结果最多恢复 24 小时，但不得延长有效期或产生第二次执行权 |
| helper 清理授权 | 签发后 2 分钟 | 不补发原授权；重新检查后取得新授权 |
| 遥测会话事件 | 事件必须发生在凭据签发后 24 小时内 | 凭据最长 7 天，用于上传发生窗口内的离线事件 |
| 三用途执行事务事件 | 事件必须发生在对应授权消费后 30 天内 | 凭据最长 37 天，彼此用途/事务隔离，仅上传合法发生窗口内事件 |
| 动态 API 完整业务响应/凭据（events、consume outcome 除外） | 不适用 | committedAt 后最多恢复 24 小时 |
| 三用途 consume 最小 outcome 查询（required/notRequired） | 不授予执行能力 | 查询至 authorizationExp+61 天，仅返回 consumed/cancelled/expired 与 transactionId；tombstone 于 +62 天删除 |
| 独立对账/复核任务动作许可 | 签发后最多 5 分钟 | 重新校验任务状态/权限后签新许可，不重签旧事务或延长其窗口 |
| 独立任务事件 | 不宽于遥测24小时发生上限；质量复核还须属于绑定观察窗口 | 不宽于遥测7天上传上限，旧执行证据的窗口不因任务延长 |
| events 去重账本 | 不适用 | 至少保留至对应事件上传凭据 exp 后 2 分钟 |

到达边界时按服务端可信时间视为过期；处理/时钟裕量仅用于验证 key/去重记录的保留，不延长执行或发生窗口。完整响应恢复只返回首次提交结果，不重签/延长凭据。下载没有累计硬截止；超过会话24h必须取得新的当前资格/有期限会话，只签未来下载进度/结果并绑定原workflow/阶段/目标身份，不延长旧凭据或把新观察冒充旧时间事件。三用途客户端请求前生成并保护256-bit recovery secret及规范 consumeRequestDigest，consume 只送 secret 的 SHA-256；statusBindingHash 域分离绑定 recoveryHandleHash、scope、purpose、authorizationJti、consumeKey、transactionId和请求摘要，与消费/取消/到期业务结果原子保存。查询重算并常量时间比较，错绑/不存在/过期统一无信息且限流，不重发任何凭据。secret、完整请求或可重放绑定组合不进 URL/普通日志/崩溃报告；事件和受保护审计仅保留用途所需的无秘密 lineage/摘要。正常轮换保留验证公钥至最后签发对象有效期、上传期及恢复期结束再加至少两分钟，安全吊销立即禁止新签发及旧凭据使用，不抹去合法历史提交。

### 9.5 可信元数据时间上限

V1 元数据使用服务端可信 UTC；`now == expiresAt` 即过期。实现只能缩短下列上限，不能延长：

| 角色 | 单份元数据最大有效期 | 正常刷新要求 |
|---|---:|---|
| Root | 365 天 | 最迟在到期前 30 天发布并验证后继 Root |
| Timestamp | 24 小时 | 在线服务至少每 6 小时刷新，前一份保留至自身到期 |
| Snapshot | 7 天 | 至少每 24 小时刷新或确认，前一份保留至自身到期 |
| Target | 30 天 | 最迟在到期前 7 天发布后继版本 |
| Release | 90 天 | 最迟在到期前 30 天续签仍需可达的 Release |

Package Manifest 仍不过期。客户端离线时可以缓存并验证已取得的制品身份，但任一所需在线元数据已过期后，不得取得新决定、下载 URL 或三用途授权；恢复联网并取得从当前 Root 可验证且版本不回退的新链后才可继续。正常轮换至少保留新旧元数据的上述重叠期；紧急安全吊销通过即时 deny 失败关闭，不等待元数据自然到期。

check、download-info、validate 和 consume 在最终提交时都必须验证当前 metadataSet：Root、Timestamp、Snapshot、Target，以及 endpointChain 与 hopChain 分别引用的全部 Release Manifest；逐个校验身份、version/revision、expiresAt、引用和高水位。Release 续签或当前引用 revision 变化后，绑定旧 revision 的决定不得继续签发三用途授权或开始新的受保护执行，客户端必须重新 check；Package Manifest 不过期不豁免上层集合复核。

任何续签或字段变化只要改变 Root、Timestamp、Snapshot、Target 或 Release 的签名封装字节，就必须提升该角色对应作用域的 metadata version/revision。Release 续签创建更高 metadata revision，但 releaseId、业务版本、制品和发布说明保持不可变；当前 Snapshot/Target 改为引用新 revision，旧 revision 不能覆盖新高水位。

`RootPublishHead` 在 product 作用域唯一绑定 current Root 的 identity/version/bytesHash；Root 建立或轮换通过 PublishRootChange 对它做逐版本 CAS，杜绝两个 component 各自发布同版本不同字节 Root。`MetadataPublishHead` 在 product/component 作用域绑定 current Timestamp/Snapshot 和 `rootHeadRevisionAtPublish`。所有组件发布同时绑定 base RootPublishHead 与 base MetadataPublishHead；所有扩大资格或改变可选择集合的操作必须通过统一 PublishSelectionChange：预签受影响全部 Target、完整 Snapshot 和 successor Timestamp，并在同一提交断言产品 Root head 未变化、CAS component head、写实体 revision、selectionGeneration 与 current 指针。不同渠道和 scope 不能各自覆盖 component Snapshot。该规则覆盖 supportFloor、Deployment、Rollout、BridgeEligibility、ordinary前置路径审批、SupplyChainApproval 和 Source Facts Registry 的资格变化。紧急收紧可先写即时 deny 和 metadata_sync_pending，但同一事务必须登记持久化 MetadataReconciliationJob；恢复器只能在新 component head 成功发布的同一提交清 pending。在 `Target.selectionGeneration == SelectionScope.selectionGeneration` 且追平完成前，所有动态资格端点失败关闭。

客户端后继 Root 必须逐一连续验证，分别满足旧 Root 授权的 Root 角色阈值与后继 Root 自身阈值；同版本不同字节、跳版本和自带新 key 均拒绝。已缓存可信 Root 过期时仅可作为验证连续 Root 后继的信任锚，不授予新升级资格；只有取得未过期最终 Root 及完整当前链才可恢复新动作，无法构成可信链则失败关闭，不提供远程重置信任根或高水位入口。产品级轮换提交前，后继 Root 必须仍可验证每个 active component 的当前未过期完整链；角色 key 退出遵守先双信任、再逐组件刷新、最后移除旧 key，不能破坏另一组件。

Root 轮换只使用产品级 PublishRootChange。Release 续签和不改变可选择集合的 Target/Snapshot/Timestamp 续签必须通过 PublishMetadataRefresh 绑定两级 base head，基于最新完整集合重签，并在同一提交比较 Root head、CAS component head、原子更新 current 指针；这类刷新不递增 selectionGeneration。若同时改变可选择集合则必须改用 PublishSelectionChange。任何冲突均不得覆盖并发发布。

### 9.6 消费未知、永久停用与独立对账

所有用途及 required/notRequired 请求前，在产品锁和唯一所有权下持久化 consume_pending 及 §9.4 绑定。消费/取消 ACK 丢失、断网或超时不证明未消费/已取消；从首次发送 consume 起一次五分钟等待预算，崩溃/重启/重试不刷新，无法判断剩余预算立即核对本机安全事实。

只有仍有效所有者能证明未越 executionCommitBoundary、无受保护写入、旧版和数据完整、全部本次执行者已停止，并永久禁止该授权/事务/所有者代次再执行，才可持久化 local_execution_retired，解除自己的冻结并释放实体锁。旧准备备份不能用于新执行；独立对账占用跨重启保留，拒绝新准备/预安装/安装/激活。迟到 ACK、旧 helper 或恢复入口不得复活停用执行权，删除到期备份/secret/槽也不解除该占用。normal/silent 无既有门可使用经验证旧版；forced/独立修复门仍按需求 §5.5。不能证明安全时继续执行或人工修复保护；预安装只隔离槽，不因缺报建立应用门。

联网确认旧消费结果并取消/失效未消费授权，或核对已消费的安全取消/既有终态后，才以独立处置解除对账占用。+61d 查询关闭、secret 丢失或旧凭据不能合法恢复时，由 MFA、最小权限、受控故障角色签发独立对账任务；绑定原请求摘要、scope、purpose、authorization/transaction ID、本地停用证明及任务自身修订。helper 核对旧活动身份/数据、无本次受保护写入、无活跃写入者及永久 fencing，服务端核对旧授权及范围占用，全部满足才放行。历史结果缺失保留未知，处置只追加关联记录、不改 reporting_timeout 等原终态，不补签旧事件/授权，不授予下载或执行权；失败/丢 ACK 恢复同一任务，证明不足保留保护和人工前向修复入口。新升级完整重新准备及 required 备份，不重置任何原期限。

## 10. SN、安装标识与认证边界

- SN 只参与候选灰度包含/排除/稳定百分比分桶；灰度命中可决定本轮候选资格，但 SN 本身不是设备认证、scope 绑定、许可证或执行授权凭据。
- SN 缺失/不可读取/用户关闭发送时，不足100%走有效基线，100%命中候选；仍满足路径/平台/时间/安全资格。可用 SN 排除优先于包含，再百分比，成为基线后不再按灰度排除；变化不授予独立安全权。
- 服务端仅保存用途隔离密钥计算的 SN 摘要，原始 SN 不进入普通日志、事件或文件服务请求，灰度名单不公开。
- installId/installationScopeId 只做伪匿名关联，不证明设备/用户身份；不能仅按自生成 ID 绕过限流、贡献限制或取得高权限能力。可信 helper 在写入前验证实际 scope 和受保护事实，服务器签名不能让另一个实际安装范围执行；不声称普通凭据构成硬件远程认证。
- 未命中客户端不能通过公共 Target、定位器或错误响应枚举候选版本、Release ID或Manifest。候选开封盐非公开，决定开封证明必须匹配当前 Target；旧 opening 不在恢复/续签后自动有效。

## 11. Helper、Launcher 与本地保护

### 11.1 所有权、槽位与数据范围

- launcher/helper、信任根、高水位、准备/执行/对账/门记录均受系统权限保护，不接受 UI 或普通用户替换。helper 版本并存且独立于应用替换目录，主安装器不能删除使用中的 helper。
- 从首次协调写入者/冻结/备份之前取得唯一准备所有权和系统级产品锁，并受保护持久化代次；消费后连续转交唯一事务，崩溃/重启先恢复互斥和状态。接管精确绑定 scope、准备/对账 lineage 或执行 transactionId、所有者代次及目标 helper；旧所有者不能写入、启动、解冻或清理新代次，不能以进程消失放行第二准备。
- per-machine 协调所有用户、断开会话及后台登记写入者，安全保存/冻结并阻止新写入或旧入口绕过；迁移/required 备份覆盖共享与全部受影响用户数据，包括未登录用户。任一范围不可访问/不可验证即禁止受保护写入，不丢弃其他用户未保存内容、不用锁代替冻结确认。per-user 同样准备先于冻结。
- backupPolicy 与 migrationMode 正交，irreversible+notRequired 禁止；required 备份须验证并绑定本次准备/冻结代次，授权前完成，不能用旧解冻快照或自报 hash 代替。silent 预安装只写非活动槽，无活动数据迁移/提前备份；缺既有权限不自动提权。
- staging_completed/staging_failed/staging_cancelled 结束预安装事务并释放执行占用；staged_waiting_restart 只是内容记录。激活还须原预安装已合法提交 staging_completed；仅本地槽完整但服务端结果未知、超时或已失败时不得激活，先完成适用对账，再按新决定重新预安装。staged revision 绑定原事务、scope/channelRevision、Deployment/hop、Package/槽及 stagedAt；期限 min(stagedAt+30d,installNotAfter)，空 end 仅30d。激活新授权/新 transactionId 比较 waiting 修订并原子占用，不能串用预安装凭据或只凭槽存在激活。
- 只有原激活被服务端确认为 cancelled_before_install，helper 证明无受保护写入、旧版和槽完整、原期限/渠道及精确资格仍有效，才能终结旧 activating 修订并原子建立唯一更高 waiting 修订。继承原期限，关联原预安装及取消事务，下一次用户/系统重启重新准备、备份、新授权/事务；未知结果先对账，越界失败不得重启旧槽激活。临时 paused 保留槽恢复后，须在线重新检查仍精确选择同一 hop、原渠道/期限及身份均有效才恢复提示，否则清理；到期/撤销/改选/渠道变化不复活失效槽。槽位创建、替换、激活、新修订登记及清理共用范围互斥，预安装终态释放占用不允许并发写槽或解冻他人。永久停用后的期限清理由唯一对账所有者执行。
- helper 清理授权最多两分钟，精确绑定删除前事实/集合/后事实；行动前再次核对本地所有权及引用，不删除准备、执行、对账或槽位保护仍需的 helper，不能用旧清理授权越过后来接管。helper 自更新不提供应用降级、恢复包或自动回滚。

### 11.2 期限、预算与故障例外

备份首字节前受保护登记 staging/解密密钥引用、准备及冻结代次、sessionExpiresAt 和 initialCleanupAt=sessionExpiresAt+24h；部分写入、backup_failed 与创建中崩溃清理孤立记录。已备份未消费的合法终态确认无受保护写入后留24h；consume_pending 未知（包括本地已停用）仍按 authorizationExp+61d，不假定未消费改短期。确认 consumed 原子固定 transactionStartedAt+60d 硬上限，合法终态取 min(硬上限,terminalAt+7d/1d/30d)。活动期普通用户不能删除，终态管理员提前删除明确不可恢复确认及审计；平台副本不上传，用户导出独立路径和审计，不延长期限。

正常可信期限能力须跨休眠/重启/关机、永久离线且不受普通日期修改影响，运行中≤10min扫描，关机跨期限在下次启动且联网前清理。原本不具备能力的 targetKey 不得认证。时间未知不提前进入新强制门、不解除已有门、不激活 staged 或接受过期授权；已越界事务继续安全核对，不能恢复旧版。

仅确认计时组件损坏时持久化 retention_time_fault，保持既有加密备份及解密密钥引用/访问控制，三语告知可能超过原期限和组件修复/管理员确认删除入口，禁止新增依赖该能力的备份及升级动作，staged 禁止激活并隐藏提示。recovery secret 及可恢复副本立即清除，保留无秘密对账证明走 §9.6；备份保留例外不保护查询 secret，不延长服务端+61d/+62d。能力恢复按原期限首轮、最迟10min清理过期记录，不重建旧 secret；永久故障直到管理员明确删除，不宣称硬上限仍成立。普通离线、回拨或延期重启不触发例外，故障及处置审计不泄露备份内容。

准备/冻结/备份及执行均使用经认证非零有限预算；准备不跨当前有效会话期限，下载无总时长硬限，校验≤30min、各预安装/安装/激活≤2h，健康单次≤120s、最多重启新版本重试一次且含启动总计≤5min。重试/换源/用户切换/崩溃/重启不刷新，权限确认在冻结前。耗尽或无法证明预算时显示稳定原因/可执行入口；边界前仅安全停止后可取消/解冻，越界超时保持不可改写失败及修复门，仍运行安装器/迁移保有安全接管和冻结，不强杀系统包管理器、不并发前向修复，晚到成功不改失败。

### 11.3 本地成功与修复保护

成功须活动版本/平台/入口与授权精确一致、全部受影响数据迁移和一致性通过、进程及界面/本地就绪入口正常、配置/存储可打开、必要本地组件初始化，无循环/致命错误。健康检查不发付费外部请求、不上传或修改业务内容；模型/业务服务/登录/外网不可用不单独算本地失败。仅进程存在、版本相等或非活动槽可启动不证明成功。

无法确认越界安装/激活成功、受保护事实回退/被替换或数据一致性失效时保持同范围修复保护，不启动旧版；预安装不完整仅隔离槽。前向修复独立关联原失败与 scope，目标严格高于本机已安装/受保护写入最高目标，forced 还高于原终点，全部身份/数据/健康 succeeded 才解关联门，不改原失败。服务端缺报/报告超时不重新封锁已本地验证成功或已安全永久停用的健康旧版，但后者未对账仍不可再次升级。

## 12. 事件凭据与状态迁移

- 检查使用遥测凭据，三用途消费后各用独立事务凭据，独立对账/质量复核任务另用专用凭据；type/audience/purpose 不串用。绑定 scope/installId、decision/session/transaction/task ID、允许状态、目标及发生/上传期限。
- 服务端校验合法状态与顺序，拒绝跨事务、阶段倒退、跳关键状态和终态改写；请求/授权成功失败等服务端状态不可由客户端事件伪造。已消费渠道例外严格按 §9.3，预安装不属于继续例外。
- 直接安装/激活消费后30d无合法终态收敛为 failed_manual_repair_required(reason=reporting_timeout)；预安装只为 staging_failed，不建应用门；已提交 staging_completed 不等重启/不再报告超时。合法37d补报只诊断原事务，可更新独立质量投影，不改终态或复活槽；会话24h/7d规则同样不复活终结 lineage。
- events 提交前在线复核签名 keyId、purpose 与即时 deny。正常轮换接受窗口内未 deny 旧 key；紧急 deny 后统一 EVENT_KEY_DENIED/401/retryable=false，已提交及未提交重试不可区分，不重复写入/重放成功 ACK，已提交事实不回滚，只受控审计。客户端停旧 lineage 上传并留本地诊断，不补签受影响旧事件；未来执行须新 check，独立任务也不能绕过旧事件 deny。
- 客户端事件只证明合法凭据持有者提交，不证明物理设备、用户身份或绝对真实结果。质量结合服务器资格/授权、平台事实及反滥用；服务器未收到执行结果只为未完成/outcome_unknown，不伪造本地失败。

### 12.1 质量复核凭据与证据不可替代

复核任务及专用短期事件凭据精确绑定窗口、scope、原事务、Deployment/Rollout/原阶段/hop、目标版本/targetKey/签名 Package/制品哈希/激活模式，只报告本次身份/数据/健康，不授予下载/预安装/安装/激活、旧事件补签或旧终态改写权。任务/结果权限校验、去重及审计；记录实际身份不匹配，不能改任务目标为本机更高版本。

只有合法原执行成功、现活动内容精确同目标且窗口内新健康通过，才贡献原候选安装/健康成功；下载/校验成功不能替代安装，新健康不能推定原未知成功。原失败/未知保持原阶段分组与保守上界，更高关联修复仅证明设备恢复，不扩大原候选成功分母。全部已开始流程含失败/未知/已转更高版本须纳入，不能筛成功范围；每scope同窗口同原阶段/组最多一次，不跨阶段/窗口复制证据。

公开遥测只能触发自动质量冻结及告警，永久暂停/撤回/吊销/隔离须有权人员结合服务器授权记录复核，不能由客户端事件直接执行。扩量、解除冻结、completed 在最终提交点核对当前两链、阶段计划、全部冻结原因及质量证据/投影水位；已登记但未投影的执行仍按未完成/未知处理，迟到事件或新原因使陈旧评估失效，不能依异步缓存放行。

冻结锁存和历史评估保留，恢复投放资格不解质量冻结；解除冻结和后续完整观察按需求 §8.2.1 覆盖当前及全部原原因组，比较当前证据/冻结修订防迟到竞态。长下载有合法凭据/序号/helper事实的进度或可确认等待状态只计未完成，无累计时限/24h未知阈值；审批的有限上报/失联间隔只判可观测性，失联/状态无法确认才计未知，不能伪造执行失败或终止续传。指标改善或专用任务成功不能直接解门/扩量/completed；各组样本、时间及质量条件、权限审批全部满足才可按原百分比恢复，改代码/制品只能终止原投放发更高版本。

## 13. 密钥生命周期

密钥至少按用途隔离：

- 客户端信任根及其轮换授权。
- Manifest/发布元数据签名。
- 在线决定、三用途授权、独立对账/质量复核任务及各自事件凭据签名；同一密钥体系也必须区分签名角色、purpose/type/audience与作用域，禁止签名跨用途解释。
- SN 灰度摘要和请求幂等摘要。
- 服务端敏感恢复数据加密，以及本地备份解密密钥；消费查询 recovery secret 独立管理，不冒充备份解密密钥。

安全要求：

- 私钥保存在受控 KMS/HSM 或等价服务中，不进入代码、配置文件、日志和构建产物。
- 生产签名和高风险密钥操作要求审批、最小权限和审计。管理接口按操作者实际身份、角色及产品/渠道/目标范围做服务端授权，不能信任 UI 隐藏入口或请求自报权限；高风险操作要求 MFA。Stable 发布、撤回、安全恢复及关键策略变更须双人审核，审批绑定命令及对象修订/内容，变更后重新审批，不能由同一身份自批或将另一渠道/旧修订的审批重放。
- 新验证公钥必须先传播到客户端可验证的信任链，再启用新私钥签发。
- 正常轮换后的旧公钥保留到所有已签发凭据和恢复窗口结束。
- 怀疑泄露时立即停止签发、吊销受影响密钥、撤回相关发布并要求客户端重新检查。
- 密钥删除不得破坏仍在有效期或恢复窗口内的合法结果验证。

具体密钥数量、阈值和存储拓扑由安全设计评审确定，不在产品需求主文档中固定。

## 14. 错误与失败关闭

签名/引用/高水位、大小/哈希/平台身份、授权用途/绑定/时限、两链正向资格、实际来源/scope/updater事实或必要权限/冻结/备份不符时，拒绝产生新的受保护执行权。已取得决定、已下载、已消费或原类型 forced 均不豁免边界前最终复核。

失败关闭按用途和 executionCommitBoundary 执行 §9.3，不要求远程强杀已越界安装器或误启旧版；未越界仅确认安全停止后取消，消费未知走 §9.6。已越界或无法证明数据安全则保持保护并安全收敛；预安装的非活动槽失败不能被误报为应用失败。不能以无反馈/超时/服务器故障伪造成功、取消或失败事实，不能因原 endpoint 失效解除独立修复门。

错误使用稳定机器码和简中/英文/日文资源；secret/凭据/内部请求/候选名单/本地路径不进入响应。错误不得返回任意支持 URL；固定 supportGuideCode 由应用映射到发布内官方 HTTPS/本地帮助。consume-status 以及 deny 后 events 保持各自无信息规则，限流和审计不产生新的存在性旁路。

### 15.1 网络来源最小化

为限制公开遥测接口的伪造和单一代理簇对质量指标的影响，接入网关可以处理连接源 IP，但必须遵守：

- 在边缘即时派生 ASN 和截断前缀（IPv4 最长 `/24`、IPv6 最长 `/48`）。KMS 主密钥按 `purpose=quality-prefix + ISO UTC week` 派生周 key，计算 `prefixHmac=HMAC(weekKey, normalizedPrefix)`；同一周内稳定、跨周不可关联。业务数据库只保存 weekId、HMAC 和 ASN 分类，不得保存原始 IP、明文截断前缀或周 key。
- 原始 IP 和明文截断前缀只允许在边缘内存中完成派生；原始 IP 可以进入独立受限的安全访问日志且最长保留 7 天，明文截断前缀不得落盘。用途隔离的前缀 HMAC/ASN 记录最长保留 30 天，到期删除或不可逆聚合。
- 只有携带合法服务端事件凭据并通过 lineage 校验的质量事件才可贡献样本；每个 installationScopeId 在一个 `UTC自然周+完整固定聚合单元` 内最多贡献 1。对同一 `weekId+完整单元+prefixHmac+UTC日`，最多选取按规范事件时间、eventId 升序最早的 1 个不同 installationScopeId 计入 k；其余只用于滥用检测，不增加匿名集。该规则在贡献发生时应用，不看 scope 的创建日或历史年龄，因此预养 scope 不豁免；单一前缀每周最多贡献 7。
- 普通运营 V1 的网络来源分析面查询族只包含版本化、非重叠 UTC 周物化立方体的完整叶子单元，维度严格为 `(platform family,targetKey,major.minor version,channel,ASN class)`。接口不提供或导出总计、边际、部分维度汇总、逐前缀、任意/相邻时间窗、交互下钻和临时过滤；未知查询形状固定拒绝。应用贡献上限后，叶子单元合格贡献者 `k>=20` 才返回值，`k<20` 只返回 suppressed，不返回近似值或上下界。同一周快照冻结后不因迟到数据重写。由于公开查询族不存在重叠合计，不再依赖不确定的互补抑制选择。
- 原始受限安全日志、前缀/ASN摘要及逐实例明细仅安全/受控故障角色访问并审计；普通运营只访问上述已抑制完整叶子，导出逐字复制可见值，不生成合计或补算隐藏单元。两个统计面的权限/查询族不混用，不公开跨周可关联范围标识。
- 网络簇只用于限流、反滥用、质量去重和单簇贡献上限，不得用于广告画像、用户身份推断、许可准入或差异化更新资格。
- 隐私说明必须披露处理目的、数据形式和保留期。

### 15.2 发布质量统计与权限隔离

普通运营发布质量面仅提供固定不重叠 UTC自然周完整叶子 (platform family,targetKey,channel,sourceVersion,targetVersion,upgradeType,fileSourceClass)。每scope每周只归首个合法升级流程，源切换统一 multi_source；去重和反滥用合格后计入，周结束七天后唯一冻结快照，k≥20可见，其余只样本不足不返回人数/近似/上下界。界面和导出只复制同一可见叶子，不给总计/边际/部分维度/任意或相邻窗/过滤/合并/下钻/关联键，迟到结果不重写。

即时阶段质量、逐实例记录及复核证据仅内部自动化/受控故障和审计角色，最小权限与完整审计；普通运营只发布状态、冻结恢复原因和受抑制周报。网络来源面是另一查询族，不含入发布周报，不联查/共享关联键/相互补算；受控诊断和导出也不能成为普通运营旁路。

- 修改任一 Manifest、引用、大小、哈希或 packageId，签名跨角色/产品/组件/作用域解释、阈值不足、未知关键字段或算法降级均拒绝；规范化歧义和候选 opening 错绑不能验证成功。
