# 普通会话原生图片输入 — 改动说明

> 日期：2026-08-11（v0.9.5 方案切换后重写；fork #3 方案历史见文末）
> 分支：`feat/native-image-input`
> 状态：已合并 `main` + `upgrade/codewhale-v0.9.5`，图片功能适配 CodeWhale v0.9.5 官方 API，验证通过，未推送

## 1. 一句话概括

普通会话的图片附件从"一律转文字描述（image_analyze 工具调用）"改为"按当前模型的真实图片能力三态路由"：支持图片的模型直接在同一请求里看原图；不支持的用配置的视觉模型兜底；都不可用时发送前明确拒绝。实现从 fork #3 的 LocalImage 结构化块方案切换为 **CodeWhale v0.9.5 官方标记方案**。

## 2. 方案（v0.9.5 官方标记）

底座 `image_attach.rs` 提供官方图片输入链路，父仓只负责生成标记：

1. 父仓把图片附件暂存到引擎执行根（复用既有 staging 校验链：basename 白名单 / symlink 防逃逸 / create_new 防覆盖），在消息文本中生成 `[Attached image: <绝对路径>]` 标记行（按用户选择顺序）。
2. 底座 `image_attach::expand_attachment_blocks` 在消息构建时解析标记行：读文件（magic bytes 识别、5 MiB/图预算），展开为 `ContentBlock::ImageUrl`（data URL）+ `<image path>` 标签块；失败附件转为 `<attachment_notice>` 文本块，不丢弃整条消息。
3. 底座 `image_attach::strip_images_when_unsupported` 在每次出站请求前按 route 能力决定是否剥离图片（历史保留图片，能力是 route 属性、随 /model 切换变化）。

**能力判定**（父仓 `image_capability.rs`）：用户显式覆盖（Enabled/Disabled）→ 内置已验证表 → Unknown。v0.9.5 起底座 `model_catalog` 不再公开，目录级 modalities 查询移除；目录级判定由底座请求前剥离承担，父仓不再重复。

| `src/features/assistant/engine.rs` | 删除 `input` 参数链；sanitize 不再保留 LocalImage 块（display 文本含标记行，图片归引擎历史管理） |
| `src/features/assistant/engine_pool.rs` | `send_reserved_user_message` 删除 `input` 参数 |

## 6. 已知风险与遗留

- **能力判定降级**：无目录级查询后 Unknown 概率上升，靠用户显式覆盖 + 底座请求前剥离兜底
- **定时会话**仍走 image_analyze 工具兜底（官方标记只接普通会话 Native 路径）
- **评审缺口**（详见记忆）：视觉模型不校验自身图片能力、测试按钮口径（2xx≠真看到图）、ACP 模型同步、EditLastTurn 重发丢图语义复核、MegaCube 真机回归
- **v0.9.5 升级未进 main**：本分支是首个 v0.9.5 适配载体；PR base 指向 `upgrade/codewhale-v0.9.5`，待其合入 main 后自动跟随
