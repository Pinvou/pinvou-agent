## 1. 一句话概括

普通会话的图片附件从"一律转文字描述（image_analyze 工具调用）"改为"按当前模型的真实图片能力三态路由"：支持图片的模型直接在同一请求里看原图；不支持的用配置的视觉模型兜底；都不可用时发送前明确拒绝。

## 3. CodeWhale 底座改动（fork 提交 4671b579b，+1368/-109，26 文件）

### 3.1 结构化用户输入
- `core/ops.rs`：`Op::SendMessage` 新增 `input: Option<UserMessageInput>`；`UserInputBlock::{Text, LocalImage{relative_path, mime_type, display_name}}`。纯文本调用全部传 `None`，行为零变化。
- `models.rs`：`ContentBlock::LocalImage` 持久化只存 workspace 相对路径 + MIME + 展示名 + 字节数，**绝不存 Base64**。

### 3.2 请求前物化（核心安全约束）
- 新增 `vision/image_input.rs` 共享工具：workspace 相对路径校验（拒绝对路径/`..`/symlink 逃逸）、20MB 统一上限（`MAX_IMAGE_BYTES`）、PNG/JPEG/GIF/WebP/BMP 魔数嗅探（不信扩展名）。
- 物化汇聚点 = `core/engine/turn_loop.rs` 构建 `MessageRequest` 前：对消息克隆把 `LocalImage` 物化为 `data:` URL。物化产物只存在于单次请求的私有克隆，进不了 session/持久化/Op mailbox。
- 重试/恢复从相对路径重新读文件；原图丢失明确中文报错，不静默丢图、不自动降级纯文本。

### 3.3 Provider 序列化
- OpenAI Chat：`image_url` data URL（已有，补契约测试）。
- Responses API：`input_image`（已有，补契约测试）。
- Anthropic：**新转换**——`data:` URL 拆为原生 `source:{type:"base64",media_type,data}`，不再当远程 URL 发送。

### 3.4 Base64 泄漏面收口
- `mouse_ui.rs` 图片块渲染 `[image:<mime>,<n> bytes]` 占位。
- `runtime_api/sessions.rs` 图片块返回 metadata 而非 Null。
- `context_report.rs` 图片固定估算 1000 token，不物化 URL。
- compaction/purge/seam/RLM/subagent fork 路径跳过图片块（摘要不需要图片）。

### 3.5 image_analyze 加固
- 20MB 大小上限（新增）；MIME 改真实文件头嗅探；工具描述更新为"仅用于未随当前消息原生提供的图片，已随当前消息提供的图片不需要重复调用"；路径安全与错误脱敏保持原有强度。
- **请求不再携带 `temperature`**（已并入 `4671b579b`）：kimi-for-coding、gpt-5 系推理模型等只接受默认值，显式 `temperature: 0.7` 会被 400 拒绝（"only 1 is allowed"）；省略后 provider 应用默认值，对所有模型合法。以 `forkguard_vision_payload_omits_temperature` 锚定。

  影响面评估：
  - 唯一行为变化：image_analyze 请求由固定 0.7 改为 provider 默认值（OpenAI 兼容端点通常为 1.0），回答随机性略增，对图片描述/分析任务不影响可用性；原 0.7 为无出处经验值而非契约。
  - 不受影响：Native 主通道（主模型请求链路 temperature 处理未动）、纯文本会话、请求其他字段（model/messages/max_tokens/超时/重试）、API 契约（temperature 在 OpenAI 规范中为可选字段）。
  - 受益：kimi-for-coding 及同类限制性模型从必然 400 变为可用。
  - 后续如需低温：应查模型目录 `supported_parameters` 按模型下发（当前目录无一条声明 temperature，故现状等价全量省略），不得改回硬编码。

## 4. pinvou3-app 改动

### 4.1 模型能力判断（阶段 C）
- `SavedModel` 新增 `image_capability_override`（auto/enabled/disabled，serde 默认 auto，旧配置无感迁移）和 `vision_model_id`（引用另一条 SavedModel）。
- 新模块 `features/assistant/image_capability.rs`：
  - `EffectiveImageCapability` 解析优先级：用户 override → **底座模型目录 `modalities` 含 `image`**（`87e79d3a` 落地：`deepseek_tui::model_catalog`，合并链 用户覆盖→provider 缓存→内置快照；目录否定不否决，防 kimi-k2.7-code/claude-opus-4-8 这类不准的 text-only 标记误杀）→ 内置已验证能力表 → Unknown。
  - 内置表保守匹配已知多模态模型（gpt-4o/gpt-4.1/gpt-5、claude-3/4、gemini、qwen-vl 系、glm-4v、kimi-for-coding（用户实测））；其余文本模型与本地未知模型一律 Unknown——宁可未知不误判。
  - 发送前拒绝按能力细分文案：确认不支持 → 提示切换模型/配置视觉模型；能力未知 → 额外提示可在模型设置中显式开启图片输入能力（override 出口）。
  - `ImageInputMode::{Native, VisionToolFallback, Unsupported}` 按方案 §6.3 路由表。

### 4.2 视觉模型配置（阶段 E）
- 删除"无条件复用主模型为视觉模型"旧逻辑。新规则：显式 `vision_model_id` 优先（凭据走系统凭据库，不存第二份明文）；主模型确认支持图片时可复用自身做 workspace 图片分析；否则**不注册** `image_analyze`。

### 4.3 普通会话接线（阶段 D）
- `attachments.rs` 新增 `PreparedUserMessage{display_text, input_blocks, attachments, image_mode}`；非图片附件行为逐字节不变。
- 三路径：
  - **Native**：文字 + 图片同一条用户消息直发主模型，不注入"看不到图"提示，支持纯图片与多图保序；
  - **VisionToolFallback**：保留 image_analyze 兜底链路；
  - **Unsupported**：发送前拒绝，稳定错误码 `image_input_unsupported`，不创建 Engine turn，前端展示中文指引。
- 恢复/重试：`sanitize_messages` 保留 LocalImage 引用块；桌面 chat 与远控 web_access_chat 共用同一路由缝；scheduled 会话维持现状。

### 4.4 ACP 对齐（阶段 F）
- 双层 gating：adapter `PromptCapabilities.image` **且** 当前具体模型能力为 Supported 才放行图片。
- 模型解析：ACP wire model 名映射同名 SavedModel（承接用户 override），否则查内置表，判不出为 Unknown；Unknown 拒绝并提示可在设置中显式确认。
- timeline 收口：过滤 agent 回显的二进制块，图片只存 metadata 不落 Base64；不引入 image_analyze，保持 ACP 原生 Image 块传输。

### 4.5 云端隐私提示（§11.8/§11.9，`da146e8e` + `f7f1b98a`）
- `get_image_input_capability` 返回新增 `is_local_endpoint` / `vision_is_local_endpoint`（未配置视觉模型为 null），与凭据判定复用 `base_url_uses_loopback` 同一口径（loopback / local_vllm preset）。
- Native 云端路由：附件区提示"图片将随消息发送给你选择的模型服务商"；VisionToolFallback 且视觉模型为云端：提示"图片将发送给你配置的视觉模型服务商进行分析"（此前只看主模型端点，云端视觉兜底会漏提示）。
- 本地 loopback（含本地视觉模型）不出任何"云上传"字样；能力查询失败 fail-open，不误报。
- 设置页图片输入区加静态隐私说明；i18n 三语；ui_smoke / settings_ui_smoke 补对应用例。
