# 本地多模态引擎-改动说明

> 一期实现视觉（图像描述）；音频（ASR/Omni）经 modality 抽象预留，后续在同一引擎管理框架内扩展。

## 背景

纯文本对话模型无法直接读图（图片在会话中标记为 `model_no_vision`）。项目底座 CodeWhale 已有预留接口：`image_analyze` 工具（`vision/tools.rs`）会把图片 base64 内联发给任意 OpenAI 兼容端点，应用在构建 EngineConfig 时恒开 `VisionModel` feature 并设置 `vision_config`（base_url 跟随主模型端点）。本功能补上缺失的一环——**本地视觉引擎**：下载 llama.cpp + Qwen3-VL GGUF 模型并在本机运行，让 `image_analyze` 指向本地端点。

## 功能

设置页「本地多模态引擎」区块（`t.uiSettings.localEngine`）：

- **一键下载引擎**：llama.cpp 预编译二进制（Windows win-vulkan / Linux ubuntu-vulkan / macOS metal），tag 动态解析 GitHub latest（env `PINVOU3_LLAMA_ENGINE_TAG` 可指定），下载 ~40MB 到 `~/.pinvou3/llama-engine/bin/`
- **一键下载模型**：Qwen3-VL-2B Q3_K_S（0.83GB，推荐，更小档位）或 Q4_K_M（1.06GB，质量优先），视觉投影器 mmproj 一并下载；源按 ModelScope → HuggingFace → hf-mirror 顺序回退（中国大陆网络 ModelScope 最快）；sha256 + 尺寸校验（env `PINVOU3_LLAMA_MODEL_URL`/`PINVOU3_LLAMA_MODEL_SHA256` 覆盖）
- **启动/停止**：spawn llama-server（127.0.0.1 随机空闲端口，仅本机监听），GPU（Vulkan/Metal，`-ngl 99`）/ CPU（`-ngl 0`）切换；`/health` 就绪探测、stderr 尾行诊断、进程树整树终结、崩溃自动重启（60s 窗口内限 2 次）
- **接线**：引擎运行中时，`image_analyze` 的 base_url 条件覆盖为 `http://127.0.0.1:{port}/v1`；停止后恢复主模型端点原行为。EngineConfig 在会话 spawn 时快照，引擎启停后**下次会话生效**

## 架构

```
设置页「本地多模态引擎」区块
  → invoke llama_engine_*（app/commands/llama_engine.rs 薄壳透传）
  → features/llama_engine/{mod.rs, download.rs, server.rs, platform/}
  → bridge.rs vision_config.base_url = vision_endpoint().unwrap_or(base_url())
  → 底座 image_analyze → POST http://127.0.0.1:{port}/v1/chat/completions
```

- 模块：`download.rs`（引擎/模型下载、解压、校验、多源回退）、`server.rs`（子进程生命周期）、`platform/`（按 OS 适配：资产名/压缩包布局/二进制名/GPU 默认值）
- 目录：`~/.pinvou3/llama-engine/{bin,models,tmp}/`，引擎版本记入 `bin/engine-meta.json`
- 事件：`llama-engine:progress`（下载进度）、`llama-engine:state`（starting/running/stopped，含崩溃自愈）
- 安全：全部 https 下载源；服务只监听 127.0.0.1；不上传任何数据；llama.cpp（MIT）+ Qwen3-VL（Apache-2.0）

## 已知边界

- 引擎二进制仅来自官方 GitHub Releases（无镜像）；网络受限时下载较慢，失败整文件重下（无断点续传）
- Linux/macOS 未真机验证：平台布局逻辑由契约测试（`tests/llama_engine_contract.test.js`）与平台单测锁定
- app 被硬杀时可能遗留 llama-server 进程（正常退出由 kill_on_drop 保证清理）；随机端口 + 仅本机监听，危害面为零
- 会话中途启停引擎不影响当前会话（EngineConfig 快照语义），下次会话生效

## 图片输入整合（feat/native-image-input 集成）

项目已集成原生图片输入（`[Attached image]` 标记 → 底座展开为 `ContentBlock::ImageUrl`，
按主模型能力请求前剥离）。本地引擎通过 **`resolve_vision_model_config` 最高优先级规则**接入：

- **引擎运行中** → `image_analyze` 自动用本地端点（无需配置视觉模型）；
- 纯文本主模型的图片输入由此获得 `VisionToolFallback` 路由：直贴图片 → 本地引擎描述
  → 纯文本模型"看到"图片；`vision_is_local_endpoint=true` 隐私提示联动；
- **引擎停止** → 自动回落既有规则（`vision_model_id` 配置 / Supported 主模型复用 / 拒绝）。

验证：引擎停止时 `image_mode=unsupported`；引擎运行中 `image_mode=vision_tool_fallback`、
`has_vision_model=true`、`vision_is_local_endpoint=true`（真实运行确认）。

## PR3 引擎调优全套（2026-08-13）

- **三档模型表**：`qwen3vl-2b-iq2m`（极致低配，bartowski 主权重 + 官方 mmproj 跨仓混用，
  同源 bf16 转换，上线前需冒烟）/ `qwen3vl-2b-q4km`（**新装默认档**）/ `qwen3vl-4b-q4km`
  （独显档）；mmproj 全部由 F16 换 Q8_0（2B 档 819MB→445MB）。旧 `qwen3vl-2b-q3k-s`
  保留为 legacy（已下载的老安装继续可用，不强制迁移）。
- **启动参数**：`-t` 物理核数（`platform/os::physical_core_count`，Windows
  GetLogicalProcessorInformation / macOS sysctl / Linux /sys 拓扑，失败回落逻辑核数）、
  `--batch-size/--ubatch-size 1024`（1024 视觉 token 不切两批）、`--flash-attn`、
  KV cache `--cache-type-k/v q8_0`、`--mlock`；`--image-max-tokens 1024` 保持。
- **设备自动选择**：prefs `llama_engine_default_device` 缺省 auto（显式 cpu/gpu 优先）；
  检测原语 `platform/os::gpu_class`（Windows DXGI 枚举：专用显存 ≥5.6GB → 独显，
  Radeon 680M/780M/880M/890M、Iris Xe、Arc Graphics 白名单 → 强核显，均以
  vulkan-1.dll 存在为前提，枚举失败 → CPU；macOS 恒 GPU，Linux 首版恒 CPU）。
  强核显的微基准终裁（`-ngl 0` vs `-ngl 99` 小图探测）首版未实现，先按白名单定档（TODO）。
  引擎状态新增 `detectedDevice`/`recommendedModel`，设置页据此给档位打「推荐」标。
- **warmup**：引擎进入 Running 后后台发一次内置 64×64 小图请求（max_tokens 16），
  消除首请求冷启动；失败静默。
- **发送前预缩放**：粘贴/拖放链路超长边图片 canvas 压到 1500px JPEG q0.9 再入附件
  （`src/features/attachments/image-prescale.js`），并提示「图片较大已压缩，识别可能较慢」；
  无 canvas 环境原样回落。原生文件选择器链路只拿到路径、JS 侧无字节，未做预缩放。
- **可靠性修复**：发送门等待 60s → 跟随引擎 `HEALTH_TIMEOUT`(120s)；引擎运行态翻转
  （就绪/停止）经注入钩子 bump 全部 saved_models revision，覆盖 launch 自启、手动停止、
  崩溃自愈三条路径（自愈优先复用旧端口）；spawn 期间点停止在 Healthy 分支消费
  STOP_REQUESTED 并终结进程；Native 能力 Supported 的模型跳过引擎启动，已配置云端
  视觉模型时引擎启动失败回落而非硬失败。
- **基准脚本**：`scripts/llama-engine-bench.ps1` 对 CPU/GPU × 默认/调优参数组分别起
  llama-server，打印加载/首 token/总耗时三段，供真机验证默认值决策。
