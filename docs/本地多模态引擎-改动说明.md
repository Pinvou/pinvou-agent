# 本地多模态引擎-改动说明

> 一期实现视觉（图像描述）；音频（ASR/Omni）经 modality 抽象预留，后续在同一引擎管理框架内扩展。

## 背景

纯文本对话模型无法直接读图（图片在会话中标记为 `model_no_vision`）。项目底座 CodeWhale 已有预留接口：`image_analyze` 工具（`vision/tools.rs`）会把图片 base64 内联发给任意 OpenAI 兼容端点，应用在构建 EngineConfig 时恒开 `VisionModel` feature 并设置 `vision_config`（base_url 跟随主模型端点）。本功能补上缺失的一环——**本地视觉引擎**：下载 llama.cpp + Qwen3-VL GGUF 模型并在本机运行，让 `image_analyze` 指向本地端点。

## 功能

设置页「本地多模态引擎」区块（`t.uiSettings.localEngine`）：

- **一键下载引擎**：llama.cpp 预编译二进制（Windows win-vulkan / Linux ubuntu-vulkan / macOS arm64|x64），默认锁定钉版 tag（当前 b10299，env `PINVOU3_LLAMA_ENGINE_TAG` 显式覆盖，`latest` 为显式 opt-in），钉版资产带 size+sha256 强制校验、失败即拒装；下载 ~40MB 到 `~/.pinvou3/llama-engine/bin/`
- **一键下载模型**：Qwen3-VL-2B Q4_K_M（1.06GB，默认推荐）或 4B Q4_K_M（2.4GB，独显推荐），视觉投影器 mmproj 一并下载；源按 ModelScope → HuggingFace → hf-mirror 顺序回退（中国大陆网络 ModelScope 最快，镜像内容完整性由 sha256 钉死）；内置钉版 sha256 + 尺寸强制校验（开发可用 per-asset env `PINVOU3_LLAMA_GGUF_SHA256`/`PINVOU3_LLAMA_MMPROJ_SHA256` 覆盖，旧 `PINVOU3_LLAMA_MODEL_SHA256` 保留为兜底）；下载前检查磁盘可用空间（约 1.2× 余量）
- **启动/停止**：spawn llama-server（127.0.0.1 随机空闲端口，仅本机监听），GPU（Vulkan/Metal，`-ngl 99`）/ CPU（`-ngl 0`）切换；`/health` 就绪探测、stderr 尾行诊断、进程树整树终结、崩溃自动重启（60s 窗口内限 2 次，累计上限 5 次，超限落 Stopped）
- **接线**：引擎运行中时，`image_analyze` 的 base_url 条件覆盖为 `http://127.0.0.1:{port}/v1`；停止后恢复主模型端点原行为。EngineConfig 在会话 spawn 时快照，引擎启停后**下次会话生效**

## 架构

```
设置页「本地多模态引擎」区块
  → invoke llama_engine_*（app/commands/llama_engine.rs 薄壳透传）
  → features/llama_engine/{mod.rs, download.rs, server.rs, platform/}
  → bridge.rs vision_config.base_url = vision_endpoint().unwrap_or(base_url())
  → 底座 image_analyze → POST http://127.0.0.1:{port}/v1/chat/completions
```

- 模块：`download.rs`（引擎/模型下载、解压、校验、多源回退）、`server.rs`（子进程生命周期）、`platform/`（按 OS 适配：资产名/压缩包布局/二进制名/GPU 默认值）
- 目录：`~/.pinvou3/llama-engine/{bin,models,tmp}/`，引擎版本记入 `bin/engine-meta.json`
- 事件：`llama-engine:progress`（下载进度）、`llama-engine:state`（starting/running/stopped，含崩溃自愈）
- 安全：全部 https 下载源；服务只监听 127.0.0.1；不上传任何数据；llama.cpp（MIT）+ Qwen3-VL（Apache-2.0）

## 已知边界

- 引擎二进制仅来自官方 GitHub Releases（无镜像）；网络受限时下载较慢，失败整文件重下（无断点续传）
- Linux/macOS 未真机验证：平台布局逻辑由契约测试（`tests/llama_engine_contract.test.js`）与平台单测锁定
- app 被硬杀时可能遗留 llama-server 进程（正常退出由 kill_on_drop 保证清理）；随机端口 + 仅本机监听，危害面为零
- 会话中途启停引擎不影响当前会话（EngineConfig 快照语义），下次会话生效

## 图片输入整合（feat/native-image-input 集成）

项目已集成原生图片输入（`[Attached image]` 标记 → 底座展开为 `ContentBlock::ImageUrl`，
按主模型能力请求前剥离）。本地引擎通过 `resolve_vision_model_config` 接入，优先级：

0. 模型显式选择「本地识图引擎」（`vision_prefer_local_engine`）且引擎运行中 → 本地端点
   （视为该模型的显式视觉模型配置）；
1. 配置了 `vision_model_id` → 用户配置的视觉模型；
2. 主模型能力确认 Supported → 复用主模型；
3. **本地兜底**：全局兜底开关开启（默认开）且引擎运行中 → 本地端点。
   只有未配置视觉模型的纯文本模型会到达规则 3——本地引擎不覆盖显式配置；
   纯文本主模型的图片输入由此获得 `VisionToolFallback` 路由：直贴图片 → 本地引擎描述
   → 纯文本模型"看到"图片；`vision_is_local_endpoint=true` 隐私提示联动；
4. 引擎停止 → 自动回落既有规则（`vision_model_id` 配置 / Supported 主模型复用 / 拒绝）。

验证：引擎停止时 `imageMode=unsupported`；引擎运行中 `imageMode=vision_tool_fallback`、
`hasVisionModel=true`、`visionIsLocalEndpoint=true`（真实运行确认；`ImageInputCapabilityInfo`
自 2026-08-26 起统一 camelCase 序列化）。

### 视觉兜底默认值与存量用户影响

- **默认值 on**：全局兜底开关 `prefs.advanced.llama_engine_vision_fallback` 默认开启
  （`bridge.rs` 中 `unwrap_or(true)`），无需用户操作即生效。
- **生效前提**：仅当本地引擎**运行中**才接管；引擎停止或未安装时，解析自动回落既有
  规则（显式视觉模型 / Supported 主模型复用 / 拒绝），与此前行为完全一致。
- **对纯文本模型用户的影响**：未显式配置视觉模型的纯文本模型，升级后收到图片会改走
  「本地引擎描述 → 纯文本模型」的兜底路由（此前为标记 `model_no_vision` 拒绝）。图片
  字节不离开本机，但首次触发可能伴随引擎自动启动与模型加载等待；已显式配置视觉模型
  或选择「本地识图引擎」的模型不受影响，不被接管。
- **关闭路径**：设置页 → 模型 → 本地识图 → 「行为」区块的「自动作为图片识别兜底」
  开关，关闭后恢复旧行为（开关持久化在 prefs.advanced）。

## PR3 引擎调优全套（2026-08-13）

- **模型表（2026-08-20 起两档）**：`qwen3vl-2b-q4km`（**新装默认档**）/
  `qwen3vl-4b-q4km`（独显档）；mmproj 全部由 F16 换 Q8_0（2B 档 819MB→445MB）。
  IQ2_M 极致低配档与 Q3_K_S legacy 档因量化过低识图质量不可用已下线，
  老安装残留文件不受影响（原三档模型表与跨仓混用方案见 git 历史）。
- **启动参数**：`-t` 物理核数（`platform/os::physical_core_count`，Windows
  GetLogicalProcessorInformation / macOS sysctl / Linux /sys 拓扑，失败回落逻辑核数）、
  `--batch-size/--ubatch-size 1024`（1024 视觉 token 不切两批）、
  `--flash-attn on`（b10362 起必须带值）、KV cache `--cache-type-k/v q8_0`；
  `--image-max-tokens 1024` 保持。**不传 `--mlock`**：b10362 起
  `--mlock`（含 `--load-mode mlock`）与 `-ngl 0` 纯 CPU 加载组合在模型
  mmap 阶段触发 `GGML_ASSERT(addr)` 崩溃（真机二分定位，引擎侧回归）。
- **mmproj GPU 卸载按设备条件化**：llama.cpp 默认把视觉编码器卸载到 GPU
  （`--mmproj-offload` enabled，与 `-ngl` 解耦，这就是 CPU 模式启动时
  仍有一段 GPU 负载的原因）。但弱核显实测 CPU 编码反而更快（UHD 750
  Vulkan 1027 token 46.5s vs CPU 33.8s，快约 27%，两轮一致），故 CPU 档
  传 `--no-mmproj-offload`，独显档保持默认卸载。
- **设备自动选择**：prefs `llama_engine_default_device` 缺省 auto（显式 cpu/gpu 优先）；
  检测原语 `platform/os::gpu_class`（Windows DXGI 枚举：专用显存 ≥5.6GB → 独显，
  Radeon 680M/780M/880M/890M、Iris Xe、Arc Graphics 白名单 → 强核显，均以
  vulkan-1.dll 存在为前提，枚举失败 → CPU；macOS 按架构区分：arm64（Metal）恒 GPU，
  Intel（x86_64）按核显档归 CPU；Linux 首版恒 CPU）。
  强核显的微基准终裁（`-ngl 0` vs `-ngl 99` 小图探测）首版未实现，先按白名单定档（TODO）。
  引擎状态新增 `detectedDevice`/`recommendedModel`，设置页据此给档位打「推荐」标。
- **warmup**：引擎进入 Running 后后台发一次内置 64×64 小图请求（max_tokens 16），
  消除首请求冷启动；失败静默。
- **发送前预缩放**：粘贴/拖放链路超长边图片 canvas 压到 1500px JPEG q0.9 再入附件
  （`src/features/attachments/image-prescale.js`），并提示「图片较大已压缩，识别精度可能略降」；
  无 canvas 环境原样回落。原生文件选择器链路只拿到路径、JS 侧无字节，未做预缩放。
- **可靠性修复**：发送门等待对齐引擎 `HEALTH_TIMEOUT`(300s，"门控不得先于引擎放弃")；引擎运行态翻转
  （就绪/停止）经注入钩子 bump 全部 saved_models revision，覆盖 launch 自启、手动停止、
  崩溃自愈三条路径（自愈优先复用旧端口）；spawn 期间点停止在 Healthy 分支消费
  STOP_REQUESTED 并终结进程；Native 能力 Supported 的模型跳过引擎启动，已配置云端
  视觉模型时引擎启动失败回落而非硬失败。
- **口径对齐与取消语义**：`vision_local_gate` 的「已配置视觉模型」判定与 resolve 规则 1
  统一走 `api_key_for_saved_model`——悬空 id 与凭据缺失（如 keychain 条目被删）都按
  未配置处理，兜底引导（自动启动/安装提示）不再静默失效；发送门下载所有权判定抽出为
  纯函数（`src/features/chat/local-engine-gate.mjs`，配套行为测试），在途下载由被顶替
  流程发起时由新流程继承，取消按钮不再因顶替退化为 no-op。
- **基准脚本**：`scripts/llama-engine-bench.ps1` 对 CPU/GPU × 默认/调优参数组分别起
  llama-server，打印加载/首 token/总耗时三段，供真机验证默认值决策。
