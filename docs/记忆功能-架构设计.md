# pinvou 记忆系统设计方案

> 状态：评审稿 v9
> 适用产品：pinvou，本地 AI 通用办公助手
> 设计目标：让 pinvou 在用户允许的前提下，自动整理用户的稳定偏好、工作背景、当前关注和近期动态，并在后续对话中以短摘要形式使用。

---

## 1. 设计目标

pinvou 的记忆系统不是把聊天记录永久塞进模型，也不是让用户手动维护配置文件。它的目标是：

- 减少用户重复说明自己的称呼、偏好、工作背景和近期事项。
- 让不同 session 之间可以自然接上上下文。
- 自动发现有价值的信息，但长期记忆保持克制。
- 让用户随时能查看、编辑、删除、归档或关闭记忆。
- 给模型看的记忆短、准、不过期，不把历史垃圾无限累积进上下文。

记忆系统只记录“以后仍然有用”的信息。当前 session 的聊天细节、工具日志、临时文件、项目目录、模型配置、pinvou 运行环境，都不应该作为用户记忆保存。

---

## 2. 核心原则

### 2.1 用户可控

记忆有总开关。

- 关闭时：不自动整理新记忆，不向模型注入记忆。
- 开启时：系统自动整理和使用记忆。
- 已保存的数据不因关闭开关而删除，用户可以重新开启后继续使用。

### 2.2 LLM 负责理解，系统负责约束

记忆内容的理解、归类、清洗、合并，主要交给 LLM 判断。

系统只负责：

- 什么时候触发记忆复盘。
- 哪类记忆能自动写入，哪类必须确认。
- 敏感信息过滤。
- 去重、合并、过期、归档。
- 数据落盘和 UI 展示。
- 用户选择“忽略”或“不再提示”后的处理。

不要用关键词或正则直接把用户原话截成记忆。关键词可以作为触发信号，但不能作为最终写入内容。

### 2.3 结构化存储，摘要注入

记忆的事实源是结构化数据，不是一份无限增长的 `memory.md`。

每轮对话前，系统从结构化数据生成一段短摘要给模型使用。摘要只是缓存，可以随时重建，不是事实源。

### 2.4 工作背景是用户背景

工作背景记录的是“用户是谁、长期做什么、长期关注什么”，不是 pinvou 当前运行环境。

可以记：

- 用户长期从事的领域。
- 用户长期维护的项目。
- 用户常做的任务类型。
- 用户常用的交付物形式。
- 用户长期偏好的工作方式。

不应该记：

- pinvou 当前用了什么模型。
- 当前 app 的内部路径。
- 某次 session 临时打开了哪个文件。
- 当前调试状态、临时配置、工具日志。

如果用户本身长期开发 pinvou，可以记为“用户长期参与 pinvou 本地 AI 办公助手开发”，但不要把 pinvou 的当前技术栈当作用户背景。

## 3. 记忆分层

### 3.1 长期记忆

长期记忆是未来很多次对话都可能继续有用的信息。默认长期保留，不自动过期。

| 类别 | 记录内容 | 写入策略 | 使用方式 |
|---|---|---|---|
| 用户画像 `profile` | 用户希望如何被称呼、如何称呼助手、默认语言或稳定输出习惯 | 明确、低敏、高置信内容可自动写；其他进入候选确认 | 常驻注入 |
| 长期偏好 `preferences` | 回答风格、工作方式、文档格式、报告结构等 | 默认候选确认 | 常驻或按场景注入 |
| 工作背景 `work_context` | 用户长期角色、领域、项目、任务类型、工具流、交付物期待 | 默认候选确认；极高置信、低敏时可自动更新 | 摘要注入 |

长期记忆误写成本高，所以策略要保守。

### 3.2 近期记忆

近期记忆是最近一段时间有用的信息，会自动过期或被归档。

| 类别 | 记录内容 | 写入策略 | 生命周期 |
|---|---|---|---|
| 当前关注 `current_focus` | 用户最近正在推进、后续还可能继续聊的事项 | 高置信、低敏时可自动写 | 默认约 21 天，可续期 |
| 近期动态 `recent_activity` | 最近刚完成的交付、修复、报告、文档、调研结果 | 明确完成态、高置信、低敏时可自动写 | 默认约 14 天 |

近期记忆不应该频繁打扰用户。只要信息明确、低敏、对后续有用，可以自动整理。

近期动态不能只写“完成了某某某”。它应该包含以后接着聊时有用的线索，例如交付物、结果、主题或关键内容。

### 3.3 短期上下文

短期上下文不属于全局记忆，主要包括：

- 当前 session 的聊天历史。
- 当前 turn 的用户消息和助手回复。
- 当前 turn 的工具调用摘要。
- 未处理的候选记忆。

短期上下文可以用于判断是否生成记忆，但不会直接作为全局记忆长期保存。

### 3.4 兼容层

当前系统仍保留 `recent_work` 兼容数据，用于读取旧的近期工作信息。

产品概念上不把它作为独立分类展示。它应逐步并入：

- 正在推进的事项 → `current_focus`
- 已完成的事项 → `recent_activity`

## 4. 总体架构

```text
用户对话
  ↓
Turn Capture
收集本轮用户消息、助手回复、工具摘要、交付状态
  ↓
Memory Review
由 LLM 判断是否需要新增、更新、合并、跳过或生成候选
  ↓
Memory Gate
做安全、敏感、置信度、类别、去重、用户控制检查
  ↓
Memory Store
结构化保存 profile / preferences / work_context / current_focus / recent_activity / pending / never
  ↓
Runtime Memory
按当前有效记忆生成短摘要
  ↓
模型上下文 + 记忆中心 UI
```

各模块职责：

| 模块 | 职责 |
|---|---|
| Turn Capture | 只收集本轮有用材料，不判断内容意义 |
| Memory Review | 判断内容是否值得记、属于哪类、如何清洗和合并 |
| Memory Gate | 防误写、防敏感、防重复、决定自动写还是候选确认 |
| Memory Store | 保存结构化记忆，是事实源 |
| Runtime Memory | 生成给模型看的短摘要，是派生缓存 |
| Memory Center | 给用户查看、编辑、删除、归档记忆 |

## 5. 写入流程

### 5.1 触发时机

记忆复盘不需要每轮都跑，只在有价值的节点触发。

主要触发：

1. 用户明确表达长期信息
   例如“以后叫我欣哥”“回答先给结论”“默认用中文”。

2. 本轮完成明确交付
   例如生成文档、完成报告、修复问题、整理方案、完成调研。

3. 用户在设置里手动修改
   例如编辑称呼、删除偏好、归档近期事项。

触发只是“进入复盘”，不是直接写入。

### 5.2 复盘判断

复盘时，系统把以下信息交给后台记忆整理：

- 本轮用户消息。
- 本轮助手回复。
- 工具调用摘要，尤其是写文件、改文件、生成产物。
- 已有长期记忆。
- 已有当前关注和近期动态。
- 待确认候选。
- 用户选择过“不再提示”的内容。

LLM 输出的是候选决策，不直接写文件。

### 5.3 写入结果

复盘后可能产生五类结果：

| 结果 | 含义 |
|---|---|
| 跳过 | 没有值得记的信息 |
| 自动写入 | 低敏、高置信、未来有用的信息直接保存 |
| 自动更新 | 和已有记忆同主题，合并成新版本 |
| 候选确认 | 需要用户确认后再写入 |
| 归档 | 已过期或被新信息替代 |

### 5.4 候选确认流程

需要确认的内容以轻量记忆候选卡展示：

```text
记忆候选
我可以记住这条偏好
“回答默认先给结论，整体保持简洁。”

[记住] [这次忽略] 不再提示
```

用户选择：

- 记住：写入对应类别。
- 这次忽略：本次不写，下次类似内容仍可再提示。
- 不再提示：加入 never list，后续类似内容不再打扰。

未处理的候选在重新打开 session 后应恢复显示。

## 6. 自动写入策略

### 6.1 可以自动写入

满足这些条件时可以自动写：

- 内容低敏。
- 置信度高。
- 和已有记忆不冲突。
- 对未来对话明显有用。
- 不在用户的“不再提示”列表中。

典型可自动写：

- 明确的称呼和助手昵称。
- 本轮明确完成的交付。
- 最近正在持续推进的工作。
- 已有当前关注或近期动态的同主题更新。

### 6.2 默认需要确认

这些内容默认候选确认：

- 长期回答偏好。
- 长期工作方式。
- 文档和报告偏好。
- 用户工作背景。
- 较敏感或不确定的近期事项。

### 6.3 必须跳过

这些内容不进入记忆：

- 一次性问答。
- 普通闲聊。
- 临时情绪。
- 密码、token、手机号、证件号、地址等敏感信息。
- 外部事实本身。
- 能从文件、知识库、项目目录重新读取的内容。
- pinvou 自己的运行状态和调试信息。

## 7. 数据结构

### 7.1 存储目录

```text
~/.pinvou3/user/memory/
  profile.json
  preferences/
    <topic>.json
  work_context/
    <topic>.json
  current_focus.jsonl
  recent_activity.jsonl
  recent_work.jsonl        # 兼容旧近期工作
  _pending.jsonl
  _never.jsonl
  snapshot.md              # 同步记忆时生成的设备记忆调试快照，不是事实源
  runtime/
    <session_id>.md
```

### 7.2 用户画像 profile

用于保存稳定、低敏的用户资料和输出习惯。

```json
{
  "version": 1,
  "revision": 1,
  "updated_at": "时间",
  "identity": {
    "call_name": "用户希望被如何称呼",
    "assistant_alias": "用户如何称呼助手"
  },
  "conventions": {
    "language": "默认语言",
    "doc_standard": "稳定文档标准",
    "number_usage": "稳定数字用法",
    "style_notes": ["稳定输出习惯"]
  }
}
```

### 7.3 长期偏好 preferences

一条偏好描述一个长期习惯。

```json
{
  "id": "唯一标识",
  "kind": "preference",
  "topic": "answer_style | workflow_preference | document_preference",
  "scope": "unconditional",
  "text": "清洗后的偏好内容"
}
```

标准 topic：

| topic | 含义 |
|---|---|
| `answer_style` | 回答风格、长短、语气、结构 |
| `workflow_preference` | 开发、测试、协作、处理任务的习惯 |
| `document_preference` | 报告、PPT、公文、表格等办公交付偏好 |

### 7.4 工作背景 work_context

记录用户长期工作画像，每个 topic 尽量只有一条主记忆。

```json
{
  "id": "唯一标识",
  "kind": "work_context",
  "topic": "role_domain | project_context | task_pattern | tooling_context | output_expectation",
  "text": "清洗后的用户工作背景",
  "source": "来源",
  "confidence": 0.9,
  "created_at": "时间",
  "updated_at": "时间"
}
```

标准 topic：

| topic | 含义 |
|---|---|
| `role_domain` | 用户长期角色、行业、领域 |
| `project_context` | 用户长期维护或持续参与的项目 |
| `task_pattern` | 用户经常做的任务类型 |
| `tooling_context` | 用户稳定使用的工具流 |
| `output_expectation` | 用户长期期待的交付物形态 |

### 7.5 当前关注 current_focus

记录最近正在推进、短期内可能继续有用的事项。

```json
{
  "id": "唯一标识",
  "kind": "current_focus",
  "topic": "current_work",
  "text": "正在推进的事项",
  "source": "来源",
  "confidence": 0.9,
  "created_at": "时间",
  "updated_at": "时间",
  "last_hit": "最近命中时间",
  "ttl_days": 21,
  "status": "active | archived"
}
```

### 7.6 近期动态 recent_activity

记录最近完成的交付或重要进展。

```json
{
  "id": "唯一标识",
  "kind": "recent_activity",
  "topic": "completed_work",
  "text": "已完成的事项及可复用线索",
  "source": "来源",
  "confidence": 0.9,
  "created_at": "时间",
  "updated_at": "时间",
  "last_hit": "最近命中时间",
  "ttl_days": 14,
  "status": "active | archived"
}
```

近期动态的内容应尽量回答：

- 完成了什么。
- 产物是什么。
- 主题或关键结论是什么。
- 后续继续该主题时有什么线索。

### 7.7 待确认 pending

保存自动发现但还没得到用户确认的记忆候选。

```json
{
  "id": "唯一标识",
  "kind": "profile | preference | work_context | current_focus | recent_activity",
  "topic": "主题",
  "content": "候选记忆内容",
  "source": "来源",
  "status": "pending_confirm | confirmed | ignored",
  "seen_count": 1,
  "created_at": "时间",
  "updated_at": "时间"
}
```

`pending` 不注入模型上下文。

### 7.8 不再提示 never

保存用户明确选择“不再提示”的内容模式。

```json
{
  "id": "唯一标识",
  "pattern": "不再提示的内容",
  "reason": "user_selected",
  "created_at": "时间"
}
```

`never` 不注入模型上下文，只用于候选过滤。

### 7.9 设备记忆快照 snapshot.md

`snapshot.md` 是给调试和跨设备排查用的单文档。

- 用户在记忆中心点击“同步记忆”时生成或覆盖。
- 内容包括长期记忆、近期记忆、待确认、不再提示、当前 session 的 runtime 摘要，以及底部结构化 JSON 快照。
- 它不是事实源，不参与记忆清洗，不直接注入模型。
- 真正的记忆仍以 `profile.json`、`preferences/`、`work_context/`、`current_focus.jsonl`、`recent_activity.jsonl` 等结构化文件为准。

### 7.10 Runtime Memory

`runtime/<session_id>.md` 是派生缓存，用于给模型注入短摘要。

```text
<pinvou_user_memory>
权威层级：低于用户当前指令；与本轮冲突以本轮为准。

画像：
- ...

长期偏好：
- ...

工作背景：
- ...

当前关注（会过期）：
- ...

近期动态（会过期）：
- ...
</pinvou_user_memory>
```

runtime 文件不是事实源，可以删除后重建。

## 8. 注入策略

只注入已经生效、未过期、允许使用的记忆。

不注入：

- `_pending`
- `_never`
- archived 记忆
- 过期近期记忆
- 原始聊天记录
- 工具日志
- 文件内容

注入优先级：

1. 用户画像
2. 长期偏好
3. 工作背景
4. 当前关注
5. 近期动态
6. 兼容旧近期工作

建议总注入量控制在 2K 到 3K tokens 以内。

---

## 9. 数量和长度限制

这些限制是产品边界。内容是否值得记、如何总结，仍由 LLM 判断。

| 类别 | 存储上限 | 单条长度建议 | 注入上限 |
|---|---:|---:|---:|
| `profile` | 固定 schema | 称呼 24 字以内；习惯字段 80 字以内 | 全量注入 |
| `preferences` | active 20 条 | 120 字以内 | 最多 20 条 |
| `work_context` | 5 个标准 topic | 160 字以内 | 最多 5 条 |
| `current_focus` | active 8 条 | 180 字以内 | 最近 3 条 |
| `recent_activity` | active 20 条 | 180 字以内 | 最近 5 条 |
| `recent_work` | 兼容层 | 80 字摘要 | 最近 3 条 |
| `_pending` | 20 条 | 120 字以内 | 不注入 |
| `_never` | 200 条 | 120 字以内 | 不注入 |

超限时优先合并同主题内容，其次归档低命中或较旧内容。不要直接把一句话截断成残句。

---

## 10. 过期和合并

### 10.1 长期记忆

长期记忆默认不过期，但同主题应合并，不应无限新增。

例如：

- 旧：回答风格要求简洁。
- 新：回答默认先给结论，整体保持简洁。

应合并为：

- 回答默认先给结论，整体保持简洁。

### 10.2 当前关注

当前关注默认约 21 天有效。

如果后续对话再次命中同主题，可以续期或更新内容。如果任务完成，应转为近期动态，旧当前关注可归档。

### 10.3 近期动态

近期动态默认约 14 天有效。

过期后不再注入。重要动态如果反复出现，可能被提炼为长期工作背景或长期偏好。

### 10.4 候选记忆

候选记忆按内容去重。同一条候选不应重复弹。

用户选择：

- 忽略：本次关闭。
- 不再提示：加入 never，后续类似内容不再生成候选。

---

## 11. 记忆中心

设置页只保留一个“记忆”入口，不展开全部细节。

入口展示：

- 当前是否启用。
- 记忆有什么用。
- 已记录多少有效记忆。
- 开启后显示“查看和管理”。

记忆中心分两页：

| 页面 | 内容 |
|---|---|
| 长期记忆 | 称呼、助手昵称、长期偏好、工作背景 |
| 近期记忆 | 当前关注、近期动态 |

每条记忆支持：

- 查看
- 编辑
- 删除
- 归档（仅近期记忆）

不需要“添加记忆”作为主入口。记忆应主要由 AI 自动整理，用户只在必要时管理。

---

## 12. 非记忆内容

以下内容不要放进用户记忆：

| 内容 | 应该归属 |
|---|---|
| 当前 session 聊天历史 | session 历史 |
| 生成的文件、PPT、报告、图片 | 产物系统 |
| 用户上传或挂载的文档 | 本地知识库 / 文件系统 |
| 项目目录、代码文件、配置文件 | 工作区 / 文件系统 |
| pinvou 当前模型、运行参数、调试路径 | 系统状态 |
| 工具调用原始日志 | session / debug 日志 |
| 外部事实、新闻、行情 | 搜索或知识来源，不作为用户记忆 |

记忆只记录“关于用户、用户偏好、用户长期工作背景、用户当前关注和近期动态”的摘要。

## 13. 当前方案结论

最终设计可以概括为：

```text
长期记忆：记住用户是谁、偏好什么、长期做什么。
近期记忆：记住用户最近在推进什么、刚完成什么。
短期上下文：只服务当前 session，不变成全局记忆。
候选确认：长期或不确定内容先问用户。
自动写入：低敏、高置信、近期工作类内容可以自动写。
用户控制：总开关 + 记忆中心 + 单条编辑/删除/归档。
模型注入：只注入生效摘要，不注入 pending / never / 原始历史。
```

这套方案的关键不是“记得越多越好”，而是“只把后续真正有用的用户信息整理成短、准、可过期、可管理的记忆”。
